# Catty Agent Protocol v1

## 1. Scope and conventions

`protocol_version` is `"1.0"`. All Catty-defined external JSON field names use
`snake_case`. JSON Schema keywords such as `additionalProperties` retain their
standard spelling.

The service is loopback-only. v1 operates exclusively on an in-memory
`MockWorld`; no real C++ world object or pointer crosses this protocol.

IDs generated by the service use `crypto.randomUUID()`:

- `request_id`
- `session_id`
- `world_id`
- `tool_call_id`
- `entity_id`
- `undo_token`

Timestamps are Unix epoch milliseconds.

## 2. Canonical envelope

The canonical envelope is:

```json
{
  "protocol_version": "1.0",
  "request_id": "b2894e08-a2ce-4db2-90dd-9362f98825a2",
  "session_id": "2d8f6082-9c9c-4791-8d5d-f2af00c1113f",
  "world_id": "3d73d0f1-123f-4824-ae4e-eae96397547b",
  "type": "tools.execute",
  "timestamp_ms": 1785312000000,
  "payload": {
    "tool_calls": []
  }
}
```

`POST /v1/tools/execute` accepts this canonical form. For local scripting it
also accepts the documented flat form. `POST /v1/agent/run` uses its concise
endpoint-specific body.

An unsupported version returns `UNSUPPORTED_PROTOCOL_VERSION`.

## 3. Sessions and worlds

`POST /v1/sessions` creates a Session and its default MockWorld:

```json
{
  "ok": true,
  "protocol_version": "1.0",
  "session_id": "2d8f6082-9c9c-4791-8d5d-f2af00c1113f",
  "world_id": "3d73d0f1-123f-4824-ae4e-eae96397547b",
  "world_revision": 0,
  "error": null
}
```

Sessions and worlds are process-local and in memory. A Session owns exactly one
MockWorld in v0.1.

A world snapshot has this shape:

```json
{
  "world_id": "3d73d0f1-123f-4824-ae4e-eae96397547b",
  "revision": 1,
  "entities": [],
  "history": []
}
```

An Entity contains:

```json
{
  "entity_id": "3402b82a-6d81-44c8-819a-70bea25907ca",
  "generation": 1,
  "name": "cube_1",
  "entity_type": "primitive",
  "primitive_type": "cube",
  "transform": {
    "position": [0, 0, 0],
    "rotation": [0, 0, 0],
    "scale": [1, 1, 1]
  },
  "properties": {
    "color": [1, 1, 1, 1],
    "visible": true,
    "label": ""
  }
}
```

Limits:

- `primitive_type`: `cube`, `sphere`, `cylinder`, `plane`
- `position`: three finite numbers from -100000 through 100000
- `rotation`: three finite Euler-angle numbers from -360000 through 360000
- `scale`: three finite numbers greater than 0.0001 and at most 10000
- `color`: four finite numbers from 0 through 1 (RGBA)
- `label`: at most 256 characters
- no arbitrary properties

## 4. Tool definitions

Every registry entry has `name`, `description`, JSON `schema`,
`mutates_world`, `undoable`, and `execute`. All argument schemas use
`additionalProperties: false`.

| Tool | Mutation | Undoable | Arguments |
| --- | --- | --- | --- |
| `world.get_summary` | no | no | `{}` |
| `world.query_entities` | no | no | optional exact `name`, `entity_type`, `primitive_type`, `limit` |
| `entity.get` | no | no | `entity_id` |
| `entity.spawn_primitive` | yes | yes | `primitive_type`; optional `name`, partial `transform`, allowlisted `properties` |
| `entity.set_transform` | yes | yes | `entity_id`, non-empty partial `transform` |
| `entity.set_property` | yes | yes | `entity_id`, `property_name`, correctly typed `value` |
| `entity.destroy` | yes | yes | `entity_id` |
| `history.undo` | yes | no | optional `undo_token`; defaults to latest available |

`entity.set_property.property_name` is restricted to `color`, `visible`, and
`label`.

## 5. ToolCall and ToolResult

ToolCall:

```json
{
  "tool_call_id": "6d3411b8-020e-423a-a1e4-5eb610c69a91",
  "tool_name": "entity.spawn_primitive",
  "expected_revision": 0,
  "dry_run": false,
  "args": {
    "primitive_type": "cube",
    "properties": {
      "color": [1, 0, 0, 1]
    }
  }
}
```

Successful ToolResult:

```json
{
  "ok": true,
  "request_id": "b2894e08-a2ce-4db2-90dd-9362f98825a2",
  "tool_call_id": "6d3411b8-020e-423a-a1e4-5eb610c69a91",
  "before_revision": 0,
  "after_revision": 1,
  "changes": [
    {
      "operation": "spawn",
      "entity_id": "3402b82a-6d81-44c8-819a-70bea25907ca",
      "before": null,
      "after": {}
    }
  ],
  "undo_token": "3a797fd1-7827-40cb-bd7e-b037d47e9346",
  "error": null,
  "data": {},
  "dry_run": false
}
```

`changes` contains structured before/after data. `data` contains the tool's
read result or resulting entity.

## 6. Error model

Stable errors have this shape:

```json
{
  "code": "INVALID_ARGUMENT",
  "message": "Invalid arguments for tool entity.spawn_primitive",
  "details": {},
  "retryable": false
}
```

Defined codes:

- `INVALID_REQUEST`
- `UNSUPPORTED_PROTOCOL_VERSION`
- `UNKNOWN_SESSION`
- `UNKNOWN_WORLD`
- `UNKNOWN_TOOL`
- `INVALID_ARGUMENT`
- `ENTITY_NOT_FOUND`
- `REVISION_CONFLICT`
- `PERMISSION_DENIED`
- `MODEL_OUTPUT_INVALID`
- `EXECUTION_FAILED`
- `UNDO_NOT_AVAILABLE`
- `REQUEST_TOO_LARGE`
- `BUSY`
- `TIMEOUT`
- `INTERNAL_ERROR`

Common HTTP mappings are 400 for malformed input, 403 for permission denial,
404 for unknown resources/tools/entities, 409 for revision/busy conflicts, 413
for oversized bodies, 500 for execution/internal failures, and 504 for timeout.

## 7. Revision and idempotency

- Read-only transactions do not change `world_revision`.
- A successful transaction containing one or more writes increments revision
  exactly once.
- A failed transaction does not change revision.
- `dry_run: true` performs protocol, revision, registry, schema, and execution
  checks against temporary state, returns predicted changes, creates no undo
  record, and does not change revision.
- All ToolCalls in a batch must have the same `expected_revision` and
  `dry_run` value.
- A revision mismatch returns `REVISION_CONFLICT` before mutation.

`request_id` is idempotent within its Session. Repeating a completed request
returns the first result with `"replayed": true` and does not execute again.
Concurrent repeats wait for the first request. A different request while the
same Session is executing may return retryable `BUSY`.

## 8. Batch transactions

`POST /v1/tools/execute` accepts `tool_calls`. The batch is atomic by default:

1. every ToolCall and argument set is validated;
2. a structured clone of MockWorld and UndoJournal state is captured;
3. tools run in array order;
4. all changes commit together, or all world/journal state is restored;
5. a successful write batch receives one revision increment and one
   `undo_token`.

On failure, `failed_tool_call_index` identifies the failing array index.
Earlier ToolResults are marked `rolled_back: true`. `history.undo` must be the
only call in its transaction.

Flat request example:

```json
{
  "protocol_version": "1.0",
  "request_id": "b2894e08-a2ce-4db2-90dd-9362f98825a2",
  "session_id": "2d8f6082-9c9c-4791-8d5d-f2af00c1113f",
  "world_id": "3d73d0f1-123f-4824-ae4e-eae96397547b",
  "tool_calls": [
    {
      "tool_call_id": "6d3411b8-020e-423a-a1e4-5eb610c69a91",
      "tool_name": "entity.spawn_primitive",
      "expected_revision": 0,
      "dry_run": false,
      "args": {
        "primitive_type": "cube"
      }
    }
  ]
}
```

Batch response:

```json
{
  "ok": true,
  "request_id": "b2894e08-a2ce-4db2-90dd-9362f98825a2",
  "tool_results": [],
  "world_revision": 1,
  "undo_token": "3a797fd1-7827-40cb-bd7e-b037d47e9346",
  "error": null,
  "replayed": false
}
```

## 9. Undo

v0.1 can undo only the latest successful write transaction for a world. The
token becomes unusable after a successful undo. Undo:

- restores the complete pre-transaction MockWorld state;
- supports spawn, transform, property, destroy, and a full batch;
- increments to a **new** revision instead of moving revision backward;
- returns `UNDO_NOT_AVAILABLE` for missing, stale, or reused tokens.

The UndoRecord currently stores a structured clone of the pre-transaction
MockWorld. This is a MockWorld-only temporary strategy. A future C++ adapter
must replace it with engine-native stable entity handles, ChangeSets,
transaction boundaries, and undo application.

## 10. Endpoints

### `GET /v1/health`

Returns:

```json
{
  "ok": true,
  "protocol_version": "1.0",
  "mock": true,
  "busy": false,
  "status": "mock (no CURSOR_API_KEY)"
}
```

### `POST /v1/sessions`

Body may be `{}` or `{ "protocol_version": "1.0" }`. Returns HTTP 201 and the
new Session/World identifiers.

### `POST /v1/agent/run`

Request:

```json
{
  "session_id": "2d8f6082-9c9c-4791-8d5d-f2af00c1113f",
  "request_id": "b2894e08-a2ce-4db2-90dd-9362f98825a2",
  "message": "生成一个红色立方体",
  "expected_revision": 0
}
```

Optional fields are `protocol_version` and `world_id`.

Response:

```json
{
  "ok": true,
  "request_id": "b2894e08-a2ce-4db2-90dd-9362f98825a2",
  "assistant_message": "已生成一个红色立方体。",
  "tool_results": [],
  "world_revision": 1,
  "undo_token": "3a797fd1-7827-40cb-bd7e-b037d47e9346",
  "error": null,
  "replayed": false
}
```

Provider text is never authoritative. If any tool fails, AgentService replaces
the provider's text with a failure message based on CommandExecutor's result.

### `POST /v1/tools/execute`

Accepts the canonical `tools.execute` envelope or the flat batch form shown in
section 8. Returns the batch response and ToolResults.

### `GET /v1/world/snapshot`

Query:

```text
/v1/world/snapshot?session_id=<uuid>&world_id=<optional-uuid>
```

Response:

```json
{
  "ok": true,
  "protocol_version": "1.0",
  "snapshot": {},
  "error": null
}
```

### `POST /v1/history/undo`

Request:

```json
{
  "session_id": "2d8f6082-9c9c-4791-8d5d-f2af00c1113f",
  "request_id": "40644ffc-0e8a-4405-bba4-9dbd9d744996",
  "expected_revision": 1,
  "undo_token": "3a797fd1-7827-40cb-bd7e-b037d47e9346"
}
```

`undo_token` may be omitted to request the latest available transaction.
Optional fields are `protocol_version`, `world_id`, `tool_call_id`, and
`dry_run`.

### `GET /v1/events`

Accepts optional `after=<integer>` and returns the same bounded event stream as
the legacy endpoint with `ok` and `protocol_version` added.

## 11. Legacy compatibility

The following endpoints remain available with their original fields, status
codes, and asynchronous `/chat` -> `/events` flow:

- `GET /health`
- `POST /chat`
- `GET /events`
- `POST /shutdown`

FilterScreenProbes 代码解析

RenderLumenScreenProbeGather 的第四个子阶段。它拿着 TraceScreenProbes 填满的、每根光线的 incoming radiance（噪声很大、每 probe 只有极少采样），通过"合成 → 时域累积 → 空域滤波 → 转 irradiance → 补边界 → 生成 mip"六道工序，把稀疏噪声数据处理成平滑、可被下一阶段双线性插值的 probe 辐照度场，写入 GatherParameters。这是把"少量样本"变成"能用信号"的降噪阶段。

完整源码对照

以下是 FilterScreenProbes 的完整 C++ 编排源码。各 CS 与滤波核细节见函数附录。

Engine/Source/Runtime/Renderer/Private/Lumen/LumenScreenProbeFiltering.cpp

0. 核心思想：从稀疏噪声到平滑可积分信号

① CompositeTraces（每光线结果 → gather 分辨率 radiance）
② CalculateMoving（供时域用的运动标记）
③ 时域滤波（跨帧累积，可选）
④ 空域滤波（跨邻居 probe 加权，多 pass，可选）
⑤ ConvertToIrradiance（SH3 / Octahedron 分叉）
⑥ FixupBorders + ⑦ GenerateMip（供双线性 + mip 采样）

说明

上一阶段 TraceScreenProbes 交出的 radiance 是极度欠采样的：每 probe 只发了几十根光线、每根一个方向，直接用会满屏噪点。FilterScreenProbes 的任务就是把这些稀疏样本变成能被下一阶段安全插值的平滑信号。

它的策略是多轴累积样本：时域上跨帧复用历史 probe（等效增加采样数），空域上跨相邻 probe 加权（等效扩大采样核），二者都靠"重投影 + 权重判定"避免拖影/漏光。

最后把方向性 radiance 压成积分友好的表示（SH3 系数或 octahedron irradiance 图），再补边界、建 mip，让 InterpolateAndIntegrate 阶段可以用一次双线性 + mip 采样就拿到某方向的辐照度。

1. CompositeTraces：光线 scatter 合成（汇聚起点）

FScreenProbeCompositeTracesWithScatterCS ... GroupPerProbe
RWScreenProbeRadiance / HitDistance / TraceMoving / ExtraAO
MaxRayIntensity = min(CVar, 100000)  // 量化到 uint 前的钳制
permutation: ThreadGroupSize / StructuredImportanceSampling / ExtraAO

说明

汇聚第一步把 trace 缓冲里"每根光线一个结果"scatter 合成到 gather octahedron 分辨率的 radiance 图。注意 tracing 分辨率与 gather 分辨率可能不同——重要性采样阶段发的光线方向是不规则的，这里要把它们按方向落回规整的 gather octahedron 格子。

不同点FStructuredImportanceSampling 为真时，光线来自结构化采样表，需要按 RayInfo 解出方向再 scatter；为假时是规则映射。MaxRayIntensity 把亮度钳到上限，因为合成过程会量化到 uint（防止个别超亮样本造成精度灾难，也抑制萤火虫噪点）。

同时产出 HitDistance（供空域滤波判断邻居是否可信）、TraceMoving（供下一步算运动）、ExtraAO（可选环境光遮蔽）。GroupPerProbe 表示一个线程组负责一个 probe 的整张 octahedron。

2. CalculateMoving：每 probe 运动标记

FScreenProbeCalculateMovingCS ... GroupPerProbe
ScreenProbeTraceMoving → RWScreenProbeMoving
DebugForceTracesMoving（调试可强制全部为运动）

说明

把上一步产出的、每根光线的 TraceMoving 信息归约成"每 probe 一个"运动标记 ScreenProbeMoving。所谓 moving，指这个 probe 看到的场景内容在运动（命中了动态物体）。

这个标记后续用于时域/空域滤波的权重：运动区域应减少历史权重，避免拖影；静止区域可以放心累积历史以降噪。它是连接"降噪强度"与"画面运动"的开关信号。

3. 时域滤波：跨帧重投影累积（可选发散）

bUseProbeTemporalFilter = UseProbeTemporalFilter() && 历史有效
    && !bCameraCut && !bPrevTransformsReset && Extent/Format 匹配
FScreenProbeTemporallyAccumulateTraceRadianceCS ... ThreadPerGather
HistoryWeight = 0.5   HistoryUVMinMax（排视口外双线性）
保存历史 = CompositedScreenProbeRadiance（时域滤波前！）

说明

发散整个 pass 由 bUseProbeTemporalFilter 门控——需要历史纹理有效、非相机切换、非变换重置、且历史尺寸/格式匹配。任一不满足就跳过，只靠空域滤波。

启用时，用上一帧保存的 HistoryScreenProbeTranslatedWorldPosition 做重投影，把历史 probe radiance 采样回当前 probe 并按 HistoryWeight=0.5 混合（指数移动平均）。HistoryUVMinMax 把采样限制在有效视口内，避免双线性读到视口外脏数据。

一个关键细节：汇聚保存到历史的是 CompositedScreenProbeRadiance——即合成后、时域滤波前的版本，而不是滤波后的结果。这样能避免历史反馈自我强化（否则 EMA 会无限自累积、导致过度平滑和拖影）。

4. 空域滤波：邻域 probe 加权（可选，多 pass）

UseProbeSpatialFilter() && HalfKernelSize > 0
for PassIndex in [0, NumPasses):
    FScreenProbeFilterGatherTracesCS ... ThreadPerGather
    MaxRadianceHitAngle / PositionWeightScale / HalfKernelSize
    ping-pong: ScreenProbeRadiance / ExtraAO 逐 pass 交换
保存历史 = ScreenProbeRadiance（最终滤波后）

说明

发散同样由 UseProbeSpatialFilter() && HalfKernelSize>0 门控。启用时循环 GLumenScreenProbeSpatialFilterNumPasses 次，每 pass 对每个 gather texel 采样邻居 probe 的同方向 radiance，按角度权重（SpatialFilterMaxRadianceHitAngle）和位置权重（PositionWeightScale + HitDistance）加权平均。

不同点permutation FScreenProbeDisocclusion 决定是否额外做去遮挡处理（新出现区域历史无效时更依赖空间邻居）。每 pass 通过 SpatialFilterPassIndex 调整核行为，纹理在 FilteredScreenProbeRadiance 与源之间 ping-pong。

汇聚与时域相反，这里保存到历史的是最终滤波后的 ScreenProbeRadiance（写入 ImportanceSamplingHistory + SceneDepth + WorldPosition + ViewRect），因为下一帧的重要性采样和时域重投影都需要"这一帧最好的结果"作参考。

5. ConvertToIrradiance：转积分友好表示（大分叉）

Format = GetScreenProbeIrradianceFormat(ShowFlags, AOIntensity)
if SH3:  SHAmbient(1 texel) + SHDirectional(6 texel 宽)
else:    IrradianceWithBorder（octahedron irradiance 图）
WaveOpWaveSize: 64 优先 / 32 次选 / 0 无 wave（仅 TGSize^2<=64）
FScreenProbeConvertToIrradianceCS ... GroupPerProbe

说明

发散这是本阶段的第二处大分叉，由 GetScreenProbeIrradianceFormat 决定输出哪种表示：

SH3 路径：把整张 radiance octahedron 投影成 3 阶球谐——一张 SHAmbient（DC 项，每 probe 1 texel）加一张 SHDirectional（方向项，宽度×6 存 6 个系数）。极致紧凑，插值阶段用 SH 点乘余弦瓣即可得任意法线方向辐照度。Octahedron 路径：直接产出带边界的 irradiance 图，保留更多方向细节，适合需要 AO/方向性更强的场景。格式选择与 LumenAmbientOcclusionIntensity 相关。

不同点FWaveOpWaveSize 按硬件能力选 64/32/0——该 pass 需要跨线程归约（把 octahedron 所有方向积分成 SH 系数），wave intrinsics 可省掉 groupshared 同步。GroupPerProbe，一组算一个 probe。

6. FixupBorders + GenerateMip：为采样铺路（汇聚收尾）

FScreenProbeFixupBordersCS ... ThreadPerGatherWithBorder
→ ScreenProbeRadianceWithBorder（desc 带 NumMips 层）
for MipLevel in [1, NumMips):
    FScreenProbeGenerateMipLevelCS：ParentMip → 当前 Mip

说明

汇聚octahedron 映射的接缝处（面与面边界）在双线性采样时会跨越不连续的 UV。FixupBorders 生成一张带 border 的 radiance 图，把每个 octahedron 面的边缘像素复制/镜像到 border 区，这样下一阶段做双线性插值时不会读到错误的相邻面数据。

随后 GenerateMip 循环对 with-border 图逐级下采样，生成 GLumenScreenProbeGatherNumMips 层 mip 金字塔。插值积分阶段会根据表面粗糙度/锥角选择合适 mip——粗糙表面用高 mip（更模糊、噪声更少），光滑表面用低 mip（更锐利）。这就是用一次 mip 采样近似不同立体角积分的技巧。

最终总结

说明

FilterScreenProbes 是 Lumen Screen Probe Gather 的降噪核心。它接过 ③ TraceScreenProbes 那张每 probe 只有极少样本、噪声极大的 radiance 缓冲，通过时域（跨帧）与空域（跨邻居）两个维度累积等效采样，把稀疏噪声磨成平滑信号。

它的两处工程精髓值得记住：一是历史保存的时机差异——时域历史必须存"滤波前"版本以防反馈自累积，而重要性采样历史存"滤波后"版本供下一帧决策；二是ConvertToIrradiance 的表示分叉——SH3 极致紧凑、Octahedron 保方向细节，配合 FixupBorders + mip 金字塔，让下一阶段能以极低成本采样任意方向、任意粗糙度的辐照度。

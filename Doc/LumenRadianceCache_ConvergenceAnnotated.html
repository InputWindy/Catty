Radiance Cache 代码解析（世界空间辐照度缓存）

Lumen 的世界空间辐照度缓存，是 ③ TraceScreenProbes 里"屏幕外 / 光线没打中"时的远场兜底光源，也是 Lumen 能做无限反弹 / 远场 GI 的关键机制。核心是一组以相机为中心、按 clipmap 分级的世界空间 probe：每帧只在固定预算内重追一小部分 probe（其余复用历史），probe 沿各方向追进 Lumen Scene（Surface Cache）取辐照度，滤波后缓存成 atlas 供各特性插值采样。本页解析入口 LumenRadianceCache::UpdateRadianceCaches 的完整更新流水线。

上下文：谁调用它、它喂给谁

Radiance Cache 不在 ①~⑤ 的线性调用链上，而是一个跨阶段的世界空间依赖。它由 RenderLumenScreenProbeGather 在 ① 之后、③ 之前调用更新（见 ScreenProbeGather 主文档），产出的 FRadianceCacheInterpolationParameters 随后被 ③ TraceScreenProbes 作为远场兜底采样（SampleRadianceCacheInterpolated），也被 ② 的重要性采样、反射、半透明体积等复用。它内部追踪的命中点辐照度来自 Lumen Scene / Surface Cache。

1. 核心思想：为什么需要它、它凭什么便宜

说明

共同点和屏幕 probe 一样，它也是"稀疏采样 + 后续插值"的思路，也一样要 trace、filter、算 irradiance、补边生成 mip——流水线骨架和 ④ FilterScreenProbes 高度同构。

不同点屏幕 probe 是屏幕空间、每帧全量重建；Radiance Cache 是世界空间、跨帧持久、预算增量更新。正是"持久 + 预算"让它能覆盖屏幕外与远场，并以极低单帧成本模拟多次反弹（这一帧的 probe radiance 里已经含有上一帧其它 probe 的贡献）。

它是 Lumen 区别于纯屏幕空间 GI（如 SSGI）的本质所在：GI 不再受限于屏幕可见性。

2. Setup / Mark：clipmap 状态、atlas 分配、标记被用到的 probe

说明

作用：RadianceProbeIndirectionTexture 是一张 3D clipmap 纹理，存"某个世界格子对应哪个 probe 槽位"。Mark 阶段先全清为 invalid，再由各消费者广播回调，把"我这帧会采样到的世界位置"周围的格子标记为 used。

不同点标记是回调驱动的：谁要用 Radiance Cache，谁就往回调数组里 AddLambda。这样同一份世界缓存可以同时服务屏幕 probe、半透明体积、头发、反射，避免为每个特性各建一份。

共同点bPersistentCache 是贯穿全流程的开关，几乎每个 pass 都据它决定"复用历史 buffer"还是"从头分配 + 清零"。

3. Allocate + 预算：优先级直方图决定这帧重追谁

说明

作用：这是"预算重追"的心脏。不是每帧追所有 probe，而是给每个 probe 算一个优先级（越久没更新、越近相机越优先），用直方图 + 选桶在固定预算 NumProbesToTraceBudget 内挑出最该更新的一批。

共同点和 ② GenerateImportanceSamplingRays 的"固定预算下按重要性分配"是同一种工程思想——都是把有限算力投给收益最高的采样。

不同点② 分配的是"一个屏幕 probe 内的光线方向"；这里分配的是"整个世界里哪些 probe 值得重追"，粒度更粗、跨越帧。

4. GenTraceTiles + Trace：追进 Surface Cache 取命中辐照度

说明

作用：把选中的 probe 沿各方向追进场景。命中点的颜色不是现算的，而是直接读 Surface Cache（Lumen Scene 的表面辐照度缓存）——这一步把"光线打中物体后返回什么颜色"外包给了 Surface Cache 专题。

不同点硬件 RT 可用时走 RenderLumenHardwareRayTracingRadianceCache，软件路径走 RadianceCacheTraceFromProbes（Global SDF marching），二者产出同一份 atlas。↳ 下钻：Hardware Ray Tracing 后端解析（RenderLumenHardwareRayTracingRadianceCache 即其消费者之一）

共同点和 ③ TraceScreenProbes 一样是"trace tile + indirect dispatch + 命中读 Surface Cache"，可复用同一套 FLumenCardTracingParameters。

5. Filter / Irradiance / Mip：磨平并生成最终 atlas

说明

作用：追出来的 raw radiance 先空域滤波去噪，再按需算出辐照度与遮挡，最后补边 + 生成 mip 得到可被平滑插值采样的 FinalRadianceAtlas。

共同点"trace → filter → convert to irradiance → fixup borders + mip"这条尾链和 ④ FilterScreenProbes 几乎一模一样，连 mip 补边的动机（防插值时跨 probe 漏色）都相同。

不同点最后一步 ConvertToExternal 把所有 atlas / freelist / indirection 存回 RadianceCacheState（挂在 ViewState 上），这是屏幕 probe 没有的——它让缓存跨帧存活，是"持久 + 预算"得以成立的落点。

最终总结

一句话

Radiance Cache = 以相机为中心的 clipmap 世界 probe 场，每帧在固定预算内重追一小撮 probe（其余复用历史），probe 追进 Surface Cache 取辐照度、滤波缓存成 atlas，作为屏幕 probe 追丢时的远场兜底。

它用"持久 + 预算"两个设计，把"覆盖屏幕外 + 远场 + 多次反弹"这件本该很贵的事摊平到多帧，成本可控。

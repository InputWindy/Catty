1. Clipmap / Indirection：世界怎么映射到 probe

说明

RadianceProbeIndirectionTexture 是"世界坐标 → probe 槽位"的查找表；FinalRadianceAtlas 是"probe 槽位 → radiance"的存储。两者一间接、一存储，配合 clipmap 实现"近密远疏"的世界采样。

共同点octahedron 编码、补边、mip 与屏幕 probe / ④ 的做法一致，为的是可平滑插值、防漏色。

不同点indirection 是 3D clipmap（世界空间），屏幕 probe 的 indirection 是 2D（屏幕 tile）。

2. 预算调度：优先级直方图 + 选桶（为什么每帧只追一部分）

说明

作用：这是 Radiance Cache 单帧成本可控的关键。用一个直方图对所有候选 probe 的优先级做统计，再用"从高到低累加到吃满预算"的选桶法，O(桶数) 时间内定出本帧要更新的阈值，避免排序全部 probe。

不同点边界桶（正好跨过预算的那个桶）里的 probe 只追一部分，用 MaxTracesFromMaxUpdateBucket 控制，保证严格不超预算。

共同点"直方图分桶 + 选桶"是 Lumen 里反复出现的预算裁剪套路（tile 分类、trace compaction 亦是同源思路）。

3. 持久缓存：Free List 让 probe 跨帧存活

说明

作用：Free List 把 probe 槽位当内存池管理，实现"常驻 + 回收"。被持续采样的 probe 一直活着并偶尔重追；长期不用的被回收。这套机制配合预算重追，共同构成"跨帧持久"。

不同点只有 bPersistentCache 为真才迁移历史；一旦分辨率变化或全局光照突变（如切换天光），就退化为全量重建并解除预算限制，保证正确性优先。

5. RadianceCacheTraceFromProbes permutation

说明

共同点和 ③ TraceScreenProbes 的后端一样，都吃 FLumenCardTracingParameters（绑定 Surface Cache），命中后读表面缓存，未命中按天光/SDF 覆盖处理。

不同点Radiance Cache 的 trace 面向"世界 probe 的 octahedron 方向域"，而非"屏幕 probe 的方向域"；且 SkyVisibility 是它特有的 permutation（用于遮挡感知天光）。

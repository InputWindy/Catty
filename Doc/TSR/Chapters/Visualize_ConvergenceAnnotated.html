r.TSR.Visualize：把中间纹理染色 TSRVisualize.usf

TSR 的每个 pass 都会产出一堆中间纹理（DecimateMask、HistoryRejection、HistoryMetadata、ThinGeometry……），平时都是内部数据。VisualizeCS 把它们按 VisualizeId 取出来、映射成直观颜色写到输出：

if (VisualizeId == 0) OutputColor = DisplayHistorySampleCount(Ctx); // 累积了几帧 else if (VisualizeId == 1) OutputColor = DisplayParallaxDisocclusionMask(Ctx); else if (VisualizeId == 2) OutputColor = DisplayHistoryRejection(Ctx); // #4 拒绝 else if (VisualizeId == 4) OutputColor = DisplayResurrectionMask(Ctx); // #3 复活 else if (VisualizeId == 6) OutputColor = DisplaySpatialAntiAliasingMask(Ctx); else if (VisualizeId == 7) OutputColor = DisplayAntiFlickering(Ctx); else if (VisualizeId == 15) OutputColor = DisplayThinGeometry(Ctx); // #7 薄几何

16 种模式，一一对应前面各篇

16 个可视化模式（EVisualizeId 0~15）几乎就是前七篇的"体检项"：HistorySampleCount（#5 累积）、HistoryRejection/HistoryClamp（#4 拒绝）、ResurrectionMask/ResurrectedColor（#3 复活）、SpatialAntiAliasingMask（#6 空间AA）、AntiFlickering（防闪烁分析）、一组 ReprojectionField*（#2 重投影场 8~14）、ThinGeometry（#7）。完整含义见附录表。

怎么读这些颜色 Reading the colors

可视化的配色是有约定的——记住"红坏绿好、粉=相机切换"就能快速判断：

颜色含义（以样本数/拒绝可视化为例）
■ 绿 kGreen累积充分 / 历史被采纳 —— 健康区域
■ 橙 kOrange样本数中等，正在爬升
■ 红 kRed样本数低 / 历史被拒绝 —— 刚 disocclusion 或剧烈变化
■ 粉 kPink相机切换（camera cut）/ 该启发式被禁用
■ 青绿空间AA 兜底介入（#6）

调参用它，排 bug 也用它

举例：画面某处拖影 → 开 r.TSR.Visualize 2 看是不是该处历史被错误采纳（该红不红）；画面糊 → 开 r.TSR.Visualize 0 看样本数是不是一直上不去（大片红，说明历史反复被拒绝）；细线闪烁 → r.TSR.Visualize 15 看薄几何有没有被检测到。每个 CVar 的注释里都写了对应用哪个 Visualize 模式来调（例如重投影边缘外扩用 =11 调、历史复活用 =5 调）。

Overview / 概览模式 Tiled overview

EVisualizeId 有三个负值是概览：ShowFlag(-1) / Overview(-2) / ReprojectionFieldOverview(-3)。它们不是单张图，而是把多个模式渲染成小图拼成 4×4 宫格叠在画面中央（VisualizeRect 取输出的中间 1/2 区域），一眼看全 TSR 的状态：

Overview (-1/-2)样本数 / 视差遮挡 / 拒绝 / 复活 / 防闪烁 / 薄几何（若开）拼图
ReprojectionFieldOverview (-3)重投影场专项：Summary / Null·Clamped·Dilated Jacobian / Offset / Coverage / AA

ShowFlag 与 CVar 双入口

r.TSR.Visualize 默认 -1；也可用编辑器 VisualizeTSR show flag 触发概览。二者最终都走到同一个 FTSRVisualizeCS dispatch，只是概览会多次调用 Visualize() lambda 把不同 VisualizeId 的结果填进宫格瓦片（FVisualizeBufferTile）。

ITemporalUpscaler：TSR 只是"默认实现" The pluggable interface

回到最开始：整个 12-pass 的 TSR，对渲染器而言只是 ITemporalUpscaler 接口的一个实现。渲染器每帧只调接口的 AddPasses(GraphBuilder, View, Inputs)，拿回 FOutputs{ FullRes, NewHistory }——至于里面是 TSR 还是 DLSS，它并不关心。

class ITemporalUpscaler : public ISceneViewFamilyExtention { struct FInputs { OutputViewRect; TemporalJitterPixels; SceneColor; SceneDepth; SceneVelocity; PrevHistory; }; struct FOutputs { FScreenPassTexture FullRes; TRefCountPtr<IHistory> NewHistory; }; virtual FOutputs AddPasses(FRDGBuilder&, const FSceneView&, const FInputs&) const = 0; virtual float GetMinUpsampleResolutionFraction() const = 0; // 支持的最低渲染比例 virtual float GetMaxUpsampleResolutionFraction() const = 0; virtual ITemporalUpscaler* Fork_GameThread(...) const = 0; };

历史的自描述：GetDebugName 配对校验

接口有个精巧设计：IHistory（跨帧保存的历史）也带 GetDebugName()，且必须与产生它的 upscaler 的 GetDebugName() 指向同一个字符串常量。这样上一帧若是 DLSS 的历史、这一帧却切到了 TSR，引擎能立刻发现"历史类型不匹配"而安全丢弃，不会把 DLSS 的历史喂给 TSR 导致崩溃。IHistory 还实现 GetGPUSizeBytes() 用于显存统计。

DLSS / FSR / XeSS 如何接管 Third-party plugins

第三方上采样插件（NVIDIA DLSS、AMD FSR、Intel XeSS）不改引擎源码，只做一件事：实现 ITemporalUpscaler，把自己注册到全局 GTemporalUpscaler。选择由 r.TemporalAA.Upscaler 控制：

r.TemporalAA.Upscaler行为
0强制用渲染器默认上采样器（即 TSR 本体）
1（默认）用 GTemporalUpscaler——可被第三方插件覆盖；没插件时仍回落到 TSR

互斥约束：时序 vs 空间上采样

渲染器强制校验：TemporalUpscalerInterface 与 PrimarySpatialUpscalerInterface 不能同时存在（SceneRendering.cpp 的 checkf）——要么走时序上采样（TSR/DLSS/FSR2/XeSS），要么走纯空间上采样，不能既时序又空间地重复放大。另外 GetMainTAAPassConfig(View)==EMainTAAPassConfig::TSR 是很多 pass（如运动矢量、半透明合成）判断"是否走 TSR 路径"的开关，第三方 upscaler 接管时这些分支也随之改变。

全书收束 The whole picture

从一束抖动的采样到一帧稳定的 4K

八篇走完，TSR 的全貌清晰了：#1 低分辨率 + jitter + 跨帧累积的总设计 → #2 膨胀速度、编码重投影场，回答"这个像素上一帧在哪" → #3 用 guide 重投影历史、算 DecimateMask，回答"历史还能用吗" → #4 着色分析拒绝不可信历史，回答"哪里该丢历史" → #5 EMA 累积 + 权重松弛，回答"怎么把新旧融合" → #6 Nyquist 重建 + 空间AA 兜底，回答"被拒的像素怎么补" → #7 薄几何专项通道，回答"细线怎么救" → #8 可视化看穿内部、接口对外可替换。核心思想始终如一：用一套连续权重体系，在"复用历史"与"信任当前帧"之间为每个像素做最优判断。

1r.TSR.Visualize（16 模式 + 3 概览）把 TSR 内部中间量染色叠屏，是调参与排查鬼影/糊/闪烁的核心工具，配色约定"红坏绿好粉切换"。

2TSR 只是 ITemporalUpscaler 的默认实现；接口以 FInputs/FOutputs + 自描述 IHistory 让 DLSS/FSR/XeSS 可无缝替换。

3r.TemporalAA.Upscaler 选择默认 TSR 或第三方 GTemporalUpscaler；时序与空间上采样互斥。

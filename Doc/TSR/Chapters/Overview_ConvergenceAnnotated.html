#1 TSR 总览与设计动机 · 时序上采样为何可行

TSR 是 UE5 默认的时序上采样抗锯齿器：在低分辨率渲染，靠跨帧累积 + 亚像素抖动拼出高分辨率无锯齿画面。本篇建立全局直觉——为什么低分辨率能拼出高分辨率、jitter 的作用、历史（history）的角色、单帧 12 个 pass 的数据流全景、输入输出、以及 TSR 作为 ITemporalUpscaler 与 DLSS/FSR 的关系。符号取自 UE5.8 TemporalSuperResolution.cpp（3780 行）。

核心问题：为什么低分辨率能拼出高分辨率 Why temporal upsampling works

4K 一帧要着色约 800 万像素，是 1080p 的 4 倍。TSR 的赌注是：只在 1080p 着色，但每帧把采样点抖动到高分辨率网格的不同位置，再跨帧把这些采样拼起来——几帧之内，高分辨率网格的每个格子都被覆盖过，于是"重建"出一张 4K 图。

1低分辨率渲染场景在 View.ViewRect（如 1080p）着色，成本只有输出的 1/4
▶
2亚像素抖动 Jitter每帧相机投影矩阵加一个亚像素偏移，采样点落在高分辨率网格的不同子位置
▶
3跨帧累积把多帧不同采样点重投影对齐后累积进历史，重建高分辨率信号

抖动（jitter）是时序上采样的燃料

若每帧都在同一位置采样，累积再多帧也还是 1080p 的信息。TSR 靠每帧不同的亚像素 jitter（一个 Halton 序列偏移，加在投影矩阵的 TemporalJitterPixels 上）让连续帧采样到高分辨率网格的不同点——这与超分辨率成像里"多张微移照片合成一张高清图"是同一个原理。代价是：一旦画面变化（相机/物体运动、着色变化），历史里的采样点就可能不再对应当前几何，直接累积会拖影（ghosting）。所以 TSR 的绝大部分复杂度不在"累积"，而在判断历史哪些能信、能信多少——这就是中篇 #4/#5 的主题。

输入与输出：TSR 在管线里的位置 Inputs / Outputs

TSR 是一个 ITemporalUpscaler，在后处理链最前端运行。入口 AddTemporalSuperResolutionPasses 接收上一帧历史、产出这一帧历史与高分辨率 SceneColor：

FDefaultTemporalUpscaler::FOutputs AddTemporalSuperResolutionPasses( FRDGBuilder& GraphBuilder, const FViewInfo& View, const FDefaultTemporalUpscaler::FInputs& PassInputs, // SceneColor / Depth / Velocity（低分辨率） const FTSRPassConfig& PassConfig, // 一堆 r.TSR.* 打包成的配置 const FTSRHistory& InputHistory, // 上一帧历史（持久化纹理集） FTSRHistory& OutputHistory); // 本帧历史（喂给下一帧） // 分辨率：输入低、输出高（MainUpsampling 模式） FIntRect InputRect = View.ViewRect; // 如 1920×1080 OutputRect.Max = View.GetSecondaryViewRectSize(); // 如 3840×2160
输入 FInputs说明
SceneColor低分辨率、带 jitter 的场景颜色（Nanite/Lumen/MegaLights 的产物）
SceneDepth深度缓冲，用于重投影、速度膨胀、遮挡判定
SceneVelocity运动矢量（未覆盖处用相机运动推算），历史对齐的关键
PostDOFTranslucencyResources景深后的半透明，单独处理避免污染历史

TSR 吃的是"上游全部渲染的成果"

读过本文档集 Nanite 篇会很熟悉：SceneColor 是 Nanite visibility buffer 延迟着色 + Lumen GI + MegaLights 光照的最终合成，Velocity 由几何 pass 输出。TSR 位于这一切的最下游——它不关心颜色怎么来的，只负责把"低分辨率带抖动序列"重建成"高分辨率成片"。因此 TSR 的质量高度依赖上游 velocity 的正确性：velocity 错了，历史就对不齐，直接鬼影。

历史：TSR 的记忆 FTSRHistory

历史是 TSR 跨帧的持久化状态，一组 RDG 外部纹理，逐帧 ping-pong。它不只存颜色，还存累积所需的元数据：

历史内容作用
累积颜色 ColorArray核心：重建出的高分辨率颜色，逐帧加权累积
累积样本数 Metadata每像素已累积多少帧（上限 MaxHistorySampleCount），决定新帧权重
Moire / 闪烁 luma抑制周期性闪烁（开 ShadingRejectionFlickering 时存，ETSRHistoryFormatBits::Moire）
Alpha 通道支持带 alpha 的后处理时存（ETSRHistoryFormatBits::AlphaChannel）
Guide / 引导重投影与拒绝所需的引导信息
// 历史颜色格式：默认 R11G11B10 省带宽；需要 alpha 时退化到 RGBA16F EPixelFormat HistoryColorFormat = (PassConfig.HistoryR11G11B10 != 0 && !bSupportsAlpha) ? PF_FloatR11G11B10 : PF_FloatRGBA; // 累积样本上限，clamp 到 [8, 32]，默认 r.TSR.History.SampleCount = 16 const float MaxHistorySampleCount = FMath::Clamp(PassConfig.HistorySampleCount, 8.0f, 32.0f);

历史复活（History Resurrection）

UE5.8 的 TSR 支持历史复活（ResurrectionEnable）：除了最近几帧的 transient 历史，还周期性地（FrameStoragePeriod）把更早的历史存进纹理数组的额外 slice。当某像素的近期历史被判定失效、但更久前的历史其实仍有效（比如被短暂遮挡又露出）时，可以"复活"那份老历史，避免从零重建导致的糊。历史因此是一个纹理数组序列（FTSRHistorySliceSequence），FrameStorageCount clamp 到 [4, GMaxTextureArrayLayers]。

全景：单帧 12 个 pass 的数据流 The per-frame pipeline

按 GPU 单帧执行顺序（TemporalSuperResolution.cpp 中 AddPass 的调用次序），TSR 一帧跑这些 compute pass：

#Pass职责本书章节
0MeasureFlickeringLuma测量亮度用于闪烁抑制（可选）#4/#8
1ClearPrevTextures清理上帧临时纹理#8
2DilateVelocity速度膨胀 + 最近遮挡物 + 重投影场#2
3DecimateHistory把历史重投影、重采样到当前抖动网格#3
4DetectThinGeometry标记薄几何（细线/栅栏）#7
5WeightRelaxation权重松弛预处理#5/#7
6RejectShading着色拒绝：逐像素估计历史可信度#4
7SpatialAntiAliasing历史被拒时的空间 AA 兜底#6
8UpdateHistory按权重累积进历史（最大 pass，1426 行）#5
9ResolveHistory解析历史到输出分辨率 + 锐化#6
10Visualize调试可视化（可选）#8

一条主线 + 若干旁路

主线是 DilateVelocity → DecimateHistory → RejectShading → UpdateHistory → ResolveHistory 这五步：算清运动 → 对齐历史 → 判断历史可信度 → 加权累积 → 解析输出。其余都是为主线服务的旁路：MeasureFlickeringLuma/DetectThinGeometry/WeightRelaxation 为拒绝与累积提供额外信号，SpatialAntiAliasing 在历史完全不可信时兜底，Visualize 是调试窗口。多数 pass 可跑在 async compute（r.TSR.AsyncCompute），与图形队列并行。

质量分级：一套 permutation 三档画质 sg.AntiAliasingQuality

TSR 不为不同画质写不同代码，而是靠 shader permutation + 一组 CVar 的默认值随 sg.AntiAliasingQuality 缩放。核心开关：

CVar默认作用
r.TSR.History.SampleCount16每输出像素最多累积的帧数（越大越稳、highlight 越少噪）
r.TSR.History.ScreenPercentage100历史分辨率相对输出的倍率（>100 更清晰但更贵）
r.TSR.History.R11G11B101历史用 R11G11B10 省带宽（不支持 alpha 时）
r.TSR.History.UpdateQuality3UpdateHistory 的 permutation 档（Low/Medium/High/Epic）
r.TSR.ShadingRejection.SampleCount2历史被完全拒绝后重新累积的样本上限
r.TSR.RejectionAntiAliasingQuality3历史被拒时空间 AA 的质量
r.TSR.ReprojectionField0高质量重投影场（high/epic/cinematic 默认开）
r.TSR.WaveOps1在拒绝启发式的卷积里用 wave ops 加速
r.TSR.AsyncCompute—把 TSR pass 放 async compute 队列

TSR vs TAA/TAAU vs DLSS/FSR

TAA：时序抗锯齿，输入=输出分辨率，只抗锯齿不上采样。TAAU：TAA 上采样版，TSR 的前身，启发式较简单。TSR：UE5 自研，更强的着色拒绝启发式（甚至用小型卷积网络，见 #7）+ 重投影场 + 历史复活，在大幅上采样下仍稳。DLSS/FSR/XeSS：第三方上采样，通过同一个 ITemporalUpscaler 接口接入，与 TSR 互斥选择（见 #8）——它们吃相同的输入（低分辨率 SceneColor + Depth + Velocity + jitter），所以引擎侧的准备工作是共享的，区别只在"重建"这一步用谁的算法。

小结 Summary

1TSR 在低分辨率渲染、靠每帧亚像素 jitter + 跨帧累积重建高分辨率画面，成本远低于原生高分辨率。

2入口 AddTemporalSuperResolutionPasses 实现 ITemporalUpscaler，吃低分辨率 SceneColor/Depth/Velocity（上游 Nanite/Lumen/MegaLights 的产物），产出高分辨率 SceneColor 与本帧历史。

3历史（FTSRHistory）是持久化纹理集，存累积颜色 + 样本数 + 闪烁/alpha 元数据；UE5.8 支持历史复活用纹理数组存更久的历史。默认累积上限 16 帧。

4单帧 12 个 compute pass，主线是 DilateVelocity → DecimateHistory → RejectShading → UpdateHistory → ResolveHistory，其余为其提供信号或兜底，多数可跑 async compute。

5难点不在累积，而在抗鬼影——逐像素判断历史可信度（#4）与加权累积（#5）是全书核心。质量靠 sg.AntiAliasingQuality 驱动的 permutation + CVar 缩放。

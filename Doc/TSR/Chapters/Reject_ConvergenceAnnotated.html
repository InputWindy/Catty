#4 历史拒绝：抗鬼影的心脏 · 着色分析

全书最核心的一章。历史已对齐到当前帧，但对齐≠可信——着色变了、被遮挡过、有闪烁，历史都可能是错的。RejectShading pass 用一套着色分析卷积启发式逐像素估计历史可信度，产出连续的拒绝权重 RejectionBlendFinal。源码取自 UE5.8 TSRRejectShading.usf（953 行）+ TSRShadingAnalysis.ush（644 行）+ TSRColorSpace.ush（293 行）。

问题：对齐好的历史，凭什么信 The rejection problem

#2/#3 已把历史几何对齐到当前帧，也用 DecimateMask 标了遮挡失效。但还剩一大类历史失效不是几何问题而是着色问题：同一块几何，光照变了（灯亮了）、材质动了（水面波纹）、或者高频细节在亚像素抖动下本就会有差异。这些用深度/速度判断不出来——只能直接比对颜色。

不能简单做邻域 min/max clamp

老式 TAA 的抗鬼影是邻域颜色包围盒 clamp：把重投影历史 clamp 到当前帧 3×3 邻域的颜色 min/max 盒子里。简单但粗暴——盒子太紧会丢历史（变糊、闪），太松挡不住鬼影。TSR 的 RejectShading 换了思路：对"历史引导"和"当前输入"分别做同一套卷积滤波，比较滤波后两者的能量差，差得越多说明着色变化越剧烈、历史越不可信，拒绝权重越高。这是一套连续、空间平滑的启发式，而非硬 clamp。UE5.8 更进一步把这套启发式实现成卷积网络（见 #7），FTSRRejectShadingCS 直接继承 FTSRConvolutionNetworkShader。

MeasureRejection：拒绝启发式的核心 TSRShadingAnalysis.ush

核心函数 MeasureRejection 的逻辑骨架（简化自源码 494 行起）：

// 1. 对滤波后的历史做邻域 clamp，得到"被约束后的历史" tsr_tensor_half RawClampedEnergy = abs(ClampedFilteredHistory - FilteredHistory); // 2. clamp 改动越大 → 历史与当前差越多 → 拒绝越强。除以 Delta 归一化 tsr_tensor_half RawRejection = saturate(1.0 - max(RawClampedEnergy, 0.0) * rcp(Delta)); // 3. 空间滤波：Median3x3 去噪 + MaxRMinG3x3 形态学，避免单像素噪点乱拒绝 Deconcatenate(MaxRMinG3x3(Median3x3(Concatenate(RawClampedEnergy, RawRejection))), /* out */ FilteredClampedEnergy, /* out */ OutRejectionClampBlend); // 4. 最终拒绝权重（连续 [0,1]） OutRejectionBlendFinal = saturate(1.0 - max(FilteredClampedEnergy, 0.0) * rcp(Delta));
1滤波对历史引导与当前输入各跑卷积滤波（低通 + 形态学），压掉抖动噪声
▶
2Clamp 能量把滤波历史 clamp 到当前邻域，测量"被改动了多少"（ClampedEnergy）
▶
3归一化+空间平滑1 - Energy/Delta，再 Median/形态学滤波 → RejectionBlendFinal

Delta：拒绝的"容忍度"

Delta 是归一化尺度——它决定"多大的着色差异算作历史失效"。Delta 由输入的对比度、曝光、量化误差（HistoryGuideQuantizationError / SceneColorOutputQuantizationError）等共同决定：本来就该有的差异（量化噪声、HDR 高光的正常波动）不该触发拒绝。这就是为什么 TSR 要在感知均匀的颜色空间里做这件事，且要补偿量化误差——避免把"正常的数值噪声"误判成"着色变化"。

颜色空间：在感知均匀的地方比较 TSRColorSpace.ush

直接在线性 HDR 空间比颜色差是不行的：一个 1000 尼特的高光波动 10 尼特，和一个 1 尼特暗部波动 10 尼特，数值差相同，但人眼感知天差地别。TSR 用 HdrWeight 系列函数把颜色映射到感知/HDR 加权空间再比较：

// TSRColorSpace.ush：HDR 加权，让高光的大数值波动不至于压倒暗部 tsr_half2 HdrWeightY(tsr_half2 Luma); // 亮度 → HDR 权重 tsr_half2 HdrWeightInvY(tsr_half2 LDRLuma); // 逆变换 // 注：亮像素可能让 HdrWeight 在 fp16 下变 0，源码 clamp 到 ~0.000061（fp16 最小正规数附近）

闪烁（Moire/flickering）抑制

周期性闪烁（薄栅栏的摩尔纹、镜面高光的时序跳动）是拒绝启发式的死敌：每帧都"看起来变了"，会被持续拒绝，导致该区域永远累积不起来、一直糊/闪。当 DIM_FLICKERING_DETECTION 开启时，RejectShading 维护一份 Moire 历史（ClampPlus3x3(PrevFlickeringHistory, InputLuma)），跟踪像素亮度的周期性模式——如果一个像素是在稳定地"来回闪"而非"单向变化"，就识别为闪烁、放宽拒绝、允许它继续累积以平滑掉闪烁。这份 Moire 历史正是 #3 DecimateHistory 帮忙重投影过来的。

拒绝 ≠ 丢弃，而是"降权"

RejectionBlendFinal 是 [0,1] 的连续值：1 表示历史完全可信（几乎不用新帧，画面最稳），0 表示历史完全不可信（几乎全用新帧，等于退化到单帧、需要 #6 空间 AA 兜底）。绝大多数像素落在中间——TSR 的画质就取决于这个权重估得准不准：估太高 → 鬼影拖影；估太低 → 画面闪烁、糊、噪。ShouldSpatialAntiAlias 用 RejectionBlendFinal < 0.25（且可见锯齿/遮挡消失且不复活）来决定是否触发空间 AA。这套连续权重估计，就是 TSR 相比传统 TAA 在大幅上采样下仍稳的根本原因。

小结 Summary

1几何对齐解决不了着色变化类的历史失效，必须直接比对颜色——这就是 RejectShading 的职责。

2核心 MeasureRejection：对历史引导与当前输入各做卷积滤波，测 clamp 能量差，归一化+空间平滑成连续拒绝权重 RejectionBlendFinal，而非硬 min/max clamp。

3比较在 HDR 感知加权颜色空间做（HdrWeightY），并补偿量化误差，避免把正常噪声误判为着色变化。

4闪烁抑制用 Moire 历史识别周期性闪烁并放宽拒绝，救回栅栏/高光。UE5.8 把整套启发式实现为卷积网络（#7）。

5输出连续拒绝权重给 #5 累积、AntiAliasMask 给 #6 兜底。权重估得准不准，直接决定 TSR 的鬼影—清晰度平衡。

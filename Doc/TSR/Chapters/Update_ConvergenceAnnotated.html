#5 历史更新与累积 · 最大的 pass

拿到 #4 的拒绝权重后，UpdateHistory 把当前帧输入按权重累积进历史——这是 TSR 计算量最大的 pass（1426 行），决定了稳定性与清晰度的平衡点。本篇讲指数移动平均式累积、样本数上限、权重松弛、Catmull-Rom 重采样核、输出 mip 链。源码取自 UE5.8 TSRUpdateHistory.usf（1426 行）+ TSRWeightRelaxation.usf（263 行）+ TSRKernels.ush（455 行）。

累积的本质：加权指数移动平均 Exponential moving average

TSR 的历史累积，本质是一个逐像素的加权指数移动平均（EMA）：新历史 = 混合(旧历史, 当前输入)，混合比由 #4 的拒绝权重和已累积样本数共同决定。

// 概念式（真实代码分散在 1426 行里的多个分支） // 累积样本数越多 → 新帧占比越小 → 越稳定；被拒绝 → 样本数重置 → 新帧占比大 float NewFrameWeight = 1.0 / min(AccumulatedSampleCount + 1, MaxHistorySampleCount); NewFrameWeight = lerp(1.0, NewFrameWeight, HistoryValidity); // 拒绝时 validity↓ → 权重↑ NewHistory = lerp(ReprojectedHistory, CurrentInput, NewFrameWeight);
1重采样当前输入用 Catmull-Rom 核把低分辨率输入采到历史（高）分辨率网格
▶
2算混合权重结合拒绝权重、已累积样本数、histeresis，得每像素新帧占比
▶
3混合并写回lerp(历史, 输入)，更新样本数，输出历史 + 多级 mip

样本数 = 累积了多少帧 = 有多稳

每像素维护一个累积样本数（存在历史 metadata 里），上限 MaxHistorySampleCount（r.TSR.History.SampleCount=16，clamp[8,32]）。样本数越大，新帧的权重 1/N 越小——历史占主导，画面越稳、越少噪。当 #4 判定历史失效，样本数被按拒绝权重压低甚至重置，新帧权重回升，快速用当前内容替换掉不可信的历史。这就是"拒绝"如何落到"累积"上：拒绝不是丢弃历史，而是降低它的累积样本数。HistoryHisteresis 给这个过程加了迟滞，避免权重在边界反复横跳。

UpdateQuality：四档采样核 DIM_UPDATE_QUALITY

UpdateHistory 靠 DIM_UPDATE_QUALITY（0/1/2/3 = Low/Medium/High/Epic，默认 r.TSR.History.UpdateQuality=3）切换重采样核的形状与是否做拒绝抗锯齿：

档采样核 CONFIG_SAMPLES拒绝 AA
0 LowPLUS（十字 5 采样）关
1 MediumPLUS开
2 HighPLUS_MOVE_FAR（把最远采样移向最近角）开
3 EpicPLUS_MOVE_FAR开

采样核的取舍：范围 vs 锐度

累积时要把当前输入的一个邻域重采样到历史网格。采样越多（3X3）越平滑但越糊；越少（1X1）越锐但越容易 clamp 出错、闪。TSR 折中用 PLUS（十字 5 点）为主，高画质用 PLUS_MOVE_FAR——把十字最远的采样点移向离亚像素样本最近的角，在不增加采样数的前提下让重建更贴合真实信号位置。这类"编译期已知偏移方向 → 用 v_pk_max/min_i16 一条指令做 clamp"的优化贯穿 TSRKernels.ush，是 16bit ALU 榨性能的典型。

权重松弛：别让权重僵死 TSRWeightRelaxation

单纯的 EMA 有个病：某像素长期稳定后样本数顶到上限（16），此后即便内容开始缓慢变化，新帧权重也永远只有 1/16——历史太"重"，跟不上变化，表现为拖影或糊。WeightRelaxation pass（在 UpdateHistory 前跑）预处理这个问题：

float MaxRelaxationWeight; // 松弛后允许的最大权重 float TranslucencyRejectionThreshold; // 半透明区域的额外拒绝阈值 // 结合薄几何 coverage、Moire 亮度，适度"放松"僵死的累积权重

松弛 = 给历史"松绑"

WeightRelaxation 根据局部信号（薄几何 coverage、闪烁亮度、半透明覆盖）判断哪些像素的累积权重僵死得过头，把它们的有效样本数适度调低（等于抬高新帧权重上限 MaxRelaxationWeight），让历史能"跟上"缓慢变化——同时又不至于像完全拒绝那样丢掉稳定性。这是 TSR 在"稳定"与"响应"之间的精细调节旋钮，尤其对薄几何（#7）和半透明至关重要。它与 #4 的拒绝是互补的：拒绝处理"突变"，松弛处理"温水煮青蛙式的缓变"。

输出：历史 + mip 链 Output & mips

UpdateHistory 写出本帧历史（喂给下一帧），并按需生成多级 mip（bGenerateOutputMip1/2/3）：

RWTexture2DArray<tsr_halfC> SceneColorOutputMip1; // 半分辨率输出 if (bGenerateOutputMip1 || bGenerateOutputMip2 || bGenerateOutputMip3) { ... }

为什么顺手出 mip

后处理链的 bloom、景深等需要低分辨率版本的场景颜色。UpdateHistory 反正已经把全分辨率历史算出来了，顺手降采样出几级 mip 比后面单开 pass 再降采样便宜——又是 TSR "一次遍历多产出"的风格（#2 的速度展平同理）。累积好的历史即本帧的高分辨率场景颜色雏形，交给 #6 ResolveHistory 做最终解析与锐化。

小结 Summary

1累积本质是逐像素加权指数移动平均：新帧权重 ≈ 1/样本数，样本数上限默认 16。

2#4 的拒绝权重通过压低样本数作用于累积——拒绝即降权、重置，而非硬丢弃；HistoryHisteresis 给切换加迟滞。

3UpdateQuality 四档切换 PLUS / PLUS_MOVE_FAR 重采样核与拒绝 AA；核用 Catmull-Rom 双三次、16bit ALU 优化。

4权重松弛给僵死的累积权重"松绑"，处理缓变、薄几何、半透明，与拒绝互补。

5输出本帧历史 + 多级 mip 供后处理，累积结果交 #6 解析。这是全 TSR 最大、最影响观感的 pass。

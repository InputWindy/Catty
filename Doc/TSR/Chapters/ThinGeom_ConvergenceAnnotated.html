为什么薄几何是时序上采样的噩梦 The thin geometry problem

一根屏幕上只有 1 像素宽的电线，在 1080p 渲染、jitter 抖动下，某些帧的采样点根本落不到它身上——这一帧它"消失"了，下一帧又出现。累积历史时，这种"时有时无"会被 #4 判为剧烈着色变化 → 拒绝历史 → 无法累积 → 电线持续闪烁甚至断裂。常规的拒绝/累积逻辑对薄几何是失效的。

薄几何要"特殊照顾"

TSR 的对策：先识别出哪些像素属于薄几何（DetectThinGeometry，pass 4），给它们打上标记与 coverage，再在 #4 拒绝（DIM_THIN_GEOMETRY_DETECTION）和 #5 权重松弛里对这些像素用不同的策略：放宽拒绝、专门的权重松弛（MaxRelaxationWeight），甚至在 #2 DilateVelocity 里做专门的薄几何边缘重投影（DIM_THIN_GEOMETRY_EDGE_REPROJECTION）。目标是让细线即使"时有时无"也能稳定地累积、不闪不断。

DetectThinGeometry：怎么识别一根线 Line & edge detection

DetectThinGeometry 在深度/颜色上做边缘与线检测，区分"这是一条细线"还是"这是一大块几何的边界"：

1边缘检测水平/垂直/对角（EDGE_HORIZONTAL_VERTICAL_DIAGNAL）三方向的深度/强度梯度
▶
2线判定两侧都是"背景"、中间一条窄高对比 → 判为线（强度线检测 INTENSITY_LINE_DETECTION）
▶
3输出 coverage + 权重写薄几何 coverage 与 MaxRelaxationWeight，供 #4/#5 用

对比度门槛：别把噪声当细线

检测有几个关键旋钮：MinKeepLineContrast（低于此对比度的"线"不算，避免噪声误判）、HighContrastLineFadeRate / HighContrastLineWeight（高对比线的处理强度与淡出速率）。DIM_VARYING_RANGE_DETECTION 让检测在不同深度范围自适应——远处的线和近处的线在屏幕上宽度不同，检测尺度要跟着变。这些参数的本质是：在"救回真细线"和"别把材质纹理/噪声误判成线"之间划界。

TSRConvolutionNetwork：可复用的张量卷积原语 The convolution network

UE5.8 TSR 一个重要的工程演进：把散落在各 pass 的卷积启发式，统一抽象成 TSRConvolutionNetwork.ush——一套建立在 LaneVectorization.ush 之上的张量运算框架。

// 一个 wave 的 lane 按二维网格排布，每 lane 持有一小片像素（tsr_tensor） // LANE_COUNT_X=2, LANE_COUNT_Y=2, LaneStride=(4,2) // o o o o | o o o o ← 一个 wave 覆盖一片 tile // o o o o | o o o o 每 lane 处理 stride 内的多个像素 #define WAVE_COUNT (WAVE_COUNT_X * WAVE_COUNT_Y) #define LANE_COUNT (LANE_COUNT_X * LANE_COUNT_Y) // tsr_tensor_half / tsr_tensor_half4：跨 lane 的"张量"，卷积=lane 间 shuffle + 加权和

"卷积网络"不是深度学习那种大模型

别被名字误导——这里的"卷积网络"指的是把多层小卷积核（滤波器）串成一个可组合的信号处理管线，用 GPU 的 wave/lane 向量化高效执行：每个 lane 持有一小片像素张量（tsr_tensor），卷积操作 = lane 之间用 wave shuffle 交换数据 + 加权求和，比传统"每线程独立采样邻域"省掉大量重复纹理读取。它是手工设计的启发式滤波网络（Median、形态学、bicubic、能量估计等算子的组合），不是训练出来的神经网络。#4 的 MeasureRejection、#6 的 Nyquist 重建、#7 的线检测，都建在这套原语上——这是 UE5.8 相比早期 TSR 在薄几何/高频细节上更强的技术底座。FTSRConvolutionNetworkShader 作为这些 pass 的共同基类，统一管理 wave 配置与 permutation。

薄几何数据如何贯穿全链 ThinGeometryCommon

TSRThinGeometryCommon.ush 定义了薄几何标记的编码与在各 pass 间传递的约定。coverage 会被 #3 DecimateHistory 重投影（DIM_THIN_GEOMETRY_COVERAGE_REPROJECTION）、被 #4/#5 消费：

pass对薄几何的处理
#2 DilateVelocityDIM_THIN_GEOMETRY_EDGE_REPROJECTION：细线边缘专门重投影
#3 DecimateHistory重投影薄几何 coverage 到当前帧
#7 DetectThinGeometry检测并输出 coverage + 松弛权重

#5 UpdateHistory/WeightRelaxation用 MaxRelaxationWeight 让细线能持续累积

一条贯穿五个 pass 的"专项通道"

薄几何处理不是某一个 pass 的孤立逻辑，而是一条从 #2 到 #5 贯穿的专项数据通道：检测 → 重投影 → 影响拒绝 → 影响累积。这正体现了 TSR 的设计哲学——用一套统一的连续权重体系，为不同类型的内容（普通面、薄几何、半透明）走不同的权重路径，而不是给每种情况写独立的 if-else 分支。理解了这条通道，就理解了为什么 UE5 的电线、铁丝网在 4K 上采样下能稳住。

小结 Summary

1薄几何（细线/栅栏）在时序上采样下"时有时无"，会被常规拒绝逻辑误杀，导致闪烁断裂——必须专项处理。

2DetectThinGeometry 用多方向边缘/强度线检测识别细线，靠 MinKeepLineContrast 等门槛区分真线与噪声，输出 coverage + 松弛权重。

3TSRConvolutionNetwork 是 UE5.8 的lane 向量化张量卷积框架（非深度学习模型），被 #4/#6/#7 复用，是高频细节质量的技术底座。

4薄几何数据形成一条贯穿 #2→#5 的专项通道：检测→重投影→影响拒绝→影响累积，体现 TSR "统一权重体系、分内容路径"的哲学。

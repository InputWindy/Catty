为什么需要"膨胀"速度 The edge ghosting problem

重投影历史用的是运动矢量 velocity：把当前像素坐标减去它的屏幕速度，得到"这个像素上一帧的位置"，再去历史里采样。问题出在运动物体的边缘：前景物体在动、背景不动，边缘像素若采到背景的速度，重投影就会把前景的历史"拖"到背景上——这就是边缘拖影（edge ghosting）。

膨胀 = 取邻域"最靠近相机"的那个速度

解决办法是速度膨胀（velocity dilation）：每个像素不直接用自己的速度，而是查看邻域（TSR 用 3×3 蝶形采样），取其中深度最近（最靠前）那个像素的速度。直觉是——前景边缘应该跟着前景一起动，所以让"最靠前的东西的速度"占领边缘。这样重投影时前景边缘会去采前景的历史，背景才不会被污染。DilateVelocity pass 同时输出膨胀后的速度和最近深度（ClosestDepthOutput），供下游 DecimateHistory 使用。

三件事：膨胀、散射、重投影场 DilateVelocity pass

1速度膨胀3×3 邻域取最近深度的速度 → 输出膨胀速度 + ClosestDepthOutput（最近深度）
▶
2最近遮挡物散射ScatterClosestOccluder：用 InterlockedMax 把前景速度散播到它"下一帧会去的位置"，填补空洞
▶
3重投影场（可选）高画质下算 ReprojectionField：更精细的每像素重投影向量 + 边界 + 雅可比

散射（scatter）：把"我下一帧会挡住谁"提前写出去

膨胀是"拉"（gather）：像素主动去邻域找最近速度。但还有一类问题膨胀解决不了——遮挡消失（disocclusion）：一个物体这帧挡住了背景，下一帧移开，露出的背景在历史里根本没有对应像素。TSR 用散射（scatter）补充：ScatterClosestOccluder 让当前帧的每个像素，按自己的速度算出"我上一帧在历史里的位置"，用 InterlockedMax 把自己的深度+速度原子地写进 PrevAtomicOutput（一张 globallycoherent 的原子纹理数组）。InterlockedMax 保证多个像素抢同一个历史位置时，最靠前（深度最大 DeviceZ）的赢——即真正遮挡的那个。深度被量化进高位（<< 9），低 9 位塞 hole-filling 速度，一个 uint 同时排序深度又携带速度。

重投影场：高画质的每像素重投影 ReprojectionField

基础重投影对每个历史像素只用一个速度向量，在放大倍率高或亚像素运动时不够精细。开启 r.TSR.ReprojectionField（high/epic/cinematic 默认开）后，DilateVelocity 额外输出一张重投影场，把每像素的重投影信息编码进纹理数组：

// TSRReprojectionField.ush：一个 uint 塞三样东西 // bit[0:4) dilating offset ∈ [-1,1]^2（膨胀取自哪个邻居） // bit[4:15) ReprojectionBoundary.x 11bit // bit[15:26)ReprojectionBoundary.y 11bit uint EncodeReprojectionBoundary(tsr_short2 ReprojectionOffset, tsr_half2 ReprojectionBoundary) { uint EncodedReprojectionOffset = EncodeReprojectionOffset(ReprojectionOffset); tsr_short2 BoundaryBits = tsr_short2(round(ReprojectionBoundary * 1023)) + 1024; return EncodedReprojectionOffset | (BoundaryBits.x << 4) | (BoundaryBits.y << 15); }

重投影场 = 对深度缓冲做空间抗锯齿再算边界

DilateVelocity 里的 ComputeReprojectionBoundary 先对深度缓冲跑一遍空间抗锯齿（复用 #6 的 TSRSpatialAntiAliasing 逻辑），找出几何边界的亚像素位置，再把这个边界与膨胀方向一起编码。下游 DecimateHistory 解码后能在亚像素级别决定历史该怎么重采样——这让 TSR 在大幅上采样下的边缘更锐利、更少锯齿。只有当膨胀速度与原始速度的差异超过 ReprojectionFieldAntiAliasVelocityThreshold 且不出屏时才启用（bAntiAliasReprojectionField），省下静止区域的开销。

与运动模糊共享 flatten VelocityFlatten

注意 DilateVelocity 有个 permutation 维度 DIM_MOTION_BLUR_DIRECTIONS（0/1/2）。当开启运动模糊时，DilateVelocity 顺带把速度展平（flatten）成运动模糊需要的 tile 格式（VelocityFlattenOutput / VelocityTileArrayOutput），复用 MotionBlur/MotionBlurVelocityFlatten.ush。这是典型的 UE "顺路把邻居的活干了"——反正都遍历了一遍速度缓冲，多写一个输出比单开一个 pass 便宜。此时 TILE_SIZE 用 VELOCITY_FLATTEN_TILE_SIZE，否则默认 8。

velocity 错 → 一切皆错

DilateVelocity 是整条 TSR 链的地基：它的输出（膨胀速度、最近深度、重投影场）决定了下游 DecimateHistory 怎么对齐历史。如果上游几何 pass 输出的 velocity 本身有误（比如某些材质忘了写 velocity、WPO 顶点动画没算进 velocity），这里再怎么膨胀也救不回来，最终表现就是该物体运动时鬼影/拖影。调试鬼影问题，第一步永远是用 r.TSR.Visualize（见 #8）看重投影是否正确，再往上游查 velocity。

小结 Summary

1速度膨胀取 3×3 邻域中最近深度的速度，让前景边缘跟着前景走，消除边缘拖影；同时输出最近深度供下游用。

2最近遮挡物散射用 InterlockedMax 原子地把前景速度散播到历史空间，深度打进高位保证"最靠前的赢"，补充膨胀处理不了的遮挡关系。

3重投影场（高画质）对深度做空间抗锯齿求边界，把膨胀方向+边界编码进一个 uint，让下游在亚像素级重采样历史。

4DilateVelocity 是 TSR 的地基——它的正确性完全依赖上游 velocity 的正确性，鬼影排查从这里开始。下一篇 #3 用这些输出把历史重投影到当前抖动网格。

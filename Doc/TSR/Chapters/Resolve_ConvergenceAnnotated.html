两个 pass 的分工 SpatialAA before, Resolve after

注意帧内顺序：SpatialAntiAliasing（pass 7）在 UpdateHistory（pass 8）之前，ResolveHistory（pass 9）在最后。它们解决两个不同问题：

7SpatialAntiAliasing为 #4 标记的"历史被拒"像素，在当前单帧内算一份空间 AA，弥补时序累积的缺失
▶
8UpdateHistory（#5）累积，把空间 AA 结果也考虑进去
▶
9ResolveHistory把累积历史解析到输出分辨率 + 锐化，交后处理链

为什么被拒的像素需要空间 AA 兜底

时序抗锯齿的锯齿消除，靠的是多帧不同 jitter 采样的累积。可一旦某像素历史被 #4 判为不可信（RejectionBlendFinal < 0.25），它几乎只剩当前单帧一个采样——回到了"没有抗锯齿"的裸露状态，边缘会重新出现锯齿。SpatialAntiAliasing 就为这些像素做一次纯空间（单帧内）的抗锯齿：读 AntiAliasMaskTexture（#4 输出）定位这些像素，用 LDR 亮度做边缘检测与平滑，输出方向性 AA 信息。时序管够就用时序，时序断供就用空间——两者接力保证任何情况下边缘都不裸露。质量档 DIM_QUALITY_PRESET 决定迭代次数（1→3 次，2→8 次）。

SpatialAntiAliasing 内部：一个微型 FXAA Edge browsing

被拒像素的单帧空间 AA，内里是一套沿边缘行走（edge browsing）的算法——思路与 FXAA 同源，但用 fp16 双像素向量化重写（源码 TSRSpatialAntiAliasing.usf 88–223）：

// 仅处理 AntiAliasMask>0 的被拒像素，其余直接跳过 if (all(!bAntiAlias)) { TexelOffset = 0; return; } // ① 读 3×3 LDR 亮度邻域（InputC/N/S/E/W/NE/NW/SE/SW） // ② 找边缘方向：判断边是水平还是垂直、哪一侧 FindBrowsingDirection(InputC, InputN..SW, /*out*/ NoiseFiltering, BrowseDirection, EdgeSide, EdgeLuma); LumaDelta = abs(EdgeLuma - InputC) * 0.5; WorthBrowsing = LumaDelta > SPATIAL_ANTI_ALIASER_MIN_LUMIMANCE; // ③ 沿边缘两侧各行走 CONFIG_ITERATIONS 步，测边缘长度 BrowseNeighborhoodBilinearOptimized(CONFIG_ITERATIONS, ..., /*out*/ EdgeLengthP, EdgeLengthN, bEdgeStoped...); // ④ 由边缘长度与停止位置推子像素采样偏移 TexelOffset = EdgeSide * (BrowseDelta * ComputeDistanceToEdge(bEdgeStoped..., EdgeLengthN, EdgeLengthP)); AntiAliasingOutput = (EncodeSpatialAntiAliasingOffset(TexelOffset), round(NoiseFiltering*255));

输出的不是颜色，而是“采样偏移”

关键细节：SpatialAntiAliasing 不直接输出平滑后的颜色，而是输出一个亚像素采样偏移 TexelOffset（编码进 AntiAliasingOutput）：告诉后续“沿边缘垂直方向偏移多少去采样”才能把阶梯边变平滑。这正是 FXAA 的核心思想：不模糊整块，只沿边缘法线方向做亚像素重定位，保持非边缘区域锐利。CONFIG_ITERATIONS（低档 3 / 高档 8）就是边缘行走的最大步数——走得越远，能处理的斜率越接近水平（长斜边）。NoiseFiltering 另存一份噪声抑制强度。

ResolveHistory：把历史"冲印"成成片 Resolve

历史是 TSR 内部格式（可能是 R11G11B10、可能带独立的历史分辨率）。ResolveHistory 负责把它转成后处理链期望的输出：重采样到最终输出分辨率、做锐化、处理 HDR 权重与 clamp。

// ResolveHistory 的高质量路径用 Nyquist 卷积网络重建（DIM_NYQUIST_WAVE_SIZE = 16/32） #if DIM_NYQUIST_WAVE_SIZE != 0 // 用 wave 协作 + 卷积网络做接近 Nyquist 极限的重建，TILE 带 overscan #include "TSRConvolutionNetwork.ush" #define DOWNSAMPLE_FACTOR 2u #else #define TILE_SIZE 8 // 普通路径 #endif #define KERNEL_SIZE 4 #define CONFIG_HDR_WEIGHT 1

Nyquist 重建：ResolveHistory 也用卷积网络

当 DIM_NYQUIST_WAVE_SIZE 为 16 或 32（对应 GPU 的 wave 大小）时，ResolveHistory 走高质量路径：整组线程协作把一片历史加载进寄存器/LDS，用卷积网络做接近 Nyquist 采样极限的重建。这与 #4 拒绝、#7 薄几何用的是同一套 TSRConvolutionNetwork.ush 基础设施——TSR 把"卷积网络"当作可复用的信号处理原语，在多个关键 pass 复用。锐化就发生在这一步（r.TSR.Sharpen），因为解析是历史信息转成像素前的最后一次重采样，是加锐化最合适的位置。

输出：交棒给后处理 Handoff to post-processing

ResolveHistory 的输出就是 TSR 交给后处理链的高分辨率、抗锯齿的 SceneColor。此后 bloom、tonemap、色彩分级等在这张高分辨率图上运行。

衔接说明
输出分辨率= View.GetSecondaryViewRectSize()（如 4K），不再是渲染分辨率
格式转成后处理期望的 SceneColor 格式（含 alpha 时 RGBA16F）
mip#5 顺手生成的 mip 供 bloom/DOF 使用
锐化可选，补偿时序累积与重采样带来的轻微软化

到此，TSR 主链闭合

回顾主线：#2 算清运动 → #3 对齐历史 → #4 判断可信度 → #5 加权累积 → #6 解析输出。低分辨率带抖动的输入，经过这条链，变成了高分辨率、稳定、无锯齿的成片。剩下的 #7（薄几何）和 #8（可视化/生态）是专项增强与工具，主干到这里已经完整。若把 TSR 放回本文档集的大图景：Nanite 给几何、Lumen/MegaLights 给光照，产出低分辨率 SceneColor，TSR 在管线最末端把它"冲印"成最终画面——这是"从磁盘几何到屏幕像素"的最后一步。

小结 Summary

1SpatialAntiAliasing（pass 7）为历史被拒的像素做单帧内空间抗锯齿兜底——时序断供时不让边缘裸露；质量档决定 3 或 8 次迭代。

2ResolveHistory（pass 9）把累积历史解析到输出分辨率并锐化，高质量路径用 TSRConvolutionNetwork 做 Nyquist 重建（wave 16/32）。

3输出即交给后处理链的高分辨率 SceneColor，配合 #5 的 mip；锐化补偿时序软化。

4至此 TSR 主链闭合：运动→对齐→拒绝→累积→解析。#7/#8 为专项增强与工具。

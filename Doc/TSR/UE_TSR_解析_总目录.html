UE TSR 时序超分辨率源码解析 · 总目录

TSR（Temporal Super Resolution，时序超分辨率）是 UE5 默认的时序上采样抗锯齿方案：在低分辨率下渲染场景（如 1080p → 输出 4K），靠跨帧累积历史 + 亚像素抖动（jitter）把多帧的不同采样点拼成一张高分辨率、无锯齿的画面。它同时替代了旧的 TAA/TAAU，并作为 DLSS/FSR/XeSS 等第三方上采样的原生对照实现。难点全在"复用历史"与"抗鬼影"的博弈：相机/物体一动，历史就可能失效，必须逐像素判断历史可不可信、可信多少。本书对照 UE5.8 本地源码 TemporalSuperResolution.cpp（3780 行）+ Shaders/Private/TemporalSuperResolution/（23 个 shader），按 GPU 单帧执行顺序逐 pass 解析。每主题含一份主文档（设计动机 + 数据流骨架 + 分阶段批注）与一份函数附录（pass / CS / permutation / CVar 细节）。所有符号名、CVar 默认值均取自 UE5.8 本地源码。

起步导航 · TSR 一句话

建议入口 · 先建立"历史累积 + 抗鬼影"的直觉再进各篇

这本书怎么读

TSR 的核心是一条"重投影历史 → 判断历史可信度 → 加权累积 → 解析输出"的每帧闭环。建议第一次按 #1 → #2 → #3 → #4 → #5 → #6 顺序把主干过一遍：#1 总览建立"为什么低分辨率能拼出高分辨率 + jitter + 全景"；#2 运动矢量讲"历史怎么对齐到当前帧"（速度膨胀、最近遮挡物、重投影场）；#3 历史抽取讲"把上帧历史重采样到当前抖动网格"；#4 历史拒绝是抗鬼影的心脏（着色分析、颜色空间 clamp、闪烁抑制）；#5 历史更新是最大的 pass（1426 行，累积权重与松弛）；#6 解析讲"历史怎么变成最终像素 + 空间抗锯齿兜底"。主干通了以后，再看 #7 薄几何/卷积网络与 #8 可视化调试 / DLSS·FSR 对接。关键常量：历史最多累积 r.TSR.History.SampleCount = 16 帧、历史分辨率 r.TSR.History.ScreenPercentage = 100%（相对输出）、历史位深 r.TSR.History.R11G11B10 = 1、更新质量 r.TSR.History.UpdateQuality = 3（受 sg.AntiAliasingQuality 驱动）。若读过本文档集 Nanite 篇，TSR 正是吃 Nanite/Lumen 输出、闭合"从几何光照到最终像素"的最后一环。

一眼看懂：TSR 单帧的 12 个 pass

① 输入与重投影MeasureFlickeringLuma
DilateVelocity（速度膨胀 + 最近遮挡物）
DecimateHistory（历史重投影抽取）
② 抗鬼影判定DetectThinGeometry + WeightRelaxation
RejectShading（着色拒绝：历史可信度）
SpatialAntiAliasing（拒绝时空间 AA 兜底）
③ 累积与解析UpdateHistory（加权累积，1426 行）
ResolveHistory（解析到输出分辨率）
④ 输出与调试高分辨率无锯齿 SceneColor
→ 后处理链
TSR Visualize（调试可视化）

与传统 TAA 最大的不同：TSR 是时序上采样（输入分辨率 < 输出分辨率），且抗鬼影靠一套着色分析卷积启发式（shading rejection）逐像素估计历史可信度，而非简单的邻域 min/max clamp——这让它在大幅上采样下仍能保住细节与稳定性。全流程几乎都是 compute shader，可跑 async compute。详见 #1。

与本文档集其它篇的关系

四本书的下游：从几何光照到最终像素

本书（UE TSR）与 Nanite 解析、Lumen GI 解析、虚拟纹理解析、MegaLights 解析 同属一套渲染世界观。TSR 位于渲染管线的最末端：Nanite 提供几何与 visibility buffer、Lumen/MegaLights 完成光照与着色，产出低分辨率但带抖动的 SceneColor + Depth + Velocity，TSR 再把它们跨帧累积、上采样成高分辨率成片。理解 TSR 前最好先读 Nanite 主干（几何与延迟着色的输出正是 TSR 的输入）；而 TSR 的 jitter 与 velocity 又与 Nanite 的多视图/运动矢量生成直接相关。读完这五本，UE5 "从磁盘几何到屏幕像素"的主链路就完整了。

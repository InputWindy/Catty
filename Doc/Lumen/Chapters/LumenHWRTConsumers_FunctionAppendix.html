1. 共享基类与 shader 生成宏

说明

基类把 TLAS 绑定、Surface Cache 采样、公共 permutation（含防自相交）都收进 FSharedParameters / FBasePermutationDomain。关键是那对宏：IMPLEMENT_LUMEN_RAYGEN_AND_COMPUTE_RAYTRACING_SHADERS 会为同一份 usf 逻辑同时生成 RayGen 版和 Compute(inline) 版，让上层能按硬件能力和 pass 类型自由切换而不用写两套代码。

2. Inline vs RayGen 分派

说明

两种分派用 ERayTracingShaderDispatchType 区分。核心约束写在 ShouldCompilePermutation：Inline 不允许配 HitLighting pass——因为 HitLighting 要走 shader binding table 里的材质 hit group，而 inline RayQuery 没有 SBT 机制。所以纯遮挡/纯 SurfaceCache 追踪偏好 Inline（轻），HitLighting 只能 RayGen。

不同点Inline 在 compute 内联、无管线切换；RayGen 是独立 RT 管线、功能全但重。

3. EHitLightingMode 与两遍法数据流

说明

三态里 HitLightingForReflections 是生产常用档。两遍数据流的巧妙在于第一遍就把"哪些命中需要精修"记进 buffer 和间接 dispatch args，第二遍只对这些命中发 RayGen——避免对全部像素/探针都跑昂贵的材质求值。UseHitLightingDirectLighting / UseHitLightingSkylight / GetHitLightingShadowMode 精细控制第二遍在命中点补多少光。

共同点第一遍的 Surface Cache 命中逻辑与软件 SDF 追踪完全一致。

4. 材质 hit group（CHS/AHS/MS）

说明

所有 RayGen 消费者共用同一份材质 hit group：CHS（closest hit，求值命中点材质）+ AHS（any hit，做 alpha test / 防自相交）+ MS（miss，未命中时贡献天光/远场）。这份 hit group 支持 Nanite RT permutation。因为共用，一次 shader binding table 构建就能服务反射、GI、远场等所有 RayGen 追踪。

5. 防自相交三模式

说明

光线从表面出发时因浮点误差常会"立刻打到自己"，造成假遮挡（GI/反射发黑）。三种对策：Disabled 只靠 ray 起点偏置（最快，可能漏）；Retrace 发现疑似自相交就从命中点后再追一次（准，多一次遍历）；AHS 在 any-hit shader 里用几何判据剔除（融进一次遍历，折中）。远场另有 GetFarFieldBias 加偏置。

6. SER 与间接 dispatch

说明

SER（Shader Execution Reordering）是新硬件特性：不同线程命中不同材质会导致 warp 分支发散，SER 让 GPU 按命中材质重排线程再执行 hit shader，显著提升 HitLighting 效率。间接 dispatch 则和两遍法配合——先用一个小 CS 统计实际工作量写进 indirect args，再 DispatchRaysIndirect，避免为空工作发射。

共同点间接 args 的"先统计再分派"与 Mesh SDF 剔除、Radiosity 的 indirect dispatch 同一手法。

TraceScreenProbes 代码解析

RenderLumenScreenProbeGather 的第三个子阶段，也是整条 GI 链路真正"发光线"的地方。它拿着上一阶段生成的 RayInfosForTracing，按"从廉价到昂贵"的级联顺序调度多个追踪后端（Screen Trace → Hardware RT / Mesh SDF → Global SDF + Radiance Cache），每一层只处理上一层未命中的光线，最终为每根光线填上 incoming radiance。这里是 Lumen 发散点最密集的阶段。

完整源码对照

以下是 TraceScreenProbes 的完整 C++ 编排源码。各后端 shader 与 CompactTraces 见函数附录。

Engine/Source/Runtime/Renderer/Private/Lumen/LumenScreenProbeTracing.cpp

0. 核心思想：级联追踪 + 命中压实

ClearTraces
→ ① Screen Trace（廉价，屏幕内命中）
→ CompactTraces（只留未命中光线）
→ ② HWRT 或 Mesh SDF（较贵，屏幕外几何）
→ CompactTraces（再次压实）
→ ③ Global SDF + Radiance Cache（兜底，全部命中）

说明

TraceScreenProbes 的骨架是一条从廉价到昂贵的级联管线。核心动机：不同追踪后端精度/开销差异巨大，能用便宜的就别用贵的。

屏幕空间追踪几乎免费但只覆盖屏幕内可见几何；硬件 RT / Mesh SDF 能命中屏幕外物体但更贵；Global SDF + Radiance Cache 精度最低但保证任何方向都有结果（兜底）。

串起它们的关键机制是 CompactTraces：每一层追踪后，把"还没命中的光线"压实成紧凑列表，下一层只对这些光线做 indirect dispatch。这样越贵的后端处理的光线越少——这是整个方案能在预算内跑起来的关键。

1. ClearTraces + 参数装配（汇聚起点）

FClearTracesCS ... ThreadPerTrace  // 每根光线一个线程，清空
GetLumenCardTracingParameters(...)      // Surface Cache 采样参数
SetupLumenDiffuseTracingParameters(...)  // 追踪距离/步进参数

说明

汇聚所有后端共享同一套输入：TracingParameters（如何采样 Lumen Surface Cache 拿到命中点的辐照度）和 IndirectTracingParameters（追踪距离、步进、厚度等）。

先 ClearTraces 把 trace radiance / hit distance 输出清零——因为后续每个后端只写自己命中的光线，未写的必须是干净的初值。ThreadPerTrace 表示 dispatch 粒度是"每根光线一个线程"。

2. 后端①：屏幕空间追踪（Screen Trace）

bTraceScreen = PrevScreenColor 有效 && CVar 开 && ShowFlag 开 && PP 设置开
bHZBTraversal ? ClosestHZB : FurthestHZB   // 层级 HZB 遍历
permutation: RadianceCache / HierarchicalScreenTracing / ImportanceSampling / Hair ...

说明

第一层，最廉价。它复用上一帧的 SceneColor（PrevViewInfo.ScreenSpaceRayTracingInput）在屏幕空间做 ray marching，用 HZB（层级 Z buffer）加速遍历。

不同点bHZBTraversal 决定用 Closest 还是 Furthest HZB、是否全分辨率深度；FTerminateOnLowOccupancy 在 wave occupancy 过低时提前终止（避免少量光线拖累整个 wave）。

共同点与后续后端一样，命中后用 TracingParameters 采样命中点辐照度写入 trace radiance；permutation 里的 FStructuredImportanceSampling 保证它按上一阶段生成的 RayInfosForTracing 方向表来发线。它只能命中屏幕内可见几何，未命中的留给下一层。

3. 后端②：硬件 RT 或 Mesh SDF（互斥主后端）

if (bUseHardwareRayTracing)
    RenderHardwareRayTracingScreenProbe(...)   // 真·硬件光追
else if (bTraceMeshObjects) {
    CullForCardTracing(...)                     // 剔除 + 建 SDF grid
    CompactedTraceParameters = CompactTraces(..., bCompactForSkyApply=false)
    TraceMeshSDFs()  // Mesh Distance Field + Heightfield 软件追踪
}

说明

这是最大的发散点：两条互斥的主追踪后端。

不同点硬件 RT（bUseHardwareRayTracing）走 RenderHardwareRayTracingScreenProbe，用 RTX 硬件对真实三角形求交，精度最高；Mesh SDF 分支则先 CullForCardTracing 建立距离场网格，再对 Mesh Distance Field / Heightfield 做软件 ray marching，作为无硬件 RT 时的替代。二者不会同时跑。↳ 下钻：Hardware Ray Tracing 后端解析（派发方式 / 着色模式 / 两层 TLAS）

共同点进入 Mesh SDF 前先调 CompactTraces(bCompactForSkyApply=false)——只把屏幕追踪未命中的光线压实出来，让昂贵的 SDF 追踪只处理这部分。硬件 RT 路径内部也有自己的 compaction。两者都只是"补屏幕外几何"，最终仍可能有 miss 留给第三层。

4. 后端③：Global SDF + Radiance Cache（兜底汇聚）

CompactedTraceParameters = CompactTraces(..., MaxTraceDistance=FLT_MAX, bCompactForSkyApply=true)
// 注释：Make sure the shader runs on all misses to apply radiance cache + skylight
FTraceVoxels = !bUseHardwareRayTracing && UseGlobalSDFTracing(...)
TraceVoxels()  // Global SDF 追踪 +（无论如何）应用 Radiance Cache / 天光

说明

汇聚这是所有分支最终收束的兜底层，总是执行。它的 CompactTraces 用 FLT_MAX + bCompactForSkyApply=true，确保把"到这里仍未命中"的所有光线都收集起来。

不同点是否真的 trace Global SDF 由 FTraceVoxels 决定（只在无硬件 RT 且开启 Global SDF 时）；否则这一 pass 退化为"仅应用 Radiance Cache + 天光"。

换句话说：不管前面走了哪条路，任何一根没命中的光线，最后都会在这里拿到一个结果——近处用 Global SDF 追踪世界几何，远处/无覆盖处用世界空间 Radiance Cache 和天光填充。这保证 trace radiance 纹理里没有一根光线是空的，Filter 阶段拿到的是完整数据。

这里作为远场兜底光源的 Radiance Cache 是一整套独立的世界空间辐照度缓存机制（clipmap + 持久缓存 + 预算重追），它在本阶段之前由 ScreenProbeGather 更新完毕，此处只是采样。↳ 下钻：Radiance Cache 更新流水线解析

汇聚点 / 发散点总表

环节类型说明
ClearTraces + 共享 TracingParameters汇聚所有后端统一初值与 Surface Cache 采样方式。
CompactTraces 级联压实汇聚每层之间压实未命中光线，越贵的后端处理越少光线。
TraceVoxels 兜底总是执行汇聚保证每根光线最终都有 radiance（含 Radiance Cache + 天光）。
bTraceScreen发散屏幕空间追踪是否启用（需上一帧 SceneColor）。
bUseHardwareRayTracing vs bTraceMeshObjects发散互斥主后端：硬件 RT vs Mesh SDF/Heightfield。
FTraceVoxels / FRadianceCache / FStructuredImportanceSampling发散兜底层是否真 trace Global SDF、是否用 RC、是否按重要性采样表。
bNeedTraceHairVoxel发散可选头发体素追踪，附加在某个后端上执行一次。

最终总结

说明

TraceScreenProbes 是 Lumen"发光线"的执行层，也是把你最初问题落到实处的地方。它没有让每根光线都做最贵的追踪，而是设计了一条级联管线：屏幕空间兜住大部分屏内命中，硬件 RT / Mesh SDF 补屏外几何，Global SDF + Radiance Cache 做最终兜底。

贯穿始终的 CompactTraces 是效率关键——它保证每一层昂贵后端只处理上一层剩下的 miss，把 GPU 时间花在真正需要的地方。这与上一阶段 ② 的结构化重要性采样一脉相承：预算永远优先用在最有价值的光线上。

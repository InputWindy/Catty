1. 为什么用距离场，而不是直接追三角形

说明

距离场是"不用 BVH 也能追世界"的关键：sphere tracing 每步可前进"当前到最近表面的距离"，天然跳过空白区域，无需逐三角形求交。这让 Lumen 在不支持硬件光追的硬件上也能跑 GI。代价是它是近似几何（低分辨率、丢薄物体），所以软件 Lumen 的漏光/丢细节大多源于此。

不同点硬件 RT 路径追的是精确三角形 BVH（见 HWRT），命中精确但依赖 RT 硬件；软件路径追 SDF，全平台可用但较糙。这是 Lumen "同一套上层、两套追踪后端"的分水岭。

2. Mesh SDF：逐网格的精确表示 + 流送

说明

Mesh SDF 是逐网格的高精度表示，像"几何版的虚拟纹理"：brick 按需流送、远处降 mip。它精确到能表达单个网格的凹凸，但代价是"对象多时不能每根线都遍历所有对象"——于是需要第 4 节的剔除。

共同点"brick 流送 + mip 降级"与 Surface Cache 的"卡片页按预算驻留"、虚拟纹理的按需加载同属"只驻留看得到/用得到的那部分"的思路。

3. Global SDF：相机为中心的 clipmap 合成

说明

Global SDF 把"附近所有网格"合并成一张相机中心的粗距离场，采样只需查页表 + 采一次 atlas（O(1)），非常适合远场追踪与大范围遮挡查询。三大省钱技巧：clipmap 分级（远处糙）、增量更新（每帧只重算 2 层 + 滚动边条）、稀疏页表（空区不分配 page）。

共同点clipmap 分级 + 相机中心滚动，与 Radiance Cache 的 3D clipmap probe 布局是同一套空间数据结构思路。

不同点Mesh SDF 追踪要遍历对象列表（成本随对象数涨），Global SDF 采样是固定成本（与对象数无关）——这正是"远场换成 Global SDF"的动机。

4. LumenMeshSDFCulling：让近场追踪只测试附近对象

说明

这一步是 Mesh SDF 能用于实时追踪的前提：把"逐线×逐对象"降成"逐线×本 froxel 少数对象"。剔除结果按屏幕 froxel 网格组织，与 ③ 的屏幕 probe 布局对齐，追踪 shader 直接读本 froxel 的对象列表。

共同点froxel 网格剔除与 A 的"逐 card tile 剔光"、延迟渲染的 clustered culling 完全同构：先把"谁影响谁"预计算成 per-cell 列表，再着色/追踪时只读本 cell。

最终总结

骨架

距离场是软件 Lumen 的世界表示，分两级：Mesh SDF（逐网格离线烘焙、brick 流送、每帧上传对象元数据，精确但需 froxel 剔除）与 Global SDF（相机中心 4 层 clipmap，把附近 Mesh SDF 合成进稀疏页表体积，增量更新，采样 O(1) 但较糙）。追踪时近场追 Mesh SDF、远场追 Global SDF。

它是 ③ 软追、A 屏外阴影/Radiosity 软追的共同地基，不依赖 Lumen。

阅读建议

先抓两级分工："精确但要剔除" vs "O(1) 但糙"。再看三条数据流：Mesh SDF 的烘焙→流送→上传、Global SDF 的剔除→合成→clipmap、Lumen 的froxel 剔除→绑定追踪。sphere tracing 与 brick/page 布局细节见函数附录。硬件 RT 的对照见 HWRT。

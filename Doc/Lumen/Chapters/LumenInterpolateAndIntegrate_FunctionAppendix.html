1. 四个 Compute Shader 的职责

Compute Shader职责派发方式
FInitScreenProbeTileIndirectArgsCS把 IntegrateIndirectArgs / ClearUnusedIndirectArgs 计数器清零，为后续 indirect dispatch 做准备。FIntVector(1,1,1)
FScreenProbeTileClassificationBuildListsCS读 LumenTileBitmask，判断每个 tile 需要哪种积分技术，写入对应分类 list 并累加计数。GetGroupCount(ViewportIntegrateTileDimensions, 8) / overflow 用 ClosureTile indirect
FScreenProbeIntegrateClearUnusedTileDataCS清空不会被积分 pass 覆盖的 tile（因输出 UAV SkipBarrier overlap，需显式清零防残留）。ClearUnusedIntegrateTileIndirectArgs
FScreenProbeIntegrateCS核心积分核：插值邻近 probe + 对像素 BRDF 积分，产出 Diffuse/RoughSpec/Backface/LightIsMoving。分类路径用 IntegrateIndirectArgs 偏移；全屏路径用 GetGroupCount，Z=ClosureCount

说明

前三个 CS 都是为积分核铺路的调度层：Init 清计数、BuildLists 分类、ClearUnused 清脏。真正做光照计算的只有第四个 FScreenProbeIntegrateCS——它被以不同 permutation、不同 tile list 反复调用，是整个阶段唯一的"计算主体"。

全屏路径下前三个 CS 全部省略，只保留 IntegrateCS 一次全屏 dispatch。

2. Tile 分类机制

说明

Tile 分类的动机：不同屏幕区域需要的积分功能差异很大（纯漫反射 tile vs 需要背面漫反射/AO/多层材质的 tile）。若对全屏跑同一个"全功能"shader，简单区域会白白背上复杂分支的寄存器压力，降低 GPU occupancy。

解决办法：先把每个 tile 按需求归类，为每类编译一个精简 permutation，再用 indirect dispatch 让每类 shader 只对属于它的 tile 启动。bOverflow 分支专门处理 Substrate 多 closure 场景——同一像素有多个材质层时，用额外的 closure tile buffer 覆盖。

3. FScreenProbeIntegrateCS permutation 全表

Permutation作用
FTileClassificationMode本次 dispatch 处理哪种分类的 tile；特殊值 Num 表示"全屏不分类、全功能"。
FOverflowTile是否处理 Substrate 多 closure 的溢出 tile。
FProbeIrradianceFormat与 Filter 的 ConvertToIrradiance 一致：SH3（点乘余弦瓣）或 Octahedron（采样 irradiance 图）。
FStochasticProbeInterpolation随机选单个 probe（省带宽，噪声交时域滤）vs 加权多个 probe。
FShortRangeAO / FShortRangeAOBentNormal是否应用近距离环境光遮蔽、是否用 bent normal。
FSupportBackfaceDiffuse是否额外输出背面漫反射（用于双面/次表面材质）。
FIntegrateDownsampleFactor积分分辨率下采样倍率（省算力，靠上采样补）。
FScreenProbeExtraAO是否消费 Filter 产出的 ExtraAOWithBorder。

说明

这些 permutation 共同点在于都作用于同一个积分核，最终产出同语义的输出纹理。不同点在于它们组合出"这块屏幕/这种材质到底要算多少东西"——tile 分类正是为了给每块屏幕挑一组最省的开关。

其中 FProbeIrradianceFormat 是跨阶段的强约束：它必须与 Filter 阶段 GetScreenProbeIrradianceFormat 的结果完全一致，否则积分核会用错误方式解码 probe 数据。

4. 插值 + 积分的数学含义

说明

插值解决"像素不在 probe 位置上"的问题：取邻近若干 probe，按世界位置、深度、法线一致性给权重，权重低的 probe（例如在几何边界另一侧）被压制，避免把不该来的光泄漏进来。

积分解决"probe 存的是全方向辐照度，像素只要 BRDF 加权那部分"的问题：漫反射对余弦瓣积分（SH3 路径可解析用 CalcDiffuseTransferSH3 一步算出，这正是 ① GatherScreenData 里编码余弦瓣的对偶操作）；粗糙镜面对镜面瓣积分，用之前 Filter 生成的 radiance mip 按粗糙度选层近似不同锥角。

这一步和第①阶段 GatherScreenData 形成闭环：那里为了"该往哪发线"把 BRDF 编码成 SH/PDF，这里为了"收回的光怎么加权"再用 BRDF 积分——重要性采样与积分用的是同一个 BRDF 模型。

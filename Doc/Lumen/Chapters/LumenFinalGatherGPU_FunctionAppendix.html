1. ScreenProbeTraceScreenTexturesCS

说明

屏幕探针追踪的入口。方向由 EquiAreaSphericalMapping 从 texel 坐标解码——等面积映射保证每条射线覆盖相同立体角，积分无偏。追踪从最廉价的屏幕空间开始：HZB 级联或固定步长 CastScreenSpaceRay，命中即用 EncodeProbeRayDistance 编码距离；未命中的交给更贵的 TraceMeshSDFs（近场）与 TraceVoxels（远场，Radiance Cache 兜底）。

2. CompactTraces 级联压实

说明

级联的关键优化。若不压实，每一级后端都要对全部射线 dispatch，已命中的白白浪费。ScreenProbeCompactTracesCS 在每两级之间把未命中射线紧凑收集，使下一级（更昂贵的 Mesh SDF / Voxel）只对剩余射线发起 dispatch。廉价级先吃掉大部分命中，昂贵级只处理"难啃的骨头"。

3. ImportanceSampling 生成射线

说明

重要性采样让射线预算集中到"更亮/更有贡献"的方向。先由 ComputeLightingProbabilityDensityFunctionCS 用 BRDF 与上帧光照估计每个方向的 PDF，再由 ScreenProbeGenerateRaysCS 做一次 O(N²) 并行排序、按 PDF 重新分配固定的射线总预算。所谓"3 换 1"：把一个高 PDF 方向细分成 2×2 子方向，代价是从 3 个低 PDF 方向各回收一条射线，总数守恒。

4. TemporallyAccumulate 时域

说明

时域累积把多帧噪声射线平均成稳定信号。先由 CompositeTracesWithScatterCS 用蓝噪声抖动把稀疏 trace 散射进 radiance 图，再重投影到上帧探针。PositionWeight = exp2(-10000·ΔDepth²) 是防鬼影的核心：深度差稍大权重就指数级坍缩到 0，历史被丢弃，避免运动边缘拖影。

5. FilterGatherTraces 空域

说明

空域滤波在时域之后，跨邻近探针混合以进一步降噪。权重用命中点角度而非简单距离：AngleWeight = 1 - saturate(NeighborAngle / MaxRadianceHitAngle)——邻居命中的方向若与本探针偏差过大就不参与，保证只混合"看向同一片几何/光照"的样本，避免把不同表面的光照糊到一起。

6. ConvertToIrradiance SH3

说明

最终把每探针的方向 radiance 压成紧凑表示：SH3（3 阶球谐 9 系数）或 Octahedral 贴图。落地时 ScreenProbeGatherScreenDataCS 对每个屏幕像素插值邻近探针的 SH，与 CalcDiffuseTransferSH3(Normal, 1.0) 做点积得到漫反射 irradiance。SH3 用极小存储换取平滑的半球积分，是漫反射 GI 的标准压缩。

7. RC trace tile 树细分

说明

Radiance Cache 是世界空间的稀疏 probe 缓存，给屏幕探针提供远场兜底。ScatterScreenProbeBRDFToRadianceProbesCS 把屏幕侧的 BRDF 需求散射标记到相关世界 probe。GenerateAdaptiveProbeTraceTilesCS 按需把 probe 的方向球面细分成 trace tile——需要更精细的方向细分更密，形成树状自适应结构，避免均匀高分辨率的浪费。

8. SortProbeTraceTiles 方向 bin

说明

GPU 追踪的性能取决于 warp 内射线的相干性。SortProbeTraceTilesCS 把待追踪 tile 按方向桶（NUM_DIRECTION_BINS_2D=8，即 8×8 方向分箱）排序，使方向相近的射线在 dispatch 中相邻。同向射线遍历相似的 SDF/voxel 内存区域，显著提升缓存命中与 warp 执行相干性。

9. TraceFromProbes ConeHalfAngle

说明

probe 追踪用 cone 而非纯射线，ConeHalfAngle = acosFast(1 - 1/TraceRes²)：追踪分辨率越高锥角越细、越精确。追踪后 FilterProbeRadianceWithGatherCS 用 6 个 clipmap 邻居做带 occlusion 的滤波（防漏光），CalculateProbeIrradianceCS 算辐照度，FixupBordersAndGenerateMipsCS 修边并生成 mip 供不同距离采样。cone march 本体见 Reflections GPU 附录·公共追踪。

10. probe 生命周期

说明

Radiance Cache 的 probe 数量有限，靠生命周期管理动态复用。ClearProbeFreeListCS 建空闲链表；UpdateCacheForUsedProbesCS 把本帧被引用的 probe 标记 used 并刷新寿命；AllocateUsedProbesCS 为新需求从 free list 分配 clipmap 物理槽，长期未用的回收。定位物理槽走 clipmap 三级间接寻址（clipmap → indirection → 物理 atlas），兼顾近处高密度与远处稀疏。

1. Heightfield 追踪判定链

说明

两个入口：UseHeightfieldTracingForVoxelLighting 只看"CVar 开 + 有地形"，供体素光照那侧用；UseHeightfieldTracing 再叠加"MeshSDF 追踪开 + LumenDetailTraces show flag"，供屏幕探针那侧用。MaxTracingSteps 被钳在 1~256（默认 32），步数越多越准越慢；ReceiverBias 钳在 0.001~100（默认 0.01），专修 LOD 缝隙。

2. FLumenHeightfieldGPUData 双精度布局

说明

这是一段 CPU→GPU 的硬布局：3 个 float4 一条，static_assert 防止有人改结构却忘了改 usf。MeshCardsIndex 被 bit-cast 塞进 Out[0].W 的浮点位里（GPU 端再 asuint 取回）。用 FDFVector3 是大世界坐标的标准做法——见 Distance Field 附录里 Global SDF 也用同样手法。

3. 三处 permutation 挂载

说明

没有"一个 heightfield 追踪函数"——它是散落在三个软件追踪着色器里的同一个 permutation 概念。GI 追踪与可视化用 SCENE_TRACE_HEIGHTFIELDS；直接光阴影单独用 OFFSCREEN_SHADOWING_TRACE_HEIGHTFIELDS 并带一个专门的 HeightfieldShadowRayBias（阴影光线的接收偏移，与采样用的 ReceiverBias 分开）。

共同点三处都以 GetHeightfieldMaxTracingSteps() 作步数上限。

4. 每帧增量上传

说明

地形数据量大且不常变，所以走脏索引增量上传：只有 HeightfieldIndicesToUpdateInBuffer 里的条目才重新 FillData 并上传，其余复用 GPU buffer。没有地形时绑一个 GetDefaultSRV() 空占位避免着色器缺绑定。还有一层流式保护：地形高度纹理若 HeightfieldHasPendingStreaming（还没流进来）就跳过，避免捕获到空数据。

5. FLumenCardCS 加载与参数

说明

FLumenCardCS 是个 material compute shader（每个材质一份变体），入口 LumenCardComputeShader.usf::Main。它编译很贵（注释说平均 12s），所以 GetOverrideJobPriority 提到 ExtraHigh 优先编。加载时逐级取材质 fallback，校验材质域/混合模式受 Nanite 支持，把编译好的 shader 挂到 Nanite shading pipeline 的 LumenCardData 上。捕获时 RecordLumenCardParameters 填 PassData 并绑输出。

6. Pixel/Quad binning + LOD

说明

Nanite 着色按 bin 组织：不需要屏幕导数的材质走 Pixel Binning（0），需要的走 Quad Binning（1，2×2 一组算导数）。PassData.Z 标明这是 LumenCardCapture pass，让统一的 Nanite shading 分发器路由到卡片捕获。LOD scale 因子把捕获 LOD 往低压——卡片 atlas 分辨率本就低，用屏幕级 LOD 是浪费。

不同点Pixel binning 省，Quad binning 准（能算 ddx/ddy），由材质是否用导数决定。

离线烘焙 · Mesh Cards 与 Distance Field 的构建（CPU / 编辑器侧）

前面所有主题讲的都是"运行时"。但 Lumen 能在运行时便宜地追踪，靠的是离线烘焙好的两份资产：① Mesh Cards——每个网格 6 方向、最多 32 张卡片的 OBB 布局，靠 Embree 光线投射 + Surfel 聚类生成（MeshCardRepresentation.cpp / MeshCardRepresentationUtilities.cpp）；② Mesh Distance Field——稀疏 brick 距离场，靠 Embree point query + intersect 采样、内外判定生成（MeshDistanceFieldUtilities.cpp / DistanceFieldAtlas.cpp）。两者都走 DDC（Derived Data Cache）缓存，改网格才重建。本页讲这条离线流水的算法与关键常量，所有符号取自引擎 C++ 源码。

上下文：运行时的"便宜"是离线换来的

Lumen 运行时能用 Surface Cache 采表面材质、用 Distance Field 做 cone march，前提是这两份数据已经烘好躺在资产里。烘焙发生在导入网格 / 编辑器 cook 阶段，是 CPU 密集的离线过程，产物进 DDC 缓存——只要网格与烘焙参数不变，后续加载直接命中缓存不重算。Mesh Cards 决定"这个网格从哪几个方向能被 Surface Cache 捕获"（见 Mesh Cards 运行时），Mesh Distance Field 决定"射线怎么和这个网格求交"（见 Distance Field 场景表示）。本页是这两者的生产端。共同点是都重度依赖 Embree（Intel 的 CPU 光追库，USE_EMBREE）做几何查询，都用 ParallelFor 并行、都走 DDC。

1. Mesh Cards：从 Surfel 到 6 方向卡片

说明

Mesh Cards 的本质是"把复杂网格近似成几张有向矩形卡片"，供 Surface Cache 从有限方向捕获材质。生成分三步：体素化——沿 6 个轴对齐方向各发正交射线穿过网格，Embree 命中处记为 FSurfel（含体素坐标、最近深度、覆盖度）；可见性——每个 surfel 用半球 32 射线做背面剔除，剔掉被自身遮挡的面；聚类——把 surfel 按空间/朝向聚成簇，每簇拟合一个 OBB。

最后 LimitClusters 按 WeightedCoverage 排序，只保留贡献最大的 MaxCardsPerMesh=32 张。MinDensity=0.2 过滤太稀疏的簇、NormalThreshold=0.25 控制朝向一致性。产物是 FLumenCardBuildData（OBB + 方向索引）数组，写进 FMeshCardsBuildData。

2. Mesh Distance Field：稀疏 brick 距离场

说明

Mesh Distance Field 是每个网格的有符号距离场：空间任意点到网格表面的最近距离，负值表示在网格内部。运行时 cone march 靠它做 sphere tracing。烘焙时对每个体素中心：rtcPointQuery 求最近三角形得到无符号距离，再用 rtcIntersect1 发半球射线统计背面命中比例——超过 25% 判定该点在网格内部，距离取负。

存储是稀疏的：只在表面附近的窄带（BandSizeInVoxels=4）分配 7³ 的唯一数据 brick（带 1 border 后 8³），远离表面的空区不存。3 级 mip 供不同追踪距离，距离值量化成 PF_G8（8bit）省内存。用 ParallelForTemplate 并行处理体素。

3. DDC 缓存：改网格才重建

说明

两份资产都是纯离线派生数据，走 DDC（Derived Data Cache）：由"网格内容 hash + 烘焙参数 + 版本 GUID"算出 key，缓存命中则直接取、不重算。这就是为什么第一次导入网格慢（要烘）、之后秒开。分辨率自适应网格尺寸乘 DefaultVoxelDensity=0.2，上限 MaxPerMeshResolution=256，避免小物件浪费、大物件爆内存。

版本 GUID（如 CARDREPRESENTATION_DERIVEDDATA_VER）是引擎升级时的开关：改了烘焙算法就 bump GUID，使所有旧缓存失效、触发全量重烘。烘焙走 FDistanceFieldAsyncQueue 异步队列，不阻塞编辑器主线程。

最终总结

离线烘焙是 Lumen "空间换时间"策略的生产端：把运行时昂贵的"网格→卡片布局""点→表面距离"预计算成资产。两条线共享同一套工业化基建——Embree CPU 光追做几何查询、ParallelFor 并行、DDC 缓存 + 版本 GUID 管理增量。Mesh Cards 用"体素化 surfel → 聚类 → 6 方向 ≤32 OBB"把任意网格降维成可捕获的有向面片；Mesh Distance Field 用"逐体素 point query + 半球内外判定 → 稀疏窄带 brick"把网格编码成可 sphere-trace 的距离场。理解这里能解释运行时很多常量的来源（6 方向、32 卡上限、3 mip、窄带宽度），也能解释"为什么改了网格要等烘焙"。

ScreenProbeGatherScreenData 代码解析

本章下钻 RenderLumenScreenProbeGather 的第一个子阶段：ScreenProbeGatherScreenData。它在追踪光线之前，为每个屏幕 probe 从其屏幕足迹内的像素里"预读"出一份 BRDF 概率密度函数（PDF），并检测该 probe 是否处于 disocclusion（新暴露）区域。这份 PDF 是后续 GenerateImportanceSamplingRays 分配光线方向预算的依据——本质是"先看看这个 probe 的表面在乎哪些方向，别把宝贵光线浪费在背面"。

以下是 ScreenProbeGatherScreenDataCS 的完整 shader 源码，供与下方阶段解析逐段对照。C++ dispatcher 源码见函数附录。

Engine/Shaders/Private/Lumen/LumenScreenProbeGatherScreenData.usf

0. 这个 Pass 到底要产出什么

RWBuffer<float> RWBRDFProbabilityDensityFunctionSH;   // 每 probe 9 个 SH 系数
RWTexture2D<float> RWBRDFProbabilityDensityFunction;  // 每 probe 一张 octahedron PDF 图
RWTexture2D<UNORM float> RWScreenProbeDisocclusion;   // 每 probe 1 个 disocclusion 标记

说明

ScreenProbeGatherScreenData 不追任何光线，它只做一件事：为每个 probe 估计"表面在乎哪些入射方向"，把结果编码成 BRDF 概率密度函数（PDF）。

为什么需要它：probe 只有很少的光线预算，如果均匀往整个球面射，一半会打到表面背面（NdotL≤0）纯属浪费。有了 PDF，后续 GenerateImportanceSamplingRays 就能把光线集中到 PDF 高的方向（法线附近的上半球），显著提升有效采样率。

附带产出 Disocclusion 标记：如果该 probe 覆盖的像素刚被镜头暴露、历史帧数不足，就标 1，通知后续 filter 阶段"这里没有可复用历史，需要更强的空域滤波"。

1. 线程映射：一个线程组负责一个 probe

uint2 ScreenProbeAtlasCoord = GroupId.xy;
uint ScreenProbeIndex = ScreenProbeAtlasCoord.y * ScreenProbeAtlasViewSize.x + ScreenProbeAtlasCoord.x;
uint2 ScreenProbeScreenPosition = GetScreenProbeScreenPosition(ScreenProbeIndex);
if (ScreenProbeIndex < GetNumScreenProbes() && ScreenProbeAtlasCoord.x < ScreenProbeAtlasViewSize.x)
    float ProbeSceneDepth = GetScreenProbeDepth(ScreenProbeAtlasCoord);
    if (ProbeSceneDepth > 0)  // 无效/天空 probe 直接跳过

说明

Dispatch 用的是 ProbeIndirectArgs（GroupPerProbe），所以 GroupId 天然等于 probe 在 atlas 中的坐标——汇聚整个 pass 的组织方式统一为"1 线程组 = 1 probe，组内 8×8 线程 = probe 屏幕足迹内的采样点"。

两道门禁：probe 索引越界剔除；ProbeSceneDepth>0 剔除天空/无几何的 probe。天空 probe 不需要 BRDF PDF，因为它的间接光是纯环境光，没有"表面朝向"概念。

2. 采样足迹像素 + 深度权重剔除（两条路径的公共内核）

float2 SampleOffset = ((GroupThreadId.xy + 0.5)/SIZE*2-1) * ScreenProbeDownsampleFactor;
if (bCenterSample) SampleOffset = 0;   // 保证至少 1 个像素不被剔除
float2 PixelScreenUV = ScreenUV + SampleOffset * View.BufferSizeAndInvSize.zw;
const FLumenMaterialData Material = ReadMaterialData(ScreenCoord, PixelScreenUV);
float4 PixelPlane = float4(Material.WorldNormal, dot(Material.WorldNormal, PixelPosition));
float PlaneDistance = abs(dot(float4(ProbeWorldPosition, -1), PixelPlane));
float RelativeDepthDifference = Pow2(PlaneDistance / ProbeSceneDepth);
float DepthWeight = exp2(ScreenProbeInterpolationDepthWeight * RelativeDepthDifference);

说明

共同点无论后面走 SH 还是 Octahedron 表示，这一步都相同：每个线程在 probe 的下采样足迹内取一个像素，读出材质法线，构造像素平面 PixelPlane = (N, dot(N,P))，再算它相对 probe 平面的偏离。

DepthWeight 用指数衰减把"和 probe 不在同一表面"的像素权重压到接近 0（ScreenProbeInterpolationDepthWeight 是个大负数）。这样前景 probe 不会把背景墙的法线也算进 PDF，避免跨深度边界污染。

bCenterSample（中心线程）强制 offset=0 并跳过 DepthWeight 剔除，保证每个 probe 至少有一个有效样本，PDF 不会全空。

3. 关键分叉：SH 表示 vs Octahedron 纹理表示

#if BRDF_PDF_SPHERICAL_HARMONIC
    // 路径 A：把 BRDF 累加成 9 系数三阶 SH（紧凑、默认）
#else
    // 路径 B：把每个 octahedron texel 的 PDF 逐一算出（纹理、可视化/回退）
#endif

说明

这是本 pass 唯一的算法性分叉，由编译期宏 BRDF_PDF_SPHERICAL_HARMONIC 决定。

共同点两条路径的目标完全一样——都输出"某方向被 BRDF 采到的概率"，都用第 2 步的 PixelPlane + DepthWeight 做几何剔除。

不同点路径 A 用 三阶球谐（9 系数）紧凑表示整个上半球分布，写进 RWBRDFProbabilityDensityFunctionSH buffer；路径 B 逐 texel 显式计算 octahedron 图上每个方向的 PDF，写进 RWBRDFProbabilityDensityFunction 纹理。A 存储省、后续在 shader 里按方向求值即可；B 直观、便于可视化和某些不方便用 SH 的场合。默认走 A。

4. 路径 A：Diffuse Transfer SH 累加 + 并行归约

if (HasSphericalVisibility(Material))       // 如 SSS/双面：全方向都可能采
    BRDF.V0.x = 1.0;                        // 各向同性，不裁剪任何方向
else
    BRDF = CalcDiffuseTransferSH3(Material.WorldNormal, 1.0f);  // 余弦瓣 SH
InterlockedAdd(SharedNumElements, 1, Index); WriteGroupSharedSH(BRDF, Index);
// 按 2 的幂并行归约求和
while (NumElementsToAccumulate > 1) { ...; PDF = AddSH3(PDF, GetGroupSharedSH(i+half)); ... }
RWBRDFProbabilityDensityFunctionSH[WriteIndex] = SharedSphericalHarmonic[0][k] / NumElements;

说明

每个有效像素把自己的 BRDF 贡献编码成三阶 SH：普通不透明表面用 CalcDiffuseTransferSH3(N)（法线方向的余弦瓣），特殊材质（HasSphericalVisibility，如次表面/双面植被）则退化成各向同性常量，避免把它们真正会采样的方向裁掉。

用 InterlockedAdd 把有效样本紧凑打包进 groupshared 槽位，再做经典的 按 2 的幂并行归约（每轮线程数减半，用 AddSH3 两两相加），最终 slot 0 得到组内所有样本的 SH 之和。

最后前 9 个线程各写一个系数，除以样本数归一化，得到该 probe 的平均 BRDF PDF。汇聚并行归约同时把 disocclusion 计数也一起 reduce，复用同一套同步与循环，省一次遍历。

5. 可选：Disocclusion 检测（依赖 history）

#if SCREEN_PROBE_DISOCCLUSION && VALID_HISTORY
FLumenPackedPixelData PackedPixelData = PackedPixelDataTexture[int3(ScreenCoord, 0)];
if (PackedPixelData.AnyHistoryValid()) {
    // 双线性 gather 历史累计帧数，按样本有效性加权平均
    float NumFramesAccumulated = min(WeightedAverage(HistoryNumFrames+1, W), MaxFramesAccumulated);
    bDisocclusionPixel = NumFramesAccumulated < SpatialFilterDisocclusionMaxFrames;
}
RWScreenProbeDisocclusion[coord] = SharedNumDisocclusion[0] >= NumElements * Fraction ? 1 : 0;

说明

只有当 SCREEN_PROBE_DISOCCLUSION 与 VALID_HISTORY 两个 permutation 都开时才编译这段（对应 C++ 侧的 bProbeDisocclusion 与 OldFastUpdateMode_NumFramesAccumulatedHistory != nullptr）。

逻辑：对每个足迹像素，用双线性 gather 从历史纹理取"该位置已累计多少帧"，只要累计帧数低于阈值 SpatialFilterDisocclusionMaxFrames，就认为它是新暴露像素（disocclusion）。

不同点与 BRDF 累加共用并行归约，但归约的是"disocclusion 像素计数"。最终若组内 disocclusion 像素占比超过 SpatialFilterDisocclusionFraction，整个 probe 标记为 disoccluded=1。这个标记后续驱动 filter 阶段对新暴露区做更激进的空域滤波来补偿缺失的时域历史。

6. 路径 B：Octahedron 逐 texel PDF（max NdotL）

PixelPlanes[GroupThreadId.x][GroupThreadId.y] = PixelPlane;   // 先把足迹平面存 groupshared
for each octahedron texel:
    float3 WorldConeDirection = EquiAreaSphericalMapping(ProbeUV);
    for each PixelPlane in group:
        if (DepthWeight > 0.01)
            PDF = max(PDF, max(dot(WorldConeDirection, PixelPlane.xyz), 0));  // 保守取 max NdotL
RWBRDFProbabilityDensityFunction[...] = PDF;

说明

路径 B 不做 SH 压缩，而是把 probe 足迹内的所有 PixelPlane 存进 groupshared，然后对 octahedron 图上每个方向 texel，遍历所有像素平面取 max(NdotL)。

共同点同样用 DepthWeight 剔除跨表面像素，同样表达"表面朝哪些方向敞开"。不同点它是逐方向显式求值、结果是纹理；而且用 max 而非平均——这是保守策略，只要 probe 覆盖的任一表面朝着某方向，就保留该方向的采样概率，宁可多采不漏采。

代价是每个 texel 都要 O(足迹像素数) 遍历，比 SH 的一次归约更贵，因此默认路径是 A，B 主要用于可视化（顶部 VISUALIZE_BRDF_PDF_SPHERICAL_HARMONIC）与特定回退。

汇聚点 / 发散点总表

环节类型说明
线程组=probe，组内线程=足迹像素汇聚整个 pass 统一的并行组织方式，由 GroupPerProbe indirect dispatch 保证。
ReadMaterialData + PixelPlane + DepthWeight汇聚两条表示路径的公共几何内核，负责剔除跨表面像素。
BRDF_PDF_SPHERICAL_HARMONIC 宏发散SH 9 系数（默认，紧凑）vs Octahedron 纹理（逐 texel，直观）。
HasSphericalVisibility 材质分支发散特殊材质用各向同性常量，普通表面用余弦瓣 SH。
SCREEN_PROBE_DISOCCLUSION && VALID_HISTORY发散permutation 双开时才编译历史帧数检测，输出 disocclusion 标记。
并行归约（SH 求和 + disocclusion 计数）汇聚复用同一套 2 的幂归约与 barrier，一次遍历产出两个结果。

最终总结

说明

ScreenProbeGatherScreenData 是 Screen Probe Gather 的"侦察兵"：在花费任何 trace 预算之前，先用一个 compute pass 为每个 probe 算出表面感兴趣的方向分布（BRDF PDF）和是否新暴露（Disocclusion）。

它的价值直接对应你最初的问题——"预算只够几帧一根光线"。正因为有了 PDF，下一阶段才能把稀缺的光线预算按重要性投向法线上半球，而不是浪费在背面；有了 disocclusion 标记，filter 阶段才知道哪些新区域没历史可复用、需要靠空域补。

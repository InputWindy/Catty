Surface Cache 随机直接光照（Stochastic Direct Lighting）

这是 Surface Cache 光照烘焙 里直接光照那一步的实验性新路径。传统做法是"逐光源建 tile、逐光源算阴影遮罩、批量施光"，光源一多就线性膨胀。随机路径借鉴 MegaLights 思路：每个 card texel 只随机抽少量光源样本、用光追求可见性、再靠时域累积把噪声磨平——把"光源数 × 面元数"的开销压成"每面元固定几个样本"。本篇讲清它的门禁、pass 链、与传统路径的取舍。

为什么需要它：光源数量的诅咒

传统直接光照按"光源 × 面元"膨胀

Surface Cache 的传统直接光照（见 光照烘焙）流程是：逐光源把受影响的 card tile 收集成 light tile（FBuildLightTilesCS），逐光源算阴影遮罩（屏内蹭 shadow map / 屏外追 SDF），再批量施光。光源不多时很高效，但光源数量一大，light tile 数量与施光 pass 都随光源数线性上涨——几十上百个动态光同时影响一片表面时，直接光照就成了 Surface Cache 更新的大头。

随机路径换了个思路：不再"每个光源都完整处理一遍"，而是每个 card texel 固定只抽 N 个光源样本（SamplePerTexel，默认很少），成本只与"面元数 × 每texel样本数"有关，与场景总光源数解耦。代价是单帧结果有噪声，靠时域累积（Temporal）补回来。这正是 MegaLights 的核心思想被搬到 Surface Cache 世界空间的一次落地。

传统 vs 随机：直接光照两条路

维度传统（逐光源施光）随机（Stochastic / MegaLights 式）
成本随光源数近似线性增长基本恒定（只跟每 texel 样本数走）
核心操作逐光源建 tile + 阴影遮罩 + 批量施光压缩光源列表 → 按 PDF 抽样 → 光追可见性 → 时域累积
可见性来源shadow map（屏内）/ SDF 阴影（屏外）MegaLights 光线追踪
单帧质量无噪（确定性）有噪，靠 Temporal 磨平
适用场景光源较少的常规场景大量动态光源的场景
状态默认稳定路径实验性（默认关，需显式开）

① 压缩光源列表 · CompactLightOffset / CompactLightList

FLumenSceneCompactLightOffsetCS + FLumenSceneCompactLightListCS：把"影响每个 card tile 的光源"整理成紧凑连续列表（先算偏移，再填充），让后续采样能高效地在"本 tile 的候选光源"里抽样，而不是遍历全场景光源。

② 生成光源样本 · GenerateLightSamples

FLumenSceneGenerateLightSamplesCS：对每个 card texel，按 FLightTargetPDF（正比于各光源对该 texel 的漫反射贡献估计）构建重要性采样分布，用蓝噪声（BlueNoise.ush）抽出 SamplePerTexel 个光源样本。贡献权重低于 MinWeight 的样本被丢弃，避免为可忽略光源浪费光线。

③ 求值样本 · EvaluateStandaloneLight（MegaLights RT）

FLumenSceneEvaluateStandaloneLightCS 借 MegaLights/MegaLightsRayTracing.ush 对抽中的样本发光线求可见性并做着色，得到该 texel 本帧的直接光贡献。带 Light Function（光照函数材质）的光源走 FLumenSceneEvaluateStandaloneLightMaterialCS（材质 shader 版本），矩形光可开 USE_RECT_LIGHT 走带源纹理的路径。

④ 时域累积 · Temporal

单帧只有几个样本必然有噪。Temporal pass 把本帧结果累加进历史（最多 Temporal.MaxFramesAccumulated 帧），并用邻域钳制（Temporal.NeighborhoodClampScale）限制历史值范围，防止动态光变化时拖影。这一步是随机路径"用时间换样本数"的关键，思路与屏幕探针/反射的时域降噪一脉相承。

与 MegaLights / ScreenProbe 随机采样的关系

同一套"随机采样 + 时域累积"的三处应用

共同点随机直接光照、MegaLights、屏幕探针的重要性采样，本质都是"固定预算抽样 + 时空复用降噪"：用少量随机样本替代穷举，把噪声交给时域（和空间）滤波磨平。随机直接光照可以看作把 MegaLights 的多光源采样搬进 Surface Cache 世界空间的直接光步骤。

不同点它作用在 Surface Cache 世界空间的 card texel 上（不是屏幕像素），产出的是可跨帧复用的世界空间直接光照 atlas，供 GI 追踪命中时读取；而 MegaLights 直接作用于屏幕最终像素。两者共享 MegaLightsRayTracing.ush 的求值内核，但落点不同。

最终总结

随机直接光照是 Lumen 为"大量动态光源"场景准备的实验性路径：它把 Surface Cache 直接光照从"逐光源施光（成本随光源数线性膨胀）"改成"每 texel 抽固定数量光源样本 + MegaLights 光追求可见性 + 时域累积去噪"，让直接光成本与场景光源总数解耦。pass 链是压缩光源列表 → 按 PDF+蓝噪声抽样 → 光追求值 → Temporal 累积，由 r.LumenScene.DirectLighting.Stochastic 门禁（默认关）。它和 MegaLights、屏幕探针重要性采样共享"随机采样 + 时空复用"的同一套哲学，只是落在 Surface Cache 世界空间。理解它，就理解了 Lumen 面对"多光源"这个老难题时，如何用蒙特卡洛 + 时域累积把成本重新框定。

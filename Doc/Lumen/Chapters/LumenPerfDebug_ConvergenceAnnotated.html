上下文：为什么 Lumen 排障要"分层看"

Lumen 是多层缓存 + 多级追踪 + 多段降噪的复杂系统，一个画面问题可能出在任何一层。盲目调 CVar 只会按下葫芦浮起瓢。正确姿势是先用可视化定位到层，再针对那一层调参：间接光整体缺失/发暗 → 大概率 Surface Cache 没覆盖到（Mesh Cards 问题，看 r.Lumen.Visualize.CardPlacement）；间接光有但噪 → Final Gather 采样/降噪不足；反射脏/闪 → 反射降噪；漏光 → Global DF 精度或 Surface Cache 分辨率；鬼影 → velocity/时序（外部边界，见 系统边界）。本页把"症状 → 层 → 命令/CVar"这条链路做成速查，是前面所有主题的实战出口。

1. 可视化：先定位到层

说明

可视化是排障第一步，目的是把问题归到某一层。LumenScene/SurfaceCache 可视化直接显示表面缓存内容——如果某物体在这里是黑的/缺失，说明卡片没捕获到它，间接光自然缺。CardPlacement 用颜色标出 Mesh Cards 覆盖，红色区域是"没有卡片朝这个方向"，是间接光漏洞的直接证据。GlobalDistanceField 可视化能看出远场几何是否被 SDF 正确表示——漏光常常是这里精度不够。

2. Profiler：分解 Lumen 各 pass 耗时

说明

ProfileGPU 抓单帧 GPU 耗时树，Lumen 的 pass 名都带前缀好找。典型排序：ScreenProbeGather（Final Gather）通常最贵，其中追踪与滤波占大头；Reflections 在光滑场景可能反超；SceneLighting（Surface Cache 光照烘焙）相对稳定；UpdateLumenScene 平时便宜、但物体大量变化时会尖峰（卡片捕获爆发）。找到最贵的 pass 再决定往哪个方向降质。

3. 画质问题 → 环节 → CVar 对照

说明

这是本页的核心速查。间接光缺失/发暗几乎总是 Surface Cache 问题（卡片没覆盖或分辨率不够）——先看 CardPlacement。漏光是 Lumen 最常见顽疾，根源多在 Global DF 精度不足（远场 SDF 把该挡光的墙"漏"了）或 Radiance Cache 的 occlusion 处理。噪点是采样/降噪不足，加探针密度或多累几帧。鬼影基本是外部边界问题（velocity 不准），不要在 Lumen 内部找。把症状对到层能省下大量盲调时间。

最终总结

Lumen 排障的核心心法是"先分层定位，再对症调参"——因为它是缓存×追踪×降噪的多层系统，任何单一画面问题都可能来自不同层，盲调 CVar 只会互相干扰。方法论固定三步：① 用 Visualize 系列命令把问题归到 Surface Cache / 追踪 / 降噪 / 外部边界某一层；② 用 ProfileGPU 确认性能瓶颈在哪个 pass；③ 查"症状→层→CVar"表对症下药，改完回到可视化验证。这套流程把前面所有主题的算法知识变成可操作的排障能力：知道 Surface Cache 是世界空间缓存，才懂"间接光延迟长出来"是正常的；知道反射是三段降噪，才懂反射脏该往哪调；知道时域降噪靠 velocity，才懂鬼影要去查外部边界而非 Lumen 本身。

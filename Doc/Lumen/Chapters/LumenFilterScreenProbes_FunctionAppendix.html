1. 六个 Compute Shader 的职责

Compute Shader职责关键 permutation / 参数
FScreenProbeCompositeTracesWithScatterCS把 tracing 分辨率、方向不规则的每光线结果 scatter 合成到 gather 分辨率的 ScreenProbeRadiance，并产出 HitDistance / TraceMoving / ExtraAO。FThreadGroupSize / FStructuredImportanceSampling / FScreenProbeExtraAO；MaxRayIntensity 量化钳制
FScreenProbeCalculateMovingCS将每光线的 TraceMoving 归约为每 probe 的 ScreenProbeMoving 运动标记。FThreadGroupSize；DebugForceTracesMoving

说明

六个 CS 共享同一个 ScreenProbeParameters 和 ProbeIndirectArgs（indirect dispatch，只对实际分配的 probe 启动线程组）。除 GenerateMip 用固定 GetGroupCount 外，其余都用 indirect args 的不同粒度偏移。

差异在数据流角色：Composite 是生产者（把 trace 结果落地），Temporal/Spatial 是降噪器（累积等效采样），ConvertToIrradiance 是压缩器（转积分表示），FixupBorders/GenerateMip 是采样铺路者（保证下游可安全插值）。

2. 时域重投影的权重设计

说明

时域累积不是简单叠加，要解决"历史是否可信"：

① HistoryScreenProbeTranslatedWorldPosition 提供上一帧每 probe 的世界位置，重投影时用它对齐；② HistoryDistanceThreshold 判断重投影点与当前点的世界距离，超阈值说明是新表面（历史无效，丢弃）；③ HistoryScreenProbeSceneDepth 做深度一致性校验，防止把前景/背景混在一起；④ HistoryUVMinMax 把双线性采样钳在有效视口内；⑤ PrevInvPreExposure 补偿曝光变化（历史存的是带曝光的值，需先还原）。通过校验的历史才以 HistoryWeight=0.5 混合。

3. SH3 vs Octahedron 两种 irradiance 表示

说明

不同点SH3（3 阶球谐）把整张方向性 radiance 压成 9 个系数，存成 Ambient（1）+ Directional（宽度×6）两张图。插值阶段只需把表面法线余弦瓣与 SH 点乘即可得辐照度，极致省带宽，但丢失高频方向细节。

Octahedron irradiance 则保留一张按方向排布的 irradiance 图（带 border），方向分辨率更高，适合对方向性/AO 敏感的场景，代价是更大的内存与采样带宽。

共同点两者都在同一个 FScreenProbeConvertToIrradianceCS 内由 FProbeIrradianceFormat permutation 分支产出，且都会被下游 InterpolateAndIntegrate 消费。格式选择与 LumenAmbientOcclusionIntensity 相关——需要 AO 时倾向保留更多方向信息。

4. Dispatch 粒度速查

粒度（EScreenProbeIndirectArgs）含义使用的 pass
GroupPerProbe一个线程组处理一个 probe 的整张 octahedron（需组内归约时用）。CompositeTraces / CalculateMoving / ConvertToIrradiance
ThreadPerGather一个线程处理 gather 图的一个 texel。TemporallyAccumulate / FilterGatherTraces
ThreadPerGatherWithBorder一个线程处理带边界 gather 图的一个 texel。FixupBorders
固定 GetGroupCount非 indirect，按 mip 尺寸直接算组数。GenerateMipLevel

说明

粒度选择反映各 pass 的并行结构：需要跨方向归约的（合成、算 SH 系数）用 GroupPerProbe，让一组线程协作处理一个 probe 的所有方向；逐 texel 独立的滤波用 ThreadPerGather。GenerateMip 因为 mip 尺寸逐级减半、且不依赖 probe 分配情况，直接用固定 GetGroupCount 而非 indirect args。

5. 与上下游的关系

关系对象说明
上游输入ScreenProbeParameters（trace radiance）来自 TraceScreenProbes，每根光线的 incoming radiance + moving 信息。
跨帧状态ScreenProbeGatherState读历史 radiance/depth/worldpos 做重投影；写回两套历史（合成前 + 滤波后）。
下游输出FScreenProbeGatherParametersRadiance / RadianceWithBorder / SHAmbient / SHDirectional / IrradianceWithBorder / ExtraAOWithBorder / Moving，交给 InterpolateAndIntegrate。
调用者RenderScreenProbeGather作为第四个子阶段被顺序调用，紧接 TraceScreenProbes 之后、InterpolateAndIntegrate 之前。

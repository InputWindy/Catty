0. 为什么要 GPU 实时压缩

临时目标（未压缩 RGBA8）→ CompressCS → 压缩物理页（BC/ASTC）

说明

#5 的 bCompressTextures=true 要求物理页用 GPU 压缩格式存（BC/ASTC），显存占用降到 1/4~1/8。但材质是渲进未压缩临时目标的，所以缺页现画后必须在 GPU 上实时块压缩一遍（离线烘焙的 SVT 不需要，页里已是压缩格式）。这就是本 shader 的存在意义——它是 RVT 相对 SVT 独有的一步，代价是每次现画多一趟 compute。

1. 一线程一 4×4 块

[numthreads(8,8,1)]  // 组内 64 线程 = 32×32 像素
uint2 SamplePos = SourceRect.xy + ThreadId.xy * 4;  // 每线程负责一块
ReadBlockRGB(..., BlockBaseColor);  // 读该块 4×4=16 个纹素

说明

BC/ASTC 都是 4×4 像素为一个压缩块，所以映射极自然：一个线程压一个块，ThreadId.xy * 4 定位块左上角，ReadBlock 采回 16 个纹素到本地数组。8×8 线程组一次覆盖 32×32 像素。GetDestPos 把块坐标映到物理页里的目标位置。越界块（超出 SourceRect）直接 return——RVT 页边缘不满整块时的保护。

2. 按平台 + 布局分派（发散核心）

#if ASTC_PROFIlE   CompressBlock_ASTC_*   // 移动
#elif ETC_PROFILE  CompressBlock_ETC2_*   // 部分移动
#else              CompressBC1/BC3Block  // 桌面

说明

共同点不管什么格式，流程都是"读 4×4 块 → 调 CompressBlock_* 编码 → 写目标"，且都有按 MaterialType 的多套内核：CompressBaseColorCS(单层 64 位) / CompressBaseColorNormalSpecularCS(3 层写两张 128 位)。

不同点压缩格式随平台 permutation 分三路：桌面 BC1/BC3（64/128 位块）、移动 ASTC、部分移动 ETC2。法线的 X/Y 分开塞进不同块的 alpha 通道以保精度（BlockNormalX/BlockNormalY）。这套 permutation 与 Material.usf 的 MRT 布局宏严格对应——写入侧产出几张 MRT，压缩侧就有几路对应内核。

最终总结

骨架

一线程一 4×4 块：读 16 纹素 → 按平台（BC1/BC3/ETC2/ASTC）+ 布局（1层/3层）实时块压缩 → 写压缩物理页。这是 RVT bCompressTextures 现画后的独有一趟 compute。

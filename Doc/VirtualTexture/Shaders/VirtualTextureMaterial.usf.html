VirtualTextureMaterial.usf 汇聚/发散批注版

核心源码对照 （182 行文件的核心节选，逐行真实）

Engine/Shaders/Private/VirtualTextureMaterial.usf · FPixelShaderInOut_MainPS L71

0. 两种属性来源（VT 输出 vs 标准材质）

#if VIRTUAL_TEXTURE_OUTPUT   GetVirtualTextureOutput0..8(...)
#else                        GetMaterialBaseColor/Specular/...

说明

不同点材质可以走两条路给 RVT 供数据：① 用专门的 RuntimeVirtualTextureOutput 节点（VIRTUAL_TEXTURE_OUTPUT），显式声明"这些属性写进 RVT"；② 直接用标准材质输出（BaseColor/Normal/Roughness…）。共同点两路最终都归到同一组本地变量（BaseColor/Normal/Roughness/Specular/Height/Displacement），再统一打包——这让"专用 RVT 材质"和"复用普通材质"都能画进 RVT。这是 #5 说的"把材质输出预合成进页"的入口。

1. 按 MaterialType 分 MRT 布局（发散核心）

#if OUT_BASECOLOR_NORMAL_SPECULAR
  Out.MRT[0]=BaseColor; MRT[1]=(Normal.xy,Mask); MRT[2]=(Specular,Roughness,Normal.z)

说明

全 shader 的发散点：#5 的 MaterialType（≤3 层）在这里落成不同的 MRT 输出布局——OUT_BASECOLOR(1层) / OUT_BASECOLOR_NORMAL_ROUGHNESS(2层) / OUT_BASECOLOR_NORMAL_SPECULAR(3层) / OUT_MASK4 / OUT_WORLDHEIGHT / OUT_DISPLACEMENT。法线用 PackNormal 压两分量、第三分量塞进别的 MRT 通道省带宽；BaseColor 存 sRGB 提质量；全部 * Opacity 做预乘便于后续混合。这组 MRT 就是物理页的层布局，直接对应 URuntimeVirtualTexture 的 MaterialType。

2. 与 Compress、页表的衔接

MainPS 写临时 MRT → VirtualTextureCompress.usf 压 BC/ASTC → 物理页
普通材质采样 VT 时（另一路）：查页表 → 采物理页 → 写反馈

说明

本 shader 是 RVT 的写入侧：产出的临时 MRT 交给 VirtualTextureCompress.usf ↗ 压成 GPU 压缩格式写进物理池（对应 #5 的 RenderFinalize→Finalize 分相）。另一侧的读取/反馈——普通材质采样一张 VT 时查页表间接寻址 + 写缺页反馈（#3）——由材质编译期注入的 VT 采样函数完成，与本文件的写入路径合起来构成 VT 的读写闭环。

骨架

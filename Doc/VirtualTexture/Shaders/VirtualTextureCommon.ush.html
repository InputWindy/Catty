0. 反馈请求的蓄水池采样写入（核心）

struct FVirtualTextureFeedbackParams { uint Request; uint Count; uint RequestIndex; uint Random; uint DebugCounts; };
Params.RequestIndex = View.VirtualTextureFeedbackSampleOffset % max(NUM_VIRTUALTEXTURE_FEEDBACK_REQUESTS + LIGHTMAP_VT_ENABLED, 1);
// StoreVirtualTextureFeedback: 用 reservoir sampling 从多次采样中选一个请求写出
//   rand() % (1 + Count) == 0 → 选中本次采样
Params.DebugCounts = (NUM_VIRTUALTEXTURE_SAMPLES + LIGHTMAP_VT_ENABLED) << 16;   // 供 Visualize 解包

说明

一个像素可能采样很多张 VT（多层材质、lightmap VT…），但反馈缓冲每像素只能写一条页请求。本库用蓄水池采样（reservoir sampling）公平地从这些采样里随机选一条写出（rand() % (1+Count) == 0 的经典 1/N 概率），既省带宽又无偏——CPU 收集这些请求后决定加载哪些页。DebugCounts 累计"采了几张 VT / 缺几级 mip"供 VisualizeVirtualTexture 解包着色。这是 VT 按需流送闭环的采样侧起点（页请求→#3 反馈→CPU 加载→页表更新）。

1. VTPageTableResult：间接寻址结果（核心）

struct VTPageTableResult { float2 UV; float2 dUVdx; float2 dUVdy; uint4 PageTableValue[4]; uint PackedRequest; float MipLevelFrac; ... };
uint GetVirtualTexturePendingMips(uint RequestedLevel, uint4 PackedPageTableValue, uint AccumulatedResult)
// 从页表值取最小可用 mip，与请求 mip 比较，得出还差几级（pending）

说明

VT 采样是两级间接：先查页表（VTPageTableResult 存查到的页表值 + 原始 UV + 导数 dUVdx/dy 用于选 mip），再据此算出物理池里的实际采样位置。GetVirtualTexturePendingMips 比较"想要的 mip"与"页表里实际可用的最小 mip"——差值就是 pending mips（还没流送到位的清晰度），累计进反馈供调试与流送优先级。MipLevelFrac 支持 mip 间三线性混合。这套结构 + PageTableUpdate 刷新的页表，共同实现"虚拟地址→物理 tile"的运行时翻译。

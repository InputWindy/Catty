定向光为什么非用 clipmap 不可 Why directional lights need clipmap

定向光的两难

点光/聚光的阴影视锥是有限的——一个立方体或一个锥就框住了。但定向光（太阳）没有位置，光线平行，理论上要覆盖整个可见世界。如果用单张阴影图覆盖到地平线，近处的分辨率会低到没法看；如果只覆盖近处，远处就没阴影。这正是 #7 clipmap 要解决的问题——精度需求随距离衰减。传统方案是 CSM（级联阴影图，Cascaded Shadow Maps），VSM 则把它升级成真正的 clipmap：以相机为中心，一叠按 2 的幂递增覆盖半径的层。

近处层（FirstLevel）覆盖半径小、分辨率高
脚下的清晰阴影
中间层每层半径翻倍
RadiiPerLevel = 4
远处层（LastLevel）覆盖到地平线
分辨率低但够用

VSM = VT + Clipmap 的合体 Two paradigms in one

本书最精彩的交叉点

VSM 里，每个 clipmap 层本身是一张虚拟阴影贴图——它的页也走 #2 讲的 VT 页表 + 物理池 + 缓存失效那一套（只是物理池存的是深度而非颜色）。所以 VSM 的组织是两层嵌套：外层用 clipmap（第三范式）决定"哪些层、每层覆盖多大范围、中心在哪"；内层用 VT 页表（第二范式）决定"这层里哪些页真的需要渲染、哪些能从上帧缓存复用"。FVirtualShadowMapClipmap::GetVirtualShadowMapId() 就是把 clipmap 层接到 VSM 的 VT id 上。这印证了 #7 的观点：三范式不是互斥的，可以组合。

层级构建：从 CVar 到 FLevelData Level construction

FVirtualShadowMapClipmapConfig 从 CVar 取配置（源码默认值）：

CVar默认作用
r.Shadow.Virtual.Clipmap.FirstLevel6最近层的绝对级号；越低近处阴影越清晰，但页数增加
r.Shadow.Virtual.Clipmap.LastLevel22最远层；每加一级最大覆盖半径翻倍
r.Shadow.Virtual.Clipmap.FirstCoarseLevel15从哪级开始标记粗页

每层半径：2 的幂（源码直译）

层半径由 GetLevelRadius(AbsoluteLevel) 决定，源码就一行：

// clipmap 层向下取整，半径要覆盖到 2^(Level+1) float FVirtualShadowMapClipmap::GetLevelRadius(float AbsoluteLevel) { return FMath::Pow(2.0f, AbsoluteLevel + 1.0f); }

所以 FirstLevel=6 → 半径 2⁷=128；每高一级半径翻倍；LastLevel=22 → 2²³ 约 800 万单位（覆盖极远）。绝对级号 AbsoluteLevel = ClipmapIndex + FirstLevel，级数 = LastLevel − FirstLevel + 1（默认约 17 级）。LevelData 用 TInlineAllocator<32> 内联最多 32 级，避免堆分配。

页对齐吸附（snapping）——clipmap 无闪烁的关键

源码注释点明：the centers of each of the levels can be different as they are snapped to page alignment at their respective scales。即每层中心不是简单等于相机位置，而是各自吸附到该层尺度下的页边界（FLevelData::WorldCenter、CornerOffset、RelativeCornerOffset）。这正是 #7 讲的 toroidal 环形寻址在 VSM 里的落地——相机小幅移动时，只要没跨过页边界，该层根本不用更新；跨过了也只更新新进入的边缘页。这就是为什么 VSM 的定向光阴影移动时几乎不闪、也不需要每帧全量重画。

Shader 寻址：世界坐标 → 层 → 页 Addressing

每层有独立的投影（FVirtualShadowMapProjectionShaderData，由 ComputeProjectionShaderData 生成，含 ViewToClip + PreViewTranslation = -WorldCenter）。采样一个世界点的阴影时：

1选层按到 clipmap 原点距离选绝对级
log2(dist) 类比 #7 的层选择
2投影到该层用该层 ViewToClip + WorldCenter
算出层内 UV
3VT 页表查找层内 UV → VSM 页表 → 物理页
采深度做阴影比较

与经典 clipmap 寻址对照

这三步几乎就是 #7 伪代码的 UE 实现：第 1 步"距离选层"= log2(DistToCamera/FinestRadius)；第 2 步"层内定位"用每层各自的 WorldCenter（已吸附）替代简单原点；第 3 步不同——经典 clipmap 是直接 toroidal 取模访问物理纹理，VSM 多套了一层 VT 页表间接，因为它要复用 VSM 的按需分页与缓存（不是所有层的所有页都需要，只画反馈里被采到的）。WorldToLightViewRotationMatrix 把世界空间转到光源视角（定向光只有旋转、无平移）。

缓存与失效 Cache & invalidation

VSM clipmap 的每帧增量更新靠 FVirtualShadowMapPerLightCacheEntry（PerLightCacheEntry）：

成员/方法作用

动态物体失效

移动的物体、开了 WPO/动画的几何会让它覆盖的阴影页失效——这与 #5 RVT 的脏区失效思路一致（都是"内容变了→踢页→下帧重画"）。FirstCoarseLevel/LastCoarseLevel 之间的粗页有性能模式（CVar 值=2）可抑制这类动态失效，用轻微精度换稳定帧率——这是 clipmap 分层带来的调优自由度：远处粗层可以"懒一点"。

与另外两种范式的关系 Cross-paradigm

VSM 是三范式的交汇处

共同点：VSM 的每个 clipmap 层内部完全是 #2 的 VT 机制——页表、物理池、反馈驱动的按需分页、缓存失效，一个不少（只是存深度）。

不同点：与 #1/#6 的流送不同，VSM 的阴影页不从磁盘来，是每帧现渲染的深度——这点和 #5 RVT "GPU 现画"更像。

不同点：clipmap 层的组织（层数、半径、中心吸附）是纯 #7 第三范式——由相机/光源位置几何确定，与 VT 的反馈驱动正交。VSM 把两者叠起来：clipmap 管"宏观分层"，VT 管"层内微观分页"。

本篇小结 Summary

记住这几点

1. 定向光没有有限视锥、精度随距离衰减，天然适配 clipmap——VSM 用它替代传统 CSM。

2. VSM = Clipmap（宏观分层）+ VT 页表（层内分页）的合体，是本书两种范式的交汇点。

3. 层半径 GetLevelRadius = 2^(Level+1)，级号 = FirstLevel(6)~LastLevel(22)；每层中心吸附到页边界实现 toroidal 增量更新、无闪烁。

4. 寻址三步：距离选层 → 用该层投影定位层内 UV → VT 页表查物理页采深度。缓存失效同 RVT 脏区思路。

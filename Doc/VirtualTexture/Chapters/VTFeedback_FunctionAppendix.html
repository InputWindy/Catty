FUniqueRequestList UniqueRequestList.h

用 FConcurrentLinearBulkObjectAllocator 预分配多组请求数组 + 各自的去重哈希，把不同类型的请求分开统计：

请求组计数器含义
LoadRequestsNumLoadRequests需 producer 产出 tile 数据的页
—NumNonStreamingLoadRequests其中非流式（如 RVT 现画）的数量
—NumLockRequests被锁定常驻的 tile
MappingRequestsNumMappingRequests待写页表项（指向某 load）
DirectMappingRequestsNumDirectMappingRequests数据已在池，直接写页表（含 pAddress）
ContinuousUpdateRequestsNumContinuousUpdateRequests每帧持续刷新的 VT
AdaptiveAllocationsRequestsNumAdaptiveAllocationRequests自适应 VT 分配（见 #6）

Reset(bResetContinousUpdates)：每帧清空 load/mapping，continuous 可选保留。

请求 union 位域打包

FMappingRequest（64 位）

union FMappingRequest { uint64 PackedValue; struct { uint32 vAddress : 24; // 虚拟页地址 uint32 vLevel : 4; // mip 层 uint32 SpaceID : 4; // 属于哪个 space uint32 LoadRequestIndex : 16; // 指向哪个 load 请求 uint32 Local_vLevel : 4; uint32 ProducerPhysicalGroupIndex : 4; uint32 PageTableLayerIndex : 4; uint32 MaxLevel : 4; }; }; static_assert(sizeof(FMappingRequest) == sizeof(uint64), "Bad packing");

FDirectMappingRequest（96 位，含物理地址）

union FDirectMappingRequest { uint32 PackedValue[3]; struct { uint32 vAddress : 24; uint32 vLevel : 4; uint32 SpaceID : 4; uint32 pAddress : 16; // ★ 物理地址：数据已在池 uint32 PhysicalSpaceID : 8; uint32 Local_vLevel : 4; uint32 MaxLevel : 4; uint32 PageTableLayerIndex : 4; uint32 Pad : 28; }; }; static_assert(sizeof(FDirectMappingRequest) == sizeof(uint32) * 3, "Bad packing");

两者的区别一目了然：Mapping 只有 LoadRequestIndex（数据还没好，指向一个 load）；DirectMapping 直接带 pAddress + PhysicalSpaceID（数据已在池，可立即写页表）。

FTexturePagePool / FTexturePageMap TexturePagePool.h / TexturePageMap.h

FTexturePagePool 管理物理纹理图集里的页，用 二叉堆（FreeHeap，Containers/BinaryHeap.h）实现 LRU 淘汰；FTexturePageMap 跟踪单层页表的映射。一个物理页可被映射进任意多个虚拟页表。

方法 / 计数说明
Initialize(NumPages)初始化池容量
GetNumLockedPages() = GetNumPages() - FreeHeap.Num()被锁/在用的页数
GetNumMappedPages() / GetNumAllocatedPages()已映射 / 已分配页数
EvictAllPages(System)清空池（flush cache）
EvictPages(System, ProducerHandle, ...)淘汰某 producer / 某区域的页
UnmapAllPagesForSpace(...)解除某 space 地址范围的所有映射（页仍常驻）
RemapPages(...)把物理页从一个 producer 重映射到另一个（自适应 VT 用）

页与映射解耦

源码注释点明设计：Pages can be allocated for a particular virtual texture, and mapped into any number of virtual pages tables。即"物理页的分配"和"页表映射"是两件事——一个物理页可同时被多张 VT 的页表指向（共享），UnmapAllPagesForSpace 能只解映射而保留页常驻。这正是 #3 主文档里 DirectMapping 能免加载的底层支撑。

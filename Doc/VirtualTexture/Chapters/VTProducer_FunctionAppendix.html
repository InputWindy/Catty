#4 附录 · Producer 接口与页数据结构

本附录汇总生产者接口、请求状态、producer 描述、SVT 离线数据格式、转码/上传缓存与 producer 集合的核心符号。均取自 UE5.8 本地源码 Engine/Source/Runtime/RenderCore/Public/VirtualTexturing.h 与 Engine/Source/Runtime/Engine/Private/VT/。

IVirtualTexture VirtualTexturing.h

页数据生产者接口。框架（#3 的 Load 请求）只通过它取页数据，不关心背后是 GPU 现画还是磁盘流入。

方法说明
RequestPageData(RHICmdList, ProducerHandle, LayerMask, vLevel, vAddress, Priority)发起请求，返回 FVTRequestPageResult { Status, Handle }；SVT 在此发起磁盘读，Handle 为不透明句柄传给下一步
ProducePageData(RHICmdList, FeatureLevel, Flags, ProducerHandle, LayerMask, vLevel, vAddress, RequestHandle, TargetLayers)把 tile 像素写进 FVTProduceTargetLayer[]，返回一个 IVirtualTextureFinalizer*
IsPageStreamed(vLevel, vAddress) const该页是否来自流式数据（SVT true / RVT 现画 false）
GatherProducePageDataTasks(ProducerHandle, GraphEvents)收集本 producer 产出页所依赖的任务图事件，供框架等待
DumpToConsole(bVerbose)调试转储

系统保证同一 (vLevel, vAddress) 只请求一次，LayerMask 里带上本页需要的所有纹理层，一次产出多层。

EVTRequestPageStatus VirtualTexturing.h

枚举值含义
Invalid请求无效，永远不会有数据
Saturated系统某部分满载，暂时发不了；稍后重试可成功（节流关键）
Pending数据正在产出，还没好；可 produce 但可能阻塞等待
Available数据已就绪，可立即 produce
// 只要 Pending 或 Available，就认为"有数据（可能要等）" inline bool VTRequestPageStatus_HasData(EVTRequestPageStatus Status) { return Status == EVTRequestPageStatus::Pending || Status == EVTRequestPageStatus::Available; }

FVTRequestPageResult 打包 { EVTRequestPageStatus Status; uint64 Handle; }，Handle 在 ProducePageData 时原样回传。

IVirtualTextureFinalizer VirtualTexturing.h

方法读写约束
RenderFinalize(RHICmdList, System)不写物理纹理，可采样其它 VT——所有 finalizer 的这一半先跑
Finalize(RHICmdList)写物理纹理但不采它——所有 RenderFinalize 跑完后统一跑

为什么拆两半

RVT 现画一页时可能要采样别的 VT（地形材质引用另一张 VT）。这必须在"还没开始写物理池"的阶段做，否则读写同一批物理页产生 hazard。分相（先全体只读采样，再全体只写）把 GPU barrier 降到最少。

FVTProduceTargetLayer VirtualTexturing.h

ProducePageData 的输出目标，每个纹理层一个：

字段说明
TRefCountPtr<IPooledRenderTarget> PooledRenderTarget目标物理纹理（图集）
FIntVector pPageLocation页在物理图集里的落点坐标

producer 把 tile 数据写到 PooledRenderTarget 的 pPageLocation 处；框架据此把虚拟页表项指向该物理地址。

FVirtualTextureBuiltData VirtualTextureBuiltData.h

SVT 的 on-disc 数据格式。上限 VIRTUALTEXTURE_DATA_MAXLAYERS = 8 层、VIRTUALTEXTURE_DATA_MAXMIPS = 16。

成员说明
NumLayers / WidthInBlocks / HeightInBlocks / TileSize / TileBorderSize整体形状
Chunks : TArray<FVirtualTextureDataChunk>所有 tile 打包进的数据块
TileOffsetData / TileIndexPerChunk / TileIndexPerMip稀疏 chunk 内定位 tile 偏移的紧凑索引
GetTileMemory / GetTileOffset取某 tile 数据位置

FVirtualTextureDataChunk

字段说明
UE::FDerivedData DerivedData可流式引用（编辑器 DDC）
FByteBulkData BulkData运行时加载的数据
uint32 SizeInBytes / CodecPayloadSizechunk 大小 / codec 负载大小
uint32 CodecPayloadOffset[MAXLAYERS]每层 codec 负载在 chunk 内偏移
EVirtualTextureCodec CodecType[MAXLAYERS]每层用哪种 codec 解码

tile 按 Morton 序存

源码注释：The tiles are stored in Morton order inside the chunks。Z 序曲线让空间相邻的 tile 在文件里也相邻，请求一片区域时磁盘读取局部性好。UDIM 某些 mip 区域为空，用紧凑结构记录稀疏 chunk 里的实际 tile 偏移。

EVirtualTextureCodec（uint8）

codec说明
Black整页 0,0,0,0
OpaqueBlack整页 0,0,0,255
White整页 255,255,255,255
Flat整页 128,128,255,255（平法线）
RawGPUGPU 就绪格式（R8G8B8A8 / BC7 / ASTC…），转码开销最小
ZippedGPU_DEPRECATED / Crunch_DEPRECATED已弃用（压缩变体）
Max计数哨兵

常量 codec（Black/OpaqueBlack/White/Flat）整页恒定色、不占实际数据——稀疏 VT 里省下大量磁盘与显存。

FVirtualTextureCodec 是转码器，侵入式链表节点（TIntrusiveLinkedList）串成全局 LRU 链：

成员 / 方法说明

// 结果+状态的两种回传包 struct FVTCodecAndStatus { const FVirtualTextureCodec* Codec; EVTRequestPageStatus Status; }; struct FVTDataAndStatus { IMemoryReadStreamRef Data; EVTRequestPageStatus Status; };

两层缓存

一个 chunk 含多个 tile。转码缓存（codec 复用）让同一 chunk 的多个 tile 共享一次解码准备；上传缓存合并小的 GPU 上传、削峰。二者配合 #2 的单帧上传预算（MaxSVTPageUploads）做节流。

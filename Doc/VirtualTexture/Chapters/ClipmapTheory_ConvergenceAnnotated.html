从 mipmap 说起：为什么需要 clipmap The motivation

一张完整 mipmap 金字塔存了从原图到 1×1 的所有层，总大小约为原图的 4/3。但当原图大到 128K×128K（飞行模拟、地形、超大阴影图）时，光是最精细那几级就装不进显存。关键观察是：

Clipmap 的核心洞察（Tanner et al., SIGGRAPH 1998）

在任一时刻，屏幕上真正能看到的，只是每一级 mip 里靠近视点的一小块。远处用粗 mip（覆盖广但分辨率低），近处用细 mip（分辨率高但只需覆盖眼前一小片）。所以完全不必存整级——只需为每级存一个以视点为中心、固定大小的窗口（clip region）。这个"被裁剪过的 mipmap"就叫 clipmap。

完整 mipmap每级都存整张
128K² 级别根本放不下
裁剪每级只留视点附近固定大小窗口
高层（粗）小到能整级存下就整级存
Clipmap金字塔上半截=完整 mip
下半截=固定大小的 clip 窗口叠起来

Clipmap 的结构：clip 层 + mip 层 Anatomy

一个 clipmap 由两部分拼成，分界点叫 clip size（每级窗口的边长上限，如 2048）：

部分特征
Mip 层（金字塔顶部）这些级本身就 ≤ clip size，所以完整存储，和普通 mipmap 一样。任何位置都能采到——这是全局回退。
Clip 层（金字塔底部）这些级 > clip size，只存以视点为中心的 clip size × clip size 窗口。想采窗口外的高清数据？没有——只能退到更粗的层。

toroidal（环形）寻址：相机一动怎么办

相机移动时，每个 clip 层的窗口要跟着平移。如果每帧整块重传代价太大。经典做法是 toroidal addressing（环形/卷绕寻址）：窗口在物理纹理里循环取模，相机移动一格，只需更新新进入视野的边缘一条 L 形区域，其余数据原地不动、靠取模复用。这就是 clipmap 更新的精髓——增量、只更新边缘，而不是整层重建。

Geometry Clipmap（Losasso & Hoppe, SIGGRAPH 2004）

把同一思想搬到几何/地形高度场：以相机为中心的一叠嵌套正方形网格环（nested regular grids），近处网格密、远处稀，相机移动时同样用环形寻址增量更新，并在层间做几何 morphing 消除 popping。UE 的地形与距离场都受它启发。要点：clipmap 不只用于颜色纹理，任何"以相机为中心、分层 LOD、增量滚动"的数据都能套这个模型——这正是它能同时出现在阴影（#8）和 GI（#9）里的原因。

寻址：给一个世界坐标，采哪一级 Level selection

Clipmap 采样和 mipmap 不同——不是靠屏幕导数选 LOD，而是靠到相机的距离选层：

// clipmap 层选择（概念伪代码） float DistToCamera = length(WorldPos - ClipmapCenter); // 距离越远，选越粗（越高）的层；每层覆盖半径按 2 的幂递增 int Level = clamp(log2(DistToCamera / FinestRadius), 0, MaxLevel); // 层内再用 toroidal 取模定位物理坐标 float2 PhysUV = frac((WorldPos - LevelOrigin) / LevelSize);

与 VT 页表寻址的对照

VT 是"虚拟地址 → 页表查物理地址"，缺页触发反馈加载；Clipmap 是"世界坐标 + 距离 → 层号 + 环形取模"，没有缺页概念——需要的层一定在（因为层集合由相机位置决定，每帧维护好）。这是两种范式在寻址哲学上的根本差异：VT 是惰性、按需、可能缺；Clipmap 是主动、预置、恒在。

★ 三范式横向对比 The three paradigms side by side

① 整级 Mip 流送粒度：整级 mip
驱动：CPU 距离/屏幕大小预测
数据源：磁盘 bulk data
缺失处理：用已有的更粗 mip
见 #1
② 页表式 VT粒度：单页 tile
驱动：GPU 反馈（事后精确）
数据源：producer（RVT 现画 / SVT 磁盘）
缺失处理：反馈→加载→写页表
见 #2~#6
③ Clipmap粒度：以相机为心的层窗口
驱动：相机位置（主动预置）
数据源：源纹理/场景重采样
缺失处理：无缺页，退到更粗层
见 #8/#9

谁决定加载什么CPU 预测（距离×屏幕）GPU 反馈实测（谁被采）相机位置（几何确定）
间接寻址无（直接采纹理）有（页表一次查找）轻（层号+取模）

更新时机资产可见性变化每帧反馈闭环相机移动时增量滚动

一句话记住三者

共同点：三者都在解同一个问题——数据总量远大于显存，只能常驻"当前真正需要的一小部分"，本质都是空间上的 LOD + 时间上的换入换出。

不同点：区别只在"用什么信号决定那一小部分是什么"——距离预测（①）、GPU 反馈（②）、还是相机位置的几何推导（③）。信号不同，导致粒度、寻址、缺失处理全都不同。

为什么 Clipmap 特别适合阴影/距离场/GI Why camera-centric wins here

相机中心 = 这些数据的天然属性

阴影贴图、全局距离场、辐照度缓存有一个共性：它们的精度需求天然随到相机的距离衰减——近处要清晰阴影/精细 GI，远处糊一点没人看得出。这正好是 clipmap 的假设前提。而且它们通常是每帧重新生成/更新的（不是从磁盘读的静态资产），所以 VT 那套"反馈→磁盘加载"的闭环用不上，反而是 clipmap"相机一动、增量滚动重算边缘"最省。这就是为什么 UE 的 VSM（#8）对定向光、Lumen（#9）对 GI 都选了 clipmap。

本篇小结 Summary

记住这几点

1. Clipmap = 被裁剪的 mipmap：顶部几级完整存（mip 层，全局回退），底部大级只存以视点为中心的固定大小窗口（clip 层）。

2. 相机移动用 toroidal 环形寻址增量更新：只重传新进视野的边缘条带，其余取模复用。这是 clipmap 高效的核心。

3. Geometry clipmap 把同思想推广到地形/几何——任何"相机中心 + 分层 LOD + 增量滚动"的数据都适用。

4. 三范式的本质差别是决策信号：距离预测（mip 流送）vs GPU 反馈（VT）vs 相机位置（clipmap）。Clipmap 特别适合阴影/距离场/GI 这类"精度随距离衰减 + 每帧重算"的相机中心数据。

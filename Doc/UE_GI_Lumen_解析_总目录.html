阅读导引

从底层往顶层读最顺：底层的四块（距离场 / 硬件光追 / Surface Cache / Radiance Cache）都不产 GI，它们回答的是"世界几何长什么样"和"世界表面有多亮"，每帧 GI 之前就更新好；中层的三条链路是并列关系——漫反射 GI、镜面反射、半透明体积各自向底层追踪 / 采样，各产一张信号；顶层 Composite 把这些信号合入画面。

其中漫反射 GI 内部还有一层：RenderLumenFinalGather 是入口调度，按 CVar 在 Screen Probe Gather（默认主线，含 ①~⑤ 五阶段 + 收尾）、ReSTIR、Irradiance Field 三条路线里选一条走。Short Range AO 是主线积分阶段的子模块。下方章节严格按这张图的层级缩进排布。

① 底层 · 世界表示与缓存

每帧 GI 之前更新 · 被中层所有链路采样 · 不直接产 GI

这一层在做什么

这四块是 Lumen 的地基：两种追踪后端（软件距离场 / 硬件 BVH，回答"世界几何长什么样、光线打到哪"）、Surface Cache（世界表面光照库，回答"命中点有多亮"）、Radiance Cache（世界空间辐照度缓存，做远场与兜底）。它们不在任何单一链路上，而是被中层三条链路共同采样。

SDF

Distance Field 地基

追踪后端 · 软件 · Mesh SDF + Global SDF clipmap
Lumen 软件追踪路径的世界表示：两级距离场（Mesh SDF 近场 + Global SDF 远场 clipmap）的烘焙、流送、上传、froxel 剔除与 ray march 采样。不依赖 Lumen，是更底层的通用几何表示（也服务 DFAO、DF 软阴影）。

HW

Hardware Ray Tracing

追踪后端 · 硬件 · LumenHardwareRayTracingCommon
被多个追踪消费者共享的公共基础设施：门禁与回退（否则软件 Global SDF）、两种派发（Inline 计算着色器 vs RayGen 光追着色器）、三种着色模式（SurfaceCache / HitLighting / ForReflections）、两层 TLAS（近场 + 远场）与一整套稳健性 bias。两个正交维度：派发方式 × 着色模式。

HW+

HWRT 各消费者实现

五个消费者共享的硬件光追地基 + 两遍法
HW 总览的下钻：五个消费者（ScreenProbe / Reflections / RadianceCache / SceneDirectLighting / ShortRangeAO）如何共享同一个 FLumenHardwareRayTracingShaderBase、同一套 hit group 与 Inline/RayGen 分派，以及最关键的两遍法（SurfaceCache 追 + HitLighting 重着色）。

SC

Surface Cache / Lumen Scene

世界表面光照数据库 · UpdateLumenScene + RenderLumenSceneLighting
Lumen 的"世界表面数据库"：用 Mesh Card 代理网格，把材质（Albedo/Normal/Depth/Emissive）与光照（Direct/Radiosity/Final）烘进世界空间 atlas。所有追踪命中表面时不重算光照，而是查页表采样 FinalLightingAtlas。两条流水线：材质捕获 + 光照烘焙；Radiosity 读上帧 Final => 无限反弹。

下钻 · SC 的两侧流水线（供给 + 光照）
SC供

Surface Cache 供给侧

Mesh Cards 装配 + 材质捕获 · LumenMeshCards + SceneCardCapture
SC 主题的另一侧下钻（与 SC+ 光照烘焙并列）：Surface Cache 的供给流水线。Mesh Card 如何从离线 FMeshCardsBuildData 装配、Begin/Update 两阶段调度、Feedback 驱动按需捕获，以及把材质属性（Albedo/Normal/Depth/Emissive）光栅进世界空间 atlas 的全过程。与 SC+ 先后：先有供给侧捕获材质，才能在其上烘光照。

SC+

Surface Cache 光照烘焙

SceneDirectLighting + Radiosity + CombineLighting
SC 主题的下钻：Surface Cache 的光照侧流水线。直接光（屏内蹭 shadow map / 屏外追距离场）、Radiosity（读上帧 Final 做无限反弹）、以及合成为 FinalLightingAtlas 的全过程。
主文档函数附录
RC

Radiance Cache

世界空间辐照度缓存 · UpdateRadianceCaches
以相机为中心、按 clipmap 分级的世界空间 probe 缓存：每帧只在固定预算内重追一小部分 probe（其余复用历史），probe 追进 Surface Cache 取辐照度，滤波后缓存成 atlas 供中层三条链路插值采样。核心：Clipmap（近密远疏）+ Persistent（跨帧存活）+ Budget（优先级直方图选桶）。
主文档函数附录
GEO

特殊几何表示

Heightfield 软件追踪 + Nanite 卡片捕获
主流 Mesh SDF / 三角形之外，两类特殊几何如何进 Lumen 的世界表示：Landscape 地形不做 Mesh SDF，走独立的高度场软件追踪（FLumenHeightfieldGPUData 双精度数据 + SCENE_TRACE_HEIGHTFIELDS permutation）；Nanite 网格用 FLumenCardCS 计算着色器把材质捕获进 Surface Cache 卡片（NaniteLODScaleFactor 控 LOD）。两条旁路各自接入①底层的追踪后端与 Surface Cache。

② 中层 · 信号生产（并列的三条链路）

都消费①底层 · 各自产出一张信号纹理 · 交给③顶层合成

这一层在做什么

中层是三条并列的信号链路，谁也不从属于谁：漫反射 GI（Final Gather）、镜面反射、半透明/体积 GI。它们都向①底层追踪世界、采样 Surface Cache 与 Radiance Cache，只是采样方式与降噪策略不同，最终各产一张信号纹理交给 Composite。其中"漫反射 GI"内部还有一条三选一的路线树，下面缩进展开。

链路一 · 漫反射 GI（Final Gather，三条路线择一）
FG

RenderLumenFinalGather

漫反射 GI 入口调度 · 按 CVar 选路线
漫反射 GI 的入口调度层：准备场景参数、在三条路线里选一条（默认 Screen Probe Gather）、衔接 Radiance Cache 与降噪，把稀疏 probe 结果整理成可供 Composite 使用的信号纹理。

路线 A（默认主线）· Screen Probe Gather 主流程
SPG

RenderLumenScreenProbeGather

Screen Probe Gather 主流程 · 五阶段总调度
默认 Final Gather 路线的主调度函数：按顺序串起下方 ① ~ ⑤ 五个子阶段并收尾。主文档给出完整调度骨架与"目录页"视角，函数附录逐一列出各子函数源码并提供到深挖专题的下钻链接。

ScreenProbeGatherScreenData

trace 前的侦察兵 · BRDF PDF + Disocclusion
为每个 probe 计算表面 BRDF 的 PDF（该往哪些方向发线更值），并标记 disocclusion。两条路径：SH 9 系数（默认）vs Octahedron 纹理。

②

GenerateImportanceSamplingRays

结构化重要性采样 · 固定预算"3 换 1"细分
在固定光线预算下，按 BRDF PDF（可选 × Lighting PDF）把采样细分到高价值方向：剔除低 PDF 光线，把预算细分给高 PDF 方向。两趟 pass：ComputeLightingPDF + GenerateRays。
主文档函数附录
③

TraceScreenProbes

多后端级联追踪 · 发散点最密的阶段
整条 GI 真正"发光线"的地方。从廉价到昂贵的级联：屏幕空间(HZB) → 硬件 RT 或 Mesh SDF(互斥) → Global SDF + Radiance Cache 兜底。CompactTraces 每层间压实未命中光线。（追踪后端来自①底层）
主文档函数附录
④

FilterScreenProbes

降噪 · 时域/空域滤波 + 转 irradiance
把稀疏噪声的 trace radiance 磨成平滑信号：CompositeTraces → CalculateMoving → 时域滤波 → 空域滤波 → ConvertToIrradiance(SH3/Octahedron) → FixupBorders + GenerateMip。
主文档函数附录
⑤

InterpolateAndIntegrate

落地 · 从稀疏 probe 回到全屏像素
为每个屏幕像素插值邻近 probe 并按 BRDF 积分，产出屏幕空间 DiffuseIndirect / RoughSpecularIndirect。核心是 tile 分类：每块屏幕只跑它需要的 shader permutation。输出接回顶层 Composite，链路闭合。
主文档函数附录
尾

UpdateHistoryScreenProbeGather

全屏时域去噪收尾 · ⑤ 之后调用
Screen Probe Gather 的收尾步：把 ⑤ 产出的全屏 DiffuseIndirect / RoughSpecular 与上帧历史逐像素重投影混合，压噪并稳定画面，再存回 ViewState 供下帧复用。与 ④ 的时域滤波分属两层（④ 在稀疏 probe、本步在全屏像素）。核心：Fast Update Mode 快慢自适应 + 邻域钳制防鬼影。
主文档函数附录
AO

Short Range AO / Bent Normal

主线子模块 · 补降采样丢失的接触遮蔽
主线 GI 降采样会丢接触细节。Short Range AO 用 GTAO 式 horizon search（或 HWRT 短光线）在全分辨率补近距离遮蔽，产出 AO + bent normal，在 ⑤ InterpolateAndIntegrate 里参与 BRDF 积分（积分中 / 积分后两种时机）。

路线 B / C（可选替代）· 与主线并列的两条 Final Gather
ALT

另外两条 Final Gather

ReSTIR Gather + Irradiance Field Gather
Screen Probe Gather 之外的两条可切换 Final Gather 路线：ReSTIR（时空重采样重要性采样）与 Irradiance Field（世界空间辐照度探针场）。由 FinalGather 调度按 CVar 分派，与主线三选一。

链路二 · 镜面反射（与漫反射 GI 并列）
REF

RenderLumenReflections

镜面反射链路 · GGX 采样 + 三段降噪 → Textures[3]
为每个屏幕像素按 GGX 粗糙度分布生成反射方向、复用①底层追踪后端追踪世界，再经 Resolve（空间重建）→ Temporal（时域累积）→ Spatial（方差自适应双边滤波）三段降噪，产出 SpecularIndirect。省钱三招：Tile 分类 / 按粗糙度降采样 / 高糙远距退 Radiance Cache。
主文档函数附录
链路三 · 半透明 / 体积 GI（与前两条并列）
TRV

Translucency Lighting Volume

半透明 / 体积 GI · 相机对齐 froxel 体积
半透明物体拿不到 G-Buffer，无法走屏幕空间 GI。Lumen 为它建一套相机对齐的 froxel 3D 体积（log-Z 分布），逐 froxel 八面体追踪 + 投影 SH + 时域重投影，供半透明材质查询间接光。

横切 · 公共层与外围特性

不属于单一链路 · 被多条链路复用 / 补齐适配范围

这一组在做什么

这两块横跨多条链路：追踪公共层是所有追踪 pass 共享的参数打包与工具（天光泄漏、高度雾、Feedback 握手、剔除三兄弟、HZB 屏幕追踪档），被中层每条链路复用；外围与边角特性则补齐 Lumen 的适配范围（Front Layer 反射、天光双角色、Scalability 档位、离线 SDF/卡片生成），不构成主干却决定画质档位与项目适配。

TRC

说明

每个主题固定产出一对文档：主文档（*_ConvergenceAnnotated.html）包含颜色图例、"一眼看懂"汇聚/发散骨架、完整源码对照（暗色框）、分阶段批注（左代码右说明、区分共同点/不同点）、汇聚点/发散点总表与总结；函数附录（*_FunctionAppendix.html）展开子函数、Compute Shader 职责、permutation 全表与上下游关系。

本目录按数据流分层（底层 → 中层 → 顶层 → 横切）组织，缩进反映真实的调用/从属关系：中层三条链路（漫反射 GI / 镜面反射 / 半透明体积）是并列关系，漫反射 GI 内部再按 FinalGather → 三条路线 → 五阶段逐层缩进。所有源码路径均使用 UE 工程相对路径。

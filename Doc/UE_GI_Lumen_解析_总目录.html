UE Lumen GI 源码解析 · 总目录

UE5.8 渲染管线中 Lumen 全局光照（Screen Probe Gather 路线）的源码学习文档集。按调用层级组织：Final Gather 调度内部调用 Screen Probe Gather 主流程，后者再串起五个子阶段；其输出最终由顶层 Composite 合入画面（Composite 是下游消费者，并非调用方）。每个主题包含一份主文档（汇聚/发散骨架 + 完整源码对照 + 分阶段批注）与一份函数附录（子函数/CS/permutation 细节）。

数据自左向右流动：① ~ ⑤ 是 RenderLumenScreenProbeGather 内部按顺序执行的五道工序，产出屏幕空间间接光；随后经 RenderLumenFinalGather 汇总，最终由 DiffuseIndirectComposite 合入场景颜色。

调用层级：RenderLumenFinalGather 调用 RenderLumenScreenProbeGather，后者再依次调用 ① ~ ⑤ 子阶段——因此下方目录里 ScreenProbeGather 作为 FinalGather 的子项缩进、五个子阶段再缩进一层。DiffuseIndirectComposite 不是 FinalGather 的调用方，而是消费其输出的下游合成步骤，单列在最上方。若想按执行顺序学习，建议从最内层的 ① 读起，再逐层往外回看。

①

ScreenProbeGatherScreenData

trace 前的侦察兵 · BRDF PDF + Disocclusion
为每个 probe 计算表面 BRDF 的 PDF（该往哪些方向发线更值），并标记 disocclusion。两条路径：SH 9 系数（默认）vs Octahedron 纹理。
主文档函数附录
②

GenerateImportanceSamplingRays

结构化重要性采样 · 固定预算"3 换 1"细分
在固定光线预算下，按 BRDF PDF（可选 × Lighting PDF）把采样细分到高价值方向：剔除低 PDF 光线，把预算细分给高 PDF 方向。两趟 pass：ComputeLightingPDF + GenerateRays。
主文档函数附录
③

TraceScreenProbes

多后端级联追踪 · 发散点最密的阶段
整条 GI 真正"发光线"的地方。从廉价到昂贵的级联：屏幕空间(HZB) → 硬件 RT 或 Mesh SDF(互斥) → Global SDF + Radiance Cache 兜底。CompactTraces 每层间压实未命中光线。
主文档函数附录
④

FilterScreenProbes

降噪 · 时域/空域滤波 + 转 irradiance
把稀疏噪声的 trace radiance 磨成平滑信号：CompositeTraces → CalculateMoving → 时域滤波 → 空域滤波 → ConvertToIrradiance(SH3/Octahedron) → FixupBorders + GenerateMip。
主文档函数附录
⑤

InterpolateAndIntegrate

落地 · 从稀疏 probe 回到全屏像素
为每个屏幕像素插值邻近 probe 并按 BRDF 积分，产出屏幕空间 DiffuseIndirect / RoughSpecularIndirect。核心是 tile 分类：每块屏幕只跑它需要的 shader permutation。输出接回顶层 Composite，链路闭合。
主文档函数附录
尾

UpdateHistoryScreenProbeGather

全屏时域去噪收尾 · ⑤ 之后调用
Screen Probe Gather 的收尾步：把 ⑤ 产出的全屏 DiffuseIndirect / RoughSpecular 与上帧历史逐像素重投影混合，压噪并稳定画面，再存回 ViewState 供下帧复用。与 ④ 的时域滤波分属两层（④ 在稀疏 probe、本步在全屏像素）。核心：Fast Update Mode 快慢自适应 + 邻域钳制防鬼影。

跨阶段依赖 · 世界空间缓存

非线性调用链 · 所有追踪命中时的共享数据源

位置说明

这两个世界空间缓存都不在 ①~⑤ 的线性调用链上，而是跨阶段依赖。Surface Cache 是最底层的“世界表面光照数据库”，每帧早期更新；Radiance Cache 在 ① 之后、③ 之前更新，追踪时读 Surface Cache 取命中辐照度。两者又都被 ③ TraceScreenProbes、② 重要性采样、反射、半透明体积等采样。因此单列于此，各父文档已在用到它们的地方就地提供了下钻链接。

SC

Surface Cache / Lumen Scene

世界表面光照缓存 · UpdateLumenScene + RenderLumenSceneLighting
Lumen 的“世界表面数据库”：用 Mesh Card 代理网格，把材质（Albedo/Normal/Depth/Emissive）与光照（Direct/Radiosity/Final）烘进世界空间 atlas。所有追踪命中表面时不重算光照，而是查页表采样 FinalLightingAtlas。两条流水线：材质捕获 + 光照烘焙；Radiosity 读上帧 Final => 无限反弹。
主文档函数附录
RC

Radiance Cache

世界空间辐照度缓存 · UpdateRadianceCaches
以相机为中心、按 clipmap 分级的世界空间 probe 缓存：每帧只在固定预算内重追一小部分 probe（其余复用历史），probe 追进 Surface Cache 取辐照度，滤波后缓存成 atlas 供 ③/②/反射/半透明插值采样。核心：Clipmap（近密远疏）+ Persistent（跨帧存活）+ Budget（优先级直方图选桶）。

并列链路 · 镜面反射

与漫反射 GI 并列 · 产出 Composite 的 Textures[3]

位置说明

反射与 Screen Probe Gather（漫反射 GI）是并列的两条链路，同被上层调度调用、各自产信号后由 Composite 合成（GI 进 Textures[0..2]，反射进 Textures[3]）。它复用了 ③ 的追踪后端、Surface Cache 数据源与 Radiance Cache 兜底，差异全在逐像素 GGX 定向采样与三段专用降噪。

R

RenderLumenReflections

镜面反射链路 · GGX 采样 + 三段降噪
为每个屏幕像素按 GGX 粗糙度分布生成反射方向、复用 GI 追踪后端追踪世界，再经 Resolve（空间重建）→ Temporal（时域累积）→ Spatial（方差自适应双边滤波）三段降噪，产出 SpecularIndirect。省钱三招：Tile 分类 / 按粗糙度降采样 / 高糙远距退 Radiance Cache。

横切后端 · 硬件光追

非单一链路 · 被多个追踪消费者共用的求交后端

位置说明

Hardware Ray Tracing 不属于任何单一链路，而是一个横切追踪后端：当硬件支持时，它用真实 BVH 三角形求交替代软件 Global SDF，被 ③ TraceScreenProbes、反射、Radiance Cache、Surface Cache 直接光等多个消费者共用。核心洞见：求交与着色分离——HWRT 只换求交实现，命中后取光照默认仍走 Surface Cache。各父文档已在用到它的地方就地提供了下钻链接。

HW

Hardware Ray Tracing

硬件光追后端 · LumenHardwareRayTracingCommon
被多个追踪消费者共享的公共基础设施：门禁与回退（否则软件 Global SDF）、两种派发（Inline 计算着色器 vs RayGen 光追着色器）、三种着色模式（SurfaceCache / HitLighting / ForReflections）、两层 TLAS（近场 + 远场）与一整套稳健性 bias。两个正交维度：派发方式 × 着色模式。

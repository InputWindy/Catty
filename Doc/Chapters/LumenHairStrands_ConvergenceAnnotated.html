毛发遮蔽（Hair Strands Occlusion）

毛发（Hair Strands / Groom）是几万根半透明细丝，既进不了 Mesh SDF、也进不了 Surface Cache——Lumen 的两种追踪后端都"看不见"它。但毛发会对身后的不透明几何投射阴影、遮挡间接光。Lumen 为此单开一条旁路：命中世界后，额外拿光线去和 HairStrands 系统预生成的体素/深度结构求交，用毛发覆盖率把已算好的光照/反射乘一个透明度衰减。它不产生任何光照，只当遮蔽体。本篇讲清这条旁路的两种追踪方式、遮蔽语义，以及它被哪四条链路复用。

核心链条：主追踪命中世界后 → 若视图有毛发体素，再补一条毛发光线 → 得到毛发覆盖率对应的透明度 → 把已算好的光照/反射结果乘以这个透明度。毛发只减光、不加光。

为什么毛发要单独一条遮蔽旁路

两种追踪后端都"看不见"毛发

Lumen 的世界表示只有两种：Mesh SDF / Global SDF（软件追踪）与 BVH TLAS（硬件追踪），命中后统一查 Surface Cache 取光照。但毛发是几万根亚像素级的半透明曲线——它没有距离场、不进 Surface Cache 卡片、也不是常规三角形网格。所以无论软件还是硬件追踪，光线都会直接穿过毛发，就像它不存在一样。

可现实里毛发会挡光：角色头发会在脸上和肩膀投下柔和阴影，会遮住来自身后的间接光与反射。如果 Lumen 完全无视毛发，就会出现"头发不投 GI 阴影"的漏光。这条旁路的任务：在不把毛发塞进世界表示的前提下，让追踪光线也能"感知"毛发的遮挡——办法是复用 HairStrands 渲染系统已经生成好的两种结构。

方式一：Screen 追踪（TraceHairScreen）

沿毛发专属的深度 HZB 做屏幕空间 march

HairStrands 系统会渲染一张只含毛发的深度图（HairOnlyDepthTexture）并生成对应的 closest-HZB（HairOnlyDepthClosestHZBTexture）。TraceHairScreen 直接调通用的 TraceHZB，沿光线在这张毛发 HZB 上做层次化 march——命中即说明光线路径上有毛发遮挡。

这是最便宜的一档，但只覆盖屏幕内、朝向相机的毛发（屏幕空间固有局限）。所以它默认只在反射里开（r.Lumen.Reflections.HairStrands.ScreenTrace 默认 1），在 ScreenProbeGather / ShortRangeAO 里默认关（默认 0）——那两条更依赖下面的体素追踪。

方式二：Voxel 追踪（TraceHairVoxels）

遍历 Virtual Voxel 页表，累积毛发覆盖率

HairStrands 系统还会把毛发体素化进一套虚拟体素页表（VirtualVoxel：稀疏 page + NodeDesc）。TraceHairVoxels 沿光线遍历这些 voxel node，对每个 node 调 ComputeHairCountVirtualVoxel 累积路径上的毛发数量 HairCount，再转成透明度：Transparency = saturate(1 − HairCount)。多个 node 取 min（越挡越暗），直到 Transparency 逼近 0 提前终止。

它不受屏幕空间限制，能处理任意方向、屏幕外的毛发遮挡，是主力方式（四个消费者默认都开 VoxelTrace）。为补偿体素分辨率粗，用 GetHairVoxelJitter2 对起点做抖动，并按 bIsReflectionTracing 在 Shadow 档（反射，密度/步进更保守）与 Environment 档（GI，更平滑）间切换 DensityScale / SteppingScale。

遮蔽语义：毛发只减光、不加光

把透明度乘回已算好的结果

这是整条旁路的点睛之笔。追踪命中世界、算出 TraceResult.Lighting 后，若毛发光线也命中（且比不透明命中更近），就做三步：

Lighting *= HairTransparency（光照被毛发衰减）、Transparency *= HairTransparency（累积透明度）、OpaqueHitDistance = min(HairHitT, ...)（命中距离取更近的毛发）。

注意毛发从不往 Lighting 里加任何颜色——它不是光源、不查 Surface Cache，纯粹作为半透明遮蔽体存在。源码注释写得很直白："hair casting shadow onto opaques"（毛发对不透明物投射阴影）。所以毛发在 Lumen 里的角色，和"特殊几何"里的 Heightfield/Nanite 是反着的：那些是"要被照亮的表面"，毛发是"挡在中间的帘子"。

与其它遮蔽/追踪的异同

同是"额外一条遮蔽光线"，但数据源独立

共同点和级联追踪里"屏幕空间 → SDF/HWRT → Radiance Cache 兜底"一样，毛发也是在主追踪之后再补一条光线做遮挡判定；Screen/Voxel 两档也对应"便宜屏幕空间 vs 通用世界空间"的经典分档思路。

不同点它的数据源完全来自 HairStrands 渲染系统（HairOnlyDepth HZB、Virtual Voxel 页表），Lumen 只是消费者而非生产者——这套体素/深度不是 Lumen 建的，也不进 Surface Cache。而且它只输出透明度、不输出光照，与所有其它追踪（命中后取光照）方向相反。可以理解为：Lumen 把毛发当成一层"会飘的、半透明的遮光网"，挂在世界几何前面。

最终总结

毛发遮蔽是 Lumen 为"进不了世界表示的几万根半透明细丝"专门开的一条遮蔽旁路：因为毛发既无 SDF 也无 Surface Cache 卡片，两种追踪后端都会穿过它，于是 Lumen 在主追踪命中世界之后再补一条毛发光线——要么走便宜的 Screen 追踪（在毛发专属深度 HZB 上 march），要么走主力的 Voxel 追踪（遍历 HairStrands 的 Virtual Voxel 页表累积覆盖率），得到一个透明度后，把已算好的光照/反射结果乘以这个透明度做衰减。关键是它只减光、不加光，纯当半透明遮蔽体，实现"头发对不透明几何投 GI 阴影 / 遮反射 / 补接触 AO"。这条旁路横跨 Screen Probe Gather、Reflections、Short Range AO、Visualize 四条链路，全部复用同一份 LumenHairTracing.ush 与同一个"有没有毛发体素"的门禁，数据则全部借自 HairStrands 渲染系统。理解它，就补齐了 Lumen 对特殊几何（Heightfield / Nanite / 毛发）的最后一块拼图。

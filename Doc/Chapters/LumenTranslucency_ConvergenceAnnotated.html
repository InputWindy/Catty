半透明 / 体积 GI · Translucency Volume + Radiance Cache

整本书的主线（Screen Probe / Reflections）都只处理不透明表面——它们写 GBuffer、能被屏幕探针命中。可玻璃、烟雾、粒子这类半透明物体没有 GBuffer，屏幕空间那套完全用不上。Lumen 为它们单开一条路：把间接光烘焙进一个相机对齐的 3D froxel 体积（Lumen.TranslucencyVolume），每个 froxel 存一份 球谐(SH)辐照度，半透明像素着色时按世界位置查这个体积做三线性插值。本页讲清这条体积 GI 管线：froxel 网格布局、逐 froxel 八面体追踪、可分离滤波、SH 投影 + 时域重投影，以及它专属的 Translucency Radiance Cache。

1. froxel 体积：为什么半透明要"存进 3D 网格"

说明

半透明没有唯一深度，屏幕空间的探针/reservoir 全部失效。Lumen 的答案是体积化：把相机视锥切成一个 3D froxel 网格（XY 按像素、Z 按对数分布，近处密远处疏），每个 froxel 里存一份低频 SH 辐照度。这样任何深度、任何叠层的半透明像素，都能按自己的世界位置在体积里三线性插值取到 GI。

共同点froxel 的 log-Z 分布与 clustered/volumetric fog 的体素切法完全同源；SH 存储与 Radiance Cache/Irradiance Field 探针的低频辐照度表示一致。

不同点不透明 GI 是屏幕 2.5D（每像素一个表面）；半透明 GI 是视锥 3D 体积（每体素一份辐照度），因为半透明本质是体积散射、无单一表面。

2. 逐 froxel 八面体追踪 + 可分离滤波

说明

每个 froxel 不是只追一根线，而是追一整张八面体 atlas（把球面方向展开成 2D），才能积出各方向来的辐照度。追踪后端和主线共享：能用硬件 RT 就 HardwareRayTraceTranslucencyVolume，否则退回 TraceVoxelsTranslucencyVolume 走 Global SDF voxel 追踪。追完的原始辐射很噪，用一个可分离高斯滤波压噪——3D 卷积拆成 X/Y/Z 三趟一维卷积，把 O(n³) 降到 O(3n)。

共同点八面体映射、"命中读 Surface Cache / 远场采 Radiance Cache"、HW/SDF 双后端，与主线 Screen Probe 追踪逐条对应。

3. SH 投影 + 时域重投影：低频稳定的体积 GI

说明

最后一步把每 froxel 的方向辐射投影成球谐(SH)存两张 3D 纹理：漫反射 GI 是低频的，SH 用极少系数就能表达方向性，采样也便宜。为压噪它同样做时域重投影：用上一帧的 world-to-clip 把当前 froxel 投回历史体积三线性采样，按 HistoryWeight 混合——因为是世界对齐的体积，跨帧重投影天然稳定，闪烁比屏幕空间还小。

共同点时域重投影 + HistoryWeight 混合 + 双缓冲乒乓，与 ScreenProbe 的 历史更新机制同构。

不同点ScreenProbe 存屏幕空间辐射并靠运动矢量重投影；这里存世界对齐 3D SH，重投影用世界位置→上帧 clip，无需运动矢量、且对半透明叠层天然正确。

体积 GI 再次印证 Lumen 的模块化："追踪后端 + Surface Cache + Radiance Cache"这套地基完全复用，变的只是上层如何组织采样与存储——不透明用屏幕探针，半透明用视锥 froxel 体积。看懂它，就理解了为什么 Lumen 能用一套缓存喂养这么多种消费者。

最终总结

一句话

半透明物体没有 GBuffer、没有唯一深度，屏幕空间那套 GI 全部失效，所以 Lumen 为它们单开一条体积路线：把间接光烘进相机对齐的 3D froxel 网格（XY 按像素、Z 按对数），每 froxel 逐八面体追踪 → 可分离高斯降噪 → 投影成 SH 并时域重投影累积，最终挂到 View 上供任意深度/叠层的半透明像素三线性查询。追踪后端、Surface Cache、Radiance Cache 全部复用主线地基——它只是"同一套缓存"的又一种上层消费者。

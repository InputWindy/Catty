1. Sphere Tracing：距离场怎么被"追"

说明

Sphere tracing 是距离场追踪的核心算法：利用"到最近表面的距离"作为安全步长，一步跨过整段空白，无需 BVH。这就是为什么距离场追踪对硬件无特殊要求。步进上限、偏置都由 IndirectTracingParameters 传入（③、Radiosity 软追共用）。

不同点硬件 RT 用加速结构精确求三角形交点；sphere tracing 是数值逼近，步数受限时会漏掉薄物体或在掠射角抖动。

2. Mesh SDF brick 布局与流送

说明

Mesh SDF 用 brick 稀疏存储 + 流送 控制显存：空 brick 不存、远处降 mip、按需驻留。这与 Surface Cache 卡片页、Nanite/虚拟纹理是同一套"按可见性/距离流送"的资源管理哲学。

共同点brick atlas + 间接寻址与 Global SDF 的 page atlas + 页表、Surface Cache 的卡片 atlas + 页表结构一致。

3. UpdateDistanceFieldObjectBuffers：对象上传字段

说明

这一步把"本帧场景里有哪些 Mesh SDF 对象、各自的世界变换/包围盒/brick 地址"增量同步到 GPU。WorldToVolumeT 让追踪时能把世界射线变换进对象的归一化体积空间去采 SDF；ExpandSurfaceDistance 表面外扩用于稳定命中。

共同点增量 add/remove + 上传 buffer，与 Surface Cache 的 UploadPageTable / UpdateCardSceneBuffer 同为"CPU 场景变化 → GPU buffer 增量同步"。

4. Global SDF clipmap 增量更新

说明

Global SDF 用三招把"每帧维护一个覆盖全场景的体积"变便宜：分层（远处糙）、每帧只更 2 层、toroidal 滚动只补边条。bLumenEnabled / LumenSceneViewDistance 让 clipmap 范围能按 Lumen 的追踪距离扩展。

共同点"每帧只更新一部分 + 相机中心滚动"与 Surface Cache/Radiance Cache 的预算重烘、增量更新是同一成本控制哲学。

说明

合成分两步：先给每个 page 收集对象列表（剔除），再把这些对象的距离场取最小值合并（min = 到最近表面）。FComposeParentDistanceField 让内层未覆盖处回退到外层 clipmap，保证连续；CoverageAtlas 让追踪能快速跳过"确定没有几何"的 page。着色器文件：GlobalDistanceFieldCompositeObjects.usf。

6. LumenMeshSDFCulling：两步剔除

说明

两步剔除（视锥粗剔 → froxel 精剔）把近场 Mesh SDF 追踪的复杂度从"逐线×全对象"降到"逐线×本 froxel 少数对象"。froxel 网格与 ③ 的屏幕 probe 空间对齐，Heightfield（地形）单独一套列表并行处理。

共同点与延迟渲染 clustered light culling、A 的 card tile 剔光同构——都是 per-cell 预剔列表。

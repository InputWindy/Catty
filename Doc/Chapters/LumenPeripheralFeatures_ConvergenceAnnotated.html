上下文：它们各挂在主干的哪里

四块特性接入主干的位置不同：Front Layer 反射是 Reflections 的一个 permutation 分支（FRONT_LAYER_TRANSLUCENCY），复用整条反射追踪/解析管线，只是输入换成透明前层的 GBuffer。天光横切所有追踪（ray miss 时的兜底光，见 追踪公共层的 SkylightLeaking）与 Surface Cache 直接光（skylight 作为一个光源烘进 atlas）。Scalability 是一层贯穿全局的 CVar 网，尤其 r.Lumen.FinalGatherMethod 在 Screen Probe Gather 与 Irradiance Field Gather之间切换整条 GI 主路。离线 SDF/卡片则发生在 cook/build 期，产出 Mesh SDF 与 供给侧装配用的 FMeshCardsBuildData。

1. Front Layer 反射：给水面/玻璃一层清晰反射

说明

透明物体不写不透明 GBuffer，主反射管线看不到它们。Front Layer Translucency 的思路是把"最靠前的一层透明表面"单独渲成一份 GBuffer，然后复用整条 Lumen 反射管线——只加一个 FRONT_LAYER_TRANSLUCENCY permutation。三个关键特判：走全分辨率（前层反射要清晰，不降采样）、只算一层 closure（薄前层不堆叠多层材质）、用前层自己的 LumenTileBitmask 分类。这样水面/玻璃能拿到和不透明物体一致质量的 Lumen 反射，而不用另写一套追踪。

共同点追踪/空间重建/解析全和不透明反射共用同一批 shader——只是输入输出换成前层。

2. 天光：ray miss 的兜底与全局补光

说明

天光在 Lumen 里不是一个独立通道，而是两处复用的环境光：其一，作为追踪公共层里 ray-miss 的兜底（SkylightLeaking，光线没打到东西时采预滤的天光 cubemap，避免死黑）；其二，作为 Surface Cache 直接光烘焙时的一个环境光源，让所有间接命中都能吃到天光。它的价值是补上"封闭/遮蔽区域"的最后一点环境亮度，但量级必须和场景直接光匹配，否则 GI 整体偏色。

3. Scalability：从 Switch 2 到工作站

说明

Lumen 要覆盖从 Switch 2 到高端工作站的硬件跨度，靠的是分层的 ECVF_Scalability CVar。最上层是硬门槛：r.Lumen.Supported 关了连 shader 都不编，运行时还查 R16_UINT TypedUAVLoad 能力。中层是性能开关（async/waveops/线程组/光照数据格式）随画质档自动切。最重磅的是 r.Lumen.FinalGatherMethod——它直接切换整条 GI 主路：0=Irradiance Field（世界空间探针预积分，快但糙，面向中端/Switch 2），1=Screen Probe（屏幕探针自适应，高质量，默认）。这是 Lumen 里最大的一个"档位分叉"。

不同点Irradiance Field 预积分 irradiance、无屏幕探针；Screen Probe 逐屏幕探针追踪 + 自己的时域累积——两条完全不同的 gather 主路。

4. 离线 Mesh SDF / 卡片：运行时数据的来源

说明

一个容易忽略的事实：Lumen 运行时不生成几何表示，只消费烘焙期的产物。Mesh SDF 在 cook/build 期为每个静态网格算好体素距离场存进 atlas；Mesh Cards 布局（FMeshCardsBuildData）在 build 期分析网格决定卡片数量/朝向/尺寸，随资产烘焙。运行时的 LumenMeshCards 只做装配合并。这意味着离线生成的质量直接决定运行时 GI 上限——一个网格若没生成 SDF 或卡片，它在 Lumen 里就"隐身"，不参与 GI/反射。这也是为什么调 Lumen 有时要回头查资产的距离场生成设置。

最终总结

这四块"边角料"共同决定了 Lumen 的适用边界。Front Layer 反射用一个 permutation 让透明前层（水面/玻璃）复用整条反射管线拿到清晰反射，代价是全分辨率+单 closure。天光不是独立通道，而是 ray-miss 兜底与 Surface Cache 直接光两处复用的环境补光，负责消灭死黑。Scalability 是一层贯穿的 CVar 网，从 r.Lumen.Supported 的硬门槛到 r.Lumen.FinalGatherMethod 的整路分叉，让 Lumen 从 Switch 2 缩放到工作站。离线 Mesh SDF/卡片则提醒我们：Lumen 运行时只消费烘焙产物，几何表示的质量在 cook 期就定了。理解这四块，才算真正理解 Lumen 不只是"一套算法"，而是"一套能落到各种硬件、各种材质的完整系统"。

追踪公共层 · 所有追踪 pass 共享的参数与工具

Screen Probe Gather、Reflections、Translucency、Radiance Cache——这些追踪 pass 看起来各干各的，其实都先调同一批公共函数把"追踪所需的一切"打包好：Surface Cache 的四张 atlas、Global SDF 页表、天光泄漏、高度雾、Feedback 回写缓冲、Mesh SDF 剔除网格……这一层就是 LumenTracingUtils。本页讲清这个"公共供给层"：GetLumenCardTracingParameters（把 atlas/feedback/雾/天光泄漏一次性塞进 FLumenCardTracingParameters）、一族追踪参数结构体（Card/MeshSDF/Indirect/Diffuse/HZBScreen）、半球方向采样生成器、Mesh SDF/Heightfield 视锥网格剔除，以及最关键的屏幕空间追踪工具 SetupHZBScreenTraceParameters——它让每条光线在打 SDF/硬件 RT 之前先复用上一帧屏幕颜色。理解这一层，就理解了"Lumen 的每条 trace 到底带着什么上路"。

上下文：谁在用这一层

这一层没有"入口帧"——它是被所有追踪 pass 反复调用的工具箱。GetLumenCardTracingParameters 被 Screen Probe Gather、Reflections、Radiance Cache、Radiosity 等全部调用，因为任何 trace 命中 Surface Cache 都要采那四张 atlas、都要往 Feedback 缓冲回写"我采了哪些页"（供 供给侧下帧决定驻留）。SetupHZBScreenTraceParameters 被 Reflections（软件+硬件）、ScreenProbeTracing、ShortRangeAO 调用——它们都想在打昂贵的 SDF/硬件光线前，先用 HZB 在上一帧的屏幕颜色里试着找命中（最便宜的一档）。所以这一层是"横切"性质：不属于某条链路，而是每条链路都踩的地基。

1. 为什么要有公共层：追踪的"公共契约"

说明

公共层解决的是"每条 trace 命中 Surface Cache 后动作一致"这个事实：查 atlas、天光泄漏补天空、施加高度雾、回写 Feedback——四件事对谁都一样。把它抽成一个 FLumenCardTracingParameters 结构体 + 一个 GetLumenCardTracingParameters 填充函数，任何 pass 只需一行就把这套契约带上路，避免每个 pass 各写一遍导致漂移。

共同点与 光照烘焙共用同一批 atlas 句柄——供给侧写，追踪侧读，靠这个结构体对齐。

2. 天光泄漏与高度雾：ray miss 的收尾

说明

天光泄漏是处理 ray miss 的兜底：一条光线没打到任何几何时，与其返回纯黑，不如让天空"漏"一点进来。用 Roughness=0.3 预滤天光 cubemap 藏掉太阳等高频，随距离渐强。高度雾则给 trace 命中的光照加雾——但源码里 HeightFogOnGI 默认关，因为漫反射 GI 上雾几乎看不出、还会与直接光在浓雾场景里失配（天光被雾抹掉）；只有反射上默认开。

不同点反射施雾（默认开），GI 施雾（默认关）——同一个 HeightFog 机制，两条链路策略相反。

3. Feedback 回写：追踪侧与供给侧的握手

说明

这是理解 Surface Cache "按需驻留"的一环：追踪 shader 每命中一个页，就按 TileJitter 抖动抽样往 RWSurfaceCacheFeedbackBuffer 追加一条"我用了这个页"。抖动是为了用稀疏采样覆盖全部页而不爆缓冲。ResLevelBias + 0.5f 是个经典的 uint→float 取整技巧。这些数据下一帧被供给侧的 UpdateSurfaceCacheFeedback 读走，转成驻留决策——供给和消费在这里闭环。

4. 剔除三兄弟：把场景几何塞进视锥网格

说明

软件追踪不可能对每条光线遍历场景所有 Mesh SDF。公共层先做一遍视锥网格剔除（froxel：屏幕 XY 分格 + 深度 Z 分层），把每个 cell 附近的 SDF 物体索引预存进 GridCulled...IndicesArray。追踪时 shader 用 CardGridZParams 从像素+深度反算出所在 cell，只测该 cell 的候选，避免全场景遍历。地形（Heightfield）因为表示不同单独剔一份（见 特殊几何）。

5. SetupHZBScreenTrace：最便宜的一档追踪

说明

Lumen 的追踪是成本分层的：屏幕空间 HZB trace 最便宜（只在上一帧已渲好的屏幕颜色里走 HZB 步进找命中），命中就省下昂贵的 SDF/硬件光线。SetupHZBScreenTraceParameters 就是为这一档准备输入——关键是 InputColor 的三源优先级（自定义 SSR 输入 > TAA 历史 > SSR 输入）和跨帧重投影（用 PrevScreenPositionScaleBias 把本帧屏幕点映射回上帧 UV，并做曝光校正）。这是复用时域信息、把追踪成本压到最低的公共工具。

共同点反射、屏幕探针、短程 AO 都先走这一档——它们共享同一个 setup，只是 HZBType（Closest/Furthest）按需不同。

最终总结

"追踪公共层"是 Lumen 里最不起眼却最被反复调用的一层。它把"每条 trace 命中 Surface Cache 后都要做的事"（查四张 atlas、天光泄漏补 miss、高度雾、Feedback 回写）抽成 一个参数结构体 + 一个填充函数，让 Screen Probe、Reflections、Radiance Cache 只需一行就带齐契约；它提供 视锥网格剔除把场景 SDF 预组织成"每格子的候选表"供软件追踪查；它还提供 SetupHZBScreenTraceParameters 这个"最便宜追踪档"的工具，让每条光线先在上一帧屏幕颜色里碰运气、命中就省下 SDF/硬件光线。这一层的价值在于统一契约、消除漂移、共享成本——它不属于任何一条信号链路，而是所有链路共同踩着的地基。看懂它，就看懂了 Lumen 每条 trace"到底带着什么上路、按什么顺序省钱"。

特殊几何表示 · Heightfield 地形与 Nanite 网格怎么进 Lumen

Lumen 的世界表示默认是 Mesh SDF + Global SDF（见 Distance Field）加 Surface Cache 卡片。但有两类几何"不适合"直接塞进这套流程：一是 Landscape 地形——它面积巨大、用连续 LOD（CLOD），做成 Mesh SDF 又贵又糊；二是 Nanite 网格——它没有传统的 LOD 顶点缓冲，材质要走 Nanite 自己的 compute 着色路径。本页讲清 Lumen 对这两类几何的特殊表示：地形走独立的 Heightfield 软件追踪（把地形当高度场直接步进），Nanite 网格则通过 FLumenCardCS 计算着色把材质捕获进 Surface Cache。它们是"底层世界表示"里两条容易被忽略的旁路。

上下文：它们在世界表示里的位置

两条旁路都服务于"追踪时要能命中这些几何"。Heightfield 是 Mesh SDF 软件追踪的补充后端：当 Lumen::UseHeightfieldTracing 开启，Screen Probe 追踪、场景可视化、离屏直接光阴影都会额外走一遍高度场步进（permutation SCENE_TRACE_HEIGHTFIELDS），命中地形表面后仍去 Surface Cache 采样光照。Nanite 则发生在 供给侧的 CardCapture 阶段：Nanite 网格没有传统 mesh draw，材质要靠 FLumenCardCS 这个 material compute shader 在 ENaniteMeshPass::LumenCardCapture pass 里着色，把 Albedo/Normal/Emissive 写进捕获 atlas。所以它们一个补"追踪端"，一个补"供给端"。

1. 为什么地形不做成 Mesh SDF：连续 LOD 与巨大面积

说明

地形是典型的"大而连续"几何：把它塞进 Mesh SDF 既费显存又糊。Lumen 因此给它开一条独立后端——把地形当高度场，光线直接在高度上步进（软件追踪），受 r.LumenScene.Heightfield.Tracing 控制，步数上限 MaxTracingSteps=32。命中后地形照样有自己的 Mesh Cards（MeshCardsIndex），去 Surface Cache 采样光照，所以它只是"追踪几何的方式"不同，采光仍归一。

不同点Mesh SDF 追踪查的是离线体素距离场；Heightfield 追踪查的是运行时高度场——后者才能跟上地形的 CLOD。

2. 高度场数据用双精度：大世界坐标

说明

地形横跨数公里，单精度浮点在世界坐标下会产生可见抖动，所以 BoundsCenter 用 FDFVector3（DoubleFloat：High+Low 两段模拟双精度）。GPU 数据严格 3 个 float4 一条、并 static_assert 锁死 stride，因为 usf 里 GetLumenHeightfieldData 按同样偏移解包——CPU/GPU 布局是硬契约。每帧只把 HeightfieldIndicesToUpdateInBuffer 里变化的地形增量上传，其余复用。

3. 三处都要挂 Heightfield permutation

说明

Heightfield 追踪不是一个集中函数，而是散布在每个"做软件场景追踪"的着色器里的一个 permutation 位：主线 GI 追踪（ScreenProbeTracing）、调试可视化（Visualize）、Surface Cache 离屏阴影（DirectLighting）都各挂一份 SCENE_TRACE_HEIGHTFIELDS / OFFSCREEN_SHADOWING_TRACE_HEIGHTFIELDS。这样任何需要"打一条软件光线"的地方都能顺带命中地形。

共同点三处都挂在 UseMeshSDFTracing 之下——高度场是 Mesh SDF 追踪的伴生后端，不是独立通道。

4. Nanite 网格：没有传统 LOD，靠 FLumenCardCS 着色

说明

Nanite 是"无传统 LOD"的虚拟几何——它的材质着色必须走 Nanite 自己的 compute 管线。Lumen 因此用 FLumenCardCS（一个 material compute shader，入口 LumenCardComputeShader.usf::Main）在专用 ENaniteMeshPass::LumenCardCapture pass 里把 Nanite 材质"算"进卡片 atlas，而不是光栅化。着色按 Pixel binning / Quad binning 组织（是否需要导数决定），LOD 由 NaniteLODScaleFactor 挑——毕竟卡片分辨率远低于屏幕，用最高 LOD 是浪费。

不同点传统网格用光栅化写卡片；Nanite 用 compute 着色写卡片——但产出的 atlas 通道完全一致，下游无感。

5. 边界：Nanite Landscape 还没支持

说明

源码里两处相同注释点明了当前边界：Lumen 尚不支持 Nanite Landscape。permutation 编译条件 SupportsNaniteRendering() && !SupportsLandscape() 显式把 Landscape 顶点工厂排除在 Nanite compute 捕获之外，让它回退传统路径。这也解释了为什么"Heightfield 软件追踪"这条旁路仍然必要——地形还没能完全并入 Nanite 统一管线。

最终总结

Lumen 的世界表示不是"一套 SDF 打天下"。对地形，它承认 Mesh SDF 不适合大而连续的 CLOD 几何，改用 Heightfield 软件追踪——把地形当高度场直接步进，用双精度坐标扛大世界，用 ReceiverBias 补 LOD 失配，并在每个软件追踪着色器里挂一个 permutation 位顺带命中它。对 Nanite 网格，它承认没有传统 LOD 顶点、材质得走 compute，于是用 FLumenCardCS 在专用 mesh pass 里把材质"算"进 Surface Cache 卡片，用 LOD scale 挑合适精度。两条旁路一个补追踪端、一个补供给端，最终都归一到同一套 Surface Cache atlas，下游 GI 无需区分几何来源——这正是 Lumen 把异构几何"抹平成统一光照缓存"的设计哲学。

Lumen 可视化 / 调试 · 把不可见的中间态画出来

Lumen 有大量中间数据平时看不见：Surface Cache 里烘的是什么、哪些卡片本帧被更新、探针铺在哪、SDF 追踪打到哪、GI 累积了几帧……出问题时（漏光、发暗、闪烁、掉帧）如果只能盯最终画面就无从下手。Lumen 因此内建了一整套可视化模式（r.Lumen.Visualize 25 种模式 + Overview 拼图）：把这些不可见的中间态直接画到屏幕上——Surface Cache 覆盖率、卡片权重、直接/间接光、更新热力、探针位置、追踪射线……本页讲清这套调试系统怎么组织：可视化模式表、软件 vs 硬件追踪两条可视化路径、Overview 多格拼图、以及追踪射线/探针/统计等辅助工具。

1. 25 种模式：把每一层中间态单独画出来

说明

25 种模式本质是把 Lumen 管线的每一层中间数据都开一个"探针窗口"。排查思路很直接：漏光先看 5（Surface Cache Coverage，覆盖不到的地方就会漏）；发暗/发灰看 12/13 分离直接光和间接光；闪烁/拖影看 23/24（累积帧数）和 16/17（更新热力）；掉帧看 2（Performance Overview）和 18/19（页面驻留）。每个模式对应源码里一个 VISUALIZE_MODE_* 常量（与 LumenVisualize.h 同步）。

共同点所有模式都复用生产管线读到的真实数据，不另建缓存——所见即所用。

2. 两条可视化路径：软件 SDF vs 硬件 RT

说明

可视化的追踪后端和生产完全一致：能用硬件 RT 就走 VisualizeHardwareRayTracing，否则走软件路径（CullMeshObjectsToViewGrid froxel 剔除 + 逐像素 sphere trace mesh SDF）。这条设计很重要——因为 Lumen Scene / Reflection View 模式在 HWRT 下可以开 HitLighting，直接在命中点求真实材质，让你看到"如果开了 hit lighting 反射会是什么样"，是对比软件缓存 vs 硬件真值的利器。

共同点软件路径的 froxel 剔除 + sphere trace 与 Distance Field 生产追踪逐函数对应。

3. Overview 拼图 + 叠加式调试

说明

两种展示形态互补。Overview 拼图（模式 1/2）把屏幕切成多格，每格画一个不同模式，一屏同时看 albedo/normal/直接光/间接光，快速定位"哪一层出了问题"。叠加式调试则不替换画面，而是把 3D 辅助信息画到真实场景上：RenderVisualizeTraces 把追踪射线画成线段（看 ray 走向与命中）、探针可视化画出 Radiance Cache / Radiosity 探针的空间分布、DumpStats 往控制台打卡片/SDF/剔除的数量统计。

不同点整屏模式回答"这一层数据长什么样"；叠加式回答"射线/探针在空间里怎么分布"——一个看值、一个看几何。

最终总结

一句话

Lumen 的中间态平时不可见，出问题时无从下手，所以它内建了一整套可视化调试系统：r.Lumen.Visualize 提供 25 种模式把每一层数据（Surface Cache 覆盖率、albedo/法线、直接/间接光、更新热力、累积帧数……）单独画到屏幕，Overview 还能一屏多格并排看；追踪后端与生产同源（软件 SDF 或 HWRT，后者可开 HitLighting 看真值）；此外 RenderLumenMiscVisualizations 提供叠加式的射线/探针/统计工具。它不新建数据、只可视化生产管线真正用的数据——是验证前面所有机制、排查漏光/发暗/闪烁/掉帧的实验台。

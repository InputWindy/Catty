UpdateHistoryScreenProbeGather 代码解析（全屏时域去噪）

Screen Probe Gather 链路的最后一道去噪：⑤ InterpolateAndIntegrate 产出的 DiffuseIndirect / BackfaceDiffuse / RoughSpecular 仍带时域噪声，这一步把它们与上一帧的历史做逐像素重投影混合（temporal reprojection），显著压噪并稳定画面，再把混合结果存回 ViewState 供下一帧复用。它与 ④ FilterScreenProbes 的时域滤波是两个层级：④ 在稀疏 probe 上滤波，本步在全屏最终像素上滤波。核心机制是 Fast Update Mode——光照剧变处快速响应、静止处长期累积。本页解析入口 UpdateHistoryScreenProbeGather。

1. 核心思想：为什么要在最终像素上再做一次时域

说明

这一步是"降噪金字塔"的顶层：④ 在 probe 上打底，⑤ 插值落地，本步在全屏最终像素上用精确的逐像素运动做时域累积。三层各司其职，缺一则画面要么噪、要么糊。

共同点与 ④ FilterScreenProbes 时域滤波、Surface Cache Radiosity、Radiance Cache 一样，都靠"累积历史"摊平单帧噪声/成本，都用 NumFramesAccumulated 记累积权重。

不同点④ 的历史单元是"probe radiance"，本步是"屏幕像素的最终 GI"；本步能用每像素运动矢量重投影，精度更高，但也更需要防拖影（下一节）。

2. Fast Update Mode：快慢自适应，光照剧变处不拖影

说明

时域累积的死敌是"变化"：相机或光照一动，旧历史就可能与当前像素对不上，直接混合会拖出鬼影。Fast Update Mode 让每个像素自适应——静止区域大胆累积求干净，剧变区域果断丢历史求跟手。

不同点两道保险互补：LightIsMoving 是主动信号（前序告知光在变），NeighborhoodClamp 是被动兜底（历史与邻域不符就钳掉）。前者抗光照变化，后者抗几何/遮挡变化。

共同点邻域钳制 + 曝光校正是标准 TAA/时域降噪套路，Lumen 各时域环节（含 ④）都在用。

3. 存历史与替换输出

说明

收尾两件事：把本帧结果存回 ViewState（含累积计数，否则下帧无法继续累积），再把入参引用原地替换成去噪版。存历史带一堆有效性元数据（分辨率、closure 数、格式），下一帧加载时逐项校验，任一不符就丢弃历史从头累积——这是防止读到脏数据的安全阀。

共同点QueueTextureExtraction 把 RDG 瞬态纹理提升为跨帧持久资源，与 Radiance Cache 的 ConvertToExternal、Surface Cache 的持久 atlas 同理。

最终总结

骨架

UpdateHistoryScreenProbeGather 是 Screen Probe Gather 的全屏时域收尾：加载上帧历史 → TemporalReprojection 重投影混合（Fast Update Mode 自适应快慢 + 邻域钳制防鬼影）→ 存回 ViewState → 原地替换输出。

它是"probe 层(④) → 全屏落地(⑤) → 全屏时域(本步)"降噪金字塔的顶层，把最终 GI 稳定到可直接合成的质量。

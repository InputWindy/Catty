1. Mesh Cards 生成与合并

说明

卡片布局本身是离线随网格烘出的 FMeshCardsBuildData；运行时 LumenMeshCards.cpp 只做装配与合并：把同 actor 组件（MergeComponents）或大量实例（MergeInstances）并成更少的卡片省显存，合并后按 MergedResolutionScale 降分辨率、按 MergedMaxWorldSize 限制体积，并 CullFaces 剔掉没覆盖的面。三级数据结构：PrimitiveGroup → MeshCards → Card。

2. Begin/Update 两阶段调度

说明

两阶段的意义在于并行度：Begin 只锁 readback 缓冲并把重 CPU 活派发成 UpdateSceneTask，与其它渲染准备并行跑；Update 再 Wait 收口做 GPU 侧工作。bReallocateAtlas 来自 UpdateAtlasSize()——只有分辨率/开关变化时才重建 atlas。MGPU 下每个 GPU 维护独立的 FLumenSceneData。

3. Feedback 打包与距离分桶

说明

Feedback 是 GPU→CPU 的紧凑回读：每条两个 uint32 打包了卡索引、期望分辨率、页坐标与命中数。阈值 FeedbackMinPageHits 过滤噪声。已驻留页只喂 UnlockedAllocationHeap（LRU 时间戳）；缺失页把"命中越少 → 距离惩罚越大"的公式转成 DistanceBin 并累加直方图——直方图后续用于在固定预算下从近到远批准请求。

共同点距离分桶直方图与 Radiance Cache 的 probe 优先级选桶同构。

4. 页表分配器 FLumenSurfaceCacheAllocator

说明

分配器把物理 atlas 当作固定尺寸 PhysicalPageSize 的页网格。子分配（小卡片）走 FPageBin：同尺寸的小卡片共享一个物理页、内部切格；整页分配（大卡片）直接占一页。IsSpaceAvailable 先按卡片 mip 描述算出需要多少页，供请求处理时判断是否得逐出/降级。最终 UploadPageTable 把 CPU 侧虚拟页表映射上传给 GPU 采样。

5. 请求处理与 LRU 逐出

说明

请求处理是显存取舍的核心。分配失败时的降级顺序：① LRU 逐出（EvictOldestAllocation，只逐超过 2 帧没用的页，保护刚用过的）；② 逐级降低请求分辨率直到 MinResLevel；③ 还得能塞进本帧的临时 CaptureAtlasAllocator。成功后 ReallocVirtualSurface 映射页表，并尽量走 Card Sharing（FindMatchingCardForCopy）或从自身降采样复制，减少真正的重新捕获。

不同点Locked（低分辨率常驻）页与 hi-res 请求走不同路径：前者保证基础可见性、后者是命中反馈驱动的按需加载。

6. Resample + CardCapture

说明

捕获分两步：ResampleLumenCards 先把重分配页在旧 atlas 的内容搬进捕获 atlas（换 mip、共享卡、X 翻转都在这处理），保证内容连续不闪；随后用 GPUScene + FInstanceCullingContext 组织 mesh draw，按每页的 CardCaptureAtlasRect 把材质光栅化进 CardCaptureAtlas，强制最低 LOD、关材质 mip bias。DilateOneTexel 把页边界外扩一像素，避免采样时跨页取到黑边。

7. GPU 驱动更新

说明

传统路径下场景增删与卡片剔除在 CPU 上逐 primitive 做；GPU 驱动更新把这部分搬到 GPU，用 readback 把增删 op 回传 CPU 消费（ProcessSceneAddOps/RemoveOpsReadbackData）。对开放世界、海量 instance 的场景收益明显——这也是 Begin 阶段要锁 SceneReadback 的原因。

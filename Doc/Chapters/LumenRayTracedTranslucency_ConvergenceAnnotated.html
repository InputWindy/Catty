光线追踪半透明（Ray Traced Translucency）

半透明一直是实时渲染的老大难：多层叠加、需要看穿、还要折射。Lumen 的常规半透明只有体积近似（froxel 3D 体积）——够用但糊。光线追踪半透明是更高端的一条路：复用 Lumen Reflections 的追踪基础设施，对半透明像素逐像素发射光线，像路径追踪一样穿过多层透明表面、支持光追折射，得到玻璃/水面级别的高保真效果。本篇讲它的开关、多层命中预算、与体积/前层半透明的分工，以及配套的背景可见性合成。

取舍

三条路线是质量-成本阶梯：体积近似最省最糊、前层管单层反射、光追半透明做"看穿多层 + 折射"的高端效果。RayTracedTranslucency::IsEnabled 与 FrontLayerTranslucency 存在互斥/协作关系（源码里多处一起判断），引擎据视图与设置选择走哪条。

核心机制一：多层命中（Path-Traced 风格）

为什么半透明必须"多次命中"

不透明表面追踪，一根线命中即停。但半透明要看穿：一根线可能先穿过一块玻璃、再穿过后面的水、最后打到墙。所以光追半透明沿用路径追踪思路——一根线记录多个命中事件，逐层累积透射与反射贡献。

命中层数由两个预算控制：MaxPrimaryHitEvents（主光线穿过的透明层数上限）与 MaxSecondaryHitEvents（每次命中派生的次级光线，如折射/反射分支的命中上限）。层数越多越真实，但成本随之上涨——这正是它比前层半透明贵的根本原因。

核心机制二：path throughput 剪枝

低贡献路径提前终止

路径穿过越多半透明层，累积透射率（throughput）越低——穿过五层深色玻璃后，这条路径对最终像素的贡献已微不足道。GetPathThroughputThreshold（r.RayTracedTranslucency.PathThroughputThreshold）设一个阈值：当路径累积 throughput 低于它就提前终止，不再往下追。这是路径追踪的标准俄罗斯轮盘式剪枝，把光线预算集中在"还看得见"的层上。

核心机制三：光追折射

让光线在界面处弯折

普通半透明只做"直着看穿"（alpha 混合），但真实玻璃/水会折射——光线在介质界面按折射率弯折，产生放大、错位、焦散边缘。UseRayTracedRefraction（r.RayTracedTranslucency.UseRayTracedRefraction）开启后，命中透明界面时按法线与折射率偏转光线方向再继续追，得到物理正确的折射。这是光追半透明相对屏幕空间折射的最大优势——不受屏幕边界与遮挡限制。

UseForceOpaque（ForceOpaque）则是反向开关：把半透明当不透明处理，牺牲穿透换性能，用于调试或极端降级。

背景可见性合成（CompositeBackgroundVisibility）

半透明合成有个细节问题：透过半透明能看到多少背景/天空？这由 LumenCompositeBackgroundVisibility.usf 收尾。

Engine/Shaders/Private/Lumen/LumenCompositeBackgroundVisibility.usf

LumenFinalizeBackgroundVisibilityCS：两份贡献相加

它把两部分背景可见性合到一起：不透明贡献（取自 SceneColor 的 alpha 通道 .a）与半透明贡献（ResolvedBackgroundVisibilityTexture 的两个分量）。核心一行：

RWFinalBackgroundVisibility = TranslucentContribution.x + TranslucentContribution.y * OpaqueContribution

直观理解：x 分量是半透明自身直接贡献的背景可见性，y 分量是半透明"透过去"的比例——它要乘上后面不透明层的背景可见性（OpaqueContribution）才是穿透后的最终结果。随后 LumenCopyFinalizedBackgroundVisibilityPS 把结果写进目标的 alpha，供后续合成使用。这份背景可见性也被 反射去噪 的空间滤波 pass 读取（BackgroundVisibilityTexture），用于正确合成半透明光照。

它如何复用 Lumen Reflections 基建

不重造轮子：借反射的 tile 与追踪

光追半透明的入口 TraceTranslucency(...) 直接接收 FLumenReflectionTracingParameters 与 FLumenReflectionTileParameters——也就是说它复用反射的 tile 分类结果与追踪参数。shader 侧以permutation 形式挂在反射 shader 上（FRayTracedTranslucency / FRayTracedTranslucencyLighting 在 LumenReflections.cpp；硬件光追版 FRayTracedTranslucencyHardwareRayTracing 在 LumenReflectionHardwareRayTracing.cpp）。

共同点与反射一样，命中后取光照的数据源仍是 Surface Cache，追踪后端同样是软件 SDF / 硬件光追二选一，去噪也走 反射去噪器。

不同点反射一根线命中即停；光追半透明要多层命中 + 折射 + throughput 剪枝，且产出的是"透明层的透射/反射"而非镜面反射，最后经背景可见性合成叠回 SceneColor。

最终总结

光线追踪半透明是 Lumen 半透明质量阶梯的顶端：在体积近似（糊但省）和前层单层反射之上，它用路径追踪思路对半透明像素逐像素发线，穿过多层透明表面（MaxPrimary/SecondaryHitEvents）、支持光追折射（UseRayTracedRefraction）、用 throughput 阈值剪掉低贡献路径。它不是独立系统，而是长在 Lumen Reflections 之上的消费者——复用反射的 tile 分类、追踪后端、Surface Cache 命中光照与去噪器，只是把"命中即停"换成"多层穿透"。配套的 CompositeBackgroundVisibility 负责把半透明与不透明的背景可见性正确相乘合成。理解它，就理解了 Lumen 如何用一套统一的追踪基建，同时服务反射与高保真半透明这两个看似不同的需求。

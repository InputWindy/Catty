Surface Cache / Lumen Scene 代码解析（世界表面缓存）

Lumen 的"世界表面数据库"：把场景里所有网格用一组 Mesh Card 代理起来，把它们的材质属性（Albedo/Normal/Depth/Emissive）与光照（Direct/Indirect/Final）烘进一组世界空间 Atlas。所有 Lumen 追踪（③ TraceScreenProbes、Radiance Cache、反射、半透明）命中一个表面时，都不重新算光照，而是查页表定位到卡片、直接采样 FinalLightingAtlas。它就是 Lumen 能做无限反弹 GI 的物理基础。本页解析两条更新流水线：UpdateLumenScene（材质捕获）与 RenderLumenSceneLighting（光照烘焙）。

1. 核心思想：为什么把光照"烘进世界表面"

说明

Surface Cache 的本质是把昂贵的"命中点着色"从追踪热路径里挪出来，改成离线式的世界空间缓存 + 命中时一次采样。这和 ③ 里"从廉价到昂贵级联"是同一种精打细算的思路，只是维度不同：级联省的是"追踪次数"，Surface Cache 省的是"每次命中的着色成本"。

共同点和 Radiance Cache 一样，都用"世界空间缓存 + 每帧预算重烘一小部分 + 跨帧复用"来摊平成本。

不同点Radiance Cache 缓存的是"空间中某点各方向的入射辐照度"（probe），Surface Cache 缓存的是"具体网格表面被照亮的出射颜色"（card texel）。Radiance Cache 追踪时正是读 Surface Cache 当命中光源——两者是上下游关系。

2. 流水线 A · 材质捕获（UpdateLumenScene）

说明

流水线 A 只管"表面长什么样"（材质），不含光照。它把三维网格降维成一组卡片，用真正的 mesh 渲染把材质属性烘进四张 atlas。这是整个 Surface Cache 的几何/材质地基。

不同点捕获用 ForceLowestLOD + 关 mip bias 的 SharedView，因为卡片是低分辨率代理，不需要高模；且是正交投影而非透视。

共同点"预算选页 + 持久 atlas + 重采样防闪"与 Radiance Cache 的"预算重追 + 持久 + 历史迁移"如出一辙。

3. 流水线 B · 光照烘焙（RenderLumenSceneLighting）

说明

流水线 B 给已捕获的表面"打光"。直接光逐卡片算阴影光照；Radiosity是关键——它让卡片去采样别的卡片上一帧的最终光照，于是第 N 帧的间接光里含了 N-1 帧的直接光，跨帧迭代后收敛成无限次反弹。最后 Combine 把材质与光照乘算成 FinalLightingAtlas。

不同点Radiosity 读的是上一帧的 Final（历史），因此有一帧延迟但成本极低；这与 ④ FilterScreenProbes 的时域滤波、Radiance Cache 的历史复用同属"用历史换性能"。

共同点Direct/Indirect 都走"选页预算 + card tile 逐块 dispatch"，且都支持 AsyncCompute 与主渲染 overlap。

4. 采样与反馈：追踪命中如何读、如何反哺预算

说明

这一节把"更新"与"使用"接起来。追踪时不重算光照，而是页表定位 + 采样 FinalLightingAtlas。同时通过 SurfaceCache Feedback 形成闭环：真正被采样到、但缓存精度不够的卡片会被记下，反哺下一帧的选页预算——让有限的重烘预算花在"镜头真正看得到、光线真正打得到"的表面上。

共同点这个"使用时反馈需求 → 下帧按需更新"的闭环，与 Radiance Cache 的 MarkUsedProbes 回调是完全同构的按需驱动设计。

不同点Radiance Cache 的"被用到"是 CPU/GPU 回调显式标记；Surface Cache 的"被用到"是追踪 shader 在命中时顺手写 feedback buffer，更细粒度、更贴近真实采样分布。

汇聚点 / 发散点总表

环节类型说明
UpdateLumenScene 选页发散按预算/距离/反馈挑本帧要重画的卡片页，非全量。
Card Capture → 材质 atlas汇聚mesh draw 把卡片材质统一烘进 Albedo/Normal/Depth/Emissive。
Direct / Radiosity发散两条光照支路各自选页预算、各写一张 atlas。
CombineLumenSceneLighting汇聚材质 × (直接+间接) + 自发光 → FinalLightingAtlas。
Radiosity 读上一帧 Final汇聚历史反馈闭环，构成无限反弹。
GetLumenCardTracingParameters汇聚所有追踪后端统一的 Surface Cache 采样入口。
SurfaceCache Feedback发散命中时写需求，反哺下一帧选页预算。

最终总结

骨架

Surface Cache 是 Lumen 的世界表面光照数据库，由两条每帧流水线维护：UpdateLumenScene 捕获材质，RenderLumenSceneLighting 烘焙光照（Direct + Radiosity → Combine → Final）。所有追踪命中时只做一次 atlas 采样。

三大设计与 Radiance Cache 同源：卡片/页表（空间索引）、预算重烘（成本可控）、历史复用（Radiosity 读上帧 Final = 无限反弹）。

0. 输入输出契约

FSceneTextures / FrameTemporaries / LightingChannelsTexture / View
MeshSDFGridParameters / RadianceCacheParameters
ScreenSpaceBentNormalParameters / TranslucencyVolumeRadianceCacheParameters
return FSSDSignalTextures

说明

作用：这一分支把当前 View 的屏幕 probe gather 结果转换成 Composite 可消费的 signal textures。

共同点：和其他 Final Gather 分支一样，它必须返回 FSSDSignalTextures。

不同点：它额外产出 Screen Probe 相关的 radiance、history、short-range AO、Radiance Cache 参数。

1. 早退和 Debug 初始化

check(ShouldRenderLumenDiffuseGI(Scene, View));
if (!GLumenScreenProbeGather) return black outputs;

说明

作用：确认此函数只在 Lumen diffuse GI 生效时运行；如果 CVar 禁用 ScreenProbeGather，则返回黑色占位输出。

共同点：所有后续阶段都依赖 ScreenProbeGatherCommonParameters 和有效的 View。

不同点：Debug 开关只影响可视化，不改变主输出契约。

2. ScreenProbeParameters 初始化

ScreenProbeTracingOctahedronResolution = GetTracingOctahedronResolution(View);

说明

作用：把“屏幕上要放多少 probe、每个 probe 多少方向、采样点如何随时间变化”编码进统一参数包。

共同点：后续 placement、trace、filter、integrate 都共享同一份 FScreenProbeParameters。

不同点：质量档位、ReferenceMode、jitter 固定开关会改变分辨率和时间采样行为。

3. Uniform / Adaptive Probe Placement

FScreenProbeDownsampleDepthUniformCS

说明

作用：先按 downsampled screen tile 放 uniform probes，再在插值不可靠处补 adaptive probes，最后生成后续 pass 使用的 indirect args。

共同点：所有 probe 都会被统一计入 GetNumScreenProbes 和 ProbeIndirectArgs。

不同点：Adaptive placement 可关闭；关闭后只清空相关资源，不生成额外 probes。

4. History 判断 + Screen Data Gather

bIsHistoryValid = TemporalFilter && !CameraCut && Cvars unchanged
ScreenProbeGatherScreenData(...)

说明

作用：判断是否可以复用历史，并为每个 probe 收集 BRDF/PDF、disocclusion 和历史累积状态。

共同点：无论是否使用 importance sampling，BRDF/PDF 数据都是后续采样和滤波的基础输入。

不同点：history 无效时不会读取旧的 fast update 历史，disocclusion 空域滤波也可能关闭。

ScreenProbeGatherScreenData 是 trace 前的侦察兵，为每个 probe 算 BRDF PDF 与 disocclusion。↳ 下钻：① ScreenProbeGatherScreenData 解析

5. Radiance Cache Update

if (LumenScreenProbeGather::UseRadianceCache())
ScreenGatherMarkUsedProbes(...)

HairStrandsMarkUsedProbes(...)

说明

作用：把当前屏幕 probes 会用到的世界空间 radiance cache probes 标记出来，并按预算渐进更新。

共同点：Radiance Cache 作为远处光照和 fallback 缓存，服务于后续 trace 和采样。

不同点：立体渲染、半透明体积、hair strands 都会增加不同的 mark 回调；Radiance Cache 可关闭。

UpdateRadianceCaches 内部是一整套 clipmap + 持久缓存 + 预算重追的流水线。↳ 下钻：Radiance Cache 更新流水线解析

6. Importance Sampling + Trace

if (UseImportanceSampling(View)) GenerateImportanceSamplingRays(...)
TraceRadiance / TraceHit
TraceScreenProbes(...)
Screen Trace / HWRT / Mesh SDF / Global SDF / Radiance Cache

说明

作用：决定每个 probe 朝哪些方向采样，并对这些方向执行多后端 trace，写出方向 radiance 和 hit 数据。

共同点：所有 trace 后端最终都汇聚到 TraceRadiance 和 TraceHit。

不同点：trace 后端按平台和配置分叉，可能是屏幕空间、硬件 RT、Mesh SDF、Global SDF 或 Radiance Cache fallback。

这一步实际拆成两个子阶段：GenerateImportanceSamplingRays 定方向、TraceScreenProbes 发线追踪（多后端级联，含硬件光追）。↳ 下钻：② 重要性采样 ↳ 下钻：③ TraceScreenProbes 多后端追踪 ↳ 下钻：Hardware Ray Tracing 后端

7. Filter + ShortRangeAO

FilterScreenProbes(...)
CompositeTraces / CalculateMoving / TemporalFilter / SpatialFilter
if (UseShortRangeAmbientOcclusion(...)) ComputeScreenSpaceShortRangeAO(...)

说明

作用：把 trace 方向结果变成可插值的 probe radiance，并用时域/空域滤波降低噪声；短程 AO 补充小尺度遮蔽。

共同点：滤波后都会得到 FScreenProbeGatherParameters，供 integrate 使用。

不同点：Temporal filter、Spatial filter、Extra AO、ShortRangeAO 都是可配置分支。

FilterScreenProbes 把稀疏噪声 trace 磨成平滑 probe radiance（时域/空域滤波 + 转 irradiance）。↳ 下钻：④ FilterScreenProbes 降噪

说明

作用：创建 Composite 需要的最终屏幕空间输出纹理，并把 filtered probe radiance 按材质 BRDF 积分成 diffuse GI 和 rough specular GI。

共同点：不管之前 trace/filter 怎么分叉，最终都必须写出 DiffuseIndirect 和 RoughSpecularIndirect。

不同点：Backface diffuse 和 Integrate downsample 都是条件分支，Substrate closure 数会影响 texture array 层数。

InterpolateAndIntegrate 为每个屏幕像素插值邻近 probe 并按 BRDF 积分，从稀疏 probe 落回全屏。↳ 下钻：⑤ InterpolateAndIntegrate

最终总结

骨架

RenderLumenScreenProbeGather 是默认 Screen Probe Gather 分支的完整调度函数。它先建立屏幕 probe 采样结构，再生成 trace 输入，随后 trace、filter、integrate，最终返回 Composite 所需的三路主要 signal。

这个函数本身不是某一个算法的全部细节，而是把一组 RDG pass 按依赖关系组织起来。

阅读建议

先记住四个大汇聚点：FScreenProbeParameters、TraceRadiance/TraceHit、FScreenProbeGatherParameters、FSSDSignalTextures。之后再逐个展开 ScreenData、Trace、Filter、Integrate。

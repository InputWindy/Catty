1. Render 主循环插入点

说明

Lumen 不是单个 pass，而是散布在 Render() 多个阶段的一组 pass。顺序有严格依赖：必须在 GBuffer 之后（要读它）、TSR 之前（结果给它上采样）。UpdateLumenScene + RenderLumenSceneLighting 维护 Surface Cache 独立于屏幕，ScreenProbeGather 与 Reflections 才是屏幕相关的 GI/反射。

2. UpdateLumenScene 时机

说明

关键理解：Surface Cache 更新是世界空间、跨帧渐进的，不跟屏幕每帧全刷。UpdateLumenScene 读上帧 GPU 回读的 Feedback（哪些卡片被采样了/分辨率够不够），在预算内选一批卡片页捕获。这就是为什么快速移动或新出现的物体，其间接光会有一两帧延迟"长出来"——Surface Cache 在追赶。

3. Nanite 卡片捕获接口

说明

Nanite 与 Lumen 的接缝在卡片捕获。Nanite 网格没有传统 draw call，无法直接光栅到捕获 target，因此走 LumenCardComputeShader 的 compute 路径：直接读 Nanite 的 ShadingBin/visbuffer 计算材质写 atlas。传统网格仍走光栅捕获。两条路径殊途同归——都填同一套 Depth/Albedo/Normal/Emissive atlas，下游追踪无感知。详见 Surface Cache GPU 附录·Nanite 捕获。

4. GBuffer 依赖通道

说明

Lumen 屏幕侧几乎每个环节都要读 GBuffer：深度定位探针与重投影、法线做 SH 落地点积与 BRDF、粗糙度驱动反射 tile 分类与锥角、albedo/metallic 分配能量。这就是 Lumen 强制 Deferred 的技术根因——Forward 渲染没有把这些属性完整写进 GBuffer，Lumen 无从下手。

5. Global DF vs Mesh DF

说明

距离场有两级边界。Mesh DF 是每网格的精确稀疏距离场（离线烘焙），近场追踪采它保证精度。Global DF 由 GlobalDistanceField.cpp 在运行时把镜头附近的 Mesh DF 合成进 clipmap 体素纹理，远场 cone march 采它——用一张统一的场景级 SDF 换取远距离的低开销遍历。追踪级联在近场/远场之间切换这两级，是"精度 vs 性能"的空间划分。

6. velocity / 时序

说明

velocity buffer 是 Lumen 时域稳定性的命脉。Screen Probe 时域累积、反射 Temporal 降噪都靠它把当前像素映射到上帧位置取历史。PrevScreenPos = ScreenPos - Velocity。透明物、WPO 变形、粒子等如果没正确写 velocity，重投影就会取错历史，表现为拖影/鬼影/闪烁。排障时"动的时候才有的鬼影"几乎都指向 velocity。

7. 结果进 TSR

说明

Lumen 为实时性做了低采样 + 内部时空降噪，但仍留残余噪声，设计上依赖 TSR 收尾。GI 与反射合成进 SceneColor 后，TSR 再做一层帧间累积与上采样把噪声磨平。所以 Lumen 与时序上采样是配套的——关掉 TAA/TSR 会看到明显更多的 Lumen 噪声，这不是 bug 而是分工。

8. HWRT 后端切换

说明

追踪后端是可切换的边界。软件追踪走 SDF cone march（跨平台、无需 RT 硬件）；硬件光追走 RHI RayTracing 的加速结构做精确求交（更准，尤其接触阴影/薄物体，但更贵）。关键设计：两者命中后都采同一份 Surface Cache 取表面光照——追踪只负责几何求交，光照数据层解耦。因此切后端不影响 GI 管线其余部分。

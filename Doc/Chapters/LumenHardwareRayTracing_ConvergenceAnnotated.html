Lumen Hardware Ray Tracing 代码解析（硬件光追后端）

这不是某一条链路，而是被 ③ TraceScreenProbes、反射、Radiance Cache、Surface Cache 直接光照等多个消费者共用的追踪后端。当硬件支持 RT 时，Lumen 用真实 BVH 光追替代软件 Global SDF：命中后要么采样 Surface Cache（默认、廉价），要么在命中点重新着色（Hit Lighting、精确但昂贵）。它还有两种派发方式（Inline 计算着色器 / RayGen 光追着色器）与两层 TLAS（近场 + 远场）。本页解析共用基础设施 LumenHardwareRayTracingCommon，理解它就理解了所有 HWRT 消费者的公共骨架。

1. 核心思想：为什么要硬件光追后端

说明

要抓住一个分层：求交和着色是两回事。HWRT 换掉的是"求交"实现（SDF ray march → BVH 三角形求交），命中后怎么取光照是另一个正交选择。默认仍复用 Surface Cache，这样即便用了昂贵的硬件求交，着色成本依然可控。

共同点无论软/硬件后端，命中后取光照的默认数据源都是同一张 FinalLightingAtlas（Surface Cache），保证两种后端结果风格一致、可无缝回退。

不同点软件后端命中的是 SDF 近似面，硬件后端命中的是真实三角形；后者细节更准但 BVH 维护更贵。

2. 两种派发：Inline vs RayGen

说明

Inline 把光追塞进普通计算着色器，省掉 RT pipeline 的调度开销，是绝大多数"只需采 Surface Cache"场景的首选。RayGen 才是完整光追管线，代价更高但能在命中点跑任意材质着色器 + 阴影线——Hit Lighting 必须走它。

不同点Inline 只能 SurfaceCache 着色；RayGen 才解锁 Hit Lighting。硬件不支持 RayGen 时，着色模式被强制降级为 SurfaceCache。

共同点两种派发共用同一套 FSharedParameters（TLAS/光照数据/Surface Cache），编译期靠 LUMEN_HARDWARE_INLINE_RAYTRACING 宏切换代码路径。

3. 两种着色模式：SurfaceCache vs Hit Lighting

说明

三档是"质量 vs 成本"的连续调节：SurfaceCache 最便宜、全靠缓存；HitLighting 在每个命中点重算材质并发阴影线，画质最好但极贵；中间档只给最需要锐利的反射开小灶。注意即便开 HitLighting，二次及以后的弹跳仍回落 Surface Cache，否则光追会无限递归。

共同点Hit Lighting 复用的 LightGrid / ForwardLight / ReflectionCapture 与前向着色、其它光追特性同源。

不同点SurfaceCache 命中只读一张 atlas；HitLighting 命中要跑完整材质 + 额外阴影线 dispatch，成本量级差别巨大——所以它是可缩放项（Scalability CVar 可禁）。

4. 两层 TLAS 与稳健性细节

说明

两层 TLAS 是空间上的 LOD：近处几何进详细 Base 层，远处进粗糙 FarField 层，用 FarFieldBias 隔开两层避免交界自交。一堆 bias / iteration 上限 CVar 都在解同一类问题：BVH 几何与光栅几何不完全吻合造成的自交、漏光、超时——本质是光追精度与性能/稳健性的妥协旋钮。

共同点PullbackBias 服务的"屏幕 trace → HWRT 续接"正是 ③ TraceScreenProbes 的级联顺序（先屏幕空间、丢了再交给 HWRT）。

不同点远场 TLAS 是 HWRT 独有；软件 Global SDF 用的是 clipmap 分级距离场，覆盖远近的方式不同。

最终总结

骨架

HWRT 是 Lumen 的可选横切追踪后端：门禁通过后，按硬件能力选 Inline/RayGen 派发，绑定共享的两层 TLAS + Surface Cache 参数，对真实三角形求交；命中后按 Lighting Mode 决定是采 Surface Cache（默认）还是在命中点重着色（Hit Lighting）。③、反射、Radiance Cache 等消费者都基于这套公共骨架各建 dispatch。

记住两个正交维度：派发方式（Inline/RayGen）× 着色模式（SurfaceCache/HitLighting），外加两层 TLAS 与一堆稳健性 bias。

阅读建议

先理解"求交与着色分离"，再看两种派发的能力差（Inline 便宜但只能采缓存，RayGen 才能 Hit Lighting）。想看某个消费者怎么用，从对应的 Lumen*HardwareRayTracing.cpp 入手，它们都继承本页的 base 与共享参数。permutation 与逐消费者差异见函数附录。

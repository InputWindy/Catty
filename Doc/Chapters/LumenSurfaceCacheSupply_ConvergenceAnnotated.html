Surface Cache 供给侧 · 卡片从哪来、显存怎么管

已有的 Surface Cache 主题讲的是怎么用（追踪命中查页表采样 FinalLightingAtlas）与怎么打光（光照烘焙）。但整条链有个大缺口没讲：这些 atlas 是怎么被建出来的、显存预算怎么管。本页补上这条"供给侧"链路——从场景里加进一个 primitive 开始：如何为它生成 Mesh Cards（把任意网格代理成几个朝向的矩形卡片）、每帧的场景更新调度（Begin/Update 两阶段 + 异步任务）、GPU 用完后写回的反馈如何驱动 CPU 决定"该驻留哪些页"、物理页表分配器如何装箱与 LRU 逐出、以及最后把材质光栅化捕获进 atlas。这是 Lumen 里"看不见但最烧显存"的一层。

上下文：它在整帧的什么位置

供给侧全部发生在 GI 之前。两个入口都在 FDeferredShadingSceneRenderer 上：BeginUpdateLumenSceneTasks 在帧早期启动——锁定上帧的 Feedback 与场景增删 readback、发起异步 UpdateSceneTask 收集本帧要更新的卡片页；随后 UpdateLumenScene 等任务完成，做 atlas 重分配、上传页表、执行 CardCapture 光栅化。产出的 AlbedoAtlas / NormalAtlas / DepthAtlas / EmissiveAtlas 就是 光照烘焙的输入，最终合成 FinalLightingAtlas 供所有追踪命中时采样（见 Surface Cache 主题）。

1. 卡片是怎么来的：Mesh Cards 生成与放置

说明

Lumen 不可能对任意网格逐三角形烘光照，于是用 Mesh Cards 把网格代理成若干朝向的矩形捕获面——通常沿 6 个轴对齐方向各摆几张，像给物体"贴标签"。卡片的布局（FMeshCardsBuildData）是离线随网格烘出来的，运行时只按 FLumenPrimitiveGroup 装配。一堆 CVar 控制合并策略：把同一 actor 的多个组件、或大量 ISM 实例合并成更少的卡片以省显存（合并后按 MergedResolutionScale 降分辨率），并剔掉背向/没覆盖的面。

共同点用 OBB 卡片代理网格的思路，与 Distance Field 用 SDF 代理几何是同一种"降维成可采样表示"的哲学。

2. 场景更新调度：Begin / Update 两阶段

说明

更新被刻意拆成两段：BeginUpdateLumenSceneTasks 只做"锁上帧回读 + 发起异步任务"，把最重的 CPU 活（解析 feedback、决定分配/逐出）丢进 UpdateSceneTask 与其它渲染并行；等到真要用时 UpdateLumenScene 才 Wait() 收口，做 GPU 侧的 atlas 分配、页表上传与卡片捕获。这也是为什么 Lumen 天然是"延迟一帧"的——它消费的是上一帧的采样反馈。

不同点与 ①~⑤ 那种"当帧顺序执行"的 GI 阶段不同，供给侧是跨帧异步的：本帧根据上帧反馈更新，天然有一帧延迟。

3. 反馈驱动：GPU 告诉 CPU 该驻留哪些页

说明

Lumen 不猜"哪些页有用"，而是让 GPU 如实反馈：着色时每采一次 Surface Cache 就往 feedback buffer 写一条（哪张卡、想要多高分辨率、命中了几次）。CPU 回读后分两类处理——已驻留的页只刷新它的"最后使用时间"喂给 LRU；还没驻留的页按到相机距离 + 命中次数算优先级、丢进距离分桶直方图，形成本帧的 SurfaceCacheRequests。命中越少的页优先级被压得越低（距离加权更大），避免为偶尔扫到一眼的表面浪费显存。

共同点"固定预算 + 优先级直方图选桶"的思路，与 Radiance Cache 的 probe 预算调度如出一辙。

4. 页表分配器：装箱 + LRU 逐出 + 降分辨率

说明

物理 atlas 被切成固定大小的物理页。大卡片直接占整页；一堆小卡片则走 sub-allocation——按尺寸分箱（PageBin），在一整页里切格子装箱，避免小卡片各占一页浪费。当显存不够时有两级降级：先 LRU 逐出（EvictOldestAllocation，逐出超过 2 帧没用过的页），还不够就降低请求的分辨率等级（ResLevel-- 直到 MinResLevel）。重分配时若能共享已有卡片（CardSharingId）或从自身高 mip 降采样，就直接复制、免去重新捕获。

不同点这是纯 CPU 侧的显存记账（虚拟页表 → 物理页），与 GPU 上的采样解耦；GPU 只认上传后的页表。

5. 卡片捕获：Resample + 光栅化材质进 atlas

说明

拿到"本帧要更新哪些页"后，先 ResampleLumenCards 把这些页在旧持久 atlas 里的现有内容重采样过来（可能换了 mip 或来自共享卡），保证过渡不闪；然后才是真正的捕获：用 GPUScene + FInstanceCullingContext 组织网格的 draw command，为每页算一个 CardCaptureRect，把网格材质光栅化进一张 transient 的 CardCaptureAtlas（强制最低 LOD、关 mip bias），最后拷进持久的 Albedo/Normal/Depth/Emissive atlas。到这里"材质侧"就绪，剩下的交给光照烘焙。

共同点用 GPUScene + InstanceCulling 组织 mesh draw、按 rect 批量渲染，与主渲染管线的 mesh pass 完全同源，只是渲染目标换成了世界空间 atlas。

最终总结

一句话

Surface Cache 的 atlas 不是凭空存在的。供给侧从场景 primitive 出发，先按离线烘出的布局装配 Mesh Cards（矩形卡片代理网格），每帧用 Begin/Update 两阶段异步调度：GPU 写回的采样反馈按距离+命中数排出优先级，页表分配器用装箱 + LRU 逐出 + 降分辨率在固定显存预算内取舍，最后把网格材质光栅化进 atlas。它是 Lumen 里最"隐形"却最决定显存开销的一层——理解了它，才算真正读懂 Surface Cache。

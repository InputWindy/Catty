1. BeginGatherLumenLights：异步收集影响卡片的光源

说明

收光被拆成异步任务是为了把 CPU 端的灯光遍历/裁剪与 GPU 主渲染重叠。产物 GatheredLights 是后续所有直接光 pass 的输入清单。

不同点这里收的是"影响世界卡片"的光（含屏外），比普通延迟着色收的"影响屏幕像素"的光范围更大。

2. CullDirectLightingTiles：逐 card tile 挑光

说明

逐 tile 剔光把"每块卡片只与少数几盏相关光作用"落地，避免每个卡片 texel 都遍历全部灯光。MaxLightsPerTile 直接决定内存与耗时上限。

共同点与延迟渲染的 tiled/clustered light culling 同构：先建 per-tile 光表，再着色时只读本 tile 的表。

3. 屏内 / 屏外双阴影

说明

阴影遮罩是直接光的核心难点。两个 CS 对应两种数据可得性：屏内蹭现成 shadow map（几乎免费），屏外只能追距离场（较贵但覆盖全世界）。结果都写成 per-texel 的 shadow mask，供施光 pass 相乘。

不同点屏外阴影只需要"路上有无遮挡"的二值/软遮挡，不需要像 ③ 那样求命中点的完整光照，因此可用低精度 Global SDF 换速度。硬件 RT 版见 F · HWRT 消费者 里的 LumenSceneDirectLightingHardwareRayTracing.cpp。

4. BatchDirectLighting：把光 × 阴影施加到卡片

说明

施光是直接光的汇聚点：读 per-tile 光表 + 各光的 shadow mask，逐 texel 累加出 DirectLightingAtlas。批处理（一次 dispatch 处理 tile 内全部光）是性能关键。

共同点"批量累加多光源"与延迟渲染的 tiled deferred lighting 相同；差别只是这里的着色目标是世界卡片 texel。

CS / Pass职责关键点

FLumenRadiosityDistanceFieldTracingCS
／FLumenRadiosityHardwareRayTracing[RGS\|CS]		每 probe 沿半球追踪软件追 Global/Mesh SDF；命中读上帧 Final → TraceRadianceAtlas；MaxRayIntensity 去萤火虫

说明

六个 CS 是一条"建 probe → 追踪 → 降噪 → 压缩表示 → 积分回卡片"的微型 probe GI 管线。用 SH 压缩方向辐射、用时域累积压噪声，让低分辨率半球采样也能得到平滑间接光。bUseProbeOcclusion 打开时用命中距离做遮挡测试，进一步防漏光（软追精度不足时默认关）。

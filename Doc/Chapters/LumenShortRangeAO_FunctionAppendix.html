1. 入口与后端选择

说明

入口先按 DownsampleFactor 定输出尺寸（Substrate 多层时扩容），再按画质档 LumenFinalGatherQuality 决定每像素光线数（4/8/16）。GetDownsampleFactor 有个巧妙的钳制：只有当结果要参与积分复用或时域滤波时降采样才有意义，否则退回 1× 全分辨率。后端二选一：硬件 RT 或屏幕空间 CS。

2. Shader permutation 矩阵

说明

这个 CS 的 permutation 很多，核心就三组：追踪方式（HorizonSearch 及其 HZB / bitmask 变体，或直接打 NumPixelRays 根光线）、输出（是否 OutputBentNormal）、分辨率（DownsampleFactor）。RemapPermutation 做互斥裁剪——开 HorizonSearch 时锁死 NumPixelRays=4（horizon 模式不按光线数走），避免编译无意义的组合爆炸。

3. Horizon search 参数

说明

Horizon search 的两个主 scalability 旋钮是 SliceCount（方位角切多少片）和 StepsPerSlice（每片走多少步）——它们直接决定 AO 的角度与距离分辨率。SlopeCompareToleranceScale 控制斜率比较的松紧（防自遮挡误判）。搜索半径用 MaxScreenFraction 表示（占屏幕的百分比），AO 只关心接触级的近处遮挡，所以半径很小。

共同点AO 与实验性 GI 复用同一套 horizon 框架，只是 StepsPerSlice / MaxScreenFraction 分开配。

4. Bent normal 编码

说明

是否输出 bent normal 决定纹理格式：要方向就用 PF_R32_UINT 把方向和 AO 一起打包，只要标量就用 PF_R8。纹理是 Texture2DArray，层数 = Substrate 的 ClosureCount（每层一个 BSDF）。FoliageOcclusionStrength 是个体感优化：植被和次表面材质本该透光，若被 AO 压死会显得很假，所以对这类像素钳制最大遮蔽强度。

5. 前景排除 + 时域滤波

说明

屏幕空间 AO 的经典毛病是"近处物体在它后面的远背景上投出一圈本不该有的暗"。ForegroundSampleRejectDistanceFraction 用深度差把这种前景遮挡剔掉。时域滤波则复用 Lumen 通用的邻域钳制思路：用当前帧邻域的 min/max 把历史值夹住，既压噪又不至于让过期历史拖影。

共同点邻域 min/max 钳制历史，与主线时域滤波（FilterScreenProbes / UpdateHistory）完全同一手法。

6. HW RT 短光线后端

说明

硬件 RT 后端把屏幕空间的 horizon search 换成真实的短距离光线：每像素打 NumPixelRays 根很短的 ray（长度受 MaxScreenTraceFraction 限制），命中即算遮挡，统计未命中方向得到 bent normal 与 AO。它不受屏幕空间信息缺失（屏幕外/被遮挡几何）的限制，质量更高，代价是需要 RT 硬件和 BVH。NormalBias 沿法线抬高起点防自相交。

不同点屏幕后端靠读深度找地平线（受屏幕可见性限制）；HW RT 后端真实投短光线（可命中屏幕外几何），更准更贵。

7. 关键 CVar 速查

CVar（前缀 r.Lumen.ScreenProbeGather.ShortRangeAO）默认作用
.BentNormal—是否输出 bent normal（否则纯标量 AO）
.DownsampleFactor1..2输出分辨率降采样
.HorizonSearch1启用 GTAO 式地平线搜索
.HorizonSearch.SliceCount—方位角 slice 数（主 scalability）
.HorizonSearch.StepsPerSlice3每 slice 步进数
.SlopeCompareToleranceScale.5遮挡判定斜率容差
.Temporal / .Temporal.NeighborhoodClampScale—时域滤波与邻域钳制
.ApplyDuringIntegration0积分中应用（高质拖影）vs 之后
.HardwareRayTracing / .HardwareRayTracing.NormalBias—HW RT 后端与自相交偏置
.FoliageOcclusionStrength—植被/次表面最大遮蔽钳制

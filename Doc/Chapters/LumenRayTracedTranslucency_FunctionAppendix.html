2. 入口函数

函数职责
TraceTranslucency(GraphBuilder, Scene, View, FrameTemporaries, SceneTextures, ReflectionTracingParameters, ReflectionTileParameters, DiffuseIndirectMethod, ComputePassFlags, bUseRayTracedRefraction)主入口：接收反射的追踪参数与 tile 参数，对半透明像素发线追踪
RenderHardwareRayTracingTranslucency(..., TracingParameters, ReflectionTracingParameters, ReflectionTileParameters, MaxTraceDistance, ...)硬件光追后端版本
FDeferredShadingSceneRenderer::RenderRayTracedTranslucencyView(...)渲染器层的调用点（DeferredShadingRenderer）

说明

入口签名里出现 FLumenReflectionTracingParameters / FLumenReflectionTileParameters 就是"复用反射基建"的直接证据——它不自己做 tile 分类，而是拿反射已经算好的 tile 与追踪参数来跑。追踪触发的判定散落在 TranslucentRendering.cpp、FrontLayerTranslucency.cpp、StochasticLighting.cpp 等处，均调 RayTracedTranslucency::IsEnabled(View)。

3. Shader permutation

符号位置含义
FRayTracedTranslucencyLumenReflections.cppSHADER_PERMUTATION_BOOL("RAY_TRACED_TRANSLUCENCY")：反射 shader 的半透明变体
FRayTracedTranslucencyLightingLumenReflections.cppSHADER_PERMUTATION_BOOL("RAY_TRACED_TRANSLUCENCY_LIGHTING")：半透明光照变体
FRayTracedTranslucencyHardwareRayTracingLumenReflectionHardwareRayTracing.cpp硬件光追 shader（继承 FLumenHardwareRayTracingShaderBase）

说明

光追半透明没有独立的一整套 shader 类，而是以 permutation 挂在反射 shader 上——同一份反射追踪 shader，开 RAY_TRACED_TRANSLUCENCY 宏后走多层半透明逻辑。这是"复用基建"在 shader 层面的体现，也解释了为什么它的实现分散在 LumenReflections*.cpp 而非独立文件。

4. 背景可见性合成（LumenCompositeBackgroundVisibility.usf）

Shader职责
LumenFinalizeBackgroundVisibilityCS合成半透明 + 不透明背景可见性：Final = Translucent.x + Translucent.y * OpaqueContribution
LumenCopyFinalizedBackgroundVisibilityPS把最终背景可见性写进目标 alpha（OutColor = float4(0,0,0, BackgroundVisibility)）

说明

OpaqueContribution 取自 SceneColorTexture.Load(...).a（不透明侧背景可见性存在 alpha）；TranslucentContribution 来自 ResolvedBackgroundVisibilityTexture。x = 半透明自身贡献，y = 穿透比例，因此 y * OpaqueContribution 表示"透过半透明看到的不透明背景"。这份数据也被 反射去噪 Spatial pass 读作 BackgroundVisibilityTexture 用于半透明光照合成。

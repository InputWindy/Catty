InterpolateAndIntegrate 代码解析

RenderLumenScreenProbeGather 的第五个（最后一个）子阶段。前四阶段都在稀疏的 probe 网格上工作，这里终于回到全屏像素：为每个屏幕像素找到邻近的几个 probe，把它们滤波好的辐照度按该像素的 BRDF 与法线做插值 + 积分，产出屏幕空间的 DiffuseIndirect / RoughSpecularIndirect / BackfaceDiffuseIndirect。这是 Screen Probe Gather 的"落地"阶段，输出会交给降噪器和 Composite 合入最终画面。

完整源码对照

以下是 InterpolateAndIntegrate 的完整 C++ 编排源码（两条路径）。积分核 shader 细节见函数附录。

Engine/Source/Runtime/Renderer/Private/Lumen/LumenScreenProbeGather.cpp

0. 核心思想：从稀疏 probe 回到全屏像素

输入：GatherParameters（每 probe 的滤波辐照度：SH3 或 Octahedron）
for 每个屏幕像素（可降采样）：
    找到邻近 probe → 按位置/深度/法线插值
    对像素 BRDF 积分 probe 辐照度
输出：DiffuseIndirect / RoughSpecularIndirect / BackfaceDiffuse

说明

前四阶段（GatherScreenData → Importance → Trace → Filter）都工作在稀疏 probe 网格上——每隔若干像素放一个 probe，为它算好各方向的辐照度。但最终画面需要的是每个像素的间接光。这一阶段负责把稀疏结果"插值 + 积分"回全屏。

插值：每个像素找到周围几个 probe，按世界位置、深度、法线相似度加权（UpsampleParameters），避免跨越几何边界漏光。积分：把插值出的方向性辐照度与该像素材质的 BRDF（漫反射余弦瓣 + 粗糙镜面瓣）做半球积分，得到 DiffuseIndirect 和 RoughSpecularIndirect。

整个阶段最大的工程复杂度不在数学，而在性能分流：不同屏幕区域需要的积分技术不同（纯漫反射 / 带背面 / 带 AO / 多材质层），用 tile 分类让每块屏幕只跑它真正需要的 shader permutation。

1. 路径门禁：tile 分类 vs 全屏

bUseTileClassification = CVar 开 && DiffuseIntegralMethod != 2
bApplyShortRangeAO = 开关 && AO 纹理有效 && ShouldApplyDuringIntegration
IntegrateDownsampleFactor = GetIntegrateDownsampleFactor(View)

说明

发散顶层由 bUseTileClassification 分成两条路径。tile 分类路径（默认、性能更优）把屏幕切成 tile，先分类再对每类 tile 用专用 permutation 积分；全屏路径（降级方案）直接对整个 viewport 跑一次通用 permutation 的积分。

共同点两条路径最终都调用同一个积分核 FScreenProbeIntegrateCS，消费同一份 GatherParameters，写同一组输出纹理——只是"如何组织 dispatch"不同。IntegrateDownsampleFactor 允许以更低分辨率积分再上采样（大幅省算力，靠后续降噪/上采样补细节）。

2. Tile 分类路径：InitArgs → BuildLists → ClearUnused

FInitScreenProbeTileIndirectArgsCS  // 清零 indirect args
FScreenProbeTileClassificationBuildListsCS(false)  // 主分类
  if Substrate: BuildLists(true)  // overflow（多 closure）
FScreenProbeIntegrateClearUnusedTileDataCS  // 清空未处理 tile

说明

分类路径的准备工作分三步。InitScreenProbeTileIndirectArgs 把间接派发计数器清零。TileClassificationBuildLists 读 LumenTileBitmask（此前不透明物已做过的 tile 标记），判断每个 tile 需要哪种积分技术，把 tile 索引追加进对应分类的 list，同时累加该分类的 dispatch 计数。

不同点当启用 Substrate（多材质层）时，额外跑一次 bOverflow=true 的 BuildLists，用 ClosureTilePerThreadDispatchIndirectBuffer 处理"一个像素有多个 closure"的溢出 tile。

ClearUnusedTileData 在积分前先把"不会被任何积分 pass 覆盖"的 tile 清成默认值——因为输出 UAV 用了 SkipBarrier 让多个积分 pass 并行 overlap，未覆盖区域必须显式清零，否则会读到上一帧残留。

3. Tile 分类路径：逐分类模式积分（核心发散）

for ClassificationMode in [0, Num):
    FScreenProbeIntegrateCS（专用 permutation）
    permutation: TileClassificationMode / ShortRangeAO / ProbeIrradianceFormat
                 / StochasticProbeInterpolation / BackfaceDiffuse / DownsampleFactor
    indirect dispatch @ (bOverflow?Num:0 + Mode) 偏移

说明

发散这是本阶段的核心：对 EScreenProbeIntegrateTileClassification::Num 种分类模式各跑一次积分，每种模式编译出只含它需要的功能的 shader permutation。例如"只需简单漫反射"的 tile 不会背上背面漫反射/AO 的代码分支，寄存器占用更低、occupancy 更高。

每次 dispatch 通过 IntegrateIndirectArgs 偏移到本分类模式对应的 tile list（overflow 变体再加一个 Num 偏移），因此 GPU 只对属于该模式的 tile 启动线程组。

共同点关键 permutation FProbeIrradianceFormat 必须与上一阶段 Filter 的 ConvertToIrradiance 输出格式一致（SH3 或 Octahedron）——积分核据此选择"SH 点乘余弦瓣"还是"采样 octahedron irradiance 图"。FStochasticProbeInterpolation 决定是随机选一个 probe（省带宽、噪声靠时域滤）还是加权多个 probe。

4. 非分类路径：全屏单次积分（汇聚兜底）

FTileClassificationMode = Num  // 特殊值：表示"不分类，全跑"
若无 SHAmbient → 用 SystemTextures.Black 兜底绑定
DispatchCount = GetGroupCount(ViewRect / DownsampleFactor); Z = ClosureCount
直接 dispatch（非 indirect）

说明

汇聚当 tile 分类被关闭（或 DiffuseIntegralMethod==2）时走这条降级路径：不做分类，直接对整个下采样 viewport 派发一次积分，permutation 里 FTileClassificationMode 设为特殊值 Num 表示"通用、全功能"。

不同点与分类路径的区别只在 dispatch 组织：这里用固定 GetGroupCount 直接派发、DispatchCount.Z = ClosureCount 用 Z 维覆盖多 closure，而非 indirect args + tile list。一个健壮性细节：若 GatherParameters 没有 SH 纹理（非 SH3 格式），用 SystemTextures.Black 兜底，避免着色器绑定缺失。

无论哪条路径，产出的四张纹理语义完全相同——这是"汇聚"：性能策略可变，输出契约不变。

最终总结

说明

InterpolateAndIntegrate 是 Screen Probe Gather 五阶段的收尾，也是从"稀疏 probe 世界"回到"全屏像素世界"的桥梁。它做两件事：插值——每像素按位置/深度/法线加权邻近 probe，避免漏光；积分——把插值出的方向性辐照度与像素 BRDF 做半球积分，得到 diffuse 与 rough specular 间接光。

它的工程精髓是 tile 分类：不是对全屏跑同一个"什么都支持"的重型 shader，而是先按需分类，让每块屏幕只跑它真正需要的 permutation，配合 indirect dispatch + SkipBarrier overlap，把积分开销压到最低。全屏路径则作为不支持分类时的等价兜底。

至此 RenderLumenScreenProbeGather 的五个内部子阶段全部走完：它输出的 DiffuseIndirect / RoughSpecularIndirect 会先经时域降噪（UpdateHistoryScreenProbeGather），再由更上层的 DiffuseIndirectComposite 合入场景颜色——这正好接回你最初那份 Composite 解析文档，整条 Lumen GI 链路首尾闭合。积分核 shader 与 tile 分类细节见函数附录。

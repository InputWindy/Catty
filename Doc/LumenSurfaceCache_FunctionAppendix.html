1. Mesh Card / 卡片页 / 页表：世界表面怎么索引

说明

Mesh Card 是 Surface Cache 的空间索引单元：把连续的三维表面切成一块块可寻址的卡片，卡片再映射到 atlas 页。这一层"世界 → 卡片 → atlas 坐标"的间接，作用等价于 Radiance Cache 的 RadianceProbeIndirectionTexture。

不同点Radiance Cache 索引的是"空间格子"（3D clipmap），Surface Cache 索引的是"网格表面"（贴合几何的卡片）。前者覆盖空气中任意点，后者只覆盖实体表面。

2. 选页预算：优先级直方图 + 选桶（BuildCardUpdateContext）

说明

Surface Cache 与 Radiance Cache 共用同一套预算调度心法：优先级直方图统计 + 选桶裁剪，O(桶数) 时间定出本帧更新阈值，严格不超预算。区别只是这里的调度单元是"卡片页"而非"probe"。

共同点PriorityHistogram / MaxUpdateBucket 命名与算法都与 Radiance Cache 的 SelectMaxPriorityBucket 一致——这是 Lumen 通用的成本裁剪套路。

不同点这里同时维护 Direct 与 Indirect 两套独立预算（更新速率 factor 不同），因为直接光变化快、间接光可慢更新。

4. 光照烘焙 pass（RenderLumenSceneLighting 内）

说明

三段串联：Direct 打直接光、Radiosity 补一次反弹间接光、Combine 合成 Final。无限反弹的秘密全在 Radiosity 读上一帧 Final：每帧多积累一次反弹，跨帧收敛。

共同点Radiosity 的"低分辨率追踪 + 时域累积去噪"与 ④ FilterScreenProbes 的时域滤波是同一思路（NumFramesAccumulated 控制累积权重）。

不同点它追踪的是"卡片到卡片"（世界表面互照），而 ③ 追踪的是"屏幕 probe 到世界"；但两者命中后都读同一张 FinalLightingAtlas。

5. SurfaceCache Feedback：使用反哺更新

说明

Feedback 是"按需分配精度"的闭环：不预先给所有卡片最高精度，而是让真实追踪采样告诉系统哪些卡片值得投入预算。jitter 抖动保证不会每帧都写同一批、把 feedback buffer 挤爆。

共同点与 Radiance Cache 的 MarkUsedProbes 同为"按需驱动"：只更新真正被用到的部分。

不同点probe 标记是更新前显式回调；surface feedback 是采样时顺手写、下一帧才生效，属于延迟反馈。

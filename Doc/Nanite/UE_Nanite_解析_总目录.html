UE Nanite 源码解析 · 总目录

Nanite 是 UE5 的虚拟化几何体（virtualized geometry）系统：让美术直接用电影级密度的网格（数亿三角形），引擎在运行时自动做像素级 LOD——屏幕上一个像素大约只画一个三角形，且几乎不受源模型面数影响。要做到这点，Nanite 横跨三层：① 离线构建（把网格切成簇 cluster、建 LOD DAG、编码成 GPU 页）、② 运行时 GPU 驱动管线（流送、两趟剔除、软/硬件光栅化到 visibility buffer、延迟材质着色）、③ 专项扩展（可编程光栅化、阴影 VSM、光追、体素）。本书对照 UE5.8 本地源码逐层解析，每主题含一份主文档（设计动机 + 数据流骨架 + 分阶段批注）与一份函数附录（类 / 函数 / CVar / 结构体细节）。所有符号名、常量、CVar 默认值均取自 UE5.8 本地源码。

这本书怎么读

Nanite 的核心是一条从磁盘到像素的完整数据流，建议第一次按 #1 → #2 → #3 → #4 → #6 → #7 顺序把主干过一遍：#1 总览建立"为什么 + 全景"；#2 构建 DAG 与 #3 编码讲清"离线把网格变成了什么"（簇、LOD DAG、GPU 页）；#4 流送讲"页怎么按需进显存"；#6 剔除光栅化是运行时心脏（两趟剔除 + 软/硬光栅到 visibility buffer）；#7 着色讲"visibility buffer 怎么变成 GBuffer"。主干通了以后，再看 #5 实例剔除（#6 的前置）、#8 可编程光栅化、以及三个专项案例 #9 阴影 / #10 光追 / #11 体素。关键常量：一个簇最多 128 三角形 / 256 顶点，根页 32KB、流送页 128KB。若读过本文档集的 Lumen、虚拟纹理、MegaLights 篇，可从各主题的"关系"对比 note 切入。

一眼看懂：Nanite 从磁盘到像素的数据流

① 离线构建（Editor / DDC）网格 → 切簇（≤128 tri）
→ 简化建 LOD DAG
→ 编码成 32KB/128KB 页
存进 FResources
② 运行时 GPU 管线流送页进显存 → 实例剔除
→ 层级遍历 + 集群剔除
→ 软/硬光栅化写 Visibility Buffer
→ shade binning 延迟着色
③ 专项扩展可编程光栅化 / 曲面细分
VSM 阴影复用剔除管线
光追 BLAS / stream out
体素 SVO 新路径

与传统渲染最大的不同：Nanite 几乎完全在 GPU 上驱动（culling / raster / binning 都是 compute），CPU 只提交极少的间接派发；LOD 不再是离散档位切换，而是沿 DAG 连续选择 cut，做到像素级、无 popping。详见 #1。

与本文档集其它篇的关系

四本独立的书，同一套渲染世界观

本书（UE Nanite）与 Lumen GI 解析、虚拟纹理解析、MegaLights 解析 是并列的四套渲染方案文档，各有独立总目录。交汇点有三处：① 本书 #4 流送 与虚拟纹理书的"页表式流送"是同一种"数据 > 显存"范式（一个流几何页、一个流纹理页）；② 本书 #9 阴影 直接复用虚拟纹理书 VSM Clipmap 篇的 clipmap 结构，Nanite 提供几何、VSM 提供页表；③ Nanite 提供的高密度几何是 Lumen（软件光追走 Nanite fallback mesh）与整个延迟管线的输入。读完本书主干（#1~#7）后回看其它三本，能更清楚 UE5 渲染各系统如何协同。

NaniteRasterizer.usf 汇聚/发散批注版

Nanite 的软件光栅器：一个 compute 内核逐像素扫描三角形，专治"三角形小于一像素"时硬件光栅的 quad 浪费。软件路径（MicropolyRasterize CS）与硬件路径（HWRasterizeVS/MS/PS）汇聚到同一段 RasterizeTri_Adaptive(Tri, NaniteWritePixel)，按几何类型（三角/体素/曲线/patch）与目标（主/VSM）发散。说明：完整文件 3531 行，下方内嵌核心入口与三角光栅调用的真实源码；扫描细节在 NaniteRasterizationCommon.ush。

一眼看懂：软/硬两路，一个写入

软件光栅MicropolyRasterize CS（微小三角，逐像素扫描）
硬件光栅HWRasterizeVS/MS/PS（大三角，固定功能）
▶

▶

▶

0. 软/硬双入口 + 几何类型分派

[numthreads(THREADGROUP_SIZE,1,1)] void MicropolyRasterize(...)  // 软件光栅 CS
void HWRasterizeVS/MS/PS(...)                                    // 硬件光栅（VS+MS+PS）
#if NANITE_VOXELS   ClusterTraceBricks   // 体素
#elif NANITE_CURVES ClusterRasterizeCurves
#elif PATCHES       PatchRasterize        // 细分 patch
#else               ClusterRasterize      // 三角形

说明

不同点软件光栅是 compute（MicropolyRasterize，一个线程组一个簇，逐像素扫描无 quad 浪费）；硬件光栅走固定功能（HWRasterizeVS/MS/PS）。#6 按 r.Nanite.MinPixelsPerEdgeHW=32 把簇分到 SW/HW 两组。

共同点软件路径内再按宏分几何类型：三角形（主）、体素（#11）、曲线（头发）、细分 patch（#8）。

1. SetupTriangle：子像素定点

FRasterTri Tri = SetupTriangle< NANITE_SUBPIXEL_SAMPLES, !NANITE_TWO_SIDED >(
    Raster.ScissorRect, Verts );
if( Tri.bIsValid && bTriValid ) { ... }

说明

顶点先转成子像素定点坐标（PointSubpixelClip，NANITE_SUBPIXEL_SAMPLES 定亚像素精度），SetupTriangle 算边方程、做背面剔除（!NANITE_TWO_SIDED 时）与剪裁矩形裁剪，产出 FRasterTri。定点数学保证光栅结果精确、无 T 型裂缝——这是软件光栅能替代硬件的前提。

2. RasterizeTri_Adaptive + NaniteWritePixel functor（汇聚点）

TNaniteWritePixel< FMaterialShader > NaniteWritePixel;
NaniteWritePixel.Shader = MaterialShader;   // #8 可编程光栅在此
NaniteWritePixel.PixelValue = PackVisPixelX(VisibleIndex, TriIndex);
RasterizeTri_Adaptive( Tri, NaniteWritePixel );  // 扫描 + 逐像素回调

说明

这是全 shader 的汇聚点：无论软/硬、无论目标，最终都调 RasterizeTri_Adaptive(Tri, NaniteWritePixel)。扫描器只负责"遍历三角覆盖的像素"，"命中一个像素做什么"由 functor NaniteWritePixel 决定——这是 C++ 模板 functor 在 HLSL 里的用法，把"扫描"与"写入策略"解耦。functor 内部调 EarlyDepthTest() + Write()，最终落到 NaniteWritePixel.ush ↗ 的 64 位原子 max。MaterialShader 承载材质的顶点部分，#8 可编程光栅的 WPO/位移就在这条路径上执行。

3. 发散：主视图 vs VSM 物理页

#if VIRTUAL_TEXTURE_TARGET && NANITE_LATE_VSM_PAGE_TRANSLATION
    TNaniteWritePixel< FMaterialShader, FCachedPageTable > NaniteWritePixel;  // VSM 页表
#else
    TNaniteWritePixel< FMaterialShader > NaniteWritePixel;                    // 主 VisBuffer
#endif

说明

唯一发散在写入 functor 的模板参数：主视图用 TNaniteWritePixel<FMaterialShader> 写 VisBuffer64；VSM 阴影（#9）用带 FCachedPageTable 的版本，把深度经页表翻译后写进物理页 array。扫描逻辑一行没变，只换 functor——这正是 functor 解耦的价值。PackVisPixelX 把可见簇索引 + 三角索引打进 payload。

最终总结

骨架

软/硬两路光栅 + 四种几何类型，全部汇聚到 RasterizeTri_Adaptive(Tri, functor)。扫描与写入用 functor 解耦：扫描遍历像素，functor 决定写哪、怎么写（主 VisBuffer / VSM 页 / 可视化）。

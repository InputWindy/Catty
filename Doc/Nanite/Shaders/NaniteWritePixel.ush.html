NaniteWritePixel.ush 汇聚/发散批注版

Nanite 光栅器写像素的底层原语：把 (可见簇+三角 id, 深度) 用 64 位原子 max 一次写进 visibility buffer——一条 atomic 同时完成深度测试 + 记录 id，无需独立 Z-buffer。软件光栅、硬件光栅、阴影趟、VSM 物理页写入全部汇聚到这一个原语，按目标（VisBuffer / DepthOnly / VSM array）发散。文件仅 110 行，下方内嵌完整真实源码。

一眼看懂：一个原语，四种目标

0. 输出目标（发散的根源）

RWTexture2D<uint>       OutDepthBuffer;        // DepthOnly 趟（阴影/预深度）
RWTexture2DArray<uint>  OutDepthBufferArray;   // VSM 物理页池（层=静/动/overdraw）
RWTexture2D<UlongType>  OutVisBuffer64;        // 主渲染 64 位可见性缓冲
RWTexture2D<UlongType>  OutDbgBuffer64/32;     // #if VISUALIZE 调试/overdraw

说明

同一份光栅代码要服务多种目标：主视图、阴影趟、VSM 物理页、可视化。目标不同 → 写入函数不同，这就是本文件所有发散的来源，全靠编译宏 DEPTH_ONLY / VIRTUAL_TEXTURE_TARGET / VISUALIZE 切分。

1. 汇聚点：64 位原子 max = 深度测试 + 写 id 一步到位

const UlongType Pixel = PackUlongType(uint2(PixelValue, DepthInt));
ImageInterlockedMaxUInt64(OutBuffer, PixelPos, Pixel);

说明

深度打在 64 位的高 32 位、payload（可见簇+三角 id）在低 32 位。一条 ImageInterlockedMaxUInt64 的原子 max：谁深度大（反向 Z 下=更近）谁胜出，且胜出者的 id 被一并写下——深度测试与"记录是谁"合成一次原子操作，不需要独立 Z-buffer + 单独写 id。这是 Nanite 软件光栅能高效并行的关键。不支持 64 位原子的平台直接 #error UNKNOWN_ATOMIC_PLATFORM（也是硬件光栅回退存在的原因之一）。

2. 发散：DepthOnly / VSM 用 32 位 InterlockedMax

#if VIRTUAL_TEXTURE_TARGET
    InterlockedMax( OutDepthBufferArray[ PhysicalPosition ], DepthInt );  // VSM 物理页
#elif DEPTH_ONLY
    InterlockedMax( OutDepthBuffer[ PixelPos ], DepthInt );               // 只写深度
#endif

说明

阴影/预深度趟与 VSM 只需要深度、不需要 id，用普通 32 位 InterlockedMax 即可。VSM 写的是物理页数组（OutDepthBufferArray[PhysicalPosition]，PhysicalPosition 由页表解析得到，见 Shadow #7）——这正是 Nanite 几何写进 VSM 物理页的落点，与 NaniteExportGBuffer.usf 里那条 InterlockedMax 同源。

3. EarlyDepthTest：光栅前的粗筛

bool EarlyDepthTest() {
  Depth = saturate(Depth); const uint DepthInt = asuint(Depth);
  return OutVisBuffer64[Position].y < DepthInt;  // 当前记录比我远 → 我可能可见
}

说明

写之前先读一次当前缓冲：若已记录的深度比本像素更近，本像素必被挡，直接跳过后续着色属性计算——这是省算力的早深度剔除。真正的胜出仍由 Write() 的原子 max 保证（EarlyDepthTest 只是非原子的乐观预筛，不保证正确性、只做加速）。WriteOverdraw() 则在 VISUALIZE 下累加 overdraw 计数（VSM 存在页池额外数组层 index=2）。

最终总结

骨架

一个原语 WritePixel + 一个结构 FVisBufferPixel，用 64 位原子 max 把"深度测试 + 记录可见簇/三角 id"合成一步。所有光栅路径都汇聚到它。

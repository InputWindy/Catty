NaniteShadeBinning.usf 汇聚/发散批注版

shade binning 的 GPU 实现：把每像素的材质槽（ShadingMask）按材质分箱成连续列表——一个 GPU 版计数排序。三趟 COUNT / RESERVE / SCATTER 共用同一个文件，靠 SHADING_BIN_PASS 宏切成三个变体（汇聚），各趟职责不同（发散）。说明：本文件完整 1181 行，含大量平台 CMask 写掩码优化 / VRS / VALIDATE / CMASK_CLEAR 分支；下方源码框内嵌三趟的核心内核（COUNT 的 AllocateElements/ShadingBinBuildCS 与 RESERVE 的 ShadingBinReserveCS），逐行真实、略去平台分支。

一眼看懂：三趟计数排序

输入ShadingMask（#6 每像素材质槽）
▶
① COUNT数每个 bin 覆盖多少像素（wave/group 前缀和 + InterlockedAdd）
▶
② RESERVE按计数为每 bin 分配连续范围 + 写每 bin 的 indirect dispatch args
▶
③ SCATTER把每像素落进其 bin 的连续区间
▶
输出按材质连续的像素列表 + ShadingDispatchArgs

0. 输入输出契约

Texture2D<uint> ShadingMask;                      // 输入：#6 每像素材质槽
RWByteAddressBuffer OutShadingBinData;             // 输出：meta + 按材质连续的像素列表
RWStructuredBuffer<...ScatterCounters> OutShadingBinScatterCounters; // 每 bin 计数器
RWStructuredBuffer<...ScatterRanges>   OutShadingBinScatterRanges;   // 每 bin 连续区间
RWBuffer OutShadingDispatchArgs;                   // 每 bin 的 indirect dispatch args
#define SHADING_BIN_PASS  → COUNT / RESERVE / SCATTER / VALIDATE / CMASK_CLEAR ...

说明

唯一实质输入是 #6 写的 ShadingMask（每像素一个 shading bin 号）。输出的 ShadingBinData + ShadingDispatchArgs 正是 CPU 侧 #7 拿去做逐材质 indirect dispatch 的依据。

1. 汇聚点：一个文件，三趟复用

#define SHADING_BIN_COUNT   (SHADING_BIN_PASS == NANITE_SHADING_BIN_COUNT)
#define SHADING_BIN_RESERVE (SHADING_BIN_PASS == NANITE_SHADING_BIN_RESERVE)
#define SHADING_BIN_SCATTER (SHADING_BIN_PASS == NANITE_SHADING_BIN_SCATTER)
#if SHADING_BIN_COUNT ... ShadingBinBuildCS
#elif SHADING_BIN_RESERVE ... ShadingBinReserveCS
#elif SHADING_BIN_SCATTER ... ShadingBinScatterCS

说明

共同点三趟是同一份 .usf 用 SHADING_BIN_PASS 宏编译出的三个 CS 变体，共享 GetShadingBinMeta、OutShadingBinScatterCounters 等符号——这与 CPU 侧 #7 "同一 FShadingBinBuildCS 三个 permutation" 完全对应。

不同点COUNT 只写计数器；RESERVE 定范围 + 写 dispatch args；SCATTER 落位像素。

2. COUNT：wave/group 前缀和 + 原子累加

WaveFullTileCount = WaveActiveCountBits(QuadFullTileCount != 0);  // wave 内计数
FullTileDataOffset = WavePrefixCountBits(...);                    // wave 内前缀偏移
if (WaveIsFirstLane())                                           // 每 wave 只一次原子
    InterlockedAdd(OutShadingBinScatterCounters[Bin].FullTileElementCount, WaveFullTileCount, ...);
// 多 wave 时先 group 内汇总（groupshared + GroupMemoryBarrierWithGroupSync）再一次原子

说明

关键优化：不是每个像素各做一次原子加（会把计数器挤爆），而是先在 wave 内用 WaveActiveCountBits/WavePrefixCountBits 归约，每个 wave 只对全局计数器做一次 InterlockedAdd；跨多 wave 的线程组再用 groupshared 汇总后只做一次。像素分两类：full tile（整块 tile 同材质，压缩存）与 loose（零散像素），分别计数。

3. RESERVE：定范围 + 生成 indirect args

InterlockedAdd(OutShadingBinAllocator[0], BinPixelCount, RangeStart);  // 全局连续分配
OutShadingBinScatterRanges[ShadingBin].RangeStart = RangeStart;
OutShadingBinScatterRanges[ShadingBin].RangeNum   = BinPixelCount;
Args.x = DivideAndRoundUp(BinPixelCount, COMPUTE_MATERIAL_GROUP_SIZE);  // 每 bin 的 group 数
OutShadingDispatchArgs.Store4(ShadingBin * 16u, Args);

说明

一个 bin 一个线程。用 COUNT 算出的计数，向全局分配器 OutShadingBinAllocator 原子申请一段连续区间（RangeStart/RangeNum），写进 meta；顺便生成该 bin 的 indirect dispatch 参数——ThreadGroupCountX = ceil(BinPixelCount / COMPUTE_MATERIAL_GROUP_SIZE)。#7 逐材质着色时就是 indirect 读这个 args，一个 bin 一次 dispatch。无导数材质走 loose 像素粒度、常规材质走 quad（×4 像素）粒度。

4. SCATTER：像素落位

说明

第三趟 SHADING_BIN_SCATTER 复用 BinShadingQuad 的遍历，但这次把每个像素/quad 写入 RESERVE 定好的 bin 区间里（用 OutShadingBinScatterCounters 作为区间内游标，原子自增取位）。三趟跑完，ShadingBinData 里就是一张按材质连续排列的像素列表——这正是经典 counting sort 的 count→reserve(prefix)→scatter 三步在 GPU 上的落地。

最终总结

骨架

一份 .usf、三趟（COUNT→RESERVE→SCATTER），就是 GPU 计数排序。核心工程点：用 wave/group 归约把海量像素的原子加压到"每 wave/每 group 一次"，避免计数器争用。

阅读建议

先看 #7 的 CPU 编排（AddPass 三次、只改 FBuildPassDim），再回到这里看每趟 GPU 侧做什么。full tile / loose 两类粒度是理解计数与落位的关键。

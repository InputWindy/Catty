NaniteTranscode.usf 整源解析

Nanite 的页转码（610 行）：把磁盘/流送格式的压缩簇页（顶点量化、索引位打包、属性 bitstream）在 GPU 上解码成运行时格式写入常驻集群页池——流送落地的最后一步。核心 TranscodeVertexAttributes + 主 CS @ L698。下方内嵌完整 610 行真实源码，再逐段真实代码批注。

CopyDwords @ L192 · TranscodeVertexAttributes @ L301 · 主 CS @ L698（GROUP_SIZE）

0. 解码顶点属性 bitstream（发散点）

groupshared uint GroupRefToVertex[NANITE_MAX_CLUSTER_VERTICES];
void TranscodeVertexAttributes(FPageDiskHeader PageDiskHeader, FClusterDiskHeader ClusterDiskHeader, FCluster Cluster, ...)
// 从位打包的属性流解出法线/UV/切线/颜色（每属性可变位宽）
void CopyDwords(RWByteAddressBuffer Dst, uint DstAddr, ByteAddressBuffer Src, uint SrcAddr, uint NumDwords)   // 定长直拷

说明

Nanite 磁盘格式为省空间做了极致压缩：顶点位置量化、属性（法线/UV/切线/颜色）用可变位宽 bitstream 打包、共享顶点用引用表（GroupRefToVertex）。TranscodeVertexAttributes 在 GPU 上把这些位流解码回运行时可直接寻址的格式。有些无需重排的数据用 CopyDwords 直拷。groupshared 表缓存引用/非引用顶点映射，组内并行解码。这是 流送把页搬进显存后、几何可用前的格式转换关键步——磁盘紧凑格式 ↔ GPU 运行时格式的桥。

1. 转码 CS 写入常驻页池（汇聚点）

[numthreads(GROUP_SIZE, 1, 1)] void TranscodePageToGPU(...)   // 每组转码一个簇/页
// 读 FPageDiskHeader/FClusterDiskHeader → 解码几何/属性
// 写入 ClusterPageData（常驻集群页池）对应偏移
// 之后剔除/光栅直接从页池读运行时格式簇

说明

本 shader 的汇聚点：主 CS 每线程组转码一个簇/页，读磁盘头解码几何 + 属性，写进常驻集群页池 ClusterPageData 的目标偏移。转码完成后，剔除与 光栅就能直接从页池按运行时格式读簇——无需再解压。这套"磁盘压缩格式 + GPU 转码 + 常驻页池"是 Nanite 能把海量几何数据（远超显存）按需流送的基础，配合 Streaming 的页请求/搬运。解码细节见 DataDecode。

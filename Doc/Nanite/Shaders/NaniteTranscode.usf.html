0. 为什么要 transcode

ByteAddressBuffer   SrcPageBuffer;   // 磁盘格式（紧凑位流）
RWByteAddressBuffer DstPageBuffer;   // GPU 运行时格式

说明

#3 编码把几何压成极致紧凑的磁盘位流（省磁盘/带宽），但 GPU 剔除/光栅需要能随机寻址的规整布局。#4 流送把压缩页搬进显存后，TranscodePageToGPU 做一次性 GPU 解码：SrcPageBuffer（磁盘格式）→ DstPageBuffer（运行时格式）。之后每帧剔除/光栅直接读 Dst，不再解码。这是"压缩存储、解码一次、多帧复用"。

1. 一组一簇：wave 级并行解码

const uint ClusterInstallIndex = StartClusterIndex + FlatGroupID;
if (GroupIndex >= WaveGetLaneCount()) return;  // 一个 wave 一个簇

说明

每个线程组（=一个 wave）负责一个簇，组内 lane 并行处理该簇的顶点/三角。StartClusterIndex + FlatGroupID 索引本批要装的簇（#4 决定装哪些）。FClusterInstallInfo 给出 Src/Dst 页偏移。raw copy（FPackedClusters/Material/DecodeInfo）每页只做一次，由该页的 cluster 0 承担。

2. 两趟：独立 vs 父依赖（发散点）

#if PASS == INDEPENDENT        TranscodePageIndependent(...)
#elif PASS == PARENT_DEPENDENT TranscodePageParentDependent(...)

说明

共同点两趟共用入口、共用 disk header 解析与顶点解码流程。

不同点Nanite 的 vertex ref 让一个簇的顶点可以引用另一个（可能在父页里的）簇的顶点去重。INDEPENDENT 趟解码不依赖其它页的簇（可立即完成）；PARENT_DEPENDENT 趟解码那些引用了父页顶点的簇，必须等父页先转好——所以分两趟 dispatch，保证依赖顺序。PageDependenciesBuffer 记录页间依赖。

3. 解包：vertex ref + strip 索引 + 位反量化

BuildRefTable(...)                    // 顶点引用去重表
UnpackStripIndices(...)               // strip → 三角索引
TranscodeVertexAttributes(...)        // 位反量化 pos/normal/UV/color

说明

三件解包：① BuildRefTable 展开顶点引用（同一顶点在簇/页间只存一份，此处还原）；② UnpackStripIndices 把三角带（strip）位流展开成 uint3 索引（BitsPerIndex 变长）；③ TranscodeVertexAttributes 按 DecodeInfo 对 position/normal/tangent/UV/color 做位级反量化（Low/Mid/HighBytes 三段分离存储以提升压缩率）。GroupMemoryBarrierWithGroupSync 保证 ref 表在解索引前建好。

最终总结

骨架

一组一簇：读 disk header → raw copy → 建顶点引用表 → 解 strip 索引 → 位反量化顶点属性 → 写 DstPageBuffer。按 vertex ref 是否跨页依赖分独立/父依赖两趟，保证依赖顺序。解码一次、多帧复用。

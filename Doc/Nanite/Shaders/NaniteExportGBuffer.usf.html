NaniteExportGBuffer.usf 汇聚/发散批注版

按“先看汇聚点，再看发散点”重排。这个 shader 是一组独立的全屏像素着色器入口：它们共享同一段"解包 VisBuffer64 → 写 SV_Depth"的汇聚骨架，各自把结果发散到不同导出目标（ShadingMask / Velocity / 自定义深度模板 / 阴影图深度 / 编辑器 HitProxy 与选中轮廓）。

一眼看懂：汇聚/发散骨架

共同入口每个 PS 取 PixelPos，Load VisBuffer64[PixelPos]。
解包汇聚UnpackVisPixel → DepthInt / VisibleClusterIndex / TriIndex。
覆盖判定VisibleClusterIndex==0xFFFFFFFF 则 discard。
入口发散7 个入口各自导出不同目标。
材质/编辑器发散ShadingMask、Velocity、HitProxy、Overlay。
深度汇聚几乎所有入口都 OutDepth = asfloat(DepthInt)。
写目标SV_Depth + 可选 SV_Target（RT）。

0. 固定输入输出契约

Texture2D<UlongType> VisBuffer64;              // 64 位可见性缓冲（#6 光栅产出）
Texture2D<uint>      ShadingMask;              // #if SHADING_MASK_LOAD
StructuredBuffer<FNaniteRasterBinMeta> RasterBinMeta;
Texture2D<float>  CustomDepth;                 // 自定义深度输入
Texture2D<uint2>  CustomStencil;               // 自定义模板输入
Texture2D<uint>   DepthBuffer;                 // EmitShadowMapPS 的深度源
int4 ViewRect;  uint MeshPassIndex;  ...
out float OutDepth : SV_Depth                  // 几乎所有入口都写深度
out uint OutShadingMask / out float4 OutVelocity / out uint2 OutStencil / out float4 OutHitProxyId / OutOverlay

说明

本 shader 的对外契约很稳定：读 64 位 VisBuffer64（外加各导出场景需要的辅助纹理），写 SV_Depth + 至多一两个 SV_Target。上游 #6 光栅只要把可见簇正确写进 VisBuffer64，本 shader 就能把它导出成引擎其余管线要的各种目标。

1. 汇聚点：共同解包骨架

const uint2 PixelPos = (uint2)SvPosition.xy;
const UlongType VisPixel = VisBuffer64[PixelPos];
uint DepthInt = 0, VisibleClusterIndex = 0, TriIndex = 0;
UnpackVisPixel(VisPixel, DepthInt, VisibleClusterIndex, TriIndex);
if (VisibleClusterIndex != 0xFFFFFFFF)   // 该像素有 Nanite 覆盖
    OutDepth = asfloat(DepthInt);        // 深度整数按位还原为 DeviceZ
else { OutDepth = 0.0f; discard; }       // 无覆盖：丢弃

说明

这段是全 shader 的最大公约数——上面的 MarkStencilPS 就是它的最小完整形态。VisBuffer64 高 32 位是深度整数、低 32 位是 payload（可见簇 id + 三角 id）；UnpackVisPixel 一次拆出三者。VisibleClusterIndex == 0xFFFFFFFF 是"无 Nanite 覆盖"的哨兵值，命中就 discard。

易误解：asfloat(DepthInt) 不是类型转换而是按位重解释——深度本就以 float 的位模式塞在整数里，光栅时用整数 InterlockedMax 才能做原子深度测试（反向 Z 下 max=最近）。

2. 发散点：7 个导出入口

入口额外输出发散点在哪
MarkStencilPS—无额外逻辑，纯汇聚骨架（打深度标记）
EmitSceneDepthPSShadingMask + Velocity主导出：算材质分箱掩码 + 运动矢量（见 3 / 4）
EmitSceneStencilPS—加一层"仅 decal 接收者"的门（读 ShadingMask）
EmitCustomDepthStencilPSStencil与场景自定义深度按更近者合并（见 5）
EmitShadowMapPS—深度改走阴影投影公式（见 6）
EmitHitProxyIdPSHitProxyId编辑器拾取 id（见 7）
EmitEditorSelectionDepthPSOverlay编辑器选中轮廓 / 叠加色（见 7）

说明

共同点7 个入口都从 第 1 节的解包骨架出发，最终（除 discard 外）都写 OutDepth = asfloat(DepthInt)。

不同点发散只发生在"额外导出什么"上——用 preprocessor 宏（SHADING_MASK_EXPORT / VELOCITY_EXPORT / WRITE_CUSTOM_STENCIL / DEPTH_OUTPUT_TYPE / USE_EDITOR_SHADERS / EMIT_OVERLAY）在编译期裁出每个变体，避免运行时分支。

3. EmitSceneDepthPS · ShadingMask 导出（主）

const uint ShadingBin = GetMaterialShadingBin(Cluster, PrimitiveId, MeshPassIndex, TriIndex);
const bool bIsDecalReceiver = (Flags & ..._DECAL_RECEIVER) != 0 && View.ShowDecalsMask > 0;
const bool bCastShadow      = (Flags & ..._CAST_SHADOWS) != 0;
OutShadingMask = PackShadingMask(
    ShadingBin, D3D12_SHADING_RATE_1X1,
    bIsDecalReceiver, bHasRayTracingRepresentation, bCastShadow,
    GetPrimitive_LightingChannelMask_FromFlags(Flags));

说明

这是本 shader 最重要的产出。GetMaterialShadingBin 反查该像素三角所属材质的着色分箱号，连同 decal 接收 / 光追表示 / 投影 / 光照通道等标志位打包成一个 uint。

这张 OutShadingMask 正是 #7 shade binning 的输入——后续 count/reserve/scatter 三趟按 ShadingBin 把同材质像素聚到一起，实现"每材质每像素只算一次"的延迟着色。

4. EmitSceneDepthPS · Velocity 导出

bool bWPOEnabled = (VisibleCluster.Flags & NANITE_CULLING_FLAG_ENABLE_WPO) != 0;
if (bWPOEnabled) {
    FNaniteMaterialFlags MaterialFlags = ...;
    GetMaterialRasterBinAndFlags(..., MaterialFlags);   // 查材质真是否开 WPO
    bWPOEnabled &= MaterialFlags.bWorldPositionOffset;
}
OutVelocity = CalculateNaniteVelocity(NaniteView, InstanceData, Cluster, VisibleCluster,
    float4(SvPosition.xy, asfloat(DepthInt), 1.0f), TriIndex, Flags, bWPOEnabled);

说明

运动矢量用于 TSR 等时序算法。这里算的是固定函数速度（相机/物体刚体运动）。

易误解：开了 WPO 的簇不在这里输出速度——WPO（世界位置偏移，如风吹草动）会让顶点位置随材质变化，其速度必须在 base pass 里按材质算。所以这段先探测材质是否真开 WPO，是则把 bWPOEnabled 传给 CalculateNaniteVelocity，让它在 base pass 覆盖。

5. EmitCustomDepthStencilPS · 更近者胜出合并

float SceneDepth = CustomDepth[PixelPos];              // 场景已有自定义深度
uint SceneStencil = CustomStencil[PixelPos] STENCIL_COMPONENT_SWIZZLE;
const float NaniteDepth = asfloat(DepthInt);
if (InRect && VisibleClusterIndex != 0xFFFFFFFF && NaniteDepth > SceneDepth) {
    OutDepth = NaniteDepth;                            // Nanite 更近 → 用 Nanite
    OutStencil = GetCustomStencilValue(PrimitiveData); // 写该图元自定义模板
} else {
    OutDepth = SceneDepth;  OutStencil = SceneStencil; // 否则原样透传
}

说明

自定义深度/模板要把 Nanite 几何和非 Nanite 几何合并到一张缓冲。判据是 NaniteDepth > SceneDepth——反向 Z 下越大越近，Nanite 更近就覆盖，否则透传场景值。GetCustomStencilValue（源码 L33）从 CustomStencilValueAndMask 高 8 位取 mask、与 value 相与得到最终模板值。

6. EmitShadowMapPS · 深度重映射到阴影投影

uint DepthInt = DepthBuffer[PixelPos];  if (DepthInt == 0) discard;
float DeviceZ = asfloat(DepthInt);
#if DEPTH_OUTPUT_TYPE == 0   // 标准深度
    OutDepth = DeviceZ;
#elif DEPTH_OUTPUT_TYPE == 1 // 正交阴影图
    OutDepth = 1 - DeviceZ + DepthBias;
#else                        // 透视阴影图
    OutDepth = ViewToClip22 * (DeviceZ - 1) / (DeviceZ - ViewToClip22) + DepthBias;
#endif

说明

这是 Nanite 深度进传统阴影图的接入点（见 #9 阴影集成）。三种 DEPTH_OUTPUT_TYPE 对应不同投影：标准直写、正交用线性翻转、透视用 ViewToClip22 做非线性重映射。DepthBias 抵抗阴影痤疮。注意它的深度源是单独的 DepthBuffer（阴影趟的整数深度），不是 VisBuffer64。

7. 编辑器入口：HitProxy 与选中轮廓

#if USE_EDITOR_SHADERS   // 非编辑器构建整体 discard
// EmitHitProxyIdPS：拾取 id
if ((InstanceData.Flags & ..._HAS_EDITOR_DATA) != 0u)
    OutHitProxyId = float4(InstanceData.EditorData.HitProxyId, 0);
else
    OutHitProxyId = UnpackHitProxyId(GetMaterialHitProxyId(Cluster, ...));
// EmitEditorSelectionDepthPS：选中轮廓 + 叠加色
#if ONLY_SELECTED  if (!IsInstanceSelected(...)) discard;  #endif
#if EMIT_OVERLAY   OutOverlay = LoadNaniteMaterialOverlayColor(PrimitiveId);  #endif
#endif

说明

这两个入口只在编辑器构建（USE_EDITOR_SHADERS）里有实体，运行时构建整体 discard。EmitHitProxyIdPS 导出鼠标拾取 id（优先用实例自带、否则查材质表）；EmitEditorSelectionDepthPS 为选中轮廓/关卡实例可视化写深度，可选只导出选中项、可选叠加色。OutputToInputScale/Bias 支持输出与输入分辨率不一致。

最终总结

骨架

外壳极稳定：读 VisBuffer64 → 解包 → 判覆盖 → 写 SV_Depth。这条链是所有入口的公共骨架。

复杂度全在发散区：导出什么额外目标（ShadingMask/Velocity/Stencil/HitProxy/Overlay），以及深度用什么公式（标准/正交/透视阴影）。发散靠编译期宏切变体，不是运行时分支。

阅读建议

先记住一个汇聚点：UnpackVisPixel → asfloat(DepthInt) → SV_Depth。再把 7 个入口理解成"在这条骨架上各挂一个导出目标"。想写自己的 Nanite 导出 pass，照 MarkStencilPS 这个最小形态起步最省事。

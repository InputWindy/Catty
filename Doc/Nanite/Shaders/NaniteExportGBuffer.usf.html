0. 从 Visbuffer 解出场景深度/模板（发散点）

void EmitSceneDepthPS(...)   // 从 VisBuffer64 高 32 位解出深度 → 写场景深度
void EmitSceneStencilPS(...)   // 写模板：标记 Nanite 覆盖像素
void MarkStencilPS(...)   // 用模板标出 Nanite 区域，供后续 pass 分流

说明

Nanite 的可见性存在 VisBuffer64（深度高位 + 簇/三角 ID 低位），而引擎延迟管线需要标准场景深度 + 模板。EmitSceneDepthPS 从 Visbuffer 解出深度写进场景深度缓冲；EmitSceneStencilPS/MarkStencilPS 在模板里标出 Nanite 覆盖的像素——这样非 Nanite 几何、后处理、光照等都能像对待普通几何一样处理 Nanite 区域（如用模板跳过/仅处理 Nanite 像素）。这是 Nanite 融入引擎标准延迟管线的接口层。

1. 材质着色写 GBuffer（汇聚点）

// 配合 ShadeBinning：逐材质 bin 读 Visbuffer 可见三角
// 从簇页取顶点属性 → 重心插值出该像素的材质输入
// 求值材质 → 写 BaseColor/Normal/Roughness/Metallic 到 GBuffer

说明

本 shader 的汇聚点与 ShadeBinning 配合完成延迟材质：分箱后每 bin 一次派发对应材质 shader，读 Visbuffer 得该像素可见的簇/三角，从簇页取三顶点属性（AttributeDecode）按重心插值出材质输入，求值材质图，把 BaseColor/Normal/Roughness 等写进标准 GBuffer。至此 Nanite 几何完全等价于普通延迟几何，后续光照/Lumen/阴影一视同仁。深度/模板导出 + 材质着色写 GBuffer，共同构成 Nanite 与延迟管线的完整桥接。

一、要解决什么 The problem

上千万微小三角形 × 成百上千材质，传统着色两头堵

Nanite 一帧可能有上千万个微小三角形、成百上千种材质。若沿用传统光栅"画每个三角形时顺便执行它的材质着色器"，有两个致命问题：

① 小三角形的 quad 浪费——GPU 以 2×2 quad 为单位着色，一个只覆盖几个像素的三角形会浪费大半 quad 算力（光栅阶段已解决光栅本身的浪费，但"边光栅边着色"会让着色继续浪费）。

② 材质着色器频繁切换——相邻像素可能属于不同材质，GPU 无法把同材质的着色批处理，状态切换与分支发散拖垮性能。

一句话："可见性"和"着色"耦合在一起时，几何复杂度会直接转嫁成着色开销。这正是本章要拆开的。

二、怎么解决的 How · 延迟材质 + shade binning

Nanite 的答案是彻底延迟材质：光栅阶段只把"每像素是哪个簇/三角形"写进 VisBuffer64，完全不着色；着色阶段再按材质把像素分箱，同材质像素凑成连续列表、一次 dispatch 批量着色。分箱靠一个 GPU 版计数排序（三趟）：

1COUNTNANITE_SHADING_BIN_COUNT：统计每个材质 bin 覆盖多少像素
▶
2RESERVENANITE_SHADING_BIN_RESERVE：按计数为每个 bin 在输出里预留连续范围
▶
3SCATTERNANITE_SHADING_BIN_SCATTER：把每个像素散布进它所属 bin 的列表

批注 ①：为什么按像素数预算，而不是按三角形数

NumBytes_Data = PixelCount * 8——分箱数据的规模只与屏幕像素数有关，与三角形数量无关。这是延迟材质省的根本：无论一个像素背后压了 1 个还是 100 个三角形，只有最近那个进了 VisBuffer64，分箱只处理它一次。

批注 ②：三趟复用同一个 CS

三趟不是三个 shader，而是同一个 FShadingBinBuildCS 靠 permutation（FBuildPassDim = COUNT / RESERVE / SCATTER）编译出的三个变体。CPU 侧就是把上面这段 AddPass 复制三次、只改这一个宏。真正的计数排序逻辑在 GPU shader NaniteShadeBinning.usf ↗ 里，本文档只讲 CPU 怎么编排它。

批注 ③：这就是 GPU 版计数排序

COUNT 数每桶多少 → RESERVE 定每桶起点 → SCATTER 各归各位，正是经典 counting sort。产物是一张按材质连续排列的像素列表 + 每个 bin 的间接派发参数 ShadingDispatchArgs。FNaniteShadingBinMeta 记录每 bin 的偏移与数量（详见 函数附录）。

批注 ④：分箱之后——逐材质 dispatch

拿到按材质连续的像素列表后，对每个 shading bin 发一次 indirect compute dispatch（用 ShadingDispatchArgs），一个 dispatch 只碰同材质的像素：解 visibility → 重建属性 → 执行该材质的着色器 → 写 G-Buffer（NaniteExportGBuffer.usf ↗ 的 G-Buffer 导出路径）。同一 dispatch 内共用一个材质 shader，无分支发散、无状态切换。CPU 侧的 BuildShadingCommands()（NaniteShading.cpp L654）预先准备好每材质命令。

三、解决了什么 The result

着色成本与几何复杂度彻底解耦

延迟材质 + shade binning 的净效果：着色成本 ≈ 屏幕像素数 × 材质数，与三角形数量无关。你可以往场景里堆任意多三角形，着色开销恒定在"分辨率 × 材质"这个量级。

对照第一节的两个问题：① quad 浪费没了——分箱后每个 dispatch 处理的是紧凑的同材质像素列表，不再有稀疏小三角形的空 quad；② 材质切换没了——每材质一次 dispatch，GPU 完美批处理。可见性（光栅阶段解一次）与着色（本章按材质批处理）就此拆开，这正是 Nanite "几何复杂度不再是瓶颈"总目标在着色侧的落地。

小结 Summary

记住这几点

1要解决：小三角形 + 多材质下，"边光栅边着色"会 quad 浪费 + 材质频繁切换——几何复杂度转嫁成着色开销。

2怎么解决：延迟材质——光栅只写 VisBuffer64；着色阶段用 shade binning 三趟（COUNT→RESERVE→SCATTER，同一 FShadingBinBuildCS 三个 permutation）做 GPU 计数排序，得到按材质连续的像素列表。

3怎么解决：再对每个材质发一次 indirect dispatch，共用同一材质 shader 批量着色写 G-Buffer（NaniteExportGBuffer.usf ↗）。

4解决了：着色成本 = 屏幕像素 × 材质数，与三角形数无关；可见性与着色彻底解耦。

本附录汇总可编程光栅、曲面细分工作队列、预计算细分表与重心坐标编码的核心符号。取自 UE5.8 本地源码 NaniteSplit.usf、NaniteTessellation.ush、TessellationTable.cpp/.h。

可编程光栅入口 NaniteRasterizer / FMicropolyRasterizeCS

符号说明
FMicropolyRasterizeCS软件光栅 compute，本身是 Material shader，可执行材质的 WPO/PDO
NANITE_CULLING_FLAG_ENABLE_WPO (1<<3)簇级标志：本簇启用 World Position Offset
NANITE_CULLING_FLAG_FALLBACK_RASTER (1<<4)回退到固定光栅路径（不跑可编程）
FConfiguration::bDisableProgrammable全局关闭可编程光栅（纯几何走更快固定路径）
NANITE_TESSELLATION / PIXELPROGRAMMABLE 宏shader permutation 开关：是否编译细分/像素可编程分支

WPO / PDO / 细分的分工

WPO 在顶点阶段推动世界位置；PDO 在像素阶段改深度；细分（Tessellation）在光栅前把 patch 切成微三角并沿法线位移。三者都源自同一份材质图的不同输出引脚，只在需要的 permutation 里编译。

FTessellatedPatch NaniteTessellation.ush

struct FTessellatedPatch { uint Pattern_NumVerts_NumTris; // 三字段打包进一个 uint // ...重心坐标等 }; uint GetPattern() { return Pattern_NumVerts_NumTris & 0x1FFFu; } // 低 13 位 uint GetNumVerts() { return (Pattern_NumVerts_NumTris >> 13) & 0x1FFu; } // 中 9 位 uint GetNumTris() { return Pattern_NumVerts_NumTris >> 22; } // 高 10 位

一个 uint 就编码了图案索引（≤816，13 位）、顶点数（9 位）、三角数（10 位），极致压缩。

为什么要 SnapAtEdges

相邻 patch 若各自独立细分，共享边上的顶点可能不重合 → 出现裂缝（cracks）。细分表在构建时把边上顶点吸附到由边 TessFactor 唯一决定的位置，保证接缝两侧顶点一一对应。

重心坐标编码 NaniteTessellation.ush

static const uint BarycentricMax = (1 << 15); // 必须是 2 的幂 uint EncodeBarycentrics( float3 Barycentrics ){ Barycentrics = round( Barycentrics * BarycentricMax ); // 只存 y、z 两个 16 位分量；x = Max - y - z 可反解 return (uint)Barycentrics.y | ((uint)Barycentrics.z << 16); } float3 DecodeBarycentrics( uint Encoded ){ Barycentrics.x/.y = float(Encoded & 0xffff or >>16) / BarycentricMax; // 第三个分量由 1 减出 }

15 位精度（BarycentricMax = 1<<15），两个分量塞进一个 32 位 uint。细分顶点不存新的位置/属性数据，只存"它在原 patch 三角里的重心位置"，运行时插值原顶点属性即可。

位移包围盒 NaniteSplit.usf

// [Nießner & Loop 2021] 法线锥 + 位移范围 → 保守包围盒 DisplaceBounds( ConeCenter, ConeCos, // 法线锥（轴向 + 半角余弦） DisplacementMin, DisplacementMax, // 位移贴图在该 patch 的取值范围 inout BoundsMin, BoundsMax ); // 被保守放大的包围盒

作用

位移沿法线把顶点推出原包围盒。DisplaceBounds 用法线锥圈定所有可能的位移方向、乘上位移幅度范围，得到一个刚好包住位移后几何的保守放大包围盒，回喂 #5 剔除——既不漏画（不把被推出的部分错误剔除），又不过度放大（保持剔除有效）。

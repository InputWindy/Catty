#2 Cluster 构建与 LOD DAG · 离线构建的核心算法

进入离线构建。本篇讲清 Nanite 最精巧的一步：如何把一张任意三角网格切成簇（cluster），再自底向上分组 → 简化 → 再切分，构成一棵 LOD 有向无环图（DAG），使运行时能沿 DAG 做无缝、像素级的 LOD 选择。所有符号取自 UE5.8 本地源码 NaniteBuilder/Private/Cluster.cpp、ClusterDAG.cpp、GraphPartitioner.cpp。

第一步：把网格切成簇 Graph partition into clusters

构建从 FClusterDAG::AddMesh 开始。切簇不是随便切，而是用图分割：把三角形当作图的节点、相邻（共享边）关系当作边，用 METIS 库做多路划分，目标是让每个划分（=一个簇）约 128 个三角形，且簇内三角形空间上尽量聚在一起、切割边界尽量短（边界短 = 跨簇共享顶点少 = 后续剔除/简化更干净）。

FGraphPartitioner：METIS + 空间局部性

核心类 FGraphPartitioner（构造参数 MinPartitionSize / MaxPartitionSize）先给每个元素算 Morton 码（3D 空间填充曲线，见源码 BuildLocalityLinks）做基数排序，让空间相邻的元素在数组里也相邻；再用 disjoint set 找连通岛、为邻近但不连通的元素补"locality links"（每元素最多 5 条）。这样喂给 METIS 的图既含真实拓扑邻接、也含空间邻近，划分出的簇更紧凑。PartitionStrict 严格控制每块大小落在 [Min, Max] 内。

核心循环：分组 → 简化 → 再切分 The DAG build loop

切出最细一级（LOD0）的簇后，Nanite 反复做下面这套动作，每轮生成更粗的一级，直到只剩一个根：

1分组 Group把相邻簇 8~32 个一组
GroupTriangleClusters
2合并+简化 Simplify组内三角合并成一个网格
SimplifyTriangles 减到约一半
3再切分 Split简化后的网格重新切成
≤128 三角的新簇（父簇）
4记录误差 + 连边ParentLODError 单调递增
父簇 ← 子簇组，构成 DAG

为什么是"组"而不是"单簇"简化

关键设计：简化的单位是一组相邻簇（MinGroupSize=8 ~ MaxGroupSize=32）合并后的网格，而不是单个簇。因为若逐簇简化，簇边界的顶点无法被移除（会撕裂），LOD 越粗边界越僵。把一组簇先合并再简化，组内部的边界就能一起优化掉，只有组与组之间的边界保留——这让粗 LOD 也能均匀减面。简化用 FCluster::SimplifyTriangles(TargetNumTris, TargetError)（基于二次误差度量的边折叠），目标三角数约为输入的一半（GetMaxParents ≈ 元素数 / (MaxClusterSize×2)）。简化后再 Split 切回 ≤128 的簇。

为什么是 DAG，不是树 DAG, not a tree

分组的重叠造就 DAG

如果每轮分组是固定的、互不重叠的，得到的是一棵树——但树有个致命问题：树的边界会在所有 LOD 层持续存在，形成永久裂缝。Nanite 的诀窍是每一级重新分组：这一级的分组边界，到下一级会落在组内部被简化掉。于是一个子簇可能被不同父簇的构建路径影响，形成有向无环图（DAG）而非树。FClusterGroup 记录一组子簇（Children: TArray<FClusterRef>）与该组的 LODBounds / ParentLODError；FCluster::GroupIndex 记录簇属于哪个 group。这种"层层错位重组"消除了裂缝，是 Nanite 无缝 LOD 的算法根基。

运行时如何用这棵 DAG：Cut（切割） The cut

DAG 建好后，每个簇都带一个 LODError（本簇的简化误差）和一个 ParentLODError（其父级的误差，恒 ≥ 本簇误差）。运行时不需要"选一个 LOD 档"，而是在 DAG 上找一条切割线（cut）：

Cut 的判据（单调误差保证）

对每个簇，运行时把它的 LOD 误差投影到屏幕。规则是：如果本簇的误差在屏幕上够小（可接受）、但它父级的误差太大（不可接受），就选中本簇。形式化即 ParentError > Threshold ≥ ClusterError。因为误差沿 DAG 向上单调递增，这条判据在整个 DAG 上恰好切出一条连续的、不重不漏的边界——被选中的簇集合正好平铺覆盖整个物体表面，且每个簇的精度都刚好匹配它在屏幕上的大小。构建期的 FClusterDAG::FindCut(SelectedClusters, SelectedGroups, TargetNumTris, TargetError, TargetOvershoot) 是这套 cut 逻辑的离线版（用于生成 fallback / 光追网格）；运行时版在 GPU 层级遍历里做（见 #6）。

这就是"像素级 LOD"的真相

没有 popping，是因为相邻簇的误差连续、cut 只在误差跨过阈值处移动一个簇；不受源模型面数影响，是因为 cut 选中的簇数只取决于物体在屏幕上的投影大小，而非源三角总数——远处物体的 cut 落在 DAG 高层（少量粗簇），近处落在底层（大量细簇）。

与本书其它篇的关系 Cross-topic

DAG 是全书的地基

共同点：本篇产出的 FCluster / FClusterGroup 会在 #3 被编码成 FPackedCluster 与页；LOD 误差字段（LODError / ParentLODError）会原样带到 GPU，供 #6 运行时算 cut。

不同点：本篇是纯 CPU 离线算法（图分割 + 边折叠简化），跑在编辑器/DDC；运行时（#5#6）只是"读"这棵 DAG 做遍历与判据，不再改动几何。

不同点：与传统 LOD 的离散档位不同，DAG 是连续可切的层级——这是 Nanite 相对传统 LODGroup 的本质区别。

本篇小结 Summary

记住这几点

1. 切簇用图分割（METIS + Morton 空间局部性），每簇约 128 三角形，边界尽量短。核心类 FGraphPartitioner。

2. DAG 构建循环：分组（8~32 簇）→ 合并简化到约一半 → 再切分成父簇 → 记录单调递增的 ParentLODError，逐级变粗直到根。

3. 每级重新分组让边界错位、被上层简化掉——这造就了 DAG（而非树），消除 LOD 裂缝。

4. 运行时在 DAG 上找 cut：ParentError > Threshold ≥ ClusterError，误差单调保证切出连续无缝的簇集，实现像素级、与源面数无关的 LOD。

#10 Nanite 光线追踪 · 压缩几何如何进入 BVH

下篇专项第三站：Nanite 的几何是压缩 + 流送的页数据，而光线追踪需要一棵建立在真实三角形上的加速结构（BVH/BLAS）——两者天然冲突。本篇讲清 Nanite RT 的三种模式（Fallback / StreamOut / CLAS）、簇流出建 BLAS 的过程、以及为何要有 BLAS 缓存。符号取自 UE5.8 NaniteRayTracing.cpp/.h、NaniteRayTracingASCache.cpp、NaniteInterface.h。

核心冲突：光栅化几何 vs 光追几何 The conflict

BVH 要真实三角形，Nanite 只有压缩页

光线追踪要对场景建BVH：底层 BLAS（每个网格一棵，建在它的三角形上）+ 顶层 TLAS（实例级）。但 Nanite 几何是 #3 编码后的压缩页，还按视角动态流送（#4）、按屏幕误差连续选 LOD（#5）——它根本没有一份现成的、稳定的三角形网格可以直接建 BVH。而且 Nanite 网格动辄百万三角，全量建 BLAS 显存与构建时间都撑不住。这就是 Nanite 光追要解决的根本矛盾。

三种模式 ERayTracingMode

模式值做法取舍
Fallback0用一份离线烘焙的低模代理网格（fallback mesh）建 BLAS最省，但光追结果与 Nanite 高模不完全一致
StreamOut1运行时把选中 LOD 的簇流出为三角网格，再建标准 BLAS与可见几何一致，需 compute 流出 + BLAS 构建
CLAS2用新硬件的 Cluster-Level Acceleration Structure，直接以簇为单位建/更新 AS最贴合 Nanite 簇模型，需 GPU 支持 CLAS

为什么需要三档

GetRayTracingMode() 按硬件能力与项目设置选档。老硬件无法高效重建 BLAS → 用 Fallback 代理；主流硬件 → StreamOut 把 Nanite 簇转成三角形再建 BLAS；最新硬件支持 CLAS → 以簇粒度直接构建，最贴近 Nanite 的数据模型。CheckModeChanged() 检测模式切换以重建资源。

StreamOut：把簇变回三角网格 Cluster stream-out

FRayTracingManager 管理"哪些 Nanite 图元需要光追几何"，并在页流送变化时更新对应 BLAS：

1收集可见图元AddVisiblePrimitive：本帧光追需要的 Nanite 图元
▶
2请求更新RequestUpdates：结合已装/卸载页，决定要重建哪些资源的 BLAS
▶
3StreamOutClusterscompute 把选中 LOD 的簇解码成 Vertex/Index buffer（FClusterStreamOutBuffers）
▶
4ProcessBuildRequests用流出的三角网格构建 BLAS；TLAS 引用它

选一个"够用"的 LOD 建 BVH

光追不需要屏幕像素级的 LOD（次级光线对几何精度不敏感），所以 StreamOut 选一个相对粗但足够的 LOD 切面，把那层的簇解码成三角形（ClusterVertexBuffer/ClusterIndexBuffer），既能反射/GI 出正确轮廓，又把 BLAS 规模压到可接受。AuxiliaryDataBuffer 存材质/段映射，供命中着色器取属性。

BLAS 缓存：不重复建 BLAS cache

构建 BLAS 很贵，必须缓存复用

BLAS 构建是光追里最贵的操作之一。NaniteRayTracingASCache 把已建好的 BLAS 缓存起来：只有当该资源的相关页发生流入/流出（几何精度变了）或首次可见时，才重新流出 + 重建 BLAS；否则直接复用。这与 #9 VSM 的页缓存是同一种"增量更新"哲学——都建立在 #4 的页装/卸载事件之上。ResizeBLASCacheIfNeeded 按预算管理缓存容量。

与本书其它篇的关系 Cross-topic

光追是"把 Nanite 几何导出给另一套管线"

共同点：三种模式都依赖 #4 的页装/卸载事件（RequestUpdates(..., InstalledPages, UninstalledPages)）驱动 BLAS 增量更新；StreamOut 解码簇复用 #3 的页格式。

不同点：光栅管线（#5-#7）是 Nanite 自有的可见性求解；光追是把 Nanite 几何导出成标准 BVH 交给硬件 RT/Lumen HWRT 使用——Nanite 在这里是几何提供方而非消费方。

不同点：光栅按屏幕误差连续选 LOD 追求像素精度；光追选一个够用的固定 LOD 切面建 BVH，牺牲精度换 BLAS 规模与构建成本。

本篇小结 Summary

记住这几点

1. 核心冲突：光追要真实三角形建 BVH，Nanite 只有压缩流送的页 + 连续 LOD，没有现成稳定网格。

2. 三种模式：Fallback（低模代理）/ StreamOut（簇流出为三角网格再建 BLAS）/ CLAS（硬件簇级加速结构），按硬件能力选档。

3. StreamOut 流程：收集可见图元 → RequestUpdates → StreamOutClusters 解码簇成 V/I buffer → ProcessBuildRequests 建 BLAS，选够用 LOD 压规模。

4. BLAS 缓存：NaniteRayTracingASCache 按页装/卸载事件增量重建，与 VSM 页缓存同源，避免重复建 BVH。

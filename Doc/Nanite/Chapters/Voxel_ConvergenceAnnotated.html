为什么需要体素表示 Why voxels

三角形不总是最优的几何表示

Nanite 的三角形簇擅长表现近距离、可见、需要精细轮廓的几何。但有些场景三角形并不划算：超远距离（一个物体只占几像素，还维护完整簇 DAG 太重）、次级光线/GI（不需要精确轮廓，只要大致的占用与法线）、厚度/遮挡估计。这时把几何离散成空间体素——规则的三维格子，每个格子标记"这里有没有几何"——反而更省更快。这是 Nanite 一个较新的实验性方向。

如何体素化：从深度到格子 Voxelization

AutoVoxel.usf 的核心是把屏幕像素的深度反投影成世界位置，再量化到体素格子，并按距离选层级（内建 LOD）：

// DepthToVoxel：深度 → 世界位置 → 体素坐标 + 层级 float3 VoxelPos = TranslatedWorldPosition / VoxelSize; // 距离越远，体素越大（log2 分级，等价体素版 LOD） float Level = log2( Distance * DistanceFactor ); Level = floor( max( Level, 0 ) ); VoxelPos = floor( VoxelPos * exp2( -Level ) ); return int4( VoxelPos, Level );

体素按 4×4×4 的 block 用位掩码存

AddVoxelToBlock 把一个 block 内 4×4×4 = 64 个体素的占用状态存成 64 位掩码（两个 uint32），用 InterlockedOr 原子置位：VoxelIndex = x + y*4 + z*16。这种稀疏体素 + 位掩码的组织和 SVO（稀疏体素八叉树）思想一致——只有真正有几何的格子才占存储，空区域不花代价。层级（Level）就是八叉树的深度。

Brick 光栅：把体素画出来 Rasterize bricks

体素以 brick（一小块体素集合）为单位组织与绘制。DrawVisibleBricks（Voxel.h）驱动 RasterizeBricks.usf 把可见 brick 光栅进深度/可见性：

1TileBricks按屏幕 tile 组织 brick，粗粒度剔除
▶
2ScatterBricks把 brick 散布到各自覆盖的 tile 列表
▶
3RasterizeBricksDrawBricksVS + 保守深度写，输出到 buffer

复用 Nanite 的一贯套路

注意这套 Tile → Scatter → Rasterize 与主管线的 剔除 → 分箱 → 光栅（#6）、着色的 count → reserve → scatter（#7）是同一种"GPU 分桶 + 间接派发"范式。FBrick/BrickBuffer 存 brick 数据，SV_DepthLessEqual 做保守深度输出。

可视化调试：看清 Nanite 在做什么 Visualization

Nanite 的一切都在 GPU 上、以海量微三角运行，肉眼无法直接判断对错。NaniteVisualize.cpp 提供一整套可视化模式（AddVisualizationPasses / RenderDebugViewMode），是调试与性能分析的核心工具：

可视化 / 调试视图看什么
Clusters / Triangles簇 / 三角形边界（几何密度、LOD 选择是否合理）
Overdraw同像素被光栅多少次（软/硬光栅热点）
Shading Bins（值 11u）材质分箱分布（#7 着色成本）
EDebugViewMode::Wireframe线框
ShaderComplexity / LWCComplexity着色器复杂度 / 大世界坐标复杂度
StreamingDeficit流送欠账（#4 页不够用，几何降级）
PrimitiveColor / LightmapDensity图元着色 / 光照图密度

StreamingDeficit 是流送健康度仪表盘

StreamingDeficit 直接对应 #4：当页池预算不足、请求的高精度页来不及流入时，几何被迫停在较粗 LOD，这个视图把"欠账"区域高亮出来，指导调大池预算或优化资源。

与本书其它篇的关系 · 全书收官 Cross-topic & finale

体素是 Nanite 虚拟化几何思想的延伸

共同点：体素化的按距离分级（log2 Level）与主管线的连续 LOD（#5）同源；稀疏 + 位掩码与页/簇的稀疏组织一脉相承；brick 光栅复用 GPU 分桶范式（#6/#7）。

不同点：三角形表示精确轮廓、供主视图着色（#7）；体素表示占用/法线的粗略场，供超远距离与次级光线——是"够用就好"的另一档几何 LOD。

共同点：可视化工具（本篇）是理解前面所有篇（#1-#10）的窗口——clusters 看 #2、overdraw 看 #6、shading bins 看 #7、streaming deficit 看 #4。

本篇小结 Summary

记住这几点

1. 为何体素：超远距离/次级光线/遮挡估计等场景三角形不划算，改用体素（规则空间格子标记占用）更省更快。

2. 体素化：DepthToVoxel 深度反投影量化到格子，按 log2 距离选 Level（内建体素 LOD）；4×4×4=64 体素/block 用 64 位掩码 + InterlockedOr 稀疏存（SVO 思想）。

3. Brick 光栅：TileBricks → ScatterBricks → RasterizeBricks，复用 GPU 分桶 + 间接派发范式，保守深度输出。

4. 可视化调试：EDebugViewMode + 可视化模式（clusters/triangles/overdraw/shading bins/streaming deficit）是理解与调优 Nanite 全管线的核心工具。

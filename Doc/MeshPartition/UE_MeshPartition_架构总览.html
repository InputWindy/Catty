UE5.8 Mesh Partition / Mesh Terrain · 架构总览

UE5.8 新增的大规模网格创作系统——用网格（而非高度图 Landscape）做地形/大世界几何，走「空间分区 + 非破坏性 modifier 编辑 + 平台自适应运行时表示」的管线。本篇是架构总览（非逐函数深挖）：讲清它是什么、三层结构、关键类、与 World Partition / Nanite 的关系。所有类名、路径、常量均取自 UE5.8 本地源码。

⚠ 实验性特性提醒（写作时点：UE5.8）

这是两个 Experimental 插件，默认不启用（EnabledByDefault=false / IsExperimentalVersion=true），运行时模块 MeshPartitionCompute 目前近乎空壳。API 与数据格式在转正前会大改，本篇只做架构定位，不做逐函数解析——等它转 Beta/正式再深挖。

和 Landscape 的关系

传统 Landscape 是高度图（heightmap）+ 图层驱动的地形；Mesh Terrain / Mesh Partition 换了范式——地形/大世界几何直接是网格，编辑靠 modifier 管线（非破坏式、可回溯），构建时按空间网格分区成 section，运行时按平台选择表示（与 Nanite / HLOD / World Partition 深度耦合）。它不是简单替换 Landscape，而是面向网格化大世界创作的新一套 DCC + 运行时管线。官方入门文档：dev.epicgames.com/.../introduction-to-mesh-terrain。

一眼看懂 · 三层数据流

① 创作层 Authoring（编辑器）Mesh Terrain Mode 交互工具（顶点雕刻 / 属性绘制 / 选择）+ Transformer/Modifier 管线（UTransformerPipeline）。非破坏式：编辑记录为 modifier 图，随时可改可回溯（remesh / project 等类型）。
② 分区/编译层 Partition & CompileUMeshPartitionDefinition（DataAsset）驱动构建：跑 Transformer 管线 → 按空间网格切成 FCompiledSection，受复杂度预算约束（MaxSectionComplexity），可对齐 World Partition 运行时网格。
③ 运行时表示层 Runtime RepresentationAMeshPartition actor + UMeshPartitionComponent 系列（StaticMesh / Collision）。平台自适应（PerPlatformProperties）：不同平台选不同 build variant / 表示，接 Nanite、HLOD、DataLayer。

核心思路和 Nanite/虚拟纹理一脉相承：创作端高自由度 → 构建端按预算分区压缩 → 运行时按平台/视距自适应。区别是它作用在「几何创作管线」而非「运行时渲染算法」，所以几乎没有 shader，重头在 C++ 与编辑器工具。

编辑器侧 · Mesh Terrain Mode

基于 Modeling Toolset 的编辑器模式

UMeshTerrainMode 继承 UBaseLegacyWidgetEdMode（源码 MeshTerrainMode/Private/MeshTerrainMode.cpp，~2955 行），本质是复用 Modeling Mode 的交互工具框架做地形创作：几何选择系统（UGeometrySelectionManager）、顶点雕刻（Vertex Sculpt）、属性/权重绘制（Attribute Paint，含手写笔 StylusInput 压感）、UV 编辑等。它依赖 MeshModelingToolset / MeshModelingToolsetExp / MeshLODToolset / ModelingToolsEditorMode 一整套建模工具链——所以它更像「给大世界地形定制的 Modeling Mode」，而非独立编辑器。编辑器代码占绝大头（MeshPartitionEditor 约 4 万行），运行时反而很薄（约 3.3K 行）。

与文档集其它篇的关系

它站在「几何创作」与「运行时渲染」的交界

① → Nanite（本文档集《UE Nanite》）：Mesh Partition 的「平台自适应运行时表示」是它与渲染的主接口——高端平台用 Nanite 虚拟化几何承载 section，低端走 fallback。理解 Nanite 的簇/LOD/流送后再看它的运行时层会更顺。

② → World Partition / HLOD：section 可对齐 WP 运行时网格（bSplitSectionsToMatchWorldPartitionRuntimeGrid），并接 HLODLayer / DataLayer，是大世界流送的一环——和虚拟纹理书「数据 > 显存、按需分区」的思路同源。

③ 定位差异：本文档集现有 6 本是运行时渲染方案（几乎全是 shader + GPU 管线）；Mesh Partition 是几何创作 + 构建管线（几乎全是 C++ + 编辑器工具，0 shader）。故本篇只作扩展阅读的架构总览，待其转正后再评估是否做逐模块深挖。

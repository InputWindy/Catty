RenderLumenReflections 代码解析（镜面反射链路）

Lumen 的反射入口，与 Screen Probe Gather（漫反射 GI）并列的另一条链路：为每个屏幕像素按 GGX 粗糙度分布生成反射光线、追踪世界、再经"空间重建 → 时域累积 → 空域滤波"三段专用降噪，产出 SpecularIndirect，最终由 Composite 填入 Textures[3] 合入画面。它复用了与 GI 相同的追踪后端（屏幕/Mesh SDF/硬件 RT/Radiance Cache）与 Surface Cache 数据源，但采样与降噪是为镜面量身定制的。本页解析入口 FDeferredShadingSceneRenderer::RenderLumenReflections。

上下文：它与 GI 是什么关系

并列而非从属：漫反射 GI 走 RenderLumenScreenProbeGather，镜面反射走本函数，两者都被上层 diffuse-indirect 调度调用，各自产出信号后由 DiffuseIndirectComposite 合成——GI 进 Textures[0..2]，反射进 Textures[3]。

共享底座：反射的追踪走的是与 ③ TraceScreenProbes 同一套后端（屏幕/Mesh SDF/硬件 RT），命中后同样读 Surface Cache 的 FinalLightingAtlas 取光照；高粗糙度/远距离反射还会退回 Radiance Cache。差异全在采样（GGX 定向 vs 半球）与降噪（专用 resolve/temporal/spatial vs probe 滤波）。

1. 核心思想：镜面为什么要单独一条链路

说明

镜面与漫反射的根本区别是方向性：漫反射可以"稀疏采样 + 插值"，镜面必须"逐像素定向追踪"，否则镜像会糊。这决定了反射不能挂在 Screen Probe 体系里，而要单开一条逐像素链路。

共同点追踪后端、Surface Cache 数据源、Radiance Cache 兜底、"追踪+时域累积去噪"的大思路都与 GI 一致。

不同点采样是 GGX 定向（GGXSamplingBias 偏法线降噪）；降噪是三段专用管线而非 probe 滤波；成本控制多了"按粗糙度降采样"这一招。

2. 生成方向 + 追踪（GenerateRays / TraceReflections）

说明

GenerateRays 是反射版的"重要性采样"：不像 ② 那样在半球上分配预算，而是严格沿 GGX 波瓣采一个方向。GGXSamplingBias 故意把采样往法线拉一点，牺牲一点物理精度换取显著更低的噪声（后面还有三段降噪兜底）。

共同点追踪部分与 ③ TraceScreenProbes完全同源——同一套级联后端、同一个 Surface Cache 采样、同一个 Radiance Cache 兜底。想看追踪细节请直接读 ③ 与 Surface Cache 专题；其中硬件光追后端（Inline/RayGen 派发、SurfaceCache/Hit Lighting 着色）见 ↳ 下钻：Hardware Ray Tracing 后端解析。

不同点③ 每 probe 发多根线覆盖半球；这里每像素只发一根沿反射方向的线，所以更依赖后续降噪。

3. 三段降噪：Resolve → Temporal → Spatial

说明

三段是"空间 → 时间 → 空间"的组合拳：Resolve 先借本帧邻居把单线噪声压一轮并上采样；Temporal 借历史帧累积等效样本；Spatial 再用方差自适应的双边滤波给"还没累够历史"的区域补最后一刀。二阶矩（方差）是串起后两段的关键信号。

共同点与 GI 的时域降噪（④、UpdateHistory）一样：velocity 重投影 + 邻域钳制 + NumFramesAccumulated 累积窗口，都是 TAA 家族套路。

不同点反射多了 Resolve 空间重建（GI 靠 probe 密度天然抗噪，不需要）和 二阶矩方差驱动的自适应空域滤波，因为镜面噪声结构与漫反射不同、更需要保边。

4. 历史状态与输出

说明

反射按用途维护三套独立历史（不透明/水面/半透明前层），因为它们的重投影几何和更新频率不同，混用会互相污染。历史存的是"颜色 + 二阶矩"，让下一帧既能重投影又能重新估计方差。

共同点与 UpdateHistory 一样用 QueueTextureExtraction 把 New* 提升为跨帧持久 RT，用 bCameraCut 等门禁防止读脏历史。

不同点GI 只有一套 ScreenProbeGatherState；反射按 pass 分三套。且反射历史带 HistoryScreenPositionScaleBias 这类精确的 UV 映射，因为镜面重投影对亚像素错位更敏感。

最终总结

骨架

RenderLumenReflections 是与 Screen Probe Gather 并列的镜面反射链路：TileClassification 圈定像素 → GenerateRays 按 GGX 逐像素定向 → TraceReflections 复用 GI 追踪后端 → Resolve/Temporal/Spatial 三段降噪 → 返回 SpecularIndirect 供 Composite 填 Textures[3]。

省钱三招（分类 tile / 按粗糙度降采样 / Radiance Cache 兜底）+ 降噪三段（空间重建 / 时域累积 / 双边滤波）是它的两条主线。

阅读建议

先记住"逐像素 + 定向"这个与 GI 的根本区别，再把追踪部分完全交给 ③ TraceScreenProbes 与 Surface Cache 专题（同源）。重点放在反射独有的 GGX 采样与三段降噪管线，permutation 与 tile 分类细节见函数附录。

执行顺序：VSM → Atlas → Cubemap RenderShadowDepthMaps

RenderShadowDepthMaps（ShadowDepthRendering.cpp L1919）是深度渲染的总入口，按固定顺序处理三类阴影：

void RenderShadowDepthMaps(...) { // ① VSM / Nanite 优先：把需要 Nanite 几何的阴影视图批量渲进物理页 ShadowSceneRenderer->RenderVirtualShadowMaps(GraphBuilder, bNaniteEnabled); // ② 传统 Atlas：非 VSM 的方向光/聚光阴影打包进深度 Atlas 一起渲 RenderShadowDepthMapAtlases(GraphBuilder); // ③ 点光立方体：逐光源、逐 6 面渲染 cubemap 深度 for (CubeShadow : WholeSceneShadows) for (Face : 0..5) RenderCubeFace(...); }

为什么 VSM 排在最前

VSM 依赖 Nanite 多视图批处理：把所有需要 Nanite 几何的阴影视图（Clipmap 每一级、局部光每一 mip）打包成一批 Nanite view 一次剔除光栅（NANITE_MAX_VIEWS_PER_CULL_RASTERIZE_PASS=4096），效率远高于逐张阴影图单独渲。所以它先跑、独占 Nanite 路径；剩下的非 Nanite / 非 VSM 阴影才走传统 Atlas 与 Cubemap。这一顺序正是 UE5"Nanite 优先"渲染哲学在阴影上的体现。

深度 Atlas：把多张阴影图打进一张大图 RenderShadowDepthMapAtlases

传统方案里，同一帧可能有几十张小阴影图（多盏聚光、多个 Per-Object）。UE 把它们打包进一张或几张大的深度 Atlas 纹理，每张阴影图占 Atlas 里一块矩形区域（由 FProjectedShadowInfo 的 ResolutionX/Y + BorderSize + Atlas 内偏移决定）。这样只需一个渲染目标、一次 clear，减少切换开销。

概念说明
Atlas 分配按分辨率装箱（bin packing）把各阴影图排进 Atlas
BorderSize每张阴影图周围留边，避免 PCF 采样跨到邻居
渲染设 viewport 到该阴影图区域，用光源视图投影矩阵渲深度

阴影深度着色器 EShadowDepthType permutation

阴影深度只写深度、不写颜色，用一套精简的顶点/像素着色器。它按 EShadowDepthType（见 #1 附录）选 permutation——方向光是正交投影、聚光是透视、点光是立方体、VSM 又是另一路。下面是真实像素着色器 ShadowDepthPixelShader.usf 的 Main 尾部，聚光与 VSM 两条路一目了然：

// ShadowDepthPixelShader.usf — void Main(...) 节选（真实源码） #if SUPPORT_SHADOW_DEPTH_SPOT // 聚光：反相深度 + bias 后写 SV_DEPTH Inputs.ShadowDepth = 1 - Inputs.ShadowDepth * PassStruct.ShadowParams.w; Inputs.ShadowDepth += Inputs.DepthBias; OutDepth = saturate(Inputs.ShadowDepth); #endif #if SUPPORT_SHADOW_DEPTH_VSM // VSM：解析页表 → 原子写进物理页池 FShadowPhysicalPage Page = ShadowDecodePageTable(PassStruct.VirtualSmPageTable[ CalcPageOffset(NaniteView.TargetLayerIndex, NaniteView.TargetMipLevel, vAddress >> VSM_LOG2_PAGE_SIZE).GetResourceAddress()]); if (Page.bThisLODValidForRendering) { uint2 pAddress = Page.PhysicalAddress * VSM_PAGE_SIZE + (vAddress & VSM_PAGE_SIZE_MASK); const int ArrayIndex = PageInfo.bStaticPage ? GetVirtualShadowMapStaticArrayIndex() : 0; InterlockedMax(PassStruct.OutDepthBufferArray[uint3(pAddress, ArrayIndex)], asuint(DeviceZ)); } #endif

bias 在渲染期注入 + VSM 用 InterlockedMax

聚光路径里 Inputs.DepthBias 就是渲染期注入的偏移（常量 DepthBias + 按斜率的 SlopeScaledDepthBias）把记录深度稍微"推远"，避免比较时自阴影：太小则 acne（条纹自阴影），太大则 peter-panning（阴影脱离接触点）。VSM 路径没有独立深度目标——Nanite 光栅时同一物理页纹素可能被多个三角形写入，故用 InterlockedMax(..., asuint(DeviceZ)) 原子取最大（反向 Z 下最大即最近），把深度直接写进物理页池的 OutDepthBufferArray（静/动分离由 PageInfo.bStaticPage 选 ArrayIndex）。VSM 因分辨率高得多，所需 bias 远小于传统方案。

小结 Summary

1RenderShadowDepthMaps 按 VSM/Nanite → 传统 Atlas → 点光 Cubemap 顺序渲深度，VSM 优先独占 Nanite 多视图路径。

2传统阴影图打包进深度 Atlas，靠 ResolutionX/Y + BorderSize 装箱，减少渲染目标切换。

3深度着色器按 EShadowDepthType 选 permutation（正交/透视/立方体/VSM）。

4渲染期注入 DepthBias + SlopeScaledDepthBias 对抗 acne，与 peter-panning 权衡；VSM 因高分辨率所需 bias 更小。

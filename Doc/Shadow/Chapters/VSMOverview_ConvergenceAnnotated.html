#6 VSM 总览 · 阴影的"虚拟纹理化"

Virtual Shadow Map 是 UE5 的划时代阴影方案：把阴影图做成虚拟纹理——虚拟分辨率高达 16384×16384（16K），但只为屏幕真正需要阴影的区域分配 128×128 的物理页，配合 Nanite 得到近乎逐像素的阴影。本篇建立 VSM 全局直觉：为何依赖 Nanite、方向光 Clipmap 与局部光 mip 链的分野、以及一帧的宏观数据流。符号取自 UE5.8 VirtualShadowMapArray.h/.cpp、VirtualShadowMapDefinitions.h。

核心思想：阴影图 = 虚拟纹理 Virtualized shadows

传统阴影图的死结：想要清晰就得高分辨率，但一张 16K 阴影图占的显存无法接受，而且屏幕上大部分阴影区域根本用不到那么细。VSM 借用虚拟纹理的思路破局：

1虚拟分辨率 16K逻辑上每盏灯有 16384² 的阴影图，逐像素级精度
▶
2切成 128² 的页16K 图 = 128×128 个虚拟页，每页 128² 纹素
▶
3只分配需要的页屏幕像素标记 → 只给会被采样的页配物理内存

关键常量（VirtualShadowMapDefinitions.h）

VSM_PAGE_SIZE = 128（页边长纹素）、VSM_LOG2_PAGE_SIZE = 7、VSM_LEVEL0_DIM_PAGES_XY = 128（level0 每边 128 页 → 128×128=16384 纹素 = 16K 虚拟分辨率）、VSM_MAX_MIP_LEVELS = 8、VSM_VIRTUAL_MAX_RESOLUTION_XY = 16384。物理页由 FVirtualShadowMap::PhysicalPageAddressBits = 16 寻址 → 最多 64K 个物理页；实际池大小由 r.Shadow.Virtual.MaxPhysicalPages = 2048（默认）控制。这些常量是 #7~#12 全部展开的基准。

为什么 VSM 依赖 Nanite Every shadow view is a Nanite view

VSM 一帧可能有几十上百个阴影视图（Clipmap 每一级、每盏局部光每一 mip）。如果每个都用传统 draw call 单独渲，开销爆炸。VSM 的解法是把所有阴影视图打包成一批 Nanite view，一次剔除光栅全部搞定——这正是 Nanite 多视图批处理的用武之地（NANITE_MAX_VIEWS_PER_CULL_RASTERIZE_PASS = 4096）。Nanite 的像素级 LOD 又保证阴影几何在 16K 虚拟分辨率下依然有足够细节。

三本书的合体

VSM = 虚拟纹理的页表机制（#7 页表 / 物理页池，与虚拟纹理书同源）+ Nanite 的多视图光栅（渲深度）+ 阴影自己的投影采样（#12 SMRT）。所以官方文档强调 VSM 与 Nanite "配套使用效果最佳"：非 Nanite 几何也能进 VSM，但会走较慢的常规光栅路径。

两大分野：Clipmap vs mip 链 Directional vs Local

维度方向光（Clipmap）局部光（点/聚光）
结构以相机为中心的同心方形环（#8）透视投影的 mip 链（#9）
分配AllocateDirectionalAllocateLocal(bSinglePageShadowMap)
层级Clipmap Level 6~22（CVar 默认）最多 8 级 mip
退化—远处光源退化为单页（≤8192，#9）

分配顺序有讲究

源码注释明确："All directional lights must be allocated before all local lights"（所有方向光必须在所有局部光之前分配）。FVirtualShadowMapArray 用 IsSinglePage（ID < VSM_MAX_SINGLE_PAGE_SHADOW_MAPS = 8192）与 IsDirectional 区分不同类别的虚拟阴影图，这个顺序约束保证了 ID 空间的划分。

与传统四阶段一一对应

对照 #1 的"设置→深度→投影→合成"：VSM 的①②对应"设置"（但细化到逐页）、③对应"深度"、④对应"投影+合成"。核心区别是一切按需、一切缓存——这正是接下来 #7~#12 逐一展开的主题。

小结 Summary

1VSM 把阴影图虚拟纹理化：虚拟 16K 分辨率，切成 128² 页，只分配屏幕需要的页。

2关键常量 VSM_PAGE_SIZE=128 / VSM_VIRTUAL_MAX_RESOLUTION_XY=16384 / MaxPhysicalPages=2048。

3依赖 Nanite 多视图批处理渲深度（每阴影视图=一个 Nanite view），是虚拟纹理 + Nanite + 阴影的合体。

4方向光走 Clipmap（#8）、局部光走 mip 链/单页（#9），方向光必须先于局部光分配。

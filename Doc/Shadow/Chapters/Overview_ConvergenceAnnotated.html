核心问题：深度比较 Shadow Map = depth compare

Shadow Map 的原理只有两步：① 从光源视角把场景渲成一张深度图——每个纹素记录"从光源出发，这个方向上最近的遮挡物有多远"；② 正常从相机渲染时，把每个像素的世界坐标变换到光源空间，拿它到光源的距离与深度图里记录的最近距离比较：更远 = 被挡住 = 在阴影里。

1光源视角渲深度深度图纹素 = 该方向最近遮挡物距离
▶
2相机像素变换到光源空间GetScreenToShadowMatrix 得到阴影 UV + 深度
▶
3比较深度像素深度 > 记录深度 → 在阴影中

三大顽疾：acne / peter-panning / 走样

Shadow Acne（阴影痤疮）：深度图分辨率有限，一个纹素覆盖一片斜面，比较时自己把自己判成"被挡"，出现条纹自阴影。对策是深度偏移（DepthBias + SlopeScaledDepthBias，见 #2）。Peter-Panning（彼得潘悬空）：偏移过大又会让阴影脱离接触点，物体像悬空。走样（aliasing）：阴影图纹素投到屏幕上被放大成锯齿块，对策是 PCF 多点过滤、更高分辨率、以及方向光的 CSM 分级与稳定 snapping（见 #3）。这三者是一个此消彼长的三角——UE 的所有阴影方案本质都在这三者间找平衡，而 VSM（中篇）用 16K 虚拟分辨率把"走样"从根上大幅缓解。

核心结构：FProjectedShadowInfo ShadowRendering.h

UE 用一个统一的结构 FProjectedShadowInfo（: FRefCountedObject）描述"一次要投影的阴影"，无论它是方向光级联、点光立方体、还是 Per-Object。它用一组位标志区分类型，用一组矩阵描述投影：

// ShadowRendering.h — 位标志区分阴影类型（节选） uint32 bDirectionalLight : 1; // 方向光（太阳） uint32 bOnePassPointLightShadow : 1; // 点光单趟立方体阴影（6 面一次渲） uint32 bWholeSceneShadow : 1; // 整场景阴影（CSM / 点光 / 聚光） uint32 bPreShadow : 1; // 预阴影（静态物投到动态物） uint32 bPerObjectOpaqueShadow : 1; // Per-Object 不透明阴影 uint32 bRayTracedDistanceField : 1; // 距离场阴影（#13） uint32 bCapsuleShadow : 1; // Capsule 阴影（#14） uint32 bNaniteGeometry : 1; // 由 Nanite 几何渲染 FVirtualShadowMapClipmap* VirtualShadowMapClipmap; // 非空 = VSM Clipmap（#8）
关键成员含义
CacheMode该阴影的缓存模式（EShadowDepthCacheMode，见 #5）
ShadowBounds / CascadeSettings阴影包围球 / 级联参数（分割距离、过渡）
ResolutionX/Y · BorderSize阴影图在 Atlas 中的分辨率与边框
OnePassShadowViewProjectionMatrices[6]点光 6 个立方体面的视图投影矩阵
FadeAlphas · PerObjectShadowFadeStart级联/Per-Object 的距离淡出

一个结构，一套渲染管线

把所有阴影类型收敛到 FProjectedShadowInfo 的好处是：深度渲染（RenderDepth）与投影（RenderProjection / RenderOnePassPointLightProjection / RenderRayTracedDistanceFieldProjection）都能对着同一个结构分派。它的三个 Setup*Projection 方法——SetupPerObjectProjection（#5）、SetupWholeSceneProjection（#3/#4）、SetupClipmapProjection（#8）——分别对应三大类阴影的初始化，是阅读阴影代码的三个入口。

四阶段数据流 Setup → Depth → Projection → Composite

一帧里阴影的宏观流程（对应总目录的四个阶段）：

阶段关键函数做什么
① 设置InitDynamicShadows → Setup*Projection按光源与可见性建 FProjectedShadowInfo 列表，CSM 切级联，VSM 发页请求
② 深度RenderShadowDepthMaps从光源渲深度：先 VSM/Nanite，再传统 Atlas，再 Cubemap 6 面（#2）
③ 投影RenderShadowProjections相机像素比深度，写 ScreenShadowMaskTexture；VSM 走 SMRT（#12）
④ 合成光照 pass 采样 mask光照计算时乘上阴影因子；多光源可打包 ShadowMaskBits

VSM 把①②③全部"虚拟化"

传统方案里这四步针对"每盏灯一张固定分辨率阴影图"；VSM 则把①改成"标记屏幕需要哪些虚拟页并分配物理页"（#10），②改成"只渲脏页、其余跨帧缓存"（#11），③改成"沿阴影图做 SMRT 光线步进"（#12）。理解了本篇的四阶段骨架，再看中篇就是"同一骨架换了存储与采样方式"。

小结 Summary

1阴影贴图 = 从光源渲深度图 + 从相机变换比深度；更远即在阴影中。

2三大顽疾 acne / peter-panning / 走样构成一个此消彼长的三角，所有方案都在其间取舍；VSM 用 16K 虚拟分辨率大幅缓解走样。

3核心结构 FProjectedShadowInfo 用位标志统一描述所有阴影类型，三个 Setup*Projection 是三大类阴影的入口。

4一帧阴影走 设置 → 深度 → 投影 → 合成四阶段；VSM 是把这套骨架换成"虚拟纹理页 + SMRT 采样"。

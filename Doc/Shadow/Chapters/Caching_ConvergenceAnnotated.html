#11 缓存与失效 · VSM 跨帧复用的心脏

VSM 真正的性能来源不是"渲得快"，而是"绝大多数页根本不重渲"——静止的几何、静止的灯，其阴影页跨帧一直复用。这就需要一套精密的失效机制：什么变了、哪些页作废、哪些能整体平移复用。本篇讲清缓存管理器、per-light 缓存项失效、GPU 实例失效与年龄回收。符号取自 UE5.8 VirtualShadowMapCacheManager.h/.cpp、CacheGPUInvalidation.usf。

缓存管理器：跨帧持有物理页 FVirtualShadowMapArrayCacheManager

缓存管理器（继承 ISceneExtension）是跨帧存活的对象，持有物理页池和每盏灯的缓存项：

// FVirtualShadowMapArrayCacheManager 关键职责 SetPhysicalPoolSize(...); // 建/调物理页池 FindCreateLightCacheEntry(LightId); // 取/建每盏灯缓存项 ProcessInvalidations(...); // 处理本帧所有失效 UpdateUnreferencedCacheEntries(...); // 年龄回收 ExtractFrameData(...); // 导出供下帧复用的数据

缓存项两级：per-light 与 per-clipmap-level

FVirtualShadowMapPerLightCacheEntry 是每盏灯一份；方向光下每个 clipmap 级还有 FVirtualShadowMapCacheEntry（内含 FClipmapInfo）。UpdateClipmapLevel（#8 讲过 L259）就是逐级更新这一层，产出 FNextVirtualShadowMapData（含 VSM_NEXT_FLAG_KEEP_PAGE + PageAddressOffset）告诉下一帧哪些页可平移保留。

per-light 失效判定 PerLightCacheEntry::Update L362

// FVirtualShadowMapPerLightCacheEntry::Update（L362） if (bForceInvalidate || 关键 key 变化) { RenderedFrameNumber = -1; // 标记"从未渲染"，下帧完整重渲 } // bIsUncached：失效后下一帧走 uncached， // 稳定一个静态帧后再转回缓存模式

什么会触发失效

灯的变换/参数变化、投射体（动态物）移动、可变形网格更新（Cache.DeformableMeshesInvalidate=1）、相机跨越 clipmap snap 网格。RenderedFrameNumber=-1 是"作废"信号。失效后的第一帧 bIsUncached，完整渲染；若之后场景静止，下一帧起转回缓存命中。这个"缓一帧再信任缓存"的设计避免了运动物残影。

GPU 实例失效 VirtualShadowMapCacheGPUInvalidation.usf

动态物移动导致的页失效在 GPU 上并行完成，避免 CPU 遍历成千上万实例。核心 CS VSMUpdateViewInstanceStateCS 每线程处理 32 个实例（一个 uint 一位一个实例），用位运算找出"本帧状态变了"的实例：

// VirtualShadowMapCacheGPUInvalidation.usf — VSMUpdateViewInstanceStateCS（真实源码节选） uint IsDeformingMask = LoadInstanceDeformingWord(WordIndex, SceneRendererViewId); // 本帧是否形变 uint CachedAsDynamicMask = InOutViewInstanceState[WordIndex]; // 上帧动态标记 uint TrackedMask = InOutViewInstanceState[WordIndex + StateWordStride]; // 是否已跟踪 // XOR 找出与上帧不一致、且已跟踪的实例（新增的不算状态变化） uint StateChangeMask = (IsDeformingMask ^ CachedAsDynamicMask) & TrackedMask; uint InvalidationMask = StateChangeMask & IsDeformingMask; // 只在"转为动态"时失效 FOREACH_SET_BIT_BEGIN(InvalidationMask, BitIndex, BitMask) { // 遍历置位，写失效队列 WaveInterlockedAddScalarInGroups(OutInvalidationArgs[3], OutInvalidationArgs[0], THREAD_GROUP_SIZE, 1, WriteOffset); OutInvalidationQueue[WriteOffset] = PackInvalidationItem(WordIndex*32u + BitIndex, SceneRendererViewId, ...); } FOREACH_SET_BIT_END()
VSMUpdateViewInstanceStateCS32 实例/字，XOR 找状态变化 → 写失效队列
▶
ProcessInvalidationQueueGPUCS消费失效队列，把实例覆盖的页标记失效

用 HZB 加速失效判定

Cache.InvalidateUseHZB=1：用上一帧的 HZB 判断移动实例是否真的会影响某页——若实例在该页里被完全遮挡，就无需失效该页。这把"保守全失效"收窄成"精确按需失效"，是 VSM 在大量动态物场景仍高效的关键。失效预算 DeferredInvalidationBudget=-1（不限）。

年龄回收 Age-based eviction

缓存不能无限占用物理页，靠年龄回收：

CVar默认含义
Cache.MaxPageAgeSinceLastRequest1000页超过 1000 帧未被请求 → 回收
Cache.MaxLightAgeSinceLastRequest10灯超过 10 帧未被请求 → 释放其缓存项
Cache.FramesStaticThreshold100连续静止 100 帧判定为"静态"

LastRequestedSceneFrameNumber 是一切的锚

回到 #7：每物理页的 LastRequestedSceneFrameNumber 既是 LRU 排序依据，也是年龄回收依据。页标记（#10）每帧刷新被看见页的这个字段；久未被看见的页在 UpdateUnreferencedCacheEntries 里按上表阈值回收。至此 #7~#11 的闭环完成：标记→分配→缓存→失效→回收。

小结 Summary

1FVirtualShadowMapArrayCacheManager（ISceneExtension）跨帧持有页池与缓存项，是 VSM 性能心脏。

2per-light 失效（Update L362）：key 变化/强制失效 → RenderedFrameNumber=-1；bIsUncached 缓一帧再信任缓存。

3GPU 失效两 CS（VSMUpdateViewInstanceStateCS / VSMProcessInstanceInvalidationCS）并行处理动态物，配 HZB 精确失效。

4年龄回收：页 1000 帧 / 灯 10 帧未请求即回收，锚点是 LastRequestedSceneFrameNumber。

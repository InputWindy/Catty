Per-Object 阴影 SetupPerObjectProjection

整场景阴影覆盖大范围但分辨率均摊；对某些重要动态物（角色、可交互道具），UE 单独给它一张紧贴其包围盒的高分辨率阴影图——这就是 Per-Object 阴影。SetupPerObjectProjection 用物体的包围盒拟合一个最小投影视锥，分辨率随屏幕占比缩放（r.Shadow.PerObject，随距离用 PerObjectShadowFadeStart 淡出）。

PreShadow：静态物投到动态物上

Per-Object 只处理"动态物投到别处"，而PreShadow解决反向问题——让静态环境（墙、地形）的阴影正确落到动态物上。PreShadow 把动态物周围的静态几何渲成一张预阴影图。因为静态几何不变，PreShadow 可以缓存（r.Shadow.CachePreshadow=1），并用 r.Shadow.PreshadowExpand=0.15 略微扩张包围盒留余量、r.Shadow.PreShadowResolutionFactor=0.5 降分辨率省开销。

静动分离缓存 TryToCacheShadowMap

整场景阴影（尤其点光/聚光）里，绝大多数几何是静态的——只要光源不动，它们的阴影每帧都一样，重渲纯属浪费。UE 的关键优化：把一盏灯的阴影拆成两张缓存，静态那张只在必要时重渲：

// TryToCacheShadowMap L499 — 静动分离 // 静态图：只含静态投射体，可跨帧复用 CachedShadow_Static = CreateShadow(SDCM_StaticPrimitivesOnly); // 动态图：只含动态投射体，每帧重渲 CachedShadow_Movable = CreateShadow(SDCM_MovablePrimitivesOnly); // 投影时把两张深度合并比较（取更近的遮挡）
SSDCM_StaticPrimitivesOnly静态几何深度，光源不动则缓存复用
+
MSDCM_MovablePrimitivesOnly动态几何深度，每帧重渲
▶
∪投影时合并取两者更近的遮挡 = 完整阴影

这正是 VSM 缓存的雏形

"静态部分缓存、动态部分重渲"的思想，在中篇 VSM 缓存（#11）被推向极致：VSM 不再是"整张图静/动两份"，而是逐物理页判断脏否——动态物移动只让它覆盖的少数页失效（GPU 端 VSMProcessInstanceInvalidationCS），其余页全部跨帧复用。传统方案的 EShadowDepthCacheMode 是页级缓存的思想起点。CSM 还有滚动缓存（SDCM_CSMScrolling）：相机平移时，把上帧缓存的重叠区域平移复用、只补渲新露出的边缘（r.Shadow.CSMScrollingOverlapAreaThrottle=0.75）。

小结 Summary

1Per-Object 阴影为重要动态物拟合紧贴包围盒的高分辨率阴影图（SetupPerObjectProjection）。

2PreShadow把静态环境阴影投到动态物上，因静态可缓存（CachePreshadow）、降分辨率省开销。

3静动分离缓存（TryToCacheShadowMap）把整场景阴影拆成 SDCM_StaticPrimitivesOnly（可复用）+ SDCM_MovablePrimitivesOnly（每帧渲），投影时合并。

4CSM 有滚动缓存（SDCM_CSMScrolling）；这套页/区域级缓存思想是 VSM 缓存（#11）的直接前身。

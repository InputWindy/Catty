典型组合

高端 PC/主机：VSM（方向光 Clipmap + 局部光）为主 + 接触阴影补细节，追求极致时叠光追。中端：VSM 或 CSM + 局部光阴影图 + 接触阴影。移动端：CSM（走剔除优化）+ 胶囊阴影 + 可选距离场，见下。它们不是互斥的，而是按距离/物体类型分工叠加。

移动端阴影 ShadowSetupMobile.cpp

移动端 GPU 弱、带宽紧，阴影做了大量裁剪：核心是 CSM 着色器可见性剔除——只对真正落在 CSM 且可能投射的物体开启阴影采样，减少 shader 分支与 overdraw。

// r.Mobile.Shadow.CSMShaderCullingMethod 位标志 0 // 禁用剔除 1 // 光视锥剔除（默认） 2 // 合并投射体剔除 3 // 光视锥 + 投射体 4 // 全剔除 5 // 配合距离场 // +16 位：改用球体测试

调制阴影与屏幕空间阴影

移动端还有调制阴影（RenderModulatedShadowProjections，把阴影作为半透明乘到场景上，省一次全屏 pass），由 bModulatedShadowsInUse 标记；以及移动端屏幕空间阴影（RenderMobileScreenSpaceShadows）。可见性状态存在 FMobileCSMVisibilityInfo，由 BuildCSMVisibilityState / EnableStaticMeshCSMVisibilityState 在 InitDynamicShadows 里构建。Inset 阴影默认关（r.Mobile.SupportInsetShadows=false），距离场阴影按 r.Mobile.AllowDistanceFieldShadows 开关。

一句话总纲

UE 阴影的演进主线是：从固定分辨率、每帧重渲的传统阴影图（Part 1），走向虚拟分页、需求驱动、跨帧缓存、SMRT 软阴影的 VSM（Part 2，5.8 方向光全面 Clipmap 化是里程碑）；专项方案（Part 3）在特定维度补足。理解 VSM 的关键是记住那条闭环：页标记→分配→渲染→缓存→失效→回收，一切为了"只做屏幕真正需要的那点阴影工作"。

小结 Summary

1阴影方案按距离/物体类型分工叠加，而非二选一；现代默认是 VSM 为主 + 接触阴影补细节。

2移动端核心是 CSMShaderCullingMethod（默认 1 光视锥剔除）+ 调制阴影 + 屏幕空间阴影。

3可见性状态 FMobileCSMVisibilityInfo 由 InitDynamicShadows 内的 BuildCSMVisibilityState 构建。

4全书总纲：从固定阴影图走向虚拟分页 + 需求驱动 + 跨帧缓存 + SMRT 的 VSM——只做必要的阴影工作。

0. 生成分层页标志金字塔（发散点）

void ProcessMaskMip4x4(RWTexture2D<uint> OutPageReceiverMaskMip, inout uint Mask4x4, inout uint2 MaskAddress)
[numthreads(VSM_DEFAULT_CS_GROUP_X, 1, 1)] void GenerateHierarchicalPageFlags(uint ThreadId : SV_DispatchThreadID)
// 把每页的"是否被请求"标志逐层 OR 上卷成 mip 金字塔（4×4 归约）
// 供后续遍历时快速跳过整块无请求的区域

说明

VSM 有海量页，逐页处理太慢。GenerateHierarchicalPageFlags 把每页的"本帧是否被请求/需要渲染"标志逐层归约成金字塔（ProcessMaskMip4x4 每次 4×4 OR 上卷）——就像 HZB。后续所有遍历（剔除、分配、渲染指令生成）都能在粗层整块跳过没有任何请求的区域，只下钻到有内容的页。这是 VSM 稀疏性的关键：只为屏幕真正需要阴影的地方付出代价。

1. 已映射 mip 向粗层传播（汇聚点）

[numthreads(PER_PAGE_THREAD_GROUP_SIZE_XY, PER_PAGE_THREAD_GROUP_SIZE_XY, 1)]
void PropagateMappedMips(uint3 DispatchThreadId : SV_DispatchThreadID)
// 若某精细页无独立物理页，但其粗 mip 页已映射 → 复用粗页地址
// 避免为每个精细页都分配物理内存，缓存跨 mip 共享

说明

汇聚点：PropagateMappedMips 处理 mip 层级复用——当某精细级页本身没有分配独立物理页时，若它对应的更粗 mip 页已经映射，就让精细页指向粗页（降质但省内存，远处阴影够用）。这让 VSM 的物理页池在"每级都独立分配"与"内存爆炸"间取得平衡：近处高频用精细页，远处/次要处回退粗页。配合 物理页管理 的分配/回收，构成 VSM 的虚拟→物理映射闭环。

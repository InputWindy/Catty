UE RDG 源码解析 · 总目录

RDG（Render Dependency Graph，渲染依赖图）是 UE5 现代渲染的公共底座——Nanite / Lumen / VSM / MegaLights / TSR 每一个 pass 都跑在它上面。它把渲染改写成声明式：你只描述「这个 pass 读什么、写什么」，RDG 自动完成资源生命周期管理、瞬态内存复用、屏障（barrier/transition）推导、pass 剔除、异步计算与并行执行。本书对照 UE5.8 本地源码逐层解析，覆盖核心图 → 参数绑定 → 之下的 RHI 资源管理 → 工具与实战四大部分。每主题一份主文档（设计动机 + 数据流骨架 + 真实源码段批注）与一份函数附录（类 / 函数 / 结构体 / 算法细节）。所有类名、函数、常量均取自 UE5.8 本地源码，全书零伪代码、真实源码段 + 逐段批注。

这本书怎么读

建议入口 · 先建立"声明式渲染 + 自动屏障"的直觉

一句话

RDG = 渲染版的依赖图 + 自动内存/屏障管理器：把「pass 读写了哪些资源」声明成一张有向图，RDG 在 Execute() 前编译这张图（算依赖、剔无用 pass、定资源生命周期），再执行（分配瞬态资源、批量插屏障、派发异步计算与并行录制）。开发者不再手动 RHICmdList.Transition 或手动管理 FRenderTargetPool。

第一次读建议按 #1 → #2 → #3 → #4 → #5 → #6 把主干过一遍：#1 总览建立"为什么要图"；#2 资源模型与 #3 Pass 讲清图的两类节点；#4 Builder 是使用入口；#5 编译 / #6 执行是引擎心脏（依赖分析、屏障推导、异步计算）。主干通了再看参数绑定（#10~#12）、以及最关键的 Part 3 · RHI 资源管理桥接（#13~#17）——那里讲清 RDG 与老 FRenderTargetPool / ERHIAccess 转换状态机的关系，是理解整套引擎渲染资源生命周期的钥匙。

一眼看懂：RDG 从声明到执行的数据流

① 声明 DeclareCreateTexture/Buffer
AddPass(参数结构体, lambda)
参数结构体标注读/写
② 编译 Compile建 pass 依赖图
剔除无消费者的 pass
算资源首末次使用 → 生命周期
③ 执行 Execute瞬态分配器分配资源
推导并批量插 barrier
异步计算 / 并行录制
④ 落地 RHI转译成 RHICommandList
ERHIAccess 转换
提取 persistent / 跨帧资源

与手写 RHI 最大的不同：依赖、生命周期、屏障全部由 RDG 自动推导，开发者只声明意图。代价是一层编译开销与一套需要理解的资源/pass 心智模型——本书就是把这套模型连同源码讲透。

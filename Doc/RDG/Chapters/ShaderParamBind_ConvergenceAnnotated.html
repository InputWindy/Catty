#11 参数解析与绑定到 RHI

有了元数据（#10），运行时怎么把参数结构体里的资源真正绑到 shader 的寄存器槽？答案是 SetShaderParameters——它拿 FShaderParameterBindings（编译期从 shader 反射出的槽位）+ FShaderParametersMetadata（#10 的成员表）+ 参数数据，遍历成员逐个写进命令列表。本篇讲这条绑定链。源码取自 ShaderParameterStruct.h/.cpp。

绑定链一眼看懂 The binding chain

输入来自
FShaderParameterBindingsshader 编译期反射：每个参数在 shader 里的槽位/寄存器
FShaderParametersMetadata#10 的成员表：每个成员的 UBMT 类型/偏移/名字
参数数据指针你填好的参数结构体实例

核心

SetShaderParameters 把这三者对齐：按名字匹配 metadata 成员与 shader 反射槽位，按成员的 UBMT 类型决定取 SRV/UAV/UB/常量，写进 FRHIBatchedShaderParameters 再刷到命令列表。

配套附录

SetShaderParameters 全重载（compute/graphics/RT）、ValidateShaderParameters 见 → 绑定流程附录。

SetShaderParameters：绑定入口 The bind entry

最常用的模板重载，真实源码：

// ShaderParameterStruct.h : L276-L300template <typename TShaderClass> inline void SetShaderParameters( FRHIBatchedShaderParameters& BatchedParameters, const TShaderRef<TShaderClass>& Shader, const FShaderParametersMetadata* ParametersMetadata, const typename TShaderClass::FParameters& Parameters) { ValidateShaderParameters(Shader, ParametersMetadata, &Parameters); // debug 校验（#8） // ...按 metadata 遍历成员，按 UBMT 类型取资源，写进 BatchedParameters... } // 便捷重载：从 shader 类自动取元数据 inline void SetShaderParameters(FRHIBatchedShaderParameters& BatchedParameters, const TShaderRef<TShaderClass>& Shader, const typename TShaderClass::FParameters& Parameters) { const FShaderParametersMetadata* Metadata = TShaderClass::FParameters::FTypeInfo::GetStructMetadata(); SetShaderParameters(BatchedParameters, Shader, Metadata, Parameters); }

批注

看两点：① FTypeInfo::GetStructMetadata()——这就是 #10 END_SHADER_PARAMETER_STRUCT 生成的成员表。便捷重载从 shader 类直接取它，所以业务代码通常只写 SetShaderParameters(BatchedParams, Shader, Parameters)。② 开头就调 ValidateShaderParameters——绑定前先校验（#8），发布版编空。内部实现（.cpp）按 metadata 逐个成员：常量成员 memcpy 进 uniform buffer，资源成员（SRV/UAV/UB）按 FShaderParameterBindings 里反射出的槽位号绑定。FRHIBatchedShaderParameters 是"批处理"容器——先把一整个 pass 的绑定攒起来，再一次性刷给 RHI，减少 API 调用。

还有分平台重载（compute / graphics / 光追），真实源码：

// ShaderParameterStruct.h : L303-L330void SetShaderParameters(FRHIComputeCommandList& RHICmdList, FRHIComputeShader* ShaderRHI, ...); // compute void SetShaderParameters(FRHICommandList& RHICmdList, FRHIGraphicsShader* ShaderRHI, ...); // graphics // checkf(!ShaderRHI->HasSpecializationConstants()...) —— 用特化常量的 shader 需给 ResourceExclusion

批注

不同着色阶段（compute / graphics / RT）各有重载，因为绑定的命令列表类型与 shader 对象类型不同。注意那句 checkf(!ShaderRHI->HasSpecializationConstants())——用了 specialization constants 的 shader 需要额外传 ResourceExclusion 列表（把被特化掉的资源排除出绑定），这是 UE5.8 特化常量支持带来的约束。FComputeShaderUtils::Dispatch（#9）内部调的就是 compute 版 SetShaderParameters。

本篇小结 Summary

记住这几点

1. 绑定 = 对齐三者：shader 反射槽位（FShaderParameterBindings）+ 成员元数据（#10）+ 参数数据。

2. SetShaderParameters 按 metadata 遍历成员，按 UBMT 类型取 SRV/UAV/UB/常量，写进 FRHIBatchedShaderParameters 批量刷 RHI；入口先 ValidateShaderParameters（#8）。

3. 分 compute/graphics/RT 重载；用 specialization constants 的 shader 需传 ResourceExclusion。

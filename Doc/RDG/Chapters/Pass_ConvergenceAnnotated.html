#3 Pass · 图的执行节点

图的第二类节点是 pass——一次 GPU 工作。本篇讲清 FRDGPass 的核心字段、pass 如何用参数结构体声明它读写哪些资源（这是 RDG 推导依赖与屏障的唯一信息来源）、以及 ERDGPassFlags 如何决定 pass 走哪条管线、能否被剔除/合并/并行。类/字段取自 RenderGraphPass.h、RenderGraphDefinitions.h。

一眼看懂：一个 pass 由什么构成 Anatomy of a pass

RDG_EVENT_NAME(...)

核心洞察

RDG 能自动做依赖/屏障/剔除，全靠 ParameterStruct——开发者在参数结构体里用宏声明每个资源是 SRV(读)/UAV(写)/RenderTarget(写) 等，RDG 只从这里获知 pass 的读写意图。lambda 里手动 GetRHI() 用了但没在参数结构体声明的资源，RDG 一无所知——这正是最常见的 RDG bug 来源（校验层 #8 会抓）。

配套附录

FRDGPass 全部字段、TRDGLambdaPass 模板、FRDGDispatchPass/FRDGSentinelPass 等特殊 pass 见 → Pass 类型附录；ERDGPassFlags 全枚举见 #1 附录。

FRDGPass：核心字段 Core fields

pass 的构造签名与关键成员，真实源码：

// RenderGraphPass.h : L220, L390-L394FRDGPass(FRDGEventName&& InName, FRDGParameterStruct InParameterStruct, ERDGPassFlags InFlags, ERDGPassTaskMode InTaskMode); // 关键成员（不可变）： const ERDGPassFlags Flags; // Raster/Compute/AsyncCompute/Copy/NeverCull... const ERDGPassTaskMode TaskMode; // 同步 / 并行任务 / 异步 const ERHIPipeline Pipeline; // Graphics 还是 AsyncCompute pipe（由 Flags 派生） FRDGPassHandle Handle; // pass 在图里的索引句柄 uint32 Workload = 1;

批注

四个入参正好对应"一个 pass 是什么"：名字、参数结构体（读写声明）、flags、任务模式。Pipeline 由 Flags 派生——含 AsyncCompute 就走 async compute pipe，否则走 graphics pipe；#6 执行据此把 pass 分到不同队列并在队列间插同步。Handle 是 pass 的索引句柄（同 #2 资源的 handle 思路），图内部用它排序、建依赖数组。Workload 是负载权重，用于并行录制时的任务均衡。

取参数结构体的访问器（编译期遍历它来建依赖）：

// RenderGraphPass.h : L238-L251ERDGPassFlags GetFlags() const { return Flags; } ERHIPipeline GetPipeline() const { return Pipeline; } FRDGParameterStruct GetParameters() const { return ParameterStruct; }

批注

GetParameters() 返回的 FRDGParameterStruct 就是 #5 编译期"遍历所有 pass 的参数、找出资源的生产者/消费者"的入口——编译器逐个 pass 调 GetParameters()，遍历其中的资源成员及其访问类型，据此连边。

PassFlags 决定 pass 的命运 Flags drive everything

ERDGPassFlags（uint16 位标志，完整源码见 #1 附录）不是装饰，它直接改变编译/执行行为：

标志影响的阶段后果
Raster/Compute/Copy执行graphics pipe 上用光栅/计算/拷贝命令
AsyncCompute执行派发到异步计算队列，需跨队列 fence 同步
NeverCull编译（剔除）该 pass 及其生产者永不被剔——输出图无法追踪时必打
SkipRenderPass/NeverMerge执行（合并）退出 RDG 的 RenderPass 合并优化
NeverParallel执行（并行）强制只在渲染线程执行

最常踩的坑：忘了 NeverCull

如果一个 pass 的效果不体现在任何被后续 pass 读取或被提取的 RDG 资源上（比如它只是往一个图外 buffer 写、或做 GPU readback、或有别的副作用），RDG 的剔除算法（#5）会认为"没人要它的输出"而把它整个剔掉，表现为"我的 pass 怎么没执行"。解法：给它加 ERDGPassFlags::NeverCull（或用现成的 Readback = Copy | NeverCull）。这是 RDG 新手最常见的困惑之一。

本篇小结 Summary

记住这几点

1. 一个 pass = EventName + ParameterStruct + PassFlags + Execute Lambda。

2. ParameterStruct 是 RDG 推导依赖/屏障/剔除的唯一信息源——lambda 里用但没声明的资源，RDG 不知道。

3. ERDGPassFlags 直接改变编译/执行：管线选择、是否剔除、是否合并、是否并行。输出不可追踪的 pass 必须 NeverCull。

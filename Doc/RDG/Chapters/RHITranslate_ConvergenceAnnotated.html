#17 转译到 RHICommandList / 并行 · VisualizeTexture

Part 3 收尾。RDG pass 最终要变成真实的 FRHICommandList 命令；并行录制时命令被切成多段再合并；VisualizeTexture（vis 命令）则挂在 RDG 资源上做可视化调试。本篇讲这最后一跳与调试出口。源码取自 RHICommandList.h、VisualizeTexture.h/.cpp。

最后一跳 The last hop

pass lambda → RHICommandList → 后端 → GPU

#6 讲过 pass 执行时把 FRHIComputeCommandList&/FRHICommandList& 传进 lambda。lambda 里的 RHICmdList.SetShaderParameters/DispatchComputeShader/DrawIndexedPrimitive 就是往命令列表录命令；命令列表最终提交给平台 RHI 后端（D3D12/Vulkan）翻译成原生 API 调用。RDG 只是编排谁先谁后、插哪些屏障，真正的 GPU 命令仍走 RHICmdList。

配套附录

命令列表类型（immediate vs 普通）、并行提交、VisualizeTexture 接口见 → 转译/可视化附录。

并行录制：切分与合并 Parallel command lists

为什么能并行录命令

录制命令（把 draw/dispatch 写进命令列表）是CPU 工作，且各 pass 之间只要顺序正确就能并行录。#6 的 SetupParallelExecute 把符合条件的 pass 分给多个 worker 线程，每个线程持一个非 immediate 的 FRHICommandList 各录一段，最后按图顺序把这些子命令列表拼接提交给 immediate 命令列表。这就是 #1 讲的并行约定为什么要求"lambda 用非 immediate 命令列表"——immediate 命令列表是单线程直提交的，不能并行录。FRHICommandListImmediate（主）vs FRHICommandList（并行子）的区别贯穿整个 RHI 命令系统（RHICommandList.h 5581 行）。

批注

还记得 #4 里 CreateTexture(Desc, Name) 那个 Name 吗？它就是给 VisualizeTexture 用的。开控制台敲 vis MyPass.Output，引擎会把那个 RDG 资源当帧的内容抓出来画到屏幕——直接肉眼看某个中间纹理对不对，是调试渲染最直接的手段。SUPPORTS_VISUALIZE_TEXTURE（#1 的宏）控制其可用性（非 Shipping 或带编辑器）。它与 #18 RenderGraphInsights（时间线剖析）互补：Vis 看"某资源内容对不对"，Insights 看"pass/屏障/时序对不对"。这两个加上 #8 的校验、clobber，就是 RDG 全套调试手段。

本篇小结 Summary

记住这几点

1. RDG 只编排顺序与屏障；真实 GPU 命令仍由 pass lambda 里的 RHICmdList 录制，最终交平台后端翻译。

2. 并行录制：多 worker 各持非 immediate 命令列表录一段，按图顺序拼接提交——这是 #1 并行约定要求非 immediate 列表的原因。

3. VisualizeTexture（vis 资源名）用 CreateTexture 给的 Name 把 RDG 资源画到屏幕；与 #18 Insights、#8 校验/clobber 组成全套调试。

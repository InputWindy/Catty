#10 SHADER_PARAMETER 宏体系与元数据

Part 2 开篇。RDG pass 的"参数结构体"（#3 说它是依赖推导的唯一信息源）是怎么来的？答案是一套 SHADER_PARAMETER_* 宏——它们在编译期把成员声明展开成布局元数据 FShaderParametersMetadata，让运行时能遍历、绑定、校验。本篇讲清宏如何映射到 UBMT_* 成员类型。源码取自 ShaderParameterMacros.h（1978 行）。

一个参数结构体长什么样 Example

// 典型用法（业务代码里到处是这个） BEGIN_SHADER_PARAMETER_STRUCT(FMyPassParameters, ) SHADER_PARAMETER(FVector4f, Constant) // 普通常量 SHADER_PARAMETER_RDG_TEXTURE(Texture2D, InputTexture) // RDG 纹理（读） SHADER_PARAMETER_RDG_TEXTURE_SRV(Texture2D, InputSRV) // RDG SRV（读） SHADER_PARAMETER_RDG_BUFFER_UAV(RWBuffer<float>, OutputUAV) // RDG UAV（写） END_SHADER_PARAMETER_STRUCT()

核心问题

这段宏展开后，RDG 怎么知道 InputTexture 是"读"、OutputUAV 是"写"？答案就在每个宏映射的 UBMT_* 基类型里——它编码了成员是常量/SRV/UAV/UB 以及是否 RDG 追踪。

配套附录

SHADER_PARAMETER_* 全家族与对应 UBMT_*、FShaderParametersMetadata::FMember 见 → 宏与元数据附录。

宏 → UBMT 成员类型 → 元数据 Macro to metadata

每个 SHADER_PARAMETER_RDG_* 宏都展开成一个 INTERNAL_SHADER_PARAMETER_EXPLICIT，第一个参数就是 UBMT_* 基类型。真实源码：

// ShaderParameterMacros.h : L1697-L1710#define SHADER_PARAMETER_RDG_TEXTURE(ShaderType,MemberName) \ INTERNAL_SHADER_PARAMETER_EXPLICIT(UBMT_RDG_TEXTURE, TShaderResourceParameterTypeInfo<FRDGTexture*>, FRDGTexture*, MemberName, , = nullptr, ..., TEXT(#ShaderType), false) #define SHADER_PARAMETER_RDG_TEXTURE_SRV(ShaderType,MemberName) \ INTERNAL_SHADER_PARAMETER_EXPLICIT(UBMT_RDG_TEXTURE_SRV, TShaderResourceParameterTypeInfo<FRDGTextureSRV*>, FRDGTextureSRV*, MemberName, , = nullptr, ...)

批注：UBMT 是关键

UBMT_*（Uniform Buffer Member Type）是引擎给每种参数成员打的类型标签：UBMT_RDG_TEXTURE（RDG 纹理）、UBMT_RDG_TEXTURE_SRV（RDG SRV=读）、UBMT_RDG_BUFFER_UAV（RDG UAV=写）、UBMT_INT32/UBMT_FLOAT32（常量）……宏把每个成员的 UBMT 类型 + 偏移 + 名字 + shader 端类型字符串 记进结构体的元数据。RDG 就是靠遍历这些 UBMT 标签，判断每个资源成员是读（SRV/Texture）还是写（UAV/RenderTarget）——这正是 #3 "参数结构体是依赖推导唯一信息源"的底层实现。TShaderResourceParameterTypeInfo<T> 是模板萃取，编译期算出该成员的对齐/大小/如何 memcpy。

BEGIN/END：编译期收集成员 Struct declaration

// ShaderParameterMacros.h : L1411-L1420#define BEGIN_SHADER_PARAMETER_STRUCT(StructTypeName, DllStorage) \ INTERNAL_SHADER_PARAMETER_STRUCT_BEGIN(StructTypeName,, {}, \ INTERNAL_SHADER_PARAMETER_GET_STRUCT_METADATA(StructTypeName), \ INTERNAL_SHADER_PARAMETER_STRUCT_CREATE_UNIFORM_BUFFER) #define END_SHADER_PARAMETER_STRUCT() \ zzLastMemberId; \ public: \ static TArray<FShaderParametersMetadata::FMember> zzGetMembers() { /* 逐成员回溯收集 */ }

批注：一个编译期链表技巧

BEGIN/END 之间的每个 SHADER_PARAMETER_* 宏，除了声明成员变量，还悄悄声明了一个带序号的 zzMemberId 与一个 append 函数。END_SHADER_PARAMETER_STRUCT 从 zzLastMemberId 反向回溯这条编译期成员链，把所有成员的 FMember（含 UBMT 类型、偏移、名字）收集成 TArray，构成该结构体的 FShaderParametersMetadata。这套"用重载决议 + 递增 ID 在编译期遍历成员"的技巧，是无反射的 C++ 里实现"结构体自省"的经典手法。有了元数据，运行时才能：① 绑定到 shader（#11）；② 让 RDG 遍历资源成员建依赖（#3/#5）；③ 校验（#8）。

本篇小结 Summary

记住这几点

1. SHADER_PARAMETER_* 宏把每个成员映射到一个 UBMT_* 类型标签（区分常量/SRV=读/UAV=写/RDG 追踪与否）。

2. BEGIN/END_SHADER_PARAMETER_STRUCT 用编译期成员链收集出 FShaderParametersMetadata（成员表）。

3. UBMT 标签是 RDG 判断读/写、进而推导依赖与屏障的底层依据——呼应 #3 的"参数结构体是唯一信息源"。

4. 元数据支撑三件事：绑定 shader（#11）、建依赖（#5）、校验（#8）。

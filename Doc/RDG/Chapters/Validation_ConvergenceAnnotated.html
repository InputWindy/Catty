#8 Validation · 校验层

RDG 在非发布构建下（RDG_ENABLE_DEBUG，#1）自带一套校验层，把"pass 声明与实际使用不符""读未写资源""生命周期外访问"等隐蔽 bug 在开发期就 assert 出来。本篇讲 FRDGUserValidation（用户 API 校验）与 FRDGBarrierValidation（屏障校验）的检查点。源码取自 RenderGraphValidation.h。

两个校验器 Two validators

校验器管什么
FRDGUserValidation用户 API 层：AddPass 参数合法性、执行前后状态、资源访问是否越界生命周期
FRDGBarrierValidation屏障层：transition 是否正确、是否有资源在错误访问态被用

零成本抽象

这些校验全部包在 RDG_ENABLE_DEBUG 里（#1），发布版彻底编空。开发期它们是发现 RDG 用法错误的第一道防线——尤其是 #3 讲的"lambda 里用了但没在参数结构体声明"这类问题。

配套附录

FRDGUserValidation 全部 Validate* 检查点、TryMarkForClobber clobber 机制见 → 校验点附录。

FRDGUserValidation：用户 API 校验 User validation

校验器的检查点分布在图的关键时刻，真实源码：

// RenderGraphValidation.h : L40-L113（节选）class FRDGUserValidation final { public: /** Validate pass creation. */ void ValidateAddPass(const void* ParameterStruct, const FShaderParametersMetadata* Metadata, const FRDGEventName& Name, ERDGPassFlags Flags); void ValidateAddPass(const FRDGPass* Pass); /** Validate pass state before and after execution. */ void ValidateExecutePassBegin(const FRDGPass* Pass); void ValidateExecutePassEnd(const FRDGPass* Pass); /** Validate graph state before and after execution. */ void ValidateExecuteBegin(); void ValidateExecuteEnd(); /** Attempts to mark a resource for clobbering. If already marked, returns false. */ bool TryMarkForClobber(FRDGViewableResource* Resource) const; };

批注：检查点分布

创建时 ValidateAddPass：检查参数结构体与其元数据（#10）是否匹配、flags 是否自洽（如 SkipRenderPass 只能配 Raster）。执行前后 ValidateExecutePassBegin/End：这对是抓"漏声明"的关键——它会检查 pass lambda 实际访问的资源是否都在参数结构体里声明过、是否处于正确访问态。整图前后 ValidateExecuteBegin/End：检查图整体一致性（如是否有被 extract 的资源从未被写）。回顾 #6 执行篇：ExecuteSerialPass 里就有 IF_RDG_ENABLE_DEBUG(UserValidation.ValidateExecutePassBegin(Pass)) 的调用。

Clobber：主动"投毒"暴露漏声明 Resource clobbering

TryMarkForClobber 的妙用

TryMarkForClobber 支撑一个强力调试功能（CVar r.RDG.ClobberResources）：开启后，RDG 在资源被写之前先用一个显眼的"垃圾值"填满它。这样——如果某个 pass读到了这个垃圾值，就说明它读的资源其实没被正确产生（漏了依赖或漏了声明），画面会出现明显异常，一眼定位。这是"用可见的错误逼出隐藏的漏声明"的经典手法。配合 r.RDG.CullPasses 0（#5）与 Validation assert，构成 RDG 三件调试利器。

本篇小结 Summary

记住这几点

1. 校验层全包在 RDG_ENABLE_DEBUG 里，发布版编空；开发期是 RDG 用法错误的第一道防线。

2. FRDGUserValidation 检查点：创建（ValidateAddPass）、执行前后（ValidateExecutePassBegin/End，抓漏声明）、整图前后。

3. Clobber（TryMarkForClobber + r.RDG.ClobberResources）：写前投毒，读到垃圾即暴露漏依赖/漏声明。

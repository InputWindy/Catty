#2 附录 · RDG 资源类型速查

本篇列出 RenderGraphResources.h 里的主要资源/视图类及其源码位置（UE5.8，1516 行），并给出 FRDGView 家族的真实源码定位。

FRDGView：视图基类真实源码定位

// RenderGraphResources.h : L500 起class FRDGView : public FRDGResource { // 视图指向一个 FRDGViewableResource（其父资源） // SRV/UAV 由派生类 FRDGShaderResourceView / FRDGUnorderedAccessView 具体化 // GetRHI() 在派生类里转成 FRHIShaderResourceView* / FRHIUnorderedAccessView* };

为什么视图也是图节点

视图（SRV/UAV）是 shader 真正绑定的对象——pass 参数结构体里写的是 FRDGTextureSRVRef/FRDGBufferUAVRef 而非资源本身。RDG 把视图也纳入图管理，是因为同一资源可有多个视图（不同 mip/format/subresource），而屏障与访问追踪需要精确到"哪个视图以哪种 ERHIAccess 被用"。视图的 GetRHI() 同样延迟到执行期——它依赖父资源先被分配。

Desc 结构：创建资源的配方

结构关键字段说明
FRDGTextureDescExtent / Format / NumMips / Flags(ETextureCreateFlags)等价于 RHI 纹理创建描述；CreateTexture(Desc, Name) 的入参
FRDGBufferDescBytesPerElement / NumElements / Usage(EBufferUsageFlags)StructuredBuffer/ByteAddressBuffer/VertexBuffer 等由 Usage 决定；有 CreateStructuredDesc 等 helper

要点

Desc 是不可变的（资源类里是 const）：一旦 CreateTexture/CreateBuffer 给定，资源的尺寸/格式就固定了。这让编译期可以据 Desc 精确算出资源的显存占用，为瞬态分配器的别名复用（#15）提供依据。

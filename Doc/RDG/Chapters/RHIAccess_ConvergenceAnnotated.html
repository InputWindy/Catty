#14 ERHIAccess 转换状态机 · RDG 自动屏障推导的就是它

这一章是"RDG 为什么有价值"的底层真相。手写时代要人肉调 RHICmdList.Transition(资源, 从态, 到态)；RDG 帮你自动推导——而它推导的目标就是 ERHIAccess 状态与 FRHITransitionInfo。本篇讲清这套 GPU 资源访问状态机。源码取自 RHIAccess.h、RHITransition.h。

一句话 One sentence

RDG 的自动屏障 = 自动算 ERHIAccess 转换

每个 GPU 资源任一时刻处于某个 ERHIAccess 态（被当 SRV 读？被当 UAV 写？在拷贝？）。GPU 从一种用法切到另一种，硬件需要一次 transition（屏障）刷缓存/改布局。RDG 编译期从每个 pass 参数的 UBMT 类型（#10）推出每个资源在每个 pass 的目标 access，两两相邻求差，自动生成 FRHITransitionInfo——这就是 #6 屏障三段式处理的内容。

ERHIAccess：GPU 资源访问态全集 The state set

完整真实源码——每个 access 是一个位，可组合：

// RHIAccess.h : L10-L75（节选核心）enum class ERHIAccess : uint32 { // 前态未知，需 flush 所有 GPU 缓存 Unknown = 0, // —— 只读态 Read states —— CPURead = 1 << 0, Present = 1 << 1, // 呈现到屏幕 IndirectArgs = 1 << 2, // 间接派发参数 VertexOrIndexBuffer = 1 << 3, SRVCompute = 1 << 4, // compute 里当 SRV 读 SRVGraphicsPixel = 1 << 5, SRVGraphicsNonPixel = 1 << 6, CopySrc = 1 << 7, // 拷贝源 ResolveSrc = 1 << 8, DSVRead = 1 << 9, // 深度模板读 // —— 读写态 Read-write states —— UAVCompute = 1 << 10, // compute 里当 UAV 读写 UAVGraphics = 1 << 11, RTV = 1 << 12, // 渲染目标 CopyDest = 1 << 13, // 拷贝目标 ResolveDst = 1 << 14, DSVWrite = 1 << 15, // 深度模板写 // —— 光追加速结构 / 其它 —— BVHRead = 1 << 16, BVHWrite = 1 << 17, Discard = 1 << 18, // 瞬态资源释放态 ShadingRateSource = 1 << 19, // —— 组合掩码 —— SRVMask = SRVCompute | SRVGraphics, // 所有 SRV 读 UAVMask = UAVCompute | UAVGraphics, // 所有 UAV 读写 ReadableMask = ReadOnlyMask | UAVMask, WriteOnlyExclusiveMask = RTV | CopyDest | ResolveDst, };

批注：读态 vs 读写态 是分界

枚举被清晰分成两组：只读态（SRVCompute/CopySrc/DSVRead...）与读写态（UAVCompute/RTV/CopyDest...）。这个分界正是 RDG 判断"要不要插屏障"的依据：读→读（如 SRVCompute→SRVGraphics）通常可合并、屏障轻；写→读或写→写（如 UAVCompute→SRVCompute）必须插 transition 等 GPU 把写刷完。Unknown=0 是"前态不明、保守全刷"。掩码（SRVMask/UAVMask/ReadableMask）让代码能一次判断一个 access 是否属于某类。你在 Nanite/Lumen 里见到的 ERHIAccess::UAVCompute（记忆里那个符号）就出自这里——RDG uniform buffer 或手动 UseExternalAccessMode（#16）时会显式指定它。

这就是 RDG 的核心价值

#1 说"RDG 帮你管屏障"，具体管的就是本章的 ERHIAccess 转换：把最易错、最琐碎、最难并行的"人肉插 transition"变成"声明读写意图 → 机器推导最优 transition 集合"。理解了 ERHIAccess，就理解了 RDG 到底替你省了什么。

本篇小结 Summary

记住这几点

1. ERHIAccess 是 GPU 资源访问态位集：只读态（SRV/CopySrc/DSVRead...）vs 读写态（UAV/RTV/CopyDest...），Unknown=0 保守全刷。

2. transition（屏障）= 从一个 access 切到另一个；写→读/写→写必插，读→读常可合并。

3. RDG 自动屏障 = 从 pass 参数 UBMT 推每个资源的目标 access，相邻求差自动生成 FRHITransitionInfo——这就是 RDG 替代手写 Transition 的核心价值。

4. UAVMask/SRVMask 等掩码用于快速归类；ERHIAccess::UAVCompute 是业务代码高频显式指定的态。

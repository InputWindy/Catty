#7 Uniform Buffer 与 Blackboard

两个"把数据带进图"的机制：RDG Uniform Buffer（TRDGUniformBufferRef）——把一组资源引用+常量打包成 shader 能绑定的 uniform buffer，参与图的依赖追踪；Blackboard（FRDGBlackboard）——图作用域的类型化共享数据袋，免去跨模块层层传参。源码取自 RenderGraphBlackboard.h、RenderGraphBuilder.h。

两者定位 Two mechanisms

机制解决什么生命周期
RDG Uniform Buffer把多个资源 + 常量打包给 shader 绑定，且其中的 RDG 资源仍被图追踪图内，随 pass 使用
Blackboard跨 pass/跨模块共享一次创建、多处只读的结构体，免 marshaling绑定到图分配器，图末释放

配套附录

CreateUniformBuffer 签名、FRDGBlackboard 的 Create/GetChecked 全接口见 → UB/Blackboard 附录。

RDG Uniform Buffer：带资源引用的 UB RDG uniform buffer

与普通 RHI uniform buffer 的区别

普通 uniform buffer 里若放 SRV/UAV，是"裸" RHI 视图，图无从知晓依赖。RDG uniform buffer 里放的是 FRDGTextureRef/FRDGBufferSRVRef 等图句柄——于是一个 pass 只要在参数结构体里引用了某个 RDG uniform buffer，RDG 就自动把 UB 里所有 RDG 资源纳入该 pass 的读依赖。这让"一次打包、多 pass 复用"的视图/常量集合（典型如 FViewUniformShaderParameters、场景纹理 UB）也能享受自动屏障与生命周期。GraphBuilder.CreateUniformBuffer(Parameters) 返回 TRDGUniformBufferRef<T>，在执行期才真正把里面的 RDG 资源解引用成 RHI 视图并填进 RHI uniform buffer。

Blackboard：图作用域的类型化数据袋 Blackboard

Blackboard 的设计意图与用法，源码注释逐字真实：

// RenderGraphBlackboard.h : L22-L54/** The blackboard is a map of struct instances with a lifetime tied to a render graph allocator. * It is designed to solve cases where explicit marshaling of immutable data is undesirable. * Structures are created once and the mutable reference is returned. * * Good candidates would be data that is created once and immutably fetched across the entire * renderer pipeline, where marshaling would create more maintenance burden than benefit. */ // 用法示例（源码注释里给的）： class FMyStruct { public: FRDGTextureRef TextureA = nullptr; /* ... */ }; RDG_REGISTER_BLACKBOARD_STRUCT(FMyStruct); static void InitStruct(FRDGBlackboard& GraphBlackboard) { auto& MyStruct = GraphBlackboard.Create<FMyStruct>(); // 一次创建，返回可变引用 } static void UseStruct(const FRDGBlackboard& GraphBlackboard) { const auto& MyStruct = GraphBlackboard.GetChecked<FMyStruct>(); // 多处只读取用 }

批注

Blackboard 是一个按类型索引的 struct 实例表，生命周期绑定图分配器（#4 的 FRDGAllocator）。RDG_REGISTER_BLACKBOARD_STRUCT 用模板特化给每个类型注册一个稳定的类型名/索引。用法就两步：Create<T>()（一次，返回可变引用去填）+ GetChecked<T>()（多处，取只读引用）。它解决的痛点是：像"整帧共用的场景纹理集合"这种数据，若靠函数参数一层层传，会造成巨大的签名维护负担；放 blackboard 则任何持有 GraphBuilder.Blackboard 的地方都能取。注意源码注释的告诫：只适合"一次创建、全程只读"的数据；更受约束的数据仍应显式传参——滥用 blackboard 会让数据流变隐晦。

本篇小结 Summary

记住这几点

1. RDG Uniform Buffer 里放 RDG 资源句柄——引用它的 pass 自动获得对 UB 内所有 RDG 资源的读依赖；执行期才解引用成 RHI 视图。

2. Blackboard = 图作用域、按类型索引的共享 struct 表：Create<T> 一次填、GetChecked<T> 多处只读，免层层 marshaling。

3. Blackboard 只适合"一次创建、全程只读"的数据（源码注释明确告诫），别滥用。

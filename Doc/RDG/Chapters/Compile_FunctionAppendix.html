#5 附录 · RDG 编译算法

本篇给出 FRDGBuilder::Compile 的阶段划分（真实 named event）、关键 CVar 与引用计数字段，源码定位 RenderGraphBuilder.cpp（Compile 从 L1327 起）。

Compile() 的阶段（真实 named event）

// RenderGraphBuilder.cpp : L1327 起void FRDGBuilder::Compile() { SCOPE_CYCLE_COUNTER(STAT_RDG_CompileTime); const bool bCullPasses = GRDGCullPasses > 0; if (bCullPasses || AsyncComputePassCount > 0) { SCOPED_NAMED_EVENT(PassDependencies, FColor::Emerald); // 阶段①：建依赖 // ...遍历 pass 参数，AddPassDependency } if (bCullPasses) { SCOPED_NAMED_EVENT(PassCulling, FColor::Emerald); // 阶段②：剔除 // ...反向可达 + 引用计数回退 } }

批注

两个 SCOPED_NAMED_EVENT（PassDependencies / PassCulling）就是 RenderDoc/Insights 里能看到的编译子阶段。注意建依赖的条件是 bCullPasses || AsyncComputePassCount > 0——即使关了剔除，只要有异步计算 pass，也必须建依赖（否则无法在图形/异步队列间正确插 fence）。

关键 CVar 与字段

符号作用
GRDGCullPasses>0 时启用 pass 剔除；调 0 可关闭（调试用）
AsyncComputePassCount图中异步计算 pass 数；>0 强制建依赖
FRDGPass::Producers该 pass 依赖的生产者列表（反向可达遍历用）
FRDGPass::bCulled剔除标记：编译后仍为 true 则跳过执行
FRDGViewableResource::ReferenceCount存活引用它的 pass 数；归零即释放
FRDGPass::TextureStates / BufferStates该 pass 对各资源的访问态与引用计数贡献

调试技巧

怀疑"pass 被误剔"时，把 r.RDG.CullPasses 0（对应 GRDGCullPasses）临时关掉剔除——若现象消失，说明是漏了 NeverCull 或漏声明了某输出资源（#3 的经典坑）。

#6 执行 · 屏障批处理 / 异步计算 / 并行录制

全书最硬的一章。Execute() 的后半段把编译好的图变成真实 GPU 命令：分配瞬态资源、收集并批量创建屏障（CollectPassBarriers / CreatePassBarriers）、逐 pass 走序言/尾声提交屏障并 BeginRenderPass、把 pass 分发到并行任务（SetupParallelExecute）与异步计算队列。源码取自 RenderGraphBuilder.cpp（FRDGBuilder::Execute 起 L1766）。

执行流水线 Execute pipeline

① 分配资源AllocatePooledTextures/Buffers
瞬态分配器给 RHI
② 收集+建屏障CollectPassBarriers
CreatePassBarriers（并行）
③ 并行/异步编排SetupParallelExecute
async compute 分队列
④ 逐 pass 执行Prologue(提屏障+BeginRP)
→ lambda → Epilogue

Execute 内的任务图

UE5.8 的 Execute 高度任务化：分配、收集屏障、建视图都是可并行的 UE::Tasks::FTask（CollectPassBarriersTask / AllocatePooledTexturesTask / CreateViewsTask），彼此按数据依赖串起来。这本身就是"用 RDG 的依赖思想调度 RDG 自己的执行准备工作"。

配套附录

CollectPassBarriers/CreatePassBarriers/SetupParallelExecute 的分工、UAV overlap、异步计算 fence 见 → 执行算法附录。

屏障：先收集，再并行创建，最后提交 Barriers: collect → create → submit

屏障不是逐个即时插的，而是三段式。收集（把每个 pass 需要的 transition 汇总）真实源码：

// RenderGraphBuilder.cpp : L3872-L3883void FRDGBuilder::CollectPassBarriers() { SCOPED_NAMED_EVENT_TEXT("FRDGBuilder::CollectBarriers", FColor::Magenta); SCOPE_CYCLE_COUNTER(STAT_RDG_CollectBarriersTime); for (...) { CollectPassBarriers(PassHandle); } // 逐 pass 收集所需 transition }

创建（把收集到的 transition 批量、并行地造出来）真实源码：

// RenderGraphBuilder.cpp : L3930-L3977void FRDGBuilder::CreatePassBarriers() { // ... ParallelForWithTaskContext(TEXT("FRDGBuilder::CreatePassBarriers"), TaskContexts, TransitionCreateQueue.Num(), 1, [&](FTaskContext& TaskContext, int32 Index) { CreateTransition(TaskContext, TransitionCreateQueue[Index]); // 并行造 RHI transition }); }

批注：为什么分三段

手写 RHI 是"用一个资源前，就地插一个 Transition"——分散、无法批处理、还容易在并行录制里出竞态。RDG 改成：①收集（CollectPassBarriers 把整图所有需要的 transition 汇成一个 TransitionCreateQueue）→ ②并行创建（CreatePassBarriers 用 ParallelForWithTaskContext 多线程造 RHI transition 对象）→ ③提交（在每个 pass 的序言/尾声 Submit）。这样屏障既能批量合并（减少 GPU 停顿），创建又能并行（省 CPU 时间）。这是 RDG 相比手写"自动且更优"的屏障管理的核心。

Pass 序言 / 尾声：屏障提交与 RenderPass Prologue / Epilogue

每个 pass 执行前后各有一段固定动作。序言真实源码：

// RenderGraphBuilder.cpp : L3424-L3455void FRDGBuilder::ExecutePassPrologue(FRHIComputeCommandList& RHICmdListPass, FRDGPass* Pass) { const ERDGPassFlags PassFlags = Pass->Flags; const ERHIPipeline PassPipeline = Pass->Pipeline; if (Pass->PrologueBarriersToBegin) Pass->PrologueBarriersToBegin->Submit(RHICmdListPass, PassPipeline); // begin transition if (Pass->PrologueBarriersToEnd) Pass->PrologueBarriersToEnd->Submit(RHICmdListPass, PassPipeline); // end transition if (EnumHasAnyFlags(PassFlags, ERDGPassFlags::Raster)) { if (!EnumHasAnyFlags(PassFlags, ERDGPassFlags::SkipRenderPass) && !Pass->SkipRenderPassBegin()) static_cast<FRHICommandList&>(RHICmdListPass).BeginRenderPass(Pass->GetParameters().GetRenderPassInfo(), Pass->GetName()); } BeginUAVOverlap(Pass, RHICmdListPass); // 允许连续 UAV 写重叠 }

批注

序言做三件事：①提交屏障——把编译期算好、创建好的 transition 用 Submit 真正写进命令列表（分 begin/end 两半，对应 split barrier 优化）；②开 RenderPass——光栅 pass 且没标 SkipRenderPass 时，用参数结构体里的 GetRenderPassInfo()（渲染目标绑定）BeginRenderPass；③开 UAV overlap——告诉 RHI 接下来连续的 UAV 写可以重叠不必互相等。尾声（ExecutePassEpilogue L3457）对称收尾：EndUAVOverlap + EndRenderPass。屏障提交挂在序言/尾声，正是把"图边界哨兵"（#3）之外每个 pass 都变成有明确前后处理点的原因。

并行录制与异步计算 Parallel & async

// RenderGraphBuilder.cpp : L2841-L2846void FRDGBuilder::SetupParallelExecute(...) { SCOPED_NAMED_EVENT(SetupParallelExecute, FColor::Emerald); FRDGAllocatorScope AllocatorScope(Allocators.Task); const bool bTaskModeAsyncAllowed = ParallelExecute.TaskMode == ERDGPassTaskMode::Async; // ...把可并行的 pass 切成若干批，分发到 worker 线程各自录一段命令列表 }

批注

并行录制：符合 #1 并行约定（非 immediate 命令列表 + Parallel builder flag + 非 NeverParallel）的 pass 被 SetupParallelExecute 分批丢给 worker 线程，各自录一段 FRHICommandList，最后按图顺序拼接提交。异步计算：AsyncCompute pass（#3）走独立的异步计算队列，RDG 在编译期（#5 建的跨管线依赖有序表）算好在图形/异步队列之间该插的 fence，执行期据此下 fence——让计算与光栅真正在 GPU 上并行跑。这两者是 RDG 把"手写时代要人肉排的多线程/多队列同步"自动化的收官。

本篇小结 Summary

记住这几点

1. Execute 后半段 = 分配资源 → 收集/并行创建屏障 → 并行/异步编排 → 逐 pass 序言(提屏障+BeginRP)→lambda→尾声。

2. 屏障三段式：CollectPassBarriers（汇总）→ CreatePassBarriers（ParallelFor 并行造）→ 序言/尾声 Submit。批量+并行，优于手写就地插。

3. 序言 ExecutePassPrologue：提交 begin/end 屏障 + BeginRenderPass + BeginUAVOverlap；尾声对称收尾。

4. 并行录制（SetupParallelExecute 分批到 worker）与异步计算（跨队列 fence，用 #5 的跨管线依赖表）把多线程/多队列同步自动化。

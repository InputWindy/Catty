#9 Utils · 常用封装

日常业务代码里 90% 的 RDG 用法不是裸 AddPass，而是 RenderGraphUtils.h 的一层封装：FComputeShaderUtils::AddPass（一行发起 compute dispatch）、AddCopyTexturePass、AddClearUAVPass 等。本篇讲清这些封装如何在底层拼装 pass 参数与 lambda——读懂它们才读得懂业务代码。源码取自 RenderGraphUtils.h（1449 行）。

为什么要 Utils Why utils

一句话

裸 GraphBuilder.AddPass 要手写 EventName + 参数结构体 + flags + lambda（lambda 里还要手动 SetComputePipelineState/SetShaderParameters/DispatchComputeShader）。FComputeShaderUtils::AddPass 把这套模板一行搞定——传 shader、参数、GroupCount 即可。

配套附录

FComputeShaderUtils 各重载、AddCopyTexturePass/AddClearUAVPass 全签名与 GetGroupCount 见 → Utils 附录。

FComputeShaderUtils::AddPass：一行发 compute The compute helper

它内部就是拼一个 GraphBuilder.AddPass + 在 lambda 里调 Dispatch。真实源码：

// RenderGraphUtils.h : L333, L540-L564（节选）namespace FComputeShaderUtils { /** Ideal group size 8x8 to occupy at least an entire wave on GCN, two warps on Nvidia. */ // ... template <typename TShaderClass> inline FRDGPassRef AddPass(FRDGBuilder& GraphBuilder, FRDGEventName&& PassName, /* ...ComputeShader, Parameters, GroupCount... */) { return GraphBuilder.AddPass( Forward<FRDGEventName>(PassName), ParametersMetadata, Parameters, ERDGPassFlags::Compute, [Parameters, ComputeShader, ParametersMetadata, GroupCount](FRHIComputeCommandList& RHICmdList) { FComputeShaderUtils::Dispatch(RHICmdList, ComputeShader, ParametersMetadata, *Parameters, GroupCount); }); } }

批注

看清楚：FComputeShaderUtils::AddPass 只是转发到 GraphBuilder.AddPass（#4），把 flags 固定为 ERDGPassFlags::Compute，并在自动生成的 lambda 里调 FComputeShaderUtils::Dispatch（后者做 RHICmdList.SetComputeShader + SetShaderParameters + DispatchComputeShader）。所以它不是新机制，只是模板——你的 Parameters 结构体里声明的 RDG 资源，照样走 #3/#5 的依赖追踪、#6 的屏障。还有 GroupCountCallback 重载（#4 延迟尺寸的对应物），让 dispatch 的 group 数也能延迟到执行前算。多个重载覆盖固定/回调 group count、带/不带 flags。

AddClearUAVPass / AddCopyTexturePass：琐碎但高频 Clear & copy

// RenderGraphUtils.h : L699, L758-L780（节选，重载众多）void AddCopyTexturePass(FRDGBuilder& GraphBuilder, FRDGTextureRef InputTexture, FRDGTextureRef OutputTexture, const FRHICopyTextureInfo& CopyInfo); void AddClearUAVPass(FRDGBuilder& GraphBuilder, FRDGBufferUAVRef BufferUAV, uint32 Value, ERDGPassFlags ComputePassFlags = ERDGPassFlags::Compute); void AddClearUAVPass(FRDGBuilder& GraphBuilder, FRDGTextureUAVRef TextureUAV, const FLinearColor& ClearColor, ...); // ...十余个 AddClearUAVPass 重载：float / uint / FVector4 / FUintVector4 / 数组 / 带 rect ...

批注

这些是"一句话就能加进图的琐碎 pass"。AddClearUAVPass 有十几个重载——覆盖清成标量/向量/颜色、整型/浮点、可选 rect 范围，因为清 UAV 是渲染里极高频的操作。AddCopyTexturePass 封装 RHICopyTexture，自动把 input 标为读、output 标为写（默认 Copy flag）。它们的价值在于：让你不必为"清个 buffer""拷张图"这种小事手写整套 pass 声明——但底层依然是标准 RDG pass，享受一切自动管理。读业务代码时，看到这些 helper 就知道背后是一个 RDG pass。

本篇小结 Summary

记住这几点

1. Utils 是 RDG 最常用的一层封装，业务代码 90% 走它而非裸 AddPass。

2. FComputeShaderUtils::AddPass = 转发到 GraphBuilder.AddPass（固定 Compute flag）+ 自动 lambda 里 Dispatch；不是新机制，只是模板。

3. AddClearUAVPass（十余重载）/AddCopyTexturePass 把高频琐碎操作一行化，底层仍是标准 RDG pass。

4. Part 1 到此完结：声明（#2#3#4）→ 编译（#5）→ 执行（#6） + UB/Blackboard（#7）+ 校验（#8）+ Utils（#9）。

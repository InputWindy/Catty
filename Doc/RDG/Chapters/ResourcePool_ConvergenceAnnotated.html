#15 资源池演进 · 老 FRenderTargetPool → RDG 瞬态分配器

"为什么要 RDG"的历史答案。RDG 之前，中间渲染目标靠 FRenderTargetPool / IPooledRenderTarget 手动借还；RDG 之后，靠瞬态资源分配器（transient allocator）用资源别名（aliasing）在同一块显存上复用生命周期不重叠的资源。本篇讲这条演进与 FRDGPooledBuffer 的角色。源码取自 PooledRenderTarget.h、RHITransientResourceAllocator.h。

老世界：手动池化的痛 The old pain

// PooledRenderTarget.h : L19-L40（老资源池的描述结构）/** All necessary data to create a render target from the pooled render targets. */ struct FPooledRenderTargetDesc { static FPooledRenderTargetDesc Create2DDesc(FIntPoint InExtent, EPixelFormat InFormat, const FClearValueBinding& InClearValue, ETextureCreateFlags InFlags, ...); };

批注：手动借还的三宗罪

RDG 之前，一块中间 RT 要 GRenderTargetPool.FindFreeElement(Desc, OutRef, Name) 借出 IPooledRenderTarget，用完靠引用释放归还。三个问题：① 生命周期靠人——借了忘还就一直占着显存；② 无 aliasing——两块生命周期完全不重叠的 RT 也各占各的显存，浪费；③ 屏障要自己管（#14）。整个 UE4 渲染器充斥这种手动借还，是 bug 与显存浪费的重灾区。FPooledRenderTargetDesc 就是那个时代描述 RT 的结构（RDG 的 FRDGTextureDesc 可与它互转，保证兼容）。

新世界：瞬态分配器 + 资源别名 Transient allocator + aliasing

// RHITransientResourceAllocator.h : L535-L548class IRHITransientResourceAllocator { virtual FRHITransientTexture* CreateTexture(const FRHITextureCreateInfo& CreateInfo, const TCHAR* DebugName, const FRHITransientAllocationFences& Fences) = 0; virtual FRHITransientBuffer* CreateBuffer(const FRHIBufferCreateInfo& CreateInfo, const TCHAR* DebugName, const FRHITransientAllocationFences& Fences) = 0; };

批注：aliasing 是关键升级

RDG 用编译期算出的生命周期区间（#5：首末次使用）喂给 IRHITransientResourceAllocator。分配器维护一块大显存堆，把生命周期不重叠的资源别名（alias）到同一段物理内存——A 用完了，那段内存立刻给 B 用。FRHITransientAliasingOverlap（源码 L244）记录哪些资源发生了 aliasing 重叠，配合 Fences 保证 GPU 上 A 真的用完才让 B 开始。效果：一帧几百个中间纹理可能只占相当于几十个的显存。这是 RDG 相比手动池化最直接的收益——而且全自动，开发者只管声明。CreateInfo 里带 Fences 正是 aliasing 安全的保证。注：源码注释提到 aliasing overlap 目前主要在 RHI validation 下追踪。

FRDGPooledBuffer / IPooledRenderTarget：跨帧的桥 The cross-frame bridge

不是所有资源都瞬态

瞬态 aliasing 只适用单帧内生命周期明确的资源。有些资源要跨帧存活（历史帧颜色、累积 buffer——TSR/Lumen 时域复用的核心）。这类走 TRefCountPtr<IPooledRenderTarget>（纹理）/ TRefCountPtr<FRDGPooledBuffer>（buffer）——引用计数的持久池化对象，跨帧持有。RDG 用 RegisterExternal* 把它们注册进图、用 Queue*Extraction 把图内资源提取成它们（#16）。所以完整图景是：帧内瞬态资源走 aliasing 分配器（省显存）；跨帧资源走引用计数池化对象（安全存活）——两者由 #16 的互通 API 衔接。

本篇小结 Summary

记住这几点

1. 老世界 FRenderTargetPool/IPooledRenderTarget：手动借还，无 aliasing，易漏易浪费——这是"为什么要 RDG"的痛点起点。

2. 新世界 IRHITransientResourceAllocator：用 #5 算出的生命周期，把不重叠资源 alias 到同一显存，全自动、大幅省显存；Fences 保证 GPU 安全。

3. 跨帧资源走 TRefCountPtr<IPooledRenderTarget/FRDGPooledBuffer> 持久池化对象，由 #16 的 Register/Extract 与图衔接。

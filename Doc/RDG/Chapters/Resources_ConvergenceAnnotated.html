#2 资源模型 · FRDGTexture / Buffer / View 与生命周期

图的第一类节点是虚拟资源。本篇讲清 RDG 资源的继承层次（FRDGResource → FRDGViewableResource → FRDGTexture/FRDGBuffer）、"虚拟句柄 vs 已分配 RHI"的关键区别、bExternal/bExtracted/bProduced 生命周期标志，以及 debug 下的 RHI 访问校验。所有类/字段取自 RenderGraphResources.h。

继承层次一眼看懂 Class hierarchy

FRDGResource所有 RDG 资源基类
持 Name + ResourceRHI 指针
FRDGViewableResource可被 View 引用的资源
bExternal/bExtracted/bProduced
FRDGTexture / FRDGBuffer具体纹理/缓冲
持 Desc + Flags
FRDGView 家族SRV/UAV：对资源的一个视图

两条继承线

一条是"可被视图引用的资源"：FRDGResource → FRDGViewableResource → FRDGTexture/FRDGBuffer；另一条是"视图"：FRDGView → FRDGShaderResourceView(SRV)/FRDGUnorderedAccessView(UAV)。此外还有 FRDGUniformBuffer 也直接继承 FRDGResource（见 #7）。

配套附录

各资源类的完整字段、FRDGTextureDesc/FRDGBufferDesc 结构、句柄类型见 → 资源类型附录。

基类 FRDGResource：虚拟句柄 + 延迟 RHI Virtual handle

RDG 资源的基类只做两件事：记个调试名，持一个可能为空的 RHI 指针。这是真实源码：

// RenderGraphResources.h : L134-L183class FRDGResource { public: FRDGResource(const FRDGResource&) = delete; virtual ~FRDGResource() = default; // Name of the resource for debugging purpose. const TCHAR* const Name = nullptr; /** Marks this resource as actually used. Tracks which pass dependencies were unnecessary. */ #if RDG_ENABLE_DEBUG virtual void MarkResourceAsUsed(); #else inline void MarkResourceAsUsed() {} #endif FRHIResource* GetRHI() const { IF_RDG_ENABLE_DEBUG(ValidateRHIAccess()); return ResourceRHI; } protected: FRHIResource* ResourceRHI = nullptr; #if RDG_ENABLE_DEBUG void ValidateRHIAccess() const; uint8 bAllowRHIAccess : 1; // 见 private 段 #endif friend FRDGBuilder; };

批注：为什么 GetRHI 要校验

核心一行是 FRHIResource* ResourceRHI = nullptr——声明资源时它就是空的，直到执行期被瞬态分配器回填。所以 GetRHI() 只能在 pass 执行 lambda 内调用（那时 RHI 已分配好）；若在声明期误调，debug 构建的 ValidateRHIAccess() 会断言报错。这就是源码注释反复强调的"The following methods may only be called during pass execution"。MarkResourceAsUsed() 则服务于校验：追踪某个被声明为依赖的资源是否真的被用到，帮开发者发现多余依赖。

FRDGViewableResource：三个生命周期标志 Lifetime flags

可被视图引用的资源在基类上加了三个决定生命周期与剔除的布尔。真实源码：

// RenderGraphResources.h : L293-L358class FRDGViewableResource : public FRDGResource { public: const ERDGViewableResourceType Type; /** externally registered (user holds a ref outside the graph). */ bool IsExternal() const { return bExternal; } /** queued for extraction at the end of graph execution. */ bool IsExtracted() const { return bExtracted; } /** a prior pass produced contents for this resource (any subresource write). */ bool HasBeenProduced() const { return bProduced; } protected: bool IsCullRoot() const { return bExternal || bExtracted; } };

逐标志批注

bExternal：资源是从图外注册进来的（RegisterExternalTexture，见 #16），用户在图外持有它的引用。

bExtracted：资源被 QueueTextureExtraction 排队要在图执行结束时提取出去（跨帧持有）。

bProduced：图中已有 pass 对它做过写操作——用来判断"读一个还没被写过的资源"这种错误。

关键是 IsCullRoot() = bExternal || bExtracted：外部或被提取的资源是剔除的"根"——因为它们的内容要被图外世界使用，产生它们的 pass 绝不能被剔掉。这正是 #5 编译剔除算法的起点：从所有 cull root 反向遍历，凡不可达的 pass 就是死代码。

FRDGTexture：具体纹理 Concrete texture

// RenderGraphResources.h : L569-L598class FRDGTexture final : public FRDGViewableResource { public: static const ERDGViewableResourceType StaticType = ERDGViewableResourceType::Texture; const FRDGTextureDesc Desc; // 尺寸/格式/mip/flags——创建时给定 const ERDGTextureFlags Flags; /** Returns the allocated RHI texture. (pass execution only) */ inline FRHITexture* GetRHI() const { return static_cast<FRHITexture*>(FRDGResource::GetRHI()); } inline FRDGTextureHandle GetHandle() const { return Handle; } };

批注

FRDGTexture 是 final，持一个不可变的 FRDGTextureDesc（尺寸、格式、mip 数、用途 flags——见附录）。它的 GetRHI() 把基类的 FRHIResource* 向下转成 FRHITexture*（RDG 之下真正的 GPU 纹理，见 #13）。FRDGTextureHandle 是个轻量索引句柄——图内部大量用 handle 而非裸指针来引用资源，便于数组化存储与序列化调试。FRDGBuffer 结构完全对称（持 FRDGBufferDesc，GetRHI() 转 FRHIBuffer*）。

资源的一生 Lifecycle

1 声明CreateTexture → 得句柄
ResourceRHI 仍为 null
2 编译算首末次使用
定分配/释放时机
3 分配瞬态分配器给 RHI
回填 ResourceRHI
4 使用pass lambda 内 GetRHI()
绑定到 shader
5 回收/提取帧末回池复用
或 Extract 跨帧

一句话

一个 RDG 资源从"纯句柄"（无显存）→ 编译期确定生命周期 → 执行期分配真实 RHI → pass 内使用 → 帧末回收或提取。理解这条线，就理解了为什么 GetRHI() 不能在声明期调、为什么 RDG 能把生命周期不重叠的资源别名到同一块显存（#15）。

本篇小结 Summary

记住这几点

1. 层次：FRDGResource（名+RHI指针基类）→ FRDGViewableResource（+生命周期标志）→ FRDGTexture/FRDGBuffer；视图另成 FRDGView 家族。

2. RDG 资源是虚拟句柄：ResourceRHI 声明期为 null，执行期才回填，故 GetRHI() 只能在 pass lambda 内调。

3. 三个标志 bExternal/bExtracted/bProduced：前两者构成剔除根 IsCullRoot()，是 #5 剔除算法的起点。

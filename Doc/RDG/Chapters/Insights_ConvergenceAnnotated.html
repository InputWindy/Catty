#18 RenderGraphInsights · RDG 剖析工具

Part 4 开篇。RenderGraphInsights 是个独立插件，把每帧 RDG 的 pass、资源、屏障、异步计算 timeline 通过 UE Trace 记录，在 Unreal Insights 里画成轨道（track）——用来定位"哪个 pass 慢""哪些资源没 alias 上""异步计算有没有真并行"。源码取自 Plugins/RenderGraphInsights/（RenderGraphTrack.cpp 2377 行）。

数据流 Trace → Provider → Track

环节组件作用
埋点RDG 里 IF_RDG_ENABLE_TRACE（#1）Execute 时把 pass/资源/屏障写进 UE Trace
解析FRenderGraphProvider从 trace 读回，重建每帧的图结构
绘制FRenderGraphTrack（+DrawHelper）在 Insights 时间线画 pass/资源轨道

配套附录

FRenderGraphProvider / FPassPacket / FRenderGraphTrack 文件与行号见 → Insights 附录。

Provider：从 trace 重建图 Provider

// RenderGraphProvider.h : L203-L213class FRenderGraphProvider : public TraceServices::IProvider { void AddGraph(const UE::Trace::IAnalyzer::FOnEventContext& Context, double& OutEndTime); void AddGraphEnd(); void AddPass(FPassPacket Pass); // 每个 pass 一个 packet };

批注

FRenderGraphProvider 是 Insights 的数据提供者：分析器从 UE Trace 流里读到 RDG 事件，调 AddGraph/AddPass/AddGraphEnd 重建出"这一帧有哪些图、每张图有哪些 pass"。FPassPacket 携带一个 pass 的名字、耗时、pipeline、读写资源等——正是 #3 那个 FRDGPass 的 trace 快照。因为埋点包在 IF_RDG_ENABLE_TRACE（#1）里，发布版零开销。

能看出什么 What it reveals

三类典型诊断

① pass 耗时/依赖：时间线上每个 pass 一个块，看谁最宽（GPU 慢）、谁在等谁（依赖链长）。

不同点：② 资源 aliasing：资源轨道能看出哪些资源共享了同一段显存（#15）——若某资源"本该 alias 却独占"，说明生命周期算错或漏了 NeverCull 导致 pass 没被剔。

不同点：③ 异步计算重叠度：graphics 轨道与 async compute 轨道并排，一眼看出异步计算有没有真的和光栅并行（#6），还是被 fence 卡成串行——这是异步计算调优的核心视图。

与其它调试手段的分工

#8 校验抓"用法错"、#17 vis 看"资源内容对不对"、本章 Insights 看"时序/依赖/内存对不对"。性能问题主要靠 Insights；正确性问题主要靠校验 + vis + clobber。

本篇小结 Summary

记住这几点

1. RenderGraphInsights = UE Trace 埋点（IF_RDG_ENABLE_TRACE，发布版零开销）→ FRenderGraphProvider 重建图 → FRenderGraphTrack 在 Insights 画轨道。

2. 三类诊断：pass 耗时/依赖、资源 aliasing 复用、异步计算与光栅的并行重叠度。

3. 分工：性能看 Insights；正确性看校验（#8）+ vis（#17）+ clobber。

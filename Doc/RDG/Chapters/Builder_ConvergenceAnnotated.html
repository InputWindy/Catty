#4 FRDGBuilder · 使用入口

FRDGBuilder 是开发者唯一直接打交道的门面：创建资源、添加 pass、最后 Execute。本篇讲清这套 API 的调用约定与语义——尤其是"CPU 描述贯穿整图、RHI 生命周期只对声明它的 pass 保证"这个关键契约，以及 builder 自带的线性分配器 FRDGAllocator。签名与注释取自 RenderGraphBuilder.h。

一眼看懂：一次典型用法 Typical usage

1 构造FRDGBuilder GraphBuilder(RHICmdList, RDG_EVENT_NAME(...))
2 建资源CreateTexture / CreateBuffer / CreateUAV
3 加 passAddPass(Name, Params, Flags, Lambda)
4 执行GraphBuilder.Execute()

门面模式

整个 RDG 复杂度（编译、瞬态分配、屏障、异步、并行）都藏在 Execute() 一次调用背后。开发者只需线性地"建资源 → 加 pass"，无需关心顺序之外的任何调度——这正是声明式的体验。

配套附录

CreateSRV/CreateUAV 全重载、AddPass 各签名、FRDGAllocator 与外部桥接 API 见 → Builder 接口附录。

CreateTexture / CreateBuffer：注释里藏着关键契约 The lifetime contract

这两个函数的源码注释定义了 RDG 最重要的资源契约，逐字真实：

// RenderGraphBuilder.h : L99-L110/** Create graph tracked texture from a descriptor. The CPU memory is guaranteed to be * valid through execution of the graph, at which point it is released. The underlying * RHI texture lifetime is only guaranteed for passes which declare the texture in the * pass parameter struct. The name is used for GPU debugging tools and the VisualizeTexture/Vis command. */ FRDGTextureRef CreateTexture(const FRDGTextureDesc& Desc, const TCHAR* Name, ERDGTextureFlags Flags = ERDGTextureFlags::None); /** Create graph tracked buffer from a descriptor. ... * The underlying RHI buffer lifetime is only guaranteed for passes which declare the buffer * in the pass parameter struct. ... */ FRDGBufferRef CreateBuffer(const FRDGBufferDesc& Desc, const TCHAR* Name, ERDGBufferFlags Flags = ERDGBufferFlags::None);

批注：两种"生命周期"要分清

注释区分了两层：① CPU 端的描述/句柄——从 Create 到 Execute 结束都有效；② 底层 RHI 资源——只对在参数结构体里声明了它的 pass 保证有效。换句话说，你不能指望"上一个 pass 建的 RHI 纹理，下一个没声明它的 pass 还能拿到"——因为 RDG 可能已经把那块显存别名给了别的资源（#15）。这条契约是理解 RDG 资源别名复用的关键，也是"为什么 pass 必须老实声明所有用到的资源"的根本原因。Name 还兼作 GPU 调试工具与 vis 命令（#17）的显示名。

还有一个"延迟尺寸"变体，真实源码：

// RenderGraphBuilder.h : L112-L116/** A variant of CreateBuffer where users supply NumElements through a callback. This allows * creating buffers with sizes unknown at creation time. The callback is called before executing * the most recent RDG pass that references the buffer ... */ FRDGBufferRef CreateBuffer(const FRDGBufferDesc& Desc, const TCHAR* Name, FRDGBufferNumElementsCallback&& NumElementsCallback, ERDGBufferFlags Flags = ...);

批注

这是 RDG"延迟决定"哲学的又一体现：某些 buffer 的元素数量要等前面的 GPU pass 算完才知道（比如 GPU 剔除后剩多少实例）。用回调版 CreateBuffer，RDG 会在真正需要该 buffer 的最后时刻才调回调拿到 NumElements 再分配——声明时给不出大小也没关系。Nanite/Lumen 里大量间接派发用的就是它。

Execute：一切发生的地方 Where it all happens

// RenderGraphBuilder.h : L412 · RenderGraphBuilder.cpp : L1766void Execute(); // 声明 // 实现（RenderGraphBuilder.cpp）： void FRDGBuilder::Execute() { CSV_SCOPED_TIMING_STAT_EXCLUSIVE(RDG); RHI_BREADCRUMB_EVENT_F(RHICmdList, "RenderGraphExecute", /* ... */); // 内部依次：Compile() → 分配瞬态资源 → 逐 pass 插屏障并执行 → 收尾提取 }

批注

在此之前所有的 CreateTexture/AddPass 都只是往图里记账，没有任何 GPU 工作发生。Execute() 被调用时，RDG 先跑 #5 编译（Compile()），再跑 #6 执行（分配+屏障+录制）。FRDGBuilder 通常是栈上局部对象——一个渲染视图/一帧构造一个，Execute 完即析构，其线性分配器（下段）一次性释放所有图内临时内存。

FRDGAllocator：图作用域的线性分配器 Arena allocator

为什么 RDG 自带分配器

一张图里要 new 成百上千个小对象（pass、资源、view、参数结构体副本）。若用全局堆分配，碎片与开销都不可接受。RDG 用 FRDGAllocator（RenderGraphAllocator.h）——一种 arena / 线性分配器：从大块内存里顺序切分，只分配不单独释放，图析构时整块一次性回收。这与"图是单帧、Execute 后整体丢弃"的生命周期完美契合。#1 讲的并行/异步任务如果延续到 Execute 之后，RDG 会保持 allocator 存活直到任务完成——这也是 FRDGAsyncTask 约定背后的内存安全保证。

本篇小结 Summary

记住这几点

1. FRDGBuilder 是唯一门面：构造 → CreateTexture/Buffer → AddPass → Execute，通常栈上局部对象、单帧生命周期。

2. 关键契约：CPU 描述贯穿整图，RHI 资源只对声明它的 pass 保证——这是资源别名复用的前提，也是"必须老实声明"的根因。

3. 回调版 CreateBuffer 支持延迟尺寸；Execute() 之前一切只是记账，Execute 内才跑编译+执行。

4. FRDGAllocator 是 arena 分配器：只分配、图末整块回收。

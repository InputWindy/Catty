#3 附录 · RDG Pass 类型

本篇给出 RenderGraphPass.h 里几种 pass 具体类型的真实源码：普通 TRDGLambdaPass、派发式 FRDGDispatchPass、以及图首尾的哨兵 FRDGSentinelPass。

Pass 类型清单

类型作用RenderGraphPass.h
FRDGPass所有 pass 基类：名字/参数/flags/pipeline/handleL220
TRDGLambdaPass<Params, Lambda>最常用：带参数结构体 + 执行 lambda 的 pass 模板L659
FRDGDispatchPass派发式 pass：把子命令列表异步提交L719
TRDGEmptyLambdaPass无参数（FEmptyShaderParameters）的 passL808
FRDGSentinelPass图的序言/尾声哨兵 pass（NeverCull）L821

TRDGLambdaPass：最常用的 pass 模板

// RenderGraphPass.h : L659-L673（构造 + 执行）TRDGLambdaPass(FRDGEventName&& InName, ..., const ParameterStructType* InParameterStruct, ERDGPassFlags InPassFlags, ExecuteLambdaType&& InExecuteLambda) : FRDGPass(MoveTemp(InName), FRDGParameterStruct(InParameterStruct, InParameterMetadata), InPassFlags, ExecuteLambdaTraits::TaskMode) , ExecuteLambda(MoveTemp(InExecuteLambda)) {} // 执行期真正调用 lambda： AUTORTFM_INFER void ExecuteLambdaFunc(FRHIComputeCommandList& RHICmdList) { /* 调 ExecuteLambda */ }

批注

GraphBuilder.AddPass(Name, Params, Flags, Lambda) 在内部就 new 一个 TRDGLambdaPass。它把参数结构体指针 + 其元数据打包成 FRDGParameterStruct（#5 编译遍历的对象），并存下执行 lambda。ExecuteLambdaTraits::TaskMode 是模板推导出来的——它检查 lambda 的第一个形参类型（immediate 还是普通命令列表、有没有 FRDGAsyncTask 标记）来决定这个 pass 能否并行/异步，正对应 #1 讲的并行约定。

FRDGSentinelPass：图的首尾哨兵

// RenderGraphPass.h : L821-L829/** Render graph pass used for the prologue / epilogue passes. */ class FRDGSentinelPass final : public FRDGPass { FRDGSentinelPass(FRDGEventName&& Name, ERDGPassFlags InPassFlagsToAdd = ERDGPassFlags::None) : FRDGPass(MoveTemp(Name), FRDGParameterStruct(&EmptyShaderParameters, ...), ERDGPassFlags::NeverCull | InPassFlagsToAdd, ERDGPassTaskMode::Async) { bSentinel = 1; } };

批注

每张 RDG 图内部都有两个哨兵 pass：序言（prologue）和尾声（epilogue）。它们无实际工作，但作为图的固定起点/终点，让屏障推导、外部资源的首次/末次转换、提取收尾都有明确的挂靠点。注意它们标了 NeverCull——哨兵永不被剔。这是 RDG 内部实现的一个优雅设计：把"图的边界"也建模成 pass，算法无需为边界写特例。

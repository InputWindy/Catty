Engine/Shaders/Private/MegaLights/MegaLightsShading.usf · ShadeLightSamplesCS L185 / RWResolvedDiffuseLighting L69

0. 按 tile 类型施光

tile permutation：Simple/Complex/Single/ComplexSpecial × Rect/Textured
逐样本：读可见性 → 按光源类型（Rect/IES/LightFunction）施光

说明

#4 的 ETileType 在这里落成 shader permutation：简单 tile 走精简路径、复杂 tile 才编译各向异性/次表面/矩形光带纹理等分支，空 tile 直接清零。每个降采样样本带着 追踪求出的可见性权重参与施光，支持 Rect/Textured/IES/LightFunction/Transmission。

1. Resolve：降分 → 全分，两路分离（汇聚点）

RWResolvedDiffuseLighting  / RWResolvedSpecularLighting
RWShadingConfidence  // 样本命中越一致越高

说明

本 shader 的汇聚点：把降分辨率、每像素少样本的着色结果积分 + 上采样成全分辨率的 Diffuse/Specular 两路（分开因为去噪需不同强度——镜面滤太狠糊高光），并输出 ShadingConfidence 驱动 #5 空间滤波强度。这是随机采样管线特有的"重建"步——传统确定性施光不需要。

2. 回写 VisibleLightHash：闭合历史引导

VisibleLightHashCS → 记录本 tile 哪些光可见/被挡
→ 下一帧 #2 采样的 Guide by History 读取

说明

着色顺手回写可见光哈希（MegaLightsVisibleLightHash.usf）：本帧这个 tile 里哪些光实际可见、哪些被挡，写进哈希供下一帧采样阶段做 Guide by History。这就闭合了"采样读上帧哈希 → 追踪求可见性 → 着色回写本帧哈希"的时域引导环路——MegaLights 降噪的关键闭环。

最终总结

骨架

按 tile 类型 permutation 施光（含 Rect/Textured/IES/LightFunction）→ Resolve 降分→全分重建 Diffuse/Specular 两路 + ShadingConfidence → 回写 VisibleLightHash 闭合历史引导。把"稀疏样本"变成"可去噪的两路光照"。

MegaLightsVisibleLightHash.usf 整源解析

MegaLights 时域引导环路的写端：着色求出可见性后，统计本 tile 里哪些光可见 / 哪些被挡，用 XXHash32 打进可见光哈希 + 隐藏光哈希，供下一帧 Sampling 的 Guide by History 读取。核心 VisibleLightHashCS（8×8）+ 体积版 VolumeVisibleLightHashCS。下方内嵌完整 188 行真实源码，再逐段真实代码批注。

VisibleLightHashCS @ L30 · VolumeVisibleLightHashCS @ L153

0. 逐样本统计可见/隐藏光（发散点）

for (SampleOffsetY ...) for (SampleOffsetX ...)
{
    const FLightSample LightSample = UnpackLightSample(LightSamples[SampleCoord]);
    if (LightSample.LocalLightIndex != MAX_LOCAL_LIGHT_INDEX && LightSample.Weight > 0.0)
    {
        const uint LightHash = XXHash32(LightSample.LocalLightIndex);
        if (LightSample.bVisible) MarkVisibleLight(VisibleLightHash, LightHash);
        else                      MarkHiddenLight(HiddenLightHash, LightHash);
    }
}

说明

一个线程组负责一个 VISIBLE_LIGHT_HASH_TILE_SIZE 大小的屏幕 tile，组内线程分摊 tile 内所有样本。每个已追踪样本（Weight>0）按其光源索引算 XXHash32 哈希，按 bVisible 分别 MarkVisibleLight/MarkHiddenLight 置位——用哈希位图而非精确光源列表，是为了定长、省内存、可跨帧比对。FAST_CLEAR tile（全空）直接 return。

1. 波前归约 + 写共享/全局哈希（汇聚点）

for (IndexInHash ...) VisibleLightHash[i] = WaveActiveBitOr(VisibleLightHash[i]);
for (IndexInHash ...) HiddenLightHash[i] = WaveActiveBitOr(HiddenLightHash[i]);
uint LaneIndex = WavePrefixCountBits(true);
if (LaneIndex < VISIBLE_LIGHT_HASH_SIZE) InterlockedOr(SharedVisibleLightHash[LaneIndex], VisibleLightHash[LaneIndex]);
// → GroupSync 后由前若干线程把 Shared* 写进 RWVisibleLightHash / RWHiddenLightHash

说明

本 shader 的汇聚点：哈希是 OR 可合并的位图，所以先用 WaveActiveBitOr 把整个波前的贡献折叠成一份，再用 WavePrefixCountBits 给各 lane 分配写槽、InterlockedOr 合进 groupshared，最后写进全局 RWVisibleLightHash/RWHiddenLightHash。这份哈希就是下一帧 Sampling 的 VisibleLightHashHistory——闭合"采样读上帧哈希 → 追踪求可见性 → 本 pass 写本帧哈希"的时域引导环路。

追踪与阴影 · 可见性求解

采样阶段抽出了"要算哪些光源样本"，本篇讲这些样本怎么求可见性——这是 MegaLights 阴影的本质。它有三条追踪后端（硬件光追 / 软件 Global SDF / Virtual Shadow Map），外加屏幕空间追踪作廉价首段，并用样本压缩把稀疏的有效光线挤到一起高效派发。还讲清 MarkVSMPages 如何让 VSM 只渲染真正被采样命中的页。所有符号/CVar 均取自 UE5.8 本地源码。

问题：稀疏光线的高效派发

降分辨率 + 早剔除后，光线是"稀疏"的

经过下采样和采样阶段的早剔除，真正需要追踪的光线在屏幕上分布得很不均匀——有的 tile 满是有效样本，有的几乎全空。如果直接按像素网格派发光线，大量线程会空转，浪费 GPU 占用率。MegaLights 先跑 Compact（FCompactLightSampleTracesCS）把所有有效样本压缩成一段连续列表，再用 FInitCompactedTraceTexelIndirectArgsCS 生成间接派发参数，让追踪 pass 只对"确实要追的样本"启动线程。这是所有随机采样管线（含 Lumen）通用的 compaction 技巧。

HWRT：inline vs raygen，与材质求值

硬件光追有两种派发方式：inline（compute 里 TraceRayInline，r.MegaLights.HardwareRayTracing.Inline）和 raygen（独立 ray generation shader）。命中后是否求值材质由 r.MegaLights.HardwareRayTracing.EvaluateMaterialMode 控制（见 #4 EMaterialMode）：最快的是把命中当纯遮挡（不求材质），需要 alpha test / 半透明阴影时才求 AnyHit 材质。permutation 里 FEvaluateMaterials/FSupportContinuation/FForceTwoSided 就对应这些取舍。

Screen Trace：屏内廉价首段

在主追踪之前，可选先做屏幕空间追踪（r.MegaLights.ScreenTraces）：沿光线在屏幕深度缓冲上步进求交，命中屏内几何就直接得到遮挡，省下一条昂贵的世界光线。它是 Lumen 屏幕追踪思路在阴影可见性上的复用。

CVar作用
r.MegaLights.ScreenTraces是否启用屏内首段追踪
r.MegaLights.ScreenTraces.MaxIterations屏内步进最大迭代数
r.MegaLights.ScreenTraces.RelativeDepthThickness相对深度厚度（判命中的容差）
r.MegaLights.ScreenTraces.NormalBias法线偏移，避免自相交
r.MegaLights.DistantScreenTraces远距离屏幕追踪（补世界光线的远端命中）

屏内追踪只能处理"屏幕上可见的遮挡物"，屏外遮挡仍需世界追踪，所以它是首段加速而非替代。permutation 里 FDistantScreenTraces 就是这段。

MarkVSMPages：只渲染要用的页

VSM 的"按需渲染"配合 MegaLights 采样

Virtual Shadow Map 是按页（page）稀疏分配的。若不加干预，一个走 VSM 的 MegaLights 光源会保守地标记所有可能用到的页去渲染，浪费大量 shadow 渲染成本。MegaLights::MarkVSMPages(...)（配合 r.MegaLights.VSM.MarkPages，默认 1）反过来做：先看采样阶段实际抽中了哪些光源样本、命中哪些页，只标记这些页去渲染。这让"VSM + MegaLights"这条组合真正省钱——阴影渲染量也随采样预算收敛，而非随光源数膨胀。

MegaLights.cpp L2020 · MegaLightsRayTracing.cpp L1539（MegaLights::MarkVSMPages）· CVarMegaLightsVSMMarkPages（L494）

标记完成后，FVirtualShadowMapTraceLightSamplesCS 在 MegaLightsVSMTracing.usf 里对样本采样 VSM 深度求可见性。采样阶段读到的 ShadowMaskBits 纹理也来自这条链路。

光线偏移与自相交

阴影光线最经典的坑是自相交（shadow acne）和漏光（peter panning）。MegaLights HWRT 提供一组偏移旋钮平衡两者：

CVar作用

与 Lumen 追踪的关系

同一套追踪基础设施

共同点MegaLights 的三条后端（HWRT / Global SDF / Screen Trace）与 Lumen 的追踪后端是同一套基础设施：都包含 LumenHardwareRayTracingCommon.h、共用 Global Distance Field 与屏幕追踪。求值内核 MegaLightsRayTracing.ush 更是被 Lumen 随机直接光照直接借用。

不同点MegaLights 追踪的是光源可见性阴影光线（点到光源），命中即遮挡；Lumen GI 追踪的是辐照度采集光线，命中后还要采样 Surface Cache 的世界光照。此外 MegaLights 独有 VSM 追踪后端与 MarkVSMPages，把传统 shadow map 也纳入随机采样框架，这是 Lumen GI 没有的。

最终总结

追踪阶段是 MegaLights 阴影的核心：先用 Compact 把稀疏有效样本挤成连续列表间接派发，再走三条后端之一求可见性——硬件光追（inline/raygen，精确）、软件 Global SDF（无 HWRT 兜底）、Virtual Shadow Map（把传统 shadow map 纳入随机框架），并可用 Screen Trace 作屏内廉价首段。MarkVSMPages 让 VSM 只渲染被采样命中的页，使"VSM+MegaLights"成本随采样预算收敛。一组偏移 CVar 平衡自相交与漏光。这套后端与 Lumen 共享，求值内核 MegaLightsRayTracing.ush 两处复用。

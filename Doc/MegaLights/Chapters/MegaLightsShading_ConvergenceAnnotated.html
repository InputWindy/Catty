着色与解析 · Tile 类型与结果重建

可见性求出后，MegaLights 要把"降分辨率、少样本"的结果着色并重建回全分辨率。这里两件事交织在一起：按材质复杂度把屏幕分块（tile 分类）只为需要的像素跑昂贵 shader，以及 Resolve 把稀疏样本积分成漫反射/镜面两路光照并算出着色置信度（ShadingConfidence）供去噪用。所有符号/CVar 均取自 UE5.8 本地源码。

① Tile 分类：只为复杂像素花复杂钱

不同像素的着色开销天差地别

一个只受简单点光影响的平坦表面，和一个有各向异性、次表面、多个矩形光带纹理的复杂材质像素，着色开销差几十倍。若都跑同一个"最全能"的 shader，简单像素就在为用不到的分支买单。MegaLights 用 Tile 分类（TileClassificationMark）先扫一遍屏幕，把每个 tile 打上类型标签，再对每种类型派发对应 permutation 的 shader——简单 tile 走精简 shader，复杂 tile 才走全功能 shader，空 tile 直接跳过。

Engine/Source/Runtime/Renderer/Private/MegaLights/MegaLightsInternal.h L308-331 · enum class ETileType

ETileType 沿两个维度组合：着色复杂度（Simple / Complex / Single / ComplexSpecial）× 光源形态（普通 / _Rect 矩形光 / _Rect_Textured 带纹理矩形光），外加 Empty。Substrate 材质另有 blendable / adaptive 上限。

着色类含义
SimpleShading简单材质（默认漫反+镜面），最轻
ComplexShading复杂材质（各向异性/多 BSDF 等）
SingleShading单一 BSDF 快路径
ComplexSpecialShading特殊材质（如次表面/毛发等）
Empty无有效光样本，直接清零/跳过

每种输入（GBuffer/Hair/FrontLayer）只用其中一个子集：GetShadingTileTypes(InputType, Platform) 决定该输入编译哪些 tile permutation——头发主要走 Complex，前层半透明走 Simple。

② 着色：矩形光 / 纹理 / IES / 光照函数

FShadeLightSamplesCS 对每个样本按其光源类型施光。除普通点光/聚光外，MegaLights 支持完整的面光源与调制特性（对应 tile 的 _Rect / _Rect_Textured 后缀与相关 CVar）：

特性CVar说明
矩形光—_Rect tile，面光源着色
纹理矩形光r.MegaLights.TexturedRectLights（1）_Rect_Textured tile，采源纹理
IES 光度r.MegaLights.IESProfiles（1）按 IES atlas 调制强度
光照函数r.MegaLights.LightFunctions（1）光照函数材质调制
次表面透射r.MegaLights.Transmission（true）透射项着色
光照通道r.MegaLights.LightingChannels（1）通道不匹配则阻挡

EMaterialMode：命中要不要求材质

着色的精度与追踪时的命中材质求值耦合。EMaterialMode（MegaLightsInternal.h）有三档：Disabled（命中即遮挡，最快，忽略 alpha test）、AHS（AnyHitShader，命中求材质做 alpha 遮罩，用于带镂空贴图的植被等）、RetraceAHS（先快速遮挡、需要时再用 any-hit 重追，对应追踪 permutation 的 FSupportContinuation）。由 r.MegaLights.HardwareRayTracing.EvaluateMaterialMode 选择。

③ Resolve：稀疏样本 → 全分辨率两路光照

Resolve 是本阶段的收束：把降分辨率、每像素少数样本的着色结果积分并上采样成全分辨率的漫反射 + 镜面两路光照，同时输出着色置信度。

MegaLightsResolve.cpp · FShadeLightSamplesCS::FParameters（L103-114）
RWTexture2D<float3> RWResolvedDiffuseLighting; // 漫反射结果 RWTexture2D<float3> RWResolvedSpecularLighting; // 镜面结果 RWTexture2D<float> RWShadingConfidence; // 着色置信度 [0,1] uint32 UseShadingConfidence; // r.MegaLights.ShadingConfidence

为什么分 Diffuse / Specular 两路

漫反射低频、镜面高频，去噪时需要不同强度的滤波（镜面滤太狠会糊掉高光）。Resolve 把两路分开输出，让下游去噪（#5）能分别处理。ShadingConfidence 则记录"这个像素的着色结果有多可信"——样本越充分、命中越一致，置信度越高；去噪据此决定空间滤波的力度：低置信度像素多滤、高置信度像素少动，避免过度模糊。

④ 回写 VisibleLightHash：闭合历史引导

着色阶段还顺手回写可见光哈希（FVisibleLightHashCS → VisibleLightHashCS，MegaLightsVisibleLightHash.usf）：把"本帧这个 tile 里哪些光实际可见 / 被隐藏"记录进哈希，供下一帧的采样阶段做 Guide by History（见 #2）。这就闭合了"采样读上帧哈希 → 追踪求可见性 → 着色回写本帧哈希"的时域引导环路。

与 Lumen 施光的关系

tile 分类是延迟光照的共同优化

共同点按材质复杂度分 tile、逐 tile 派发对应 permutation，是 UE 延迟光照（含 Lumen、传统 FDeferredLightPS、Substrate）通用的优化思路。MegaLights 的 ETileType 与 Substrate 的 tile 分类共享 SHADING_MAX_SUBSTRATE_* 上限。

不同点MegaLights 的着色作用在随机样本上而非直接对全光源，且必须额外做 Resolve 上采样（因为在降分辨率上采样）并输出 ShadingConfidence 驱动去噪——这是随机采样管线特有的、传统确定性施光不需要的两步。

最终总结

着色与解析把"可见性"变成"画面上的光"：先 Tile 分类（ETileType：Simple/Complex/Single/ComplexSpecial × Rect/Textured + Empty）按材质复杂度分块，只为复杂像素跑全功能 shader；FShadeLightSamplesCS 逐 tile 施光（含矩形光/纹理/IES/光照函数/透射，命中材质求值由 EMaterialMode 的 Disabled/AHS/RetraceAHS 控制）；Resolve 把降分辨率少样本结果重建成全分辨率的 Diffuse/Specular 两路 + ShadingConfidence；最后回写 VisibleLightHash 闭合历史引导环路。产物交给去噪（#5）做最后的时空磨平。

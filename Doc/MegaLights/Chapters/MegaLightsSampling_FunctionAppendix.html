④ FLightTargetPDF 求值

MegaLightsLightTargetPDF.ush L9-60
struct FLightTargetPDF { float Weight; float Luminance; }; // Luminance 线性无 falloff FLightTargetPDF GetLocalLightTargetPDF(int ForwardLightIndex, FDeferredLightData LightData, float4 LightAttenuation, float3 TranslatedWorldPosition, FMegaLightsMaterial Material, uint2 ScreenCoord) { LightData.ShadowedBits = 1; // 假设完全可见 // 头发：复杂透射 if (Material.bNeedsComplexTransmittance) LightData.HairTransmittance = EvaluateDualScattering(...); FDeferredLightingSplit SplitLighting = GetMegaLightsSplitLighting(...); float Lum = SplitLighting.LightingLuminance * View.PreExposure; if (Lum > MinSampleWeight && LightData.IESAtlasIndex >= 0) Lum *= ComputeLightProfileMultiplier(...); // IES LightTargetPDF.Luminance = Lum; Lum *= SmoothFalloffMask(Lum, MinSampleWeight); // 平滑早剔除 LightTargetPDF.Weight = log2(Lum + 1.0f); // 感知加权 return LightTargetPDF; }

为什么 log2 而不是线性

直接用线性 Luminance 当采样权重，会让一个亮度极高但实际被遮挡的光吸走几乎所有样本，造成阴影边缘噪声爆炸。log2(Lum+1) 把动态范围压平，配合 Guide by History 一起，是这套采样"面对极端亮度差仍稳定"的两大支柱。

⑤ VisibleLightHash 布局

MegaLights.cpp L520-524, L1452-1457
constexpr int32 VisibleLightHashTileSize = VISIBLE_LIGHT_HASH_TILE_SIZE; constexpr int32 VisibleLightHashSize = 4; // 每 tile 4 个 uint（可见光哈希） constexpr int32 HiddenLightHashSize = 2; // 每 tile 2 个 uint（隐藏光哈希） VisibleLightHashSizeInTiles = DivideAndRoundUp(SceneExtent, VisibleLightHashTileSize); VisibleLightHashBufferSize = TilesX * TilesY * VisibleLightHashSize; HiddenLightHashBufferSize = TilesX * TilesY * HiddenLightHashSize;

哈希把"光源 id"散列到固定位数的 bitfield：可见光用 4 uint（128 bit）、隐藏光用 2 uint（64 bit）。采样时查上帧哈希判断某光是否"曾被隐藏"，据此折减 PDF。体积分支有独立的 VolumeVisibleLightHash*（三维 tile）。哈希的构建/过滤见 #4 附录 与 #5。

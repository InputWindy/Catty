MegaLights 总览与管线入口

MegaLights 是 UE5.8 的多光源实时阴影方案（实验性）：让"投射阴影的光源"数量对帧开销的影响从"近似线性"压成"近似恒定"。它的做法借鉴离线蒙特卡洛——每像素只随机抽少量光源样本、用光线追踪求可见性、再靠时空去噪把噪声磨平。本篇建立整套书的骨架：它解决什么问题、三种模式如何判定、单帧九个阶段各干什么、三种输入有何差异。所有符号/CVar 均取自 UE5.8 本地源码。

为什么需要它：光源数量的诅咒

传统阴影按"光源 × 分辨率"膨胀

UE 的传统延迟光照对每个投射阴影的光源都要：渲染一份 shadow map（或 VSM 页）、逐光源做一次全屏施光 pass。光源少时很高效，但一片区域里几十上百个动态光同时投影时，shadow map 渲染 + 施光 pass 数量随光源数线性上涨，很快就成为帧预算的大头。这也是为什么传统项目要严格限制"投影光源"的数量。

MegaLights 换了个思路：不再"每个光源都完整算一遍阴影"，而是把它当成一个蒙特卡洛积分问题——每个像素固定只抽 NumSamplesPerPixel 个光源样本（默认 4，还会因下采样进一步折算），对样本发光线求可见性，成本只跟"像素数 × 每像素样本数"走，与场景投影光源总数解耦。代价是单帧有噪声，交给时空去噪（Temporal + Spatial）补回来。

与 Lumen Stochastic Direct Lighting 的关系

同一套内核的两处落地

共同点MegaLights 与 Lumen 的 Surface Cache 随机直接光照共享同一个求值内核 MegaLightsRayTracing.ush，本质都是"固定预算抽样 + 光追可见性 + 时域累积去噪"。可以说随机直接光照就是"把 MegaLights 的多光源采样搬进 Surface Cache 世界空间"。

不同点MegaLights 直接作用于屏幕最终像素（GBuffer / 头发 / 前层半透明），产出直接进 SceneColor；随机直接光照作用于 Surface Cache 世界空间 card texel，产出可跨帧复用的世界空间光照 atlas。本书讲屏幕像素这一侧；世界空间那一侧见 Lumen 篇。

门禁与模式判定（三级漏斗）

MegaLights 能不能开、以什么模式开，由三层判定决定，全部在 MegaLights.cpp。

Engine/Source/Runtime/Renderer/Private/MegaLights/MegaLights.cpp · IsRequested / HasRequiredTracingData / IsEnabled / GetMegaLightsMode

① IsRequested · 用户/项目是否请求

IsRequested() 要求同时满足：后处理体积开关 FinalPostProcessSettings.bMegaLights、scalability 允许 r.MegaLights.Allowed != 0、以及三个 ShowFlag（Lighting / DirectLighting / MegaLights）都开，且该平台已编译 MegaLights shader。项目级默认开关是 r.MegaLights.EnableForProject（默认 0，实验特性默认关）。

② HasRequiredTracingData · 有没有追踪后端

HasRequiredTracingData() = IsHardwareRayTracingSupported() 或 IsSoftwareRayTracingSupported()。MegaLights 必须要有一条能求可见性的追踪后端。IsEnabled = IsRequested && HasRequiredTracingData——这是全局总开关，后续几乎所有 IsUsing* 判定都以它为前提。

③ GetMegaLightsMode · 逐光源定模式

GetMegaLightsMode(ViewFamily, LightType, bLightAllowsMegaLights, ShadowMethod) 是逐光源调用的：方向光默认被排除（除非 r.MegaLights.DirectionalLights 打开），且必须 IsEnabled 且该光源允许 MegaLights。阴影方法为 Default 时按 r.MegaLights.DefaultShadowMethod 解析（1→VSM，否则→RayTracing，默认 0 即 RT）。最终返回 EnabledVSM / EnabledRT / Disabled 三选一（RT 分支还要求 IsRayTracingAllowedForView()）。

EMegaLightsMode GetMegaLightsMode(..., uint8 LightType, bool bLightAllowsMegaLights, ShadowMethod) { if ((LightType != Directional || CVarDirectionalLights) && IsEnabled(ViewFamily) && bLightAllowsMegaLights) { if (ShadowMethod == Default) ShadowMethod = (GMegaLightsDefaultShadowMethod == 1) ? VirtualShadowMap : RayTracing; if (ShadowMethod == VirtualShadowMap) return EnabledVSM; else if (View.IsRayTracingAllowedForView()) return EnabledRT; } return Disabled; }

下采样：把成本再砍一刀

确定要跑后，MegaLights 通常不在全分辨率上采样/追踪，而是先降分辨率。GetDownsampleFactorXY(InputType, Platform) 按 r.MegaLights.DownsampleMode 返回下采样因子：

DownsampleMode因子 XY含义
0(1,1)Disabled，全分辨率
1(2,1)Checkerboard 棋盘，横向减半
2（默认）(2,2)Half-resolution，1/4 像素数

Reference 模式（GetReferenceShadingPassCount > 1，仅编辑器 PC 用于对比参考）会强制回到 (1,1)。降分辨率的样本最后由 Resolve 阶段重建回全分辨率——这正是后面 tile 分类与去噪要处理的核心。

三种输入：一套管线，三个消费者

MegaLights 的采样-追踪-着色管线被三种输入复用（enum class EMegaLightsInput）。它们走同一套 CS，但通过 permutation/前缀区分资源与分辨率。

输入 EMegaLightsInput作用对象下采样 CVar命名前缀
GBuffer不透明主体像素（最主要路径）r.MegaLights.DownsampleModeMegaLights.*
HairStrands头发几何（Deep Shadow 之外的直接光）r.MegaLights.HairStrands.DownsampleModeMegaLights.HairStrands.*
FrontLayerTranslucency前层半透明表面直接光r.MegaLights.DownsampleModeMegaLights.FrontLayerTranslucency.*

最终总结

MegaLights 是 UE5.8 为"大量动态投影光源"准备的实验性方案：把逐光源阴影（成本随光源数线性膨胀）改成"每像素抽固定数量光源样本 + 光追求可见性 + 时空去噪"，让阴影成本与投影光源总数解耦。它由三级漏斗把关（IsRequested → HasRequiredTracingData → GetMegaLightsMode，默认关、需 HWRT/SWRT、不含方向光），单帧走"分块 → 下采样 → 采样 → 追踪 → 着色/解析 → 去噪"九个阶段（FMegaLightsViewContext），并被 GBuffer/HairStrands/FrontLayerTranslucency 三种输入复用。理解了这条骨架，后面每一篇都是往其中某个阶段里钻细节。

体积光照 · Froxel 网格上的 MegaLights

前五章讲的都是屏幕表面（GBuffer）的直接光照。但体积雾（Volumetric Fog）和光照半透明（Lit Translucency）需要的是空间中每一点的光照，而不只是可见表面。MegaLights 把同一套"随机采样 + 光追可见性 + 引导采样"的思路搬到了一个视锥体素网格（froxel volume）上：在每个体素里随机抽样光源、追阴影线、缓存结果，供雾和半透明查询。本章讲这个体积分支的网格布局、统一采样与三阶段管线。所有符号/CVar 均取自 UE5.8 本地源码。

① 为什么体积要独立一套：表面 ≠ 空间

屏幕像素只覆盖"可见表面"，雾要的是"整个空间"

GBuffer 管线（#1–#5）只在每个屏幕像素对应的那一个表面点上算光照。但体积雾的光线穿过空气时，每一段路程都在散射光——你需要知道摄像机到远处之间每一个空间点被多少光照亮，包括没有任何实体表面的空气。半透明物体同理，它内部各深度都要接收光照。所以体积不能复用屏幕的 2D 结果，必须在一个覆盖视锥的3D 体素网格上独立地做一遍"采样—追踪—施光"。

网格是典型的视锥对齐 froxel：XY 按 r.MegaLights.Volume.GridPixelSize=8 像素一格划分，Z 方向 r.MegaLights.Volume.GridSizeZ=128 片，且切片按 DepthDistributionScale=32 做指数分布——近处密、远处疏，匹配透视下近处需要更高精度的特性（CalculateGridZParams，同 Volumetric Fog 的 Z 布局）。

② 统一采样：雾和半透明共用一次追踪

体积雾和光照半透明本质都在问"这个空间点被哪些光照亮、有没有被挡"。MegaLights 用 r.MegaLights.Volume.Unified=1 把两者合并成一次采样+追踪，避免重复劳动：

③ 采样 + 追踪：屏幕管线的 3D 翻版

体积三阶段和屏幕管线一一对应，只是把 2D tile 换成 3D 体素、把 Texture2D 换成 Texture3D：

降采样 + HZB 剔除：体素太多，必须省

一个 froxel volume 有 (屏宽/8)×(屏高/8)×128 个体素，数量巨大。MegaLights 用两招压开销：① 降采样 r.MegaLights.Volume.DownsampleMode=2（半分辨率 2×2×2，即 8 个体素合 1 个抽样后再上采）；② HZB 遮挡剔除 r.MegaLights.Volume.HZBOcclusionTest=1：被场景深度完全遮住的体素直接跳过，不浪费光线。每体素抽 Volume.NumSamplesPerVoxel=2（可 4）个样本，低于 Volume.MinSampleWeight=0.1 影响的样本被剔除。

④ Guide by History 也搬进了体积

屏幕管线的历史引导（#2）在体积里同样存在：r.MegaLights.Volume.GuideByHistory=1 让被上帧遮蔽的光少抽样、可见的光多抽样，配合 FVolumeVisibleLightHashCS 回写、FVolumeFilterVisibleLightHashCS 对体素哈希做空间滤波（体积噪声比屏幕更明显，需要额外平滑）。FVolumeShadeLightSamplesCS 的 MaxShadingWeight / MaxShadingWeightForHiddenLight 参数则限制单样本的最大贡献，防止个别高权重样本在体积里炸出萤火虫噪点。

相位函数与体积特有参数

FMegaLightsVolumeParameters 里有一批屏幕管线没有的字段：VolumePhaseG（Henyey-Greenstein 相位函数各向异性，决定雾的前/后向散射）、MegaLightsVolumeZParams（指数 Z 分布参数）、VolumeFrameJitterOffset（时域抖动，配合体积去噪）。这些是"体积散射"物理正确所必需，而表面着色用不到。

与 Volumetric Fog / Lumen 的关系

沿用 Froxel 基建，替换光照来源

共同点视锥 froxel 网格、指数 Z 分布（CalculateGridZParams）、HG 相位函数、时域抖动去噪——这些都是 UE Volumetric Fog 的既有基建，MegaLights 体积直接沿用，产物 GetOwnMegaLightsVolume() 也是喂给同一套雾积分/半透明查询。

不同点传统 Volumetric Fog 对每个体素逐光源累加光照（光多则线性变慢，且投影光昂贵），MegaLights 体积改成每体素随机抽几个样本追阴影线——和屏幕管线一样，把开销与光源数解耦，让大量投影光的体积阴影成为可能。这正是 MegaLights "统一采样框架"的价值：屏幕和体积复用同一套 MegaLightsRayTracing.ush 追踪内核与引导采样逻辑。

最终总结

体积光照是 MegaLights 在视锥体素网格上的平行分支，解决"空间中每一点（含空气）的光照"——体积雾与光照半透明的需求。网格为 froxel（XY 每 8px 一格、Z 128 片指数分布）；Unified=1 让雾和半透明共用一次采样+追踪；三阶段 GenerateVolumeSamples → VolumeRayTrace → VolumeResolve 是屏幕管线的 3D 翻版（Texture3D、每体素 2/4 样本），并用半分辨率降采样 + HZB 剔除压体素数量、Guide by History + 哈希空间滤波压噪、相位函数/Z 参数/抖动处理体积散射物理。可跑在 async compute 上并行。至此 MegaLights 六大主题（总览→采样→追踪→着色→去噪→体积）全部闭环：一套随机采样框架，同时服务屏幕表面与体积空间的多光源直接光照与阴影。
